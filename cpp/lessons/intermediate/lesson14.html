إدارة الذاكرة الديناميكية في ++C

new / delete – التحكم اليدوي بالذاكرة

ذاكرة الكومة (Heap)

منطقة ذاكرة كبيرة تُدار يدوياً، تتيح إنشاء متغيرات تستمر بعد انتهاء الدوال.

تحكم كامل

المبرمج مسؤول عن تخصيص (new) وتحرير (delete) الذاكرة في الوقت المناسب.

مسؤولية كبيرة

سوء الإدارة يؤدي إلى تسرب الذاكرة (memory leak) أو تعطل البرنامج.

1. الذاكرة: Stack vs Heap

2. التخصيص والتحرير: new / delete

تخصيص متغير واحد أو مصفوفة على الكومة باستخدام new، وتحرير الذاكرة بـ delete.

// تخصيص متغير واحد
int *p = new int;      // تخصيص مساحة لعدد صحيح
*p = 42;               // تعيين قيمة
cout << *p;            // استخدام القيمة
delete p;              // تحرير الذاكرة (لا تنسى!)

// تخصيص مع التهيئة
int *q = new int(100); // تخصيص وتهيئة بالقيمة 100

// تخصيص مصفوفة
int *arr = new int[10]; // مصفوفة من 10 أعداد
for(int i = 0; i < 10; i++) arr[i] = i;
delete[] arr;           // تحرير مصفوفة (استخدم [])

// تخصيص مصفوفة مع تهيئة (C++11)
int *arr2 = new int[5]{1, 2, 3, 4, 5};
خطر كبير: كل new يجب أن يقابله delete، وكل new[] يقابله delete[]. الخلط يؤدي إلى سلوك غير محدد.

3. تسرب الذاكرة (Memory Leak)

يحدث عندما تفقد المؤشر إلى ذاكرة مخصصة دون تحريرها. يظل الجزء محجوزاً حتى إغلاق البرنامج.

void createLeak() {
    int *p = new int(5);
    // ننسى delete p; -> تسرب!
} // عند الخروج من الدالة، المؤشر p يختفي لكن الذاكرة لا تزال محجوزة

int main() {
    while(true) {
        int *x = new int(10);
        // بدون delete، يستهلك البرنامج ذاكرة حتى الانهيار
    }
    return 0;
}

نصيحة ذهبية: استخدم المؤشرات الذكية (smart pointers) في ++C الحديثة لتجنب التسريبات.

4. المؤشرات البرية (Dangling Pointers)

مؤشر يشير إلى ذاكرة تم تحريرها. استخدامه يؤدي إلى نتائج كارثية.

int *p = new int(42);
delete p;
// p الآن "مؤشر بري" (dangling)
cout << *p; // سلوك غير متوقع (قد ينهار البرنامج)

// الحل: تعيين المؤشر إلى nullptr بعد الحذف
delete p;
p = nullptr;

if (p != nullptr) { // آمن
    cout << *p;
}

5. تخصيص الهياكل والكائنات

struct Student {
    string name;
    int age;
    double gpa;
};

int main() {
    // تخصيص هيكل على الكومة
    Student *s1 = new Student;
    s1->name = "أحمد";
    s1->age = 22;
    s1->gpa = 3.8;

    // تخصيص مع تهيئة باستخدام {}
    Student *s2 = new Student {"فاطمة", 21, 3.9};

    cout << s2->name;
    delete s1;  // تحرير
    delete s2;

    // تخصيص مصفوفة من الهياكل
    Student *classroom = new Student[3];
    classroom[0].name = "سعيد";
    // ...
    delete[] classroom;
    return 0;
}

6. المؤشرات الذكية (C++11+)

أغلفة (wrappers) تدير الذاكرة تلقائياً. موجودة في <memory>. الأنواع الرئيسية: unique_ptr, shared_ptr, weak_ptr.

#include <memory>

int main() {
    // unique_ptr: ملكية حصرية
    std::unique_ptr<int> uptr(new int(50));
    cout << *uptr;   // 50
    // لا تحتاج delete، تتحرر تلقائياً عند الخروج من النطاق

    // shared_ptr: ملكية مشتركة (عد مرجعي)
    std::shared_ptr<int> sptr1 = std::make_shared<int>(100);
    std::shared_ptr<int> sptr2 = sptr1; // الآن العد = 2
    // عندما يخرج آخر shared_ptr من النطاق، تتحرر الذاكرة.

    // make_unique (C++14) و make_shared أفضل (أمان استثنائي)
    auto u = std::make_unique<double>(3.14);
    auto s = std::make_shared<string>("مرحبا");
    return 0;
}

7. Placement new (بناء في موقع محدد)

يسمح ببناء كائن في ذاكرة موجودة مسبقاً. نادر الاستخدام لكنه مفيد في الأنظمة المضمنة.

#include <new>  // لازم

char buffer[sizeof(int) * 10];  // ذاكرة خام

int main() {
    // بناء int في بداية buffer
    int *p = new (buffer) int(42);
    cout << *p;
    // لا تستخدم delete هنا، فقط استدعِ المدمر إذا لزم الأمر
    // p->~int();  // تدمير يدوي
    return 0;
}

أفضل الممارسات

  • استخدم new/delete فقط عند الضرورة.
  • في ++C الحديثة، استخدم المؤشرات الذكية (smart pointers).
  • بعد delete، اجعل المؤشر nullptr.
  • طابق new مع delete و new[] مع delete[].
  • تجنب تخصيص الذاكرة داخل الدوال دون توثيق المسؤولية.
  • استخدم std::vector بدل المصفوفات الديناميكية اليدوية.
