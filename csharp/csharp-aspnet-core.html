1

ما هو ASP.NET Core؟

ASP.NET Core هو إطار عمل مفتوح المصدر من مايكروسوفت لبناء تطبيقات ويب حديثة وAPIs. يشغّل على Windows وLinux وmacOS، وهو واحد من أسرع أطر الويب في العالم.

ماذا يمكنك أن تبني به؟

REST APIs

خدمات HTTP حديثة تُستهلك من الويب والموبايل.

Web Apps

تطبيقات ويب كاملة بـ Razor Pages أو MVC أو Blazor.

SignalR

اتصال ثنائي الاتجاه في الوقت الفعلي (WebSockets).

Microservices

خدمات صغيرة قابلة للنشر في حاويات Docker.

لماذا ASP.NET Core؟

  • سريع جداً: من أسرع أطر الويب (TechEmpower Benchmarks).
  • مفتوح المصدر: على GitHub، قابل للمساهمة والتخصيص.
  • عابر للمنصات: يعمل على Windows / Linux / macOS.
  • Dependency Injection مدمج: لا تحتاج مكتبات خارجية.
  • Minimal APIs: نقاط نهاية بسيطة في بضعة أسطر.
  • نظام بيئي غني: Entity Framework, Identity, SignalR...

لماذا هذا الدرس مهم؟

ASP.NET Core هو أساس كل تطبيق ويب حديث بـ C#. إتقانه يفتح لك أبواباً واسعة في سوق العمل: من شركات الناشئة إلى المؤسسات الكبرى.

مكونات الطلب

المكوّن مثال الشرح

الكود المعنى متى يُستخدم

Program.cs — نقطة الدخول

هذا الملف هو قلب التطبيق. في .NET 6+ تم تبسيطه بشكل كبير — لا يوجد Startup.cs منفصل.

Program.cs
var builder = WebApplication.CreateBuilder(args);

// 1. تسجيل الخدمات (DI Container)
builder.Services.AddControllers();
builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();

var app = builder.Build();

// 2. Middleware Pipeline
if (app.Environment.IsDevelopment())
{
    app.UseSwagger();
    app.UseSwaggerUI();
}

app.UseHttpsRedirection();
app.UseAuthorization();
app.MapControllers();

// 3. تشغيل التطبيق
app.Run();

4

Middleware Pipeline

كل طلب يمر عبر سلسلة من Middlewares. كل واحد يمكنه: معالجة الطلب، تعديله، أو تمريره للتالي.

ترتيب الـ Middlewares مهم

  1. Exception Handling: في البداية لالتقاط كل الأخطاء.
  2. HTTPS Redirection: تحويل HTTP إلى HTTPS.
  3. Static Files: تقديم الملفات الثابتة (CSS/JS).
  4. Routing: تحديد المسار المناسب.
  5. Authentication: التحقق من هوية المستخدم.
  6. Authorization: التحقق من الصلاحيات.
  7. Custom Middleware: منطقك الخاص.
  8. Endpoints: التنفيذ الفعلي.

مثال: Middleware مخصص للتسجيل

Middleware/RequestLogger.cs
public class RequestLoggerMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<RequestLoggerMiddleware> _logger;

    public RequestLoggerMiddleware(
        RequestDelegate next,
        ILogger<RequestLoggerMiddleware> logger)
    {
        _next = next;
        _logger = logger;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        var sw = Stopwatch.StartNew();

        await _next(context);

        sw.Stop();
        _logger.LogInformation(
            "{Method} {Path} → {StatusCode} in {ms}ms",
            context.Request.Method,
            context.Request.Path,
            context.Response.StatusCode,
            sw.ElapsedMilliseconds);
    }
}

تسجيله في Program.cs

Program.cs
var app = builder.Build();

app.UseMiddleware<RequestLoggerMiddleware>();

app.UseHttpsRedirection();
app.UseAuthorization();
app.MapControllers();

app.Run();

الترتيب مهم!

لو وضعت UseAuthentication قبل UseRouting، لن تعمل المصادقة. الترتيب جزء من العقد.

5

Controllers و Minimal APIs

ASP.NET Core يوفّر طريقتين لتعريف endpoints: Controllers للنظم الكبيرة، وMinimal APIs للبساطة والسرعة.

الطريقة الأولى: Controller

Controllers/UsersController.cs
using Microsoft.AspNetCore.Mvc;

namespace MyApi.Controllers;

[ApiController]
[Route("api/[controller]")]
public class UsersController : ControllerBase
{
    private readonly IUserService _service;

    public UsersController(IUserService service)
    {
        _service = service;
    }

    [HttpGet]
    public async Task<ActionResult<List<UserDto>>> GetAll()
    {
        var users = await _service.GetAllAsync();
        return Ok(users);
    }

    [HttpGet("{id}")]
    public async Task<ActionResult<UserDto>> GetById(int id)
    {
        var user = await _service.GetByIdAsync(id);
        if (user is null) return NotFound();
        return Ok(user);
    }

    [HttpPost]
    public async Task<ActionResult<UserDto>> Create(CreateUserDto dto)
    {
        var user = await _service.CreateAsync(dto);
        return CreatedAtAction(
            nameof(GetById),
            new { id = user.Id },
            user);
    }

    [HttpDelete("{id}")]
    public async Task<IActionResult> Delete(int id)
    {
        var deleted = await _service.DeleteAsync(id);
        if (!deleted) return NotFound();
        return NoContent();
    }
}

الطريقة الثانية: Minimal API

Program.cs
var app = builder.Build();

var users = app.MapGroup("/api/users")
    .WithTags("Users");

users.MapGet("/", async (IUserService svc) =>
    Results.Ok(await svc.GetAllAsync()));

users.MapGet("/{id:int}", async (int id, IUserService svc) =>
{
    var user = await svc.GetByIdAsync(id);
    return user is null
        ? Results.NotFound()
        : Results.Ok(user);
});

users.MapPost("/", async (CreateUserDto dto, IUserService svc) =>
{
    var user = await svc.CreateAsync(dto);
    return Results.Created($"/api/users/{user.Id}", user);
});

app.Run();

متى تستخدم أيهما؟

المعيار Controllers Minimal APIs
البساطة متوسطة عالية
المشاريع الكبيرة مثالي ممكن
الأداء ممتاز ممتاز
الاختبار سهل سهل
الدعم كامل كامل (من .NET 7)

توصية عملية

ابدأ بـ Minimal APIs للخدمات الصغيرة والـ microservices. انتقل إلى Controllers للمشاريع الكبيرة حيث التنظيم والوضوح مطلوبان.

6

Dependency Injection

ASP.NET Core يحتوي DI Container مدمج. تسجّل الخدمات فيه، ثم تُحقن تلقائياً في مكان استخدامها.

الدورة الحياتية (Lifetimes)

النوع الوصف الاستخدام
Singleton نسخة واحدة طوال عمر التطبيق Cache, Config, Stateless Services
Scoped نسخة لكل طلب HTTP DbContext, Repositories, Services
Transient نسخة جديدة في كل حقن Services خفيفة بلا حالة

تسجيل الخدمات

Program.cs
// Singleton — نسخة واحدة فقط
builder.Services.AddSingleton<ICacheService, MemoryCacheService>();

// Scoped — نسخة لكل طلب
builder.Services.AddScoped<IUserService, UserService>();
builder.Services.AddScoped<IUserRepository, UserRepository>();

// Transient — نسخة جديدة في كل مرة
builder.Services.AddTransient<IEmailSender, SmtpEmailSender>();

// DbContext (Scoped افتراضياً)
builder.Services.AddDbContext<AppDbContext>(opts =>
    opts.UseSqlServer(builder.Configuration.GetConnectionString("Default")));

حقن الخدمات

Services/UserService.cs
public class UserService : IUserService
{
    private readonly IUserRepository _repo;
    private readonly ILogger<UserService> _logger;
    private readonly IEmailSender _email;

    // كل هذه تُحقن تلقائياً من DI
    public UserService(
        IUserRepository repo,
        ILogger<UserService> logger,
        IEmailSender email)
    {
        _repo = repo;
        _logger = logger;
        _email = email;
    }

    public async Task<UserDto> CreateAsync(CreateUserDto dto)
    {
        var user = new User { Name = dto.Name, Email = dto.Email };
        await _repo.AddAsync(user);

        _logger.LogInformation("User {Email} created", user.Email);
        await _email.SendWelcomeAsync(user.Email);

        return new UserDto(user.Id, user.Name);
    }
}

خطأ شائع: Captive Dependency

لا تحقن Scoped داخل Singleton. الـ Scoped سيُحجز طوال عمر التطبيق — قد يُسبب تسريباً وأخطاء خطيرة.

Entity Framework Core

EF Core هو ORM رسمي من مايكروسوفت — يحوّل كائنات C# إلى جداول SQL تلقائياً، ويلغي الحاجة لكتابة SQL يدوياً في معظم الحالات.

تعريف الكيانات (Entities)

Models/User.cs
public class User
{
    public int Id { get; set; }
    public string Name { get; set; } = "";
    public string Email { get; set; } = "";
    public DateTime CreatedAt { get; set; } = DateTime.UtcNow;

    // Navigation property
    public List<Order> Orders { get; set; } = new();
}

DbContext

Data/AppDbContext.cs
using Microsoft.EntityFrameworkCore;

public class AppDbContext : DbContext
{
    public DbSet<User> Users { get; set; }
    public DbSet<Order> Orders { get; set; }

    public AppDbContext(DbContextOptions<AppDbContext> options)
        : base(options) { }

    protected override void OnModelCreating(ModelBuilder mb)
    {
        mb.Entity<User>(b =>
        {
            b.HasKey(u => u.Id);
            b.HasIndex(u => u.Email).IsUnique();
            b.Property(u => u.Email).IsRequired().HasMaxLength(200);
        });
    }
}

استخدام EF Core

Repositories/UserRepository.cs
public class UserRepository : IUserRepository
{
    private readonly AppDbContext _db;

    public UserRepository(AppDbContext db) => _db = db;

    public async Task<List<User>> GetAllAsync() =>
        await _db.Users.AsNoTracking().ToListAsync();

    public async Task<User?> GetByIdAsync(int id) =>
        await _db.Users.FindAsync(id);

    public async Task AddAsync(User user)
    {
        _db.Users.Add(user);
        await _db.SaveChangesAsync();
    }

    public async Task UpdateAsync(User user)
    {
        _db.Users.Update(user);
        await _db.SaveChangesAsync();
    }

    public async Task<List<User>> SearchAsync(string term) =>
        await _db.Users
            .Where(u => u.Name.Contains(term) || u.Email.Contains(term))
            .ToListAsync();
}

أفضل الممارسات

  • استخدم DI دائماً: لا تنشئ new HttpClient() أو new DbContext() يدوياً.
  • افصل الطبقات: Controller → Service → Repository → DbContext.
  • استخدم DTOs: لا تُرجع الكيانات مباشرة — هذا أمان وأداء.
  • Async دائماً: كل عمليات I/O يجب أن تكون async.
  • تحقق من المدخلات: استخدم DataAnnotations أو FluentValidation.
  • معالجة استثناءات مركزية: Middleware واحد بدلاً من try/catch في كل مكان.
  • سجّل الأخطاء: Serilog + Application Insights في الإنتاج.
  • وثّق بـ Swagger: كل endpoint له ملاحظات وردود واضحة.
  • الإصدار (Versioning): ابدأ من /api/v1/ لدعم التطور.
  • Rate Limiting: استخدم AspNetCoreRateLimit لحماية API.
  • CORS مضبوط: لا تستخدم AllowAnyOrigin في الإنتاج.
  • اختبر كل شيء: اختبارات وحدة + تكامل + E2E.

قاعدة ذهبية

ASP.NET Core قوي جداً، لكن قوته تأتي مع مسؤولية. ابدأ بسيطاً، أضف الطبقات تدريجياً حسب الحاجة، ولا تُفرط في التجريد من البداية.
