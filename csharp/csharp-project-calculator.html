نظرة عامة على المشروع PROJECT OVERVIEW

الآلة الحاسبة هي المشروع المثالي للبدء: بسيط الفكرة، عميق التفاصيل. ستتعلم خلاله كيف تفصل بين واجهة المستخدم ومنطق العمل، كيف تتعامل مع أخطاء الإدخال، وكيف تبني تطبيقاً سطح مكتبياً كاملاً بـ C#.

المشروع مقسّم إلى ثلاث طبقات واضحة:

الواجهة (UI)

النموذج (Form) مع الأزرار والشاشة. يستخدم WinForms أو WPF.

المنطق (Logic)

فئة CalculatorEngine مسؤولة عن الحسابات فقط — قابلة للاختبار بمعزل.

المعالجة

التعامل مع القسمة على صفر، الإدخال الخاطئ، والتدفق الرقمي.

فلسفة الفصل (Separation of Concerns): الواجهة لا تعرف كيف تُجمَع الأرقام، والمنطق لا يعرف كيف تبدو الأزرار. هذا يجعل الكود قابلاً للاختبار وإعادة الاستخدام — على نفس المنطق يمكنك بناء واجهة Console، WinForms، أو حتى Web API.

المنطق الحسابي — CalculatorEngine CALCULATION LOGIC

نبدأ بفئة CalculatorEngine — قلب التطبيق. لا تعرف عن الأزرار أو النوافذ شيئاً، فقط تقبل أرقاماً وتُرجع نتائج. هذا يجعلها قابلة للاختبار مباشرة في Console أو اختبار وحدة.

C# — CalculatorEngine.cs 
using System;

public class CalculatorEngine
{
    public double Add(double a, double b) => a + b;

    public double Subtract(double a, double b) => a - b;

    public double Multiply(double a, double b) => a * b;

    public double Divide(double a, double b)
    {
        if (b == 0)
            throw new DivideByZeroException("لا يمكن القسمة على صفر");

        return a / b;
    }

    // تنفيذ العملية حسب الرمز
    public double Execute(double a, double b, string op) => op switch
    {
        "+" => Add(a, b),
        "-" => Subtract(a, b),
        "*" => Multiply(a, b),
        "/" => Divide(a, b),
        _   => throw new ArgumentException($"عملية غير معروفة: {op}")
    };
}

لماذا نستخدم double؟ لأن الحاسبة تتعامل مع الأرقام العشرية. لكن في أنظمة المحاسبة المالية، استخدم decimal بدلاً من double لتجنب أخطاء التقريب (0.1 + 0.2 = 0.30000000000000004).

اختبار المنطق في Console

قبل بناء الواجهة، اختبر المنطق مباشرة:

C# — Test Engine in Console 
var engine = new CalculatorEngine();

Console.WriteLine(engine.Add(5, 3));      // 8
Console.WriteLine(engine.Divide(10, 2));  // 5

try
{
    engine.Divide(5, 0);
}
catch (DivideByZeroException ex)
{
    Console.WriteLine(ex.Message); // لا يمكن القسمة على صفر
}

بناء الواجهة — WinForms BUILDING THE WINFORMS UI

الآن بعد أن جهزنا المنطق، نربطه بواجهة المستخدم. في WinForms، الواجهة تُعرَّف في ملف Form1.Designer.cs (تلقائياً)، والكود المخصص في Form1.cs.

ربط زر الجمع كمثال

C# — Form1.cs (Partial) 
public partial class Form1 : Form
{
    private readonly CalculatorEngine engine = new();
    private double currentValue = 0;
    private string pendingOp = "";

    public Form1()
    {
        InitializeComponent();
    }

    // زر رقم 5
    private void btn5_Click(object sender, EventArgs e)
    {
        txtDisplay.Text += "5";
    }

    // زر الجمع
    private void btnAdd_Click(object sender, EventArgs e)
    {
        currentValue = double.Parse(txtDisplay.Text);
        pendingOp = "+";
        txtDisplay.Clear();
    }

    // زر يساوي
    private void btnEquals_Click(object sender, EventArgs e)
    {
        try
        {
            double secondValue = double.Parse(txtDisplay.Text);
            double result = engine.Execute(currentValue, secondValue, pendingOp);
            txtDisplay.Text = result.ToString();
        }
        catch (DivideByZeroException ex)
        {
            MessageBox.Show(ex.Message, "خطأ", MessageBoxButtons.OK, MessageBoxIcon.Error);
            txtDisplay.Text = "0";
        }
        catch (Exception)
        {
            MessageBox.Show("إدخال غير صالح", "خطأ", MessageBoxButtons.OK, MessageBoxIcon.Error);
            txtDisplay.Text = "0";
        }
    }
}

التوسعة والمعالجة EXTENSIONS & ERROR HANDLING

الآلة الأساسية جاهزة، لكن النسخة الاحترافية تحتاج لمزيد من الميزات. إليك أهم التوسعات:

1. معالجة الحالات الحدّية

C# — Safe Parsing 
// ❌ قد يرمي استثناء
double value = double.Parse(txtDisplay.Text);

// ✅ آمن
if (!double.TryParse(txtDisplay.Text, out double value))
{
    MessageBox.Show("الرجاء إدخال رقم صحيح");
    return;
}

2. دعم عمليات متتالية

لتطبيق يحسب 2 + 3 * 4 بشكل صحيح، تحتاج إلى مكدس عمليات (Stack) يحترم أسبقية العمليات. هذا تعقيد إضافي، لكنه يجعل الآلة قريبة من الحاسبات العلمية.

C# — Operator Precedence Hint 
// مبسّط: التقييم المباشر لا يحترم الأسبقية
// 2 + 3 * 4 = 20 (خطأ)

// للإصلاح: استخدم مكتبة Expression Trees
using System.Linq.Expressions;

var expr = Expression.Add(
    Expression.Constant(2),
    Expression.Multiply(
        Expression.Constant(3),
        Expression.Constant(4))
);

double result = Expression.Lambda<Func<double>>(expr).Compile()();
// 14 ✓

3. النسبة المئوية والعمليات الأحادية

C# — Unary Operations 
public double Square(double a) => a * a;

public double SquareRoot(double a) =>
    a < 0 ? throw new ArgumentException("الجذر التربيعي لسالب غير معرّف")
              : Math.Sqrt(a);

public double Percent(double a) => a / 100;

فخ شائع: التدقيق العشري. لا تقارن double بـ == مباشرة. استخدم Math.Abs(a - b) < 0.0001. أو استخدم decimal في التطبيقات المالية.
