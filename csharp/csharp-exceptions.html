EXCEPTION HANDLING | معالجة الاستثناءات

⚠️ معالجة الاستثناءات (Exception Handling)

بناء تطبيقات قوية ومستقرة — تعلم كيفية التعامل مع الأخطاء في C# باستخدام try, catch, finally, throw.

ما هي الاستثناءات (Exceptions)؟

الاستثناءات هي أخطاء تحدث أثناء تنفيذ البرنامج (Runtime Errors)، مثل القسمة على صفر، أو محاولة الوصول إلى عنصر غير موجود في مصفوفة. معالجة الاستثناءات تسمح للبرنامج بالتعامل مع هذه الأخطاء بشكل أنيق دون انهيار مفاجئ.

// بنية try-catch-finally الأساسية
try
{
    // الكود الذي قد يسبب استثناء
    int result = 10 / 0; // DivideByZeroException
}
catch (DivideByZeroException ex)
{
    Console.WriteLine($"خطأ: {ex.Message}");
}
catch (Exception ex)
{
    Console.WriteLine($"خطأ عام: {ex.Message}");
}
finally
{
    Console.WriteLine("يتم التنفيذ دائماً (لتنظيف الموارد)");
}
الخلاصة: try يحيط بالكود الخطير، catch يلتقط الاستثناءات، finally ينفذ دائماً (لإغلاق الملفات أو الاتصالات).

أهم أنواع الاستثناءات في C#

الاستثناءالوصفمثال
DivideByZeroExceptionالقسمة على صفرint x = 5 / 0;
NullReferenceExceptionمحاولة استخدام مرجع nullstring s = null; s.Length;
IndexOutOfRangeExceptionالوصول إلى مؤشر خارج نطاق المصفوفةint[] arr = {1,2}; arr[5]
FormatExceptionتنسيق غير صحيح للتحويلint.Parse("abc");
ArgumentExceptionمعامل غير صالح لدالةthrow new ArgumentException("خطأ");
FileNotFoundExceptionالملف غير موجودFile.ReadAllText("missing.txt");

كتلة try-catch-finally بالتفصيل

try

تحتوي على الكود الذي قد يرمي استثناء.

try
{
    // كود محتمل الخطأ
}

catch

تلتقط الاستثناءات. يمكن أن يكون عدة catch لأنواع مختلفة.

catch (SpecificException ex)
{
    // معالجة نوع محدد
}
catch (Exception ex)
{
    // معالجة عامة
}

finally

ينفذ دائماً بغض النظر عن حدوث استثناء. يستخدم لتحرير الموارد.

finally
{
    fileStream.Close();
    // تنظيف الموارد
}

throw

لرمي استثناء يدوياً.

if (age < 0)
    throw new ArgumentException("العمر لا يمكن أن يكون سالباً");

التصفية الشرطية (Exception Filters) - when

يمكن إضافة شرط when لالتقاط الاستثناء فقط عند تحقق شرط معين (C# 6+).

try
{
    int value = GetValue();
}
catch (Exception ex) when (ex.Message.Contains("timeout"))
{
    Console.WriteLine("مهلة انتهت - أعد المحاولة");
}
catch (Exception ex) when (ex is ArgumentException)
{
    Console.WriteLine("خطأ في المعاملات");
}

التعامل مع overflow: checked و unchecked

في العمليات الحسابية، يمكن أن يحدث تجاوز (overflow). checked يرمي OverflowException، بينما unchecked يتجاهل التجاوز.

checked
{
    int max = int.MaxValue;
    int overflow = max + 1; // يرمي OverflowException
}

unchecked
{
    int max = int.MaxValue;
    int overflow = max + 1; // يلتف إلى قيمة سالبة (بدون استثناء)
}

أهمية finally: تنظيف الموارد

يستخدم finally عادةً لإغلاق الملفات، اتصالات قاعدة البيانات، أو تحرير الذاكرة غير المُدارة.

StreamReader reader = null;
try
{
    reader = new StreamReader("data.txt");
    string content = reader.ReadToEnd();
}
catch (FileNotFoundException ex)
{
    Console.WriteLine("الملف غير موجود");
}
finally
{
    if (reader != null)
        reader.Close(); // تنظيف المورد
}

// بديل أفضل: using statement (تطبيق IDisposable)
using (var reader = new StreamReader("data.txt"))
{
    // يغلق تلقائياً حتى في حالة الاستثناء
}

// جرب تنفيذ عملية مختلفة لترى آلية try-catch-finally ...
💡 ملاحظة: المحاكي يوضح تدفق try-catch-finally. في التطبيقات الحقيقية، الاستثناءات تمنع انهيار البرنامج.

أفضل الممارسات في معالجة الاستثناءات

  • ✅ التقط أكثر الاستثناءات تحديداً أولاً: ضع catch الخاصة بالأنواع المحددة قبل catch العام (Exception).
  • 🚫 لا تبتلع الاستثناءات! تجنب catch الفارغ (catch {} ) دون تسجيل أو معالجة.
  • 📝 سجل الاستثناءات (Logging): استخدم إطار عمل لتسجيل الأخطاء لفهم المشاكل.
  • 🔁 استخدم finally أو using لتحرير الموارد: يضمن عدم تسرب الذاكرة أو الموارد.
  • 💣 ارمي استثناءات ذات معنى: استخدم الأنواع المضمنة أو أنشئ استثناءات مخصصة مع رسائل واضحة.
  • ⚡ لا تستخدم الاستثناءات للتحكم في التدفق: الاستثناءات مكلفة، استخدم الشروط للسيناريوهات المتوقعة.

إنشاء استثناءات مخصصة (Custom Exceptions)

public class InvalidAgeException : Exception
{
    public InvalidAgeException() { }
    
    public InvalidAgeException(string message) : base(message) { }
    
    public InvalidAgeException(string message, Exception inner) 
        : base(message, inner) { }
}

// الاستخدام:
public void SetAge(int age)
{
    if (age < 0 || age > 150)
        throw new InvalidAgeException($"العمر {age} غير صالح");
}
📌 نصيحة: قم بتوريث من Exception أو ApplicationException، ووفر ثلاثة منشئات كأفضل ممارسة.
