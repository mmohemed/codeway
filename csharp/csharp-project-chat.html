نظرة عامة على المشروع

تطبيق الدردشة هو مشروع مثالي لتعلم الاتصال الشبكي في الوقت الفعلي. يجمع بين Sockets، Tasks، إدارة الحالة، ومعالجة الأخطاء المعقدة.

ما ستتعلمه

TCP Sockets

إنشاء اتصال مباشر بين العميل والخادم عبر TCP.

Tasks غير متزامنة

استقبال وإرسال الرسائل بالتوازي دون حجب.

إدارة الجلسات

تتبع المستخدمين المتصلين وبث الرسائل لهم.

معالجة الانقطاع

التعامل مع فقدان الاتصال وإعادة الاتصال.

المتطلبات الوظيفية

  • خادم يستمع على منفذ محدد ويقبل اتصالات متعددة.
  • عميل يتصل بالخادم ويرسل ويستقبل الرسائل.
  • بث رسالة مستخدم لجميع المستخدمين الآخرين.
  • إظهار إشعارات دخول/خروج المستخدمين.
  • معالجة انقطاع الاتصال دون تعطل الخادم.

لماذا هذا المشروع؟

لأنه يغطي العمق التقني الحقيقي: الاتصال الشبكي المتزامن. هذه المهارة أساسية لأي تطبيق حديث — من الألعاب إلى منصات التعاون.

2

كيف تعمل Sockets؟

Socket هو نقطة نهاية للاتصال الشبكي. تخيله كهاتف: لكل طرف رقم (IP) ومنفذ (Port)، وبمجرد الاتصال يمكنكما تبادل الرسائل.

دورة حياة الاتصال

  1. الخادم يستمع: ينشئ TcpListener ويربطه بمنفذ (مثل 5000).
  2. العميل يتصل: ينشئ TcpClient ويتصل بـ IP الخادم والمنفذ.
  3. الخادم يقبل: عند وصول طلب، يُنشئ Socket جديد لكل عميل.
  4. تبادل البيانات: يُرسل ويستقبل عبر NetworkStream.
  5. الإغلاق: عند الانتهاء، يُغلق الاتصال من الطرفين.

TCP مقابل UDP

الخاصية TCP UDP
الموثوقية مضمونة غير مضمونة
الترتيب مضمون غير مضمون
السرعة أبطأ قليلاً أسرع
الاستخدام دردشة، بريد، ويب ألعاب، بث فيديو

لماذا TCP للدردشة؟

لأننا نحتاج ضمان وصول الرسائل بالترتيب الصحيح. لا نريد أن تظهر رسالة "كيف حالك؟" قبل "مرحباً!".

3

بروتوكول الرسائل

TCP مجرد مجرى بايتات — لا يعرف أين تنتهي رسالة وتبدأ أخرى. نحتاج بروتوكولاً لتمييز حدود الرسائل. نستخدم رسائل محددة الطول: كل رسالة تبدأ بـ 4 بايتات تحدد طولها.

لماذا نحتاج طول الرسالة؟

تخيل أن الخادم يستقبل: "مرحباً كيف حالك". هل "مرحباً" رسالة و"كيف حالك" رسالة أخرى؟ أو كلاهما رسالة واحدة؟ بدون طول محدد، لا يمكننا التمييز.

Protocol/PacketHelper.cs
using System.Buffers.Binary;

namespace ChatApp.Protocol;

public static class PacketHelper
{
    public static async Task SendAsync(
        Stream stream,
        string message,
        CancellationToken ct = default)
    {
        var body = System.Text.Encoding.UTF8.GetBytes(message);
        var header = new byte[4];

        // كتابة الطول كـ int32 بالترتيب الكبير
        BinaryPrimitives.WriteInt32BigEndian(header, body.Length);

        await stream.WriteAsync(header, ct);
        await stream.WriteAsync(body, ct);
        await stream.FlushAsync(ct);
    }

    public static async Task<string?> ReceiveAsync(
        Stream stream,
        CancellationToken ct = default)
    {
        var header = new byte[4];
        var read = await stream.ReadAsync(header, ct);

        if (read == 0) return null; // الاتصال أُغلق

        var length = BinaryPrimitives.ReadInt32BigEndian(header);

        if (length <= 0 || length > 1_000_000)
            throw new InvalidDataException("طول غير صالح");

        var body = new byte[length];
        var totalRead = 0;

        while (totalRead < length)
        {
            var n = await stream.ReadAsync(
                body.AsMemory(totalRead), ct);

            if (n == 0) throw new EndOfStreamException();
            totalRead += n;
        }

        return System.Text.Encoding.UTF8.GetString(body);
    }
}

تحقق من الطول دائماً

لو أرسل عميل خبيث طولاً ضخماً (مثل 2GB)، فسيمتلئ ذاكرة الخادم. دائماً ضع حداً أقصى (مثلاً 1MB).

4

الخادم (Server)

الخادم يستمع للاتصالات، يقبل كل عميل في Task منفصل، ويبث الرسائل للجميع. نستخدم ConcurrentDictionary لتتبع العملاء بأمان.

Server/ChatServer.cs
using System.Collections.Concurrent;
using System.Net;
using System.Net.Sockets;
using ChatApp.Protocol;

namespace ChatApp.Server;

public class ChatServer
{
    private readonly TcpListener _listener;
    private readonly ConcurrentDictionary<Guid, ClientConnection> _clients = new();
    private readonly ILogger<ChatServer> _logger;

    public ChatServer(ILogger<ChatServer> logger)
    {
        _logger = logger;
        _listener = new TcpListener(IPAddress.Any, 5000);
    }

    public async Task StartAsync(CancellationToken ct)
    {
        _listener.Start();
        _logger.LogInformation("الخادم يعمل على المنفذ 5000");

        try
        {
            while (!ct.IsCancellationRequested)
            {
                var tcpClient = await _listener.AcceptTcpClientAsync(ct);
                _ = HandleClientAsync(tcpClient, ct);
            }
        }
        catch (OperationCanceledException) { }
        finally { _listener.Stop(); }
    }

    private async Task HandleClientAsync(TcpClient tcpClient, CancellationToken ct)
    {
        var id = Guid.NewGuid();
        var connection = new ClientConnection(id, tcpClient);

        _clients[id] = connection;
        _logger.LogInformation($"عميل جديد: {id}");

        try
        {
            var stream = tcpClient.GetStream();

            // استقبال اسم المستخدم أولاً
            var username = await PacketHelper.ReceiveAsync(stream, ct);
            if (string.IsNullOrWhiteSpace(username))
            {
                tcpClient.Close();
                return;
            }

            connection.Username = username;
            await BroadcastAsync(
                $"🟢 {username} انضم إلى الدردشة", excludeId: id);

            while (!ct.IsCancellationRequested)
            {
                var message = await PacketHelper.ReceiveAsync(stream, ct);
                if (message is null) break;

                _logger.LogInformation($"[{username}] {message}");
                await BroadcastAsync($"{username}: {message}", excludeId: id);
            }
        }
        catch (Exception ex)
        {
            _logger.LogWarning(ex, $"خطأ مع العميل {id}");
        }
        finally
        {
            _clients.TryRemove(id, out _);
            tcpClient.Close();

            if (!string.IsNullOrEmpty(connection.Username))
            {
                await BroadcastAsync(
                    $"🔴 {connection.Username} غادر الدردشة", excludeId: id);
            }
        }
    }

    private async Task BroadcastAsync(string message, Guid excludeId)
    {
        foreach (var client in _clients.Values)
        {
            if (client.Id == excludeId) continue;

            try
            {
                await client.SendAsync(message);
            }
            catch
            {
                _clients.TryRemove(client.Id, out _);
            }
        }
    }
}

public class ClientConnection
{
    public Guid Id { get; }
    public string Username { get; set; } = "";
    private readonly TcpClient _tcp;
    private readonly SemaphoreSlim _sendLock = new(1);

    public ClientConnection(Guid id, TcpClient tcp)
    {
        Id = id;
        _tcp = tcp;
    }

    public async Task SendAsync(string message)
    {
        await _sendLock.WaitAsync();
        try
        {
            await PacketHelper.SendAsync(_tcp.GetStream(), message);
        }
        finally { _sendLock.Release(); }
    }
}

لماذا SemaphoreSlim في الإرسال؟

لأن الكتابة على نفس Stream من Tasks متعددة قد تسبب تشابك البيانات. الـ Semaphore يضمن أن رسالة واحدة تُكتب في كل مرة.

5

العميل (Client)

العميل يتصل بالخادم، يرسل رسائل، ويستقبل رسائل في Task منفصل. هذا يسمح للمستخدم بالكتابة أثناء استقبال الرسائل في نفس الوقت.

Client/ChatClient.cs
using System.Net.Sockets;
using ChatApp.Protocol;

namespace ChatApp.Client;

public class ChatClient : IAsyncDisposable
{
    private TcpClient? _tcp;
    private NetworkStream? _stream;
    private CancellationTokenSource? _cts;

    public event Action<string>? MessageReceived;
    public event Action? Disconnected;

    public async Task ConnectAsync(
        string host, int port, string username)
    {
        _tcp = new TcpClient();
        await _tcp.ConnectAsync(host, port);

        _stream = _tcp.GetStream();
        _cts = new CancellationTokenSource();

        // إرسال اسم المستخدم
        await PacketHelper.SendAsync(_stream, username, _cts.Token);

        // بدء الاستقبال في الخلفية
        _ = ReceiveLoopAsync(_cts.Token);
    }

    private async Task ReceiveLoopAsync(CancellationToken ct)
    {
        try
        {
            while (!ct.IsCancellationRequested)
            {
                var message = await PacketHelper.ReceiveAsync(_stream!, ct);
                if (message is null) break;

                MessageReceived?.Invoke(message);
            }
        }
        catch (OperationCanceledException) { }
        catch (Exception ex)
        {
            // يمكن تسجيل الخطأ هنا
        }
        finally
        {
            Disconnected?.Invoke();
        }
    }

    public async Task SendAsync(string message)
    {
        if (_stream is null || _cts is null)
            throw new InvalidOperationException("غير متصل");

        await PacketHelper.SendAsync(_stream, message, _cts.Token);
    }

    public async ValueTask DisposeAsync()
    {
        _cts?.Cancel();

        if (_stream is not null) await _stream.DisposeAsync();

        _tcp?.Close();
        _cts?.Dispose();
    }
}

استخدام العميل في WPF

MainWindow.xaml.cs
public partial class MainWindow : Window
{
    private readonly ChatClient _client = new();

    public MainWindow()
    {
        InitializeComponent();

        _client.MessageReceived += msg =>
        {
            // تحديث الواجهة من Thread رئيسي
            Dispatcher.Invoke(() =>
                MessagesList.Items.Add(msg));
        };

        _client.Disconnected += () =>
        {
            Dispatcher.Invoke(() =>
                StatusText.Text = "انقطع الاتصال");
        };
    }

    private async void Connect_Click(object sender, RoutedEventArgs e)
    {
        await _client.ConnectAsync("127.0.0.1", 5000, UsernameBox.Text);
        StatusText.Text = "متصل ✓";
    }

    private async void Send_Click(object sender, RoutedEventArgs e)
    {
        if (string.IsNullOrWhiteSpace(MessageBox.Text)) return;

        await _client.SendAsync(MessageBox.Text);
        MessageBox.Text = "";
    }
}

تحديث الواجهة من Threads أخرى

عند استقبال رسالة من Socket، أنت في Thread خلفي. لا تحاول تحديث عناصر WPF مباشرة — استخدم Dispatcher.Invoke.

6

إدارة الجلسات

الخادم يحتاج لتتبع من هو متصل. نستخدم ConcurrentDictionary لأن العمليات تحدث من Tasks متعددة في نفس الوقت.

لماذا ConcurrentDictionary؟

المجموعة الوصول المتزامن الاستخدام
Dictionary غير آمن Thread واحد فقط
ConcurrentDictionary آمن عمليات متوازية عالية الأداء
Dictionary + lock آمن لكن أبطأ عمليات قليلة التزامن

ميزة الأداء

ConcurrentDictionary يستخدم تقنيات متقدمة (lock-free reads) تجعله أسرع بكثير من Dictionary مع lock عند التزامن العالي.

تخزين حالة كل عميل

كل عميل له كائن ClientConnection يحتوي على:

  • Id: معرف فريد (Guid).
  • Username: اسم المستخدم الذي اختاره.
  • TcpClient: الاتصال الفعلي.
  • SemaphoreSlim: لضمان إرسال رسالة واحدة في كل مرة.
7

معالجة الانقطاعات

انقطاع الاتصال أمر حتمي — قد يغلق المستخدم التطبيق، أو تنقطع الشبكة، أو يسقط الخادم. تطبيق احترافي يتعامل مع كل هذه الحالات بسلاسة.

حالات الانقطاع

  1. إغلاق نظيف: العميل يستدعي Disconnect → يرسل إشعاراً → يُغلق.
  2. انقطاع مفاجئ: الشبكة تنقطع → ReadAsync يعيد 0 → نُغلق.
  3. مهلة (Timeout): لا يصل شيء لفترة → نستخدم CancellationToken مع مهلة.
  4. خطأ في الإرسال: Stream معطل → نحذف العميل من القائمة.

مهلة القراءة (Read Timeout)

مع مهلة
private async Task<string?> ReceiveWithTimeoutAsync(
    NetworkStream stream, TimeSpan timeout)
{
    using var cts = new CancellationTokenSource(timeout);

    try
    {
        return await PacketHelper.ReceiveAsync(stream, cts.Token);
    }
    catch (OperationCanceledException)
    {
        // انتهت المهلة — العميل بطيء أو منقطع
        return null;
    }
}

إعادة الاتصال التلقائي

Reconnect
public async Task ConnectWithRetryAsync(
    string host, int port, string username,
    int maxAttempts = 5)
{
    for (int attempt = 1; attempt <= maxAttempts; attempt++)
    {
        try
        {
            await ConnectAsync(host, port, username);
            return;
        }
        catch (SocketException)
        {
            if (attempt == maxAttempts) throw;

            var delay = TimeSpan.FromSeconds(Math.Pow(2, attempt));
            await Task.Delay(delay);
        }
    }
}

لا تترك الاتصالات الميتة

إذا لم تحذف العميل المنقطع من القائمة، ستتراكم الاتصالات الميتة وينفد ذاكرة الخادم تدريجياً.

8

أفضل الممارسات

  • استخدم async/await في كل عمليات الشبكة — لا تستخدم Blocking I/O.
  • مرّر CancellationToken لدعم إلغاء الاتصال عند الحاجة.
  • حدّد الطول الأقصى للرسالة لمنع هجمات DoS.
  • استخدم SemaphoreSlim لحماية الإرسال المتزامن.
  • تحقق من الإدخال — لا تثق بأي بيانات من العميل.
  • سجّل كل الأحداث لتتبع المشاكل.
  • اختبر الانقطاعات — اقطع الشبكة يدوياً وتحقق من السلوك.
  • استخدم TLS في الإنتاج (SslStream) لتشفير الاتصال.
