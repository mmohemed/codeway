POLYMORPHISM | تعدد الأشكال

🎭 تعدد الأشكال (Polymorphism)

قدرة الكائنات على اتخاذ أشكال متعددة — virtual, override, abstract, interface — أساس المرونة والتوسع في البرمجة الكائنية.

ما هو تعدد الأشكال؟

تعدد الأشكال (Polymorphism) هو قدرة الكائنات من أنواع مختلفة على الاستجابة لنفس الدالة (method) بطريقة خاصة بكل نوع. ينقسم إلى نوعين رئيسيين: تعدد الأشكال في وقت التشغيل (Runtime Polymorphism) عبر الوراثة و تعدد الأشكال في وقت الترجمة (Compile-time Polymorphism) عبر التحميل الزائد (Overloading).

// المفهوم الأساسي: الكائن يتصرف وفقاً لنوعه الحقيقي
Animal myAnimal = new Dog();
myAnimal.Speak();  // ينادي نسخة Dog من Speak (وليس Animal)

Animal another = new Cat();
another.Speak();   // ينادي نسخة Cat
الخلاصة: نفس الكود (استدعاء Speak) يعطي سلوكيات مختلفة حسب النوع الفعلي للكائن.

أنواع تعدد الأشكال

Runtime Polymorphism

يتم تحديد الدالة المناسبة أثناء تنفيذ البرنامج باستخدام virtual و override.

public class Shape 
{
    public virtual void Draw() 
    { Console.WriteLine("رسم شكل"); }
}
public class Circle : Shape 
{
    public override void Draw() 
    { Console.WriteLine("رسم دائرة"); }
}

Compile-time Polymorphism

التحميل الزائد للدوال (Method Overloading) — دوال بنفس الاسم ومعاملات مختلفة.

public class Calculator
{
    public int Add(int a, int b) => a + b;
    public double Add(double a, double b) => a + b;
    public int Add(int a, int b, int c) => a + b + c;
}

virtual, override, new: أدوات تعدد الأشكال

الكلمةالوصفمثال
virtualتسمح للكلاس المشتق بإعادة تعريف الدالة.public virtual void MakeSound()
overrideتعيد تعريف دالة virtual في الكلاس المشتق.public override void MakeSound()
newتخفي دالة الكلاس الأساسي (وليس إعادة تعريف).public new void MakeSound()
public class Animal 
{
    public virtual void Speak() => Console.WriteLine("صوت حيوان");
}
public class Dog : Animal 
{
    public override void Speak() => Console.WriteLine("نباح: هو هو");
}
public class RobotDog : Dog 
{
    public new void Speak() => Console.WriteLine("صوت آلي"); // إخفاء
}

// الاستخدام:
Animal a = new Dog();
a.Speak();  // نباح: هو هو (override)
Dog d = new RobotDog();
d.Speak();  // نباح: هو هو (ليس صوت آلي، لأن new لا يعمل مع تعدد الأشكال)

الكلاسات المجردة (Abstract) والدوال المجردة

الكلاس المجرد لا يمكن إنشاء كائن منه، والدالة المجردة ليس لها جسم ويجب تنفيذها في الكلاسات المشتقة.

public abstract class Vehicle
{
    public abstract void StartEngine(); // لا يوجد تنفيذ هنا
    
    public void Honk() // دالة عادية
    {
        Console.WriteLine("بوق بوق!");
    }
}

public class Car : Vehicle
{
    public override void StartEngine()
    {
        Console.WriteLine("تشغيل محرك السيارة...");
    }
}

// الاستخدام:
Vehicle myCar = new Car();
myCar.StartEngine(); // تشغيل محرك السيارة...
🧩 متى نستخدم abstract؟ عندما يكون لدينا قالب عام لا يمكن إنشاء كائن منه مباشرة، ويجب على الكلاسات المشتقة توفير التنفيذ الخاص بها.

الواجهات (Interfaces) — تعدد أشكال مرن

الواجهة تحدد عقداً (contract) من الدوال والخصائص دون تنفيذ، ويمكن للكلاسات تنفيذ واجهات متعددة.

public interface IPlayable
{
    void Play();
    void Pause();
}

public interface IRecordable
{
    void Record();
}

public class MusicPlayer : IPlayable, IRecordable
{
    public void Play() => Console.WriteLine("تشغيل الموسيقى");
    public void Pause() => Console.WriteLine("إيقاف مؤقت");
    public void Record() => Console.WriteLine("تسجيل الصوت");
}

// تعدد الأشكال عبر الواجهة
IPlayable player = new MusicPlayer();
player.Play();  // تشغيل الموسيقى
// player.Record(); // غير متاح لأن الواجهة IPlayable لا تحتوي على Record

// سيتم عرض سلوك تعدد الأشكال حسب النوع المختار ...

مقارنة: Overloading vs Overriding

الميزةOverloading (التحميل الزائد)Overriding (إعادة التعريف)
الوقتوقت الترجمة (compile-time)وقت التشغيل (runtime)
العلاقةدوال في نفس الكلاسبين كلاس أساسي ومشتق
الكلمات المفتاحيةلا توجد كلمات خاصةvirtual / override
التوقيع (signature)يجب أن يختلف (عدد/نوع المعاملات)نفس التوقيع تماماً

إرشادات ذهبية لتعدد الأشكال الاحترافي

  • 🎯 استخدم virtual بحكمة: لا تجعل كل الدوال افتراضية إلا عند الحاجة الحقيقية للتوسع.
  • 📐 مبدأ استبدال ليسكوف (LSP): الكلاسات المشتقة يجب أن تكون قابلة للاستبدال بالكلاس الأساسي دون تغيير سلوك البرنامج.
  • 🔌 الواجهات (Interfaces) مرنة جداً: تسمح بتعدد الأشكال دون الحاجة إلى وراثة كاملة.
  • ⚠️ تجنب استخدام new ما لم تكن تعرف تماماً ما تفعله (يخفي الدالة ولا يدعم تعدد الأشكال).
  • ✅ استخدم abstract classes عندما تريد مشاركة كود أساسي مع إجبار المشتقات على تنفيذ دوال معينة.
