🔒 التغليف (Encapsulation) & معدلات الوصول

حماية البيانات، إخفاء التفاصيل الداخلية، والتحكم في الوصول — الركيزة الأساسية للبرمجة الكائنية الاحترافية في C#.

ما هو التغليف (Encapsulation)؟

التغليف هو مبدأ يهدف إلى إخفاء البيانات الداخلية للكلاس ومنع الوصول المباشر إليها من الخارج، وتوفير واجهة عامة (public methods/properties) للتفاعل الآمن مع البيانات. يحمي سلامة الكائن ويمنع التعديلات غير المقصودة.

// مثال: كلاس BankAccount مع تغليف كامل
public class BankAccount
{
    private decimal balance;  // حقل خاص (مخفي)
    
    // خاصية عامة للوصول الآمن (get فقط)
    public decimal Balance 
    { 
        get { return balance; } 
    }
    
    // دالة عامة للإيداع مع التحقق
    public void Deposit(decimal amount)
    {
        if (amount > 0)
            balance += amount;
        else
            throw new ArgumentException("المبلغ يجب أن يكون موجباً");
    }
    
    // دالة عامة للسحب مع التحقق
    public bool Withdraw(decimal amount)
    {
        if (amount > 0 && balance >= amount)
        {
            balance -= amount;
            return true;
        }
        return false;
    }
}
فوائد التغليف: حماية البيانات، مرونة التعديل الداخلي دون التأثير على المستخدمين، إمكانية إضافة قواعد التحقق.

معدلات الوصول (Access Modifiers) في C#

public

متاح من أي مكان داخل التطبيق. لا توجد قيود.

public string Name { get; set; }
public void DoWork() { }

private

متاح فقط داخل نفس الكلاس. أعلى مستوى من الخصوصية.

private int id;
private void Helper() { }

protected

متاح داخل الكلاس والكلاسات المشتقة (الموروثة).

protected string secret;
protected void InternalLogic() { }

internal

متاح فقط داخل نفس التجميع (assembly/project).

internal int Counter;
internal void Reset() { }

protected internal

متاح داخل نفس التجميع OR في الكلاسات المشتقة (حتى من تجميع آخر).

protected internal void Log() { }

private protected

متاح داخل نفس الكلاس أو الكلاسات المشتقة داخل نفس التجميع فقط (C# 7.2+).

private protected void Advanced() { }

الخصائص (Properties) - آلة التغليف الحديثة

الخصائص توفر تغليفاً أنيقاً، حيث تسمح بالتحكم في عمليات get و set مع إمكانية إضافة منطق تحقق.

📦 Auto-implemented Property

public string Name { get; set; }
public int Age { get; private set; } // set فقط داخل الكلاس

⚙️ Full Property with Logic

private int temperature;
public int Temperature
{
    get { return temperature; }
    set 
    { 
        if (value < -50 || value > 60)
            throw new ArgumentOutOfRangeException();
        temperature = value;
    }
}

🔐 Readonly (get-only) Property

public string Id { get; }
public DateTime CreatedAt { get; init; } // init-only (C# 9)

🎯 Expression-bodied Property

public string FullName => $"{FirstName} {LastName}";
public double Area => Width * Height;

🛡️ مختبر التغليف التفاعلي

جرب التفاعل مع كلاس BankAccount الذي يستخدم التغليف: الحقل balance خاص (private) ولا يمكن الوصول إليه مباشرة، فقط عبر دوال آمنة.

💰 الرصيد الحالي: 0.00 ريال
لاحظ أن الحقل balance مخفي (private) ولا يمكن الوصول إليه مباشرة. كل العمليات تتم عبر واجهة عامة آمنة — هذا هو جوهر التغليف!

أفضل الممارسات والإرشادات الذهبية

  • 🎯 اجعل الحقول private دائماً — لا تسمح بالوصول المباشر إلى البيانات الداخلية.
  • 🔓 استخدم properties بدلاً من public fields — توفر مرونة وتحكماً مستقبلياً.
  • ⚖️ أقل مستوى وصول ممكن — ابدأ بـ private ثم وسّع حسب الحاجة (مبدأ مبدأ الحد الأدنى من الامتيازات).
  • 📦 استخدم get-only properties للقيم التي لا يجب تغييرها بعد الإنشاء.
  • ✅ أضف منطق التحقق (validation) في setter أو دوال التعديل.
  • 🧩 قسّم الكلاسات الكبيرة — التغليف الجيد يؤدي إلى وحدات متماسكة.

مقارنة: Public Field vs Property (تغليف)

// Anti-pattern: حقل عام (كسر التغليف)
public class BadExample
{
    public int Age;  // يمكن لأي كود خارجي تعديله دون تحقق!
}

// تطبيق صحيح للتغليف
public class GoodExample
{
    private int age;
    public int Age
    {
        get { return age; }
        set 
        { 
            if (value >= 0 && value <= 150)
                age = value;
            else
                throw new ArgumentException("عمر غير صالح");
        }
    }
}
💡 خلاصة: الخصائص (Properties) توفر طبقة من التغليف تسمح بإضافة منطق مستقبلاً دون تغيير واجهة المستخدم.
