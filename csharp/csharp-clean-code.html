1

ما هو الكود النظيف؟

الكود النظيف (Clean Code) هو كود يفهمه إنسان آخر (أو أنت بعد 6 أشهر) بسهولة. ليس الكود الذي يعمل فقط، بل الكود الذي يمكن قراءته، اختباره، وصيانته.

Martin Fowler يقول: "أي أحمق يستطيع كتابة كود يفهمه الكمبيوتر. المبرمجون الجيدون يكتبون كوداً يفهمه البشر."

لماذا يهم؟

توفير الوقت

80% من وقت المطور يُصرف في قراءة كود موجود — لا كتابة كود جديد.

العمل الجماعي

الفريق يقرأ كودك ويعدّله. الكود الغامض يُبطئ الجميع.

أخطاء أقل

الكود الواضح يقلل احتمال إدخال أخطاء عند التعديل.

رضا مهني

العمل في قاعدة كود نظيفة أكثر متعة وإنتاجية.

القاعدة الذهبية

"اقرأ كودك كأنك تقرأ جملة إنجليزية." إن لم تفهمه من القراءة الأولى — فهو يحتاج تحسيناً.

الدوال الصغيرة

القاعدة الأشهر: دالتك يجب أن تفعل شيئاً واحداً فقط، وتفعله جيداً. دالة أكبر من 20 سطراً إشارة تحذير.

قبل — دالة ضخمة
بعد — دوال صغيرة
public void ProcessOrder(Order o)
{
    if (o == null) throw ...
    if (o.Items.Count == 0) throw ...
    decimal total = 0;
    foreach (var i in o.Items) {
        total += i.Price * i.Quantity;
    }
    if (o.Coupon != null) {
        total = total * (1 - o.Coupon.Rate);
    }
    var conn = new SqlConnection(...);
    conn.Open();
    // insert order
    // send email
    // log
}

public async Task ProcessOrderAsync(Order o)
{
    Validate(o);
    var total = CalculateTotal(o);
    await _repo.SaveAsync(o, total);
    await _email.SendConfirmationAsync(o);
    _logger.Info($"Order {o.Id} done");
}

private void Validate(Order o) { ... }
private decimal CalculateTotal(Order o) { ... }

مبادئ الدوال النظيفة

  • دالة واحدة = مهمة واحدة: لا "تحقق + احسب + احفظ + أرسل" في دالة واحدة.
  • قليلة المعاملات: 0-2 مثالي. أكثر من 3 = فكّر في كلاس.
  • بلا آثار جانبية مفاجئة: دالة اسمها CheckPassword لا يجب أن تُسجّل دخول المستخدم.
  • تجنب معاملات bool: CreateUser(true, false) غامضة — استخدم enums.
  • مستوى تجريد واحد: لا تخلط بين منطق الأعمال وتفاصيل قاعدة البيانات في دالة واحدة.

علامات تحذير

دالتك أطول من شاشة؟ تحتاج تمريراً لفهمها؟ فيها أكثر من 3 مستويات تعشيش؟ ابدأ التقسيم.

التعليقات المفيدة

أفضل تعليق هو الذي لا تحتاجه. لكن عندما تكتب، اجعل التعليق يشرح "لماذا" لا "ماذا".

تعليق سيئ
تعليق جيد
// increment i by 1
i++;

// return the user
return user;

// Retry 3 times to work around the
// race condition in API v2.3
// (see issue #1234)
for (int attempt = 0; attempt < 3; attempt++)
{
    if (await TrySendAsync()) return;
}

أنواع التعليقات المفيدة

  • تحذيرات: "لا تستدعِ هذه قبل Initialize()".
  • نية: "نستخدم BinarySearch لأن القائمة مرتبة دائماً".
  • مراجع: "التنفيذ حسب RFC 7231".
  • TODO: "TODO: استبدل بـ HttpClientFactory في .NET 8".
  • XML Docs: /// <summary> على الـ public APIs.

متى تحذف تعليقاً؟

  • يشرح ماذا يفعل الكود — الكود نفسه يجب أن يوضح ذلك.
  • قديم وغير مطابق (تعليق يكذب أسوأ من عدم وجوده).
  • مكرر — التعليق نفسه في عشر أماكن لا يضيف شيئاً.
  • يمكن استبداله باسم متغير جيد.

5

تنسيق الكود

التنسيق ليس ذوقاً شخصياً — بل اتفاقية فريق. الفريق الذي يكتب بنفس الأسلوب يعمل أسرع.

قواعد أساسية

  • مسافة بادئة (Indentation): 4 مسافات (Standard C#).
  • طول السطر: أقل من 120 حرفاً.
  • مسافة بين الأعضاء: سطر فارغ بين كل method و property.
  • ترتيب الأعضاء: Constants → Fields → Constructors → Properties → Methods.
  • using: مرتّبة أبجدياً، وغير مستخدمة محذوفة.
  • File-scoped namespace: في C# 10+ استخدم namespace X; بدلاً من {}.
التنسيق الموصى به
using System;
using System.Collections.Generic;

namespace MyApp.Services; // file-scoped namespace

public class UserService
{
    // 1. Constants
    private const int MaxRetries = 3;

    // 2. Fields
    private readonly IUserRepository _repository;

    // 3. Constructor
    public UserService(IUserRepository repository)
    {
        _repository = repository;
    }

    // 4. Properties
    public string Name { get; set; } = "";

    // 5. Methods
    public async Task GetUserAsync(int id)
    {
        return await _repository.FindAsync(id);
    }
}

أتمتة التنسيق

استخدم dotnet format أو أضف .editorconfig للمشروع. Visual Studio يطبّق القواعد تلقائياً.

تجنب التكرار (DRY)

DRY (Don't Repeat Yourself) — كل معلومة في النظام يجب أن تكون في مكان واحد فقط. التكرار هو العدو الأول للصيانة.

تكرار
استخراج
public void SendWelcome(User u)
{
    var smtp = new SmtpClient(...);
    smtp.Send("noreply@site.com",
        u.Email, "مرحباً", "...");
}

public void SendReset(User u)
{
    var smtp = new SmtpClient(...);
    smtp.Send("noreply@site.com",
        u.Email, "إعادة تعيين", "...");
}

public async Task SendWelcomeAsync(User u)
    => await _email.SendAsync(u.Email,
        "مرحباً", "أهلاً بك");

public async Task SendResetAsync(User u)
    => await _email.SendAsync(u.Email,
        "إعادة تعيين", "...");

// EmailService ينفذ الإرسال مرة واحدة

لكن احترس من DRY المفرط

ليس كل تكرار سيئاً. لو كررت سطرين في دالتين لأن كل واحدة ستنمو في اتجاه مختلف — لا تُجرِد التكرار. القاعدة: الجِد فقط التكرار الذي يتغير لنفس السبب.

7

معالجة الأخطاء

الكود النظيف يتعامل مع الأخطاء بذكاء — لا يبتلعها ولا يفرط فيها.

Clean Error Handling
// ❌ ابتلاع الاستثناء
try { DoWork(); }
catch (Exception) { }  // صامت = تصحيح مستحيل

// ❌ استثناءات للتحكم في التدفق
try
{
    var user = await _repo.FindAsync(id);
    if (user == null) throw new NotFoundException();
}
catch (NotFoundException) { // منطق عادي هنا — تجنب }

// ✅ واضح ومقصود
public async Task<User?> FindUserAsync(int id)
{
    if (id <= 0)
        throw new ArgumentException("id must be positive", nameof(id));

    return await _repo.FindAsync(id);
}

// المستدعي يقرر
var user = await FindUserAsync(id);
if (user is null)
{
    _logger.Warn($"User {id} not found");
    return Results.NotFound();
}

قواعد ذهبية

  • لا تبتلع استثناء: سجّل أو أعد الرمي (rethrow).
  • رمي مبكراً: تحقق من المعاملات في بداية الدالة.
  • رسائل واضحة: "المستخدم غير موجود" أفضل من "خطأ".
  • استخدم استثناءات مخصصة عند الحاجة للتمييز.
  • finally للتنظيف: أغلق الموارد دائماً.
  • استخدم using: لضمان التخلص من الموارد تلقائياً.

قبل وبعد — تحويل كود

لنرَ كيف يتحول كود فوضوي إلى كود نظيف بتطبيق ما تعلمناه.

الكود قبل (❌)

قبل
public void p(Order o)
{
    // validate
    if (o == null) throw new Exception("null");
    if (o.Items.Count == 0) throw new Exception("empty");

    // calculate
    decimal t = 0;
    foreach (var i in o.Items) { t += i.Price * i.Qty; }
    if (o.Coupon != null) t = t * (1 - o.Coupon.Rate);
    if (t > 1000) t = t * 0.95m;

    // save
    var c = new SqlConnection("...");
    c.Open();
    new SqlCommand($"INSERT INTO Orders VALUES ({t})", c).ExecuteNonQuery();

    // email
    var s = new SmtpClient("smtp");
    s.Send("no@reply.com", o.Email, "Order", $"Total: {t}");
}

الكود بعد (✅)

بعد
public class OrderProcessor
{
    private const decimal BulkDiscountThreshold = 1000m;
    private const decimal BulkDiscountRate = 0.95m;

    private readonly IOrderRepository _repository;
    private readonly IEmailSender _email;

    public OrderProcessor(
        IOrderRepository repository,
        IEmailSender email)
    {
        _repository = repository;
        _email = email;
    }

    public async Task ProcessAsync(Order order)
    {
        Validate(order);

        var total = CalculateTotal(order);

        await _repository.SaveAsync(order, total);
        await _email.SendAsync(order.Email, "طلبك", $"الإجمالي: {total}");
    }

    private static void Validate(Order order)
    {
        ArgumentNullException.ThrowIfNull(order);

        if (order.Items.Count == 0)
            throw new ArgumentException("الطلب فارغ");
    }

    private static decimal CalculateTotal(Order order)
    {
        var total = order.Items.Sum(i => i.Price * i.Quantity);

        if (order.Coupon is not null)
            total *= (1 - order.Coupon.Rate);

        if (total > BulkDiscountThreshold)
            total *= BulkDiscountRate;

        return total;
    }
}

قائمة التحقق

راجع كودك قبل كل Commit. ضع علامة على كل بند بعد التحقق منه — القائمة تفاعلية!

Clean Code Checklist
الأسماء واضحة وتشرح النية بدون تعليق
لا توجد أسماء من حرف واحد إلا في loops قصيرة
كل دالة أقل من 20 سطراً وتفعل شيئاً واحداً
لا توجد أرقام سحرية — كلها constants مسماة
لا يوجد كود مكرر في أكثر من مكانين
التعليقات تشرح "لماذا" فقط، وليست "ماذا"
لا استثناءات مبتلعة — كلها مسجلة أو معاد رميها
كل public API له XML documentation
الواردات (using) مرتبة، وبدون غير مستخدم
الكود منسّق بأسلوب الفريق الموحد (.editorconfig)
