ما هي أنماط التصميم؟

أنماط التصميم (Design Patterns) هي حلول جاهزة ومجرّبة لمشاكل متكررة في تصميم البرمجيات. ليست كوداً تنسخه، بل قوالب ذهنية تساعدك على التفكير في الحل الصحيح.

أول من جمعها بشكل منهجي هم "عصابة الأربعة" (Gang of Four) في كتابهم الشهير Design Patterns: Elements of Reusable Object-Oriented Software عام 1994.

لماذا نحتاجها؟

لغة مشتركة

قول "استخدم Repository" أسرع من شرح الفكرة كل مرة.

حلول مجرّبة

لا تخترع العجلة — أنماط التصميم اختُبرت في آلاف المشاريع.

قابلية الصيانة

الكود المتبع لنمط معروف أسهل للفهم والتعديل.

نمو مهني

معرفة الأنماط شرط أساسي في المقابلات التقنية.

لا تُفرط في استخدامها

الأنماط أدوات، لا أهداف. استخدام نمط حيث لا حاجة له يُعقّد الكود بدلاً من تبسيطه — هذا ما يُسمى Over-engineering.

الأنماط الإبداعية (Creational)

تتحكم في عملية إنشاء الكائنات — متى، كيف، ومن المسؤول. الهدف: فصل الكود الذي يستخدم الكائن عن الكود الذي ينشئه.

Singleton
النمط الأحادي
إبداعي
الغرض
ضمان وجود نسخة واحدة فقط من الكلاس
متى تستخدمه
الإعدادات، Logger، اتصال قاعدة البيانات
Singleton.cs
public sealed class AppConfig
{
    private static readonly Lazy<AppConfig> _instance
        = new(() => new AppConfig());

    public static AppConfig Instance => _instance.Value;

    public string ConnectionString { get; private set; }

    private AppConfig()
    {
        ConnectionString = "Server=localhost;Database=AppDB";
    }
}

// الاستخدام
var config = AppConfig.Instance;
Console.WriteLine(config.ConnectionString);

تحذير

Singleton يجعل الاختبار صعباً (Global State). استخدمه فقط عند الضرورة القصوى.

Factory Method
مصنع الكائنات
إبداعي
الغرض
إنشاء كائنات دون تحديد الفئة الدقيقة
متى تستخدمه
لديك أنواع متعددة تختار بينها بناءً على شرط
Factory.cs
public interface INotification
{
    void Send(string message);
}

public class EmailNotification : INotification
{
    public void Send(string m) => Console.WriteLine($"Email: {m}");
}

public class SmsNotification : INotification
{
    public void Send(string m) => Console.WriteLine($"SMS: {m}");
}

public static class NotificationFactory
{
    public static INotification Create(string type) => type switch
    {
        "email" => new EmailNotification(),
        "sms"   => new SmsNotification(),
        _ => throw new ArgumentException("نوع غير معروف")
    };
}

// الاستخدام
var notifier = NotificationFactory.Create("email");
notifier.Send("مرحباً!");
Builder
الباني
إبداعي
الغرض
بناء كائنات معقدة خطوة بخطوة
متى تستخدمه
كائن له خصائص كثيرة (اختيارية + إلزامية)
Builder.cs
public class Pizza
{
    public string Size { get; init; } = "";
    public bool Cheese { get; init; }
    public bool Olives { get; init; }
    public bool Pepperoni { get; init; }
}

public class PizzaBuilder
{
    private string _size = "Medium";
    private bool _cheese, _olives, _pepperoni;

    public PizzaBuilder WithSize(string s) { _size = s; return this; }
    public PizzaBuilder WithCheese() { _cheese = true; return this; }
    public PizzaBuilder WithOlives() { _olives = true; return this; }
    public PizzaBuilder WithPepperoni() { _pepperoni = true; return this; }

    public Pizza Build() => new Pizza
    {
        Size = _size, Cheese = _cheese, Olives = _olives, Pepperoni = _pepperoni
    };
}

// الاستخدام — fluent API
var pizza = new PizzaBuilder()
    .WithSize("Large")
    .WithCheese()
    .WithPepperoni()
    .Build();
Abstract Factory
المصنع المجرد
إبداعي
الغرض
عائلة من الكائنات المترابطة دون تحديد فئاتها
متى تستخدمه
لديك "ثيمات" أو "مزودون" متعددون (Dark/Light، AWS/Azure)
AbstractFactory.cs
public interface IButton { void Render(); }
public interface ICheckbox { void Render(); }

public class DarkButton : IButton
{
    public void Render() => Console.WriteLine("Dark Button");
}
public class DarkCheckbox : ICheckbox
{
    public void Render() => Console.WriteLine("Dark Checkbox");
}

public interface IUIFactory
{
    IButton CreateButton();
    ICheckbox CreateCheckbox();
}

public class DarkThemeFactory : IUIFactory
{
    public IButton CreateButton() => new DarkButton();
    public ICheckbox CreateCheckbox() => new DarkCheckbox();
}

الأنماط الهيكلية (Structural)

تتحكم في كيفية تركيب الكائنات لتشكيل كائنات أكبر وأكثر وظيفية.

Adapter
المحول
هيكلي
الغرض
جعل واجهات غير متوافقة تعمل معاً
متى تستخدمه
تريد استخدام مكتبة قديمة أو خارجية بواجهة مختلفة
Adapter.cs
// واجهة قديمة في نظامك
public interface ILogger
{
    void Log(string message);
}

// مكتبة خارجية لا يمكن تعديلها
public class ThirdPartyLogger
{
    public void WriteEntry(string msg, int level) { }
}

// المحول
public class LoggerAdapter : ILogger
{
    private readonly ThirdPartyLogger _inner = new();
    public void Log(string message) => _inner.WriteEntry(message, 1);
}
Decorator
المُزيّن
هيكلي
الغرض
إضافة سلوك جديد للكائن دون تعديل فئته
متى تستخدمه
تحتاج ميزات اختيارية قابلة للتركيب (compression, encryption...)
Decorator.cs
public interface IDataSource
{
    string Read();
    void Write(string data);
}

public class FileDataSource : IDataSource
{
    public string Read() => "raw data";
    public void Write(string d) { }
}

public class DataSourceDecorator : IDataSource
{
    protected readonly IDataSource _wrapped;
    public DataSourceDecorator(IDataSource src) => _wrapped = src;
    public virtual string Read() => _wrapped.Read();
    public virtual void Write(string d) => _wrapped.Write(d);
}

public class CompressionDecorator : DataSourceDecorator
{
    public CompressionDecorator(IDataSource s) : base(s) { }
    public override string Read() => $"[decompress] {base.Read()}";
    public override void Write(string d) => base.Write($"[compress] {d}");
}

public class EncryptionDecorator : DataSourceDecorator
{
    public EncryptionDecorator(IDataSource s) : base(s) { }
    public override string Read() => $"[decrypt] {base.Read()}";
}

// تركيب متعدد الطبقات
IDataSource source = new EncryptionDecorator(
    new CompressionDecorator(
        new FileDataSource()));

Console.WriteLine(source.Read()); // [decrypt] [decompress] raw data
Facade
الواجهة الموحّدة
هيكلي
الغرض
واجهة مبسّطة لنظام معقد
متى تستخدمه
تريد إخفاء تعقيد عدة أنظمة خلف واجهة واحدة
Facade.cs
public class VideoConverter
{
    public void Convert(string file) => Console.WriteLine($"تحويل {file}");
}

public class AudioExtractor
{
    public void Extract(string file) => Console.WriteLine("استخراج الصوت");
}

public class VideoCompressor
{
    public void Compress(string file) => Console.WriteLine("ضغط الفيديو");
}

// الواجهة المبسطة
public class MediaProcessor
{
    private readonly VideoConverter _conv = new();
    private readonly AudioExtractor _aud = new();
    private readonly VideoCompressor _comp = new();

    public void Process(string file)
    {
        _conv.Convert(file);
        _aud.Extract(file);
        _comp.Compress(file);
    }
}

// المستخدم يرى شيئاً واحداً فقط
new MediaProcessor().Process("video.mp4");
Proxy
الوكيل
هيكلي
الغرض
التحكم في الوصول لكائن آخر
متى تستخدمه
حماية، تأجيل التحميل (lazy)، تخزين مؤقت
Proxy.cs
public interface IImage { void Display(); }

public class RealImage : IImage
{
    private readonly string _path;
    public RealImage(string path)
    {
        _path = path;
        LoadFromDisk(); // عملية ثقيلة
    }
    private void LoadFromDisk() => Console.WriteLine($"تحميل {_path}");
    public void Display() => Console.WriteLine($"عرض {_path}");
}

public class ImageProxy : IImage
{
    private readonly string _path;
    private RealImage? _real;

    public ImageProxy(string path) => _path = path;

    public void Display()
    {
        _real ??= new RealImage(_path); // تحميل عند الحاجة فقط
        _real.Display();
    }
}

الأنماط السلوكية (Behavioral)

تتحكم في التواصل بين الكائنات وتوزيع المسؤوليات.

Observer
المراقب
سلوكي
الغرض
إشعار عدة كائنات عند تغيّر كائن آخر
متى تستخدمه
أحداث، ناشر/مشترك، تحديث واجهات
Observer.cs
public interface IObserver
{
    void Update(string data);
}

public class Subject
{
    private readonly List<IObserver> _observers = new();

    public void Attach(IObserver o) => _observers.Add(o);
    public void Detach(IObserver o) => _observers.Remove(o);

    public void Notify(string data)
    {
        foreach (var o in _observers) o.Update(data);
    }
}

public class EmailObserver : IObserver
{
    public void Update(string data) => Console.WriteLine($"Email: {data}");
}
public class SmsObserver : IObserver
{
    public void Update(string data) => Console.WriteLine($"SMS: {data}");
}

// الاستخدام
var sub = new Subject();
sub.Attach(new EmailObserver());
sub.Attach(new SmsObserver());
sub.Notify("تم إنشاء طلبك");
Strategy
الاستراتيجية
سلوكي
الغرض
تبديل الخوارزمية في وقت التشغيل
متى تستخدمه
عدة طرق لفعل شيء (دفع، ضغط، ترتيب...)
Strategy.cs
public interface IPaymentStrategy
{
    void Pay(decimal amount);
}

public class CreditCardPayment : IPaymentStrategy
{
    public void Pay(decimal a) => Console.WriteLine($"بطاقة: {a}");
}

public class PayPalPayment : IPaymentStrategy
{
    public void Pay(decimal a) => Console.WriteLine($"PayPal: {a}");
}

public class ShoppingCart
{
    private IPaymentStrategy? _strategy;

    public void SetStrategy(IPaymentStrategy s) => _strategy = s;

    public void Checkout(decimal total)
    {
        _strategy?.Pay(total);
    }
}
Command
الأمر
سلوكي
الغرض
تغليف الطلب ككائن — قابل للتخزين والتراجع
متى تستخدمه
Undo/Redo، Queue الطلبات، التسجيل
Command.cs
public interface ICommand
{
    void Execute();
    void Undo();
}

public class AddTextCommand : ICommand
{
    private readonly List<string> _doc;
    private readonly string _text;

    public AddTextCommand(List<string> doc, string text)
    {
        _doc = doc;
        _text = text;
    }

    public void Execute() => _doc.Add(_text);
    public void Undo() => _doc.Remove(_text);
}

// تنفيذ + إمكانية التراجع
var doc = new List<string>();
ICommand cmd = new AddTextCommand(doc, "مرحباً");
cmd.Execute();
cmd.Undo();

أنماط في .NET

.NET نفسها تستخدم أنماط التصميم في مئات الأماكن. معرفتها يجعلك تفهم الإطار وتستخدمه بشكل أفضل.

النمط مثال في .NET
Singleton Application.Current, DependencyService
Factory ILoggerFactory, HttpClientFactory
Builder ConfigurationBuilder, HostBuilder
Decorator Stream + BufferedStream + GZipStream
Adapter StreamReader, DbDataAdapter
Observer الأحداث (Events) وINotifyPropertyChanged
Strategy IComparer<T>, JsonSerializerOptions
Command ICommand في WPF/MVVM

اكتشف الأنماط في .NET

عندما تقرأ كود .NET، حاول أن تتعرف على الأنماط. هذا يوطّد فهمك ويجعلك تراها في كل مكان.

8

أفضل الممارسات

  • افهم المشكلة أولاً: لا تبدأ بالنمط ثم تبحث عن مشكلة. ابدأ بالمشكلة وابحث عن النمط المناسب.
  • تجنّب الإفراط: Pattern for the sake of pattern = كود معقد. بسّط أولاً.
  • اقرأ الكود الحقيقي: افتح .NET source code وشاهد الأنماط في العمل.
  • استخدم DI Container: في .NET، معظم الأنماط تُدار عبر DI تلقائياً.
  • وثّق قراراتك: أضف تعليقاً قصيراً: "لماذا هذا النمط هنا؟".
  • ارجع للـ Refactoring: أحياناً النمط يظهر بعد إعادة الهيكلة، ليس قبلها.
  • لا تخف من التغيير: الأنماط ليست مقدسة — ما يصلح اليوم قد لا يصلح غداً.
  • اختبر النمط: اكتب اختبارات وحدة لكل نمط تستخدمه.

قاعدة ذهبية

الأنماط أدوات للتعبير، لا للإبهار. عندما تراها المناسبة، يكون الكود أبسط وأوضح — لا أعقد. إن لم يحدث ذلك، فربما لا تحتاجها.
