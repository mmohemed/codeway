نظرة عامة على المشروع

تطبيق الطقس هو مشروع مثالي لتعلم استهلاك الـ APIs الخارجية في C#. يجمع بين الاتصال بالشبكة، تحليل JSON، معالجة الأخطاء، وتصميم واجهة مستخدم جذابة.

ما ستتعلمه

الاتصال بالـ API

استخدام HttpClient لجلب البيانات من OpenWeatherMap.

تحليل JSON

قراءة استجابة JSON وتحويلها إلى نماذج C#.

معالجة الأخطاء

التعامل مع انقطاع الشبكة ومفاتيح API خاطئة.

واجهة جذابة

تصميم حديث يعكس حالة الطقس بألوان وأيقونات.

المتطلبات الوظيفية

  • البحث عن طقس أي مدينة بالاسم.
  • عرض درجة الحرارة، الوصف، الرطوبة، الرياح، والضغط.
  • عرض توقعات 5 أيام قادمة.
  • معالجة حالات التحميل والأخطاء.
  • حفظ آخر مدينة بحث عنها المستخدم.

لماذا هذا المشروع؟

لأنه يغطي أهم مهارة في تطوير التطبيقات الحديثة: الاتصال بالعالم الخارجي. كل تطبيق حقيقي اليوم يستهلك APIs.

2

ما هو الـ API؟

API (Application Programming Interface) هو وسيط يسمح لتطبيقك بالتواصل مع خدمة خارجية. تخيله كقائمة طعام في مطعم: أنت تطلب (Request)، المطبخ يحضّر (Processing)، ثم يصلك الطبق (Response).

دورة حياة طلب HTTP

  1. إنشاء الطلب: يحدد تطبيقك الـ URL، الطريقة (GET عادة)، والترويسات (Headers).
  2. الإرسال: يرسل HttpClient الطلب إلى خادم API عبر HTTPS.
  3. المعالجة: يتحقق الخادم من الطلب ويجلب البيانات.
  4. الاستجابة: يعيد الخادم كود الحالة (200, 404, 500) وبيانات JSON.
  5. التحليل: يحوّل تطبيقك JSON إلى نماذج C# ويستخدمها.

أكواد حالة شائعة

الكود المعنى ماذا تفعل؟
200 OK نجح الطلب حلّل البيانات واعرضها
404 Not Found المورد غير موجود اعرض "المدينة غير موجودة"
401 Unauthorized مفتاح API خاطئ تحقق من الإعدادات
429 Too Many Requests تجاوزت الحد المسموح انتظر ثم أعد المحاولة
500 Server Error خطأ في الخادم أعد المحاولة لاحقاً

دائماً تحقق من الحالة

لا تفترض أن كل طلب سينجح. استدعِ EnsureSuccessStatusCode() بعد كل استجابة أو تحقق يدوياً.

3

اختيار الـ OpenWeatherMap

سنستخدم OpenWeatherMap API لأنه:

  • مجاني للاستخدام الشخصي (60 طلب/دقيقة).
  • يوفر بيانات حالية + توقعات 5 أيام.
  • يدعم اللغة العربية (lang=ar).
  • توثيقه ممتاز وسهل البدء.

الـ Endpoints التي سنستخدمها

OpenWeatherMap API Endpoints
GET /data/2.5/weather?q={city}&appid={key}&units=metric&lang=ar الطقس الحالي
GET /data/2.5/forecast?q={city}&appid={key}&units=metric&lang=ar توقعات 5 أيام
GET /geo/1.0/direct?q={city}&limit=5&appid={key} إحداثيات المدينة

الحصول على مفتاح API

  1. سجّل في openweathermap.org مجاناً.
  2. اذهب إلى API Keys في لوحة التحكم.
  3. انسخ المفتاح (يبدأ العمل بعد ~10 دقائق).
  4. احفظه في متغير بيئة أو ملف appsettings.json.

لا تضع المفتاح في الكود!

استخدم متغيرات البيئة أو appsettings.json غير المرفوع إلى Git. رفع المفتاح للـ GitHub يعني تسريبه للعالم.

Models/WeatherResponse.cs
using System.Text.Json.Serialization;

namespace WeatherApp.Models;

public class WeatherResponse
{
    [JsonPropertyName("name")]
    public string CityName { get; set; } = "";

    [JsonPropertyName("main")]
    public MainInfo Main { get; set; } = new();

    [JsonPropertyName("weather")]
    public List<WeatherInfo> Weather { get; set; } = new();

    [JsonPropertyName("wind")]
    public WindInfo Wind { get; set; } = new();

    [JsonPropertyName("cod")]
    public int Code { get; set; }
}

public class MainInfo
{
    [JsonPropertyName("temp")]
    public double Temperature { get; set; }

    [JsonPropertyName("feels_like")]
    public double FeelsLike { get; set; }

    [JsonPropertyName("humidity")]
    public int Humidity { get; set; }

    [JsonPropertyName("pressure")]
    public int Pressure { get; set; }
}

public class WeatherInfo
{
    [JsonPropertyName("main")]
    public string Main { get; set; } = "";

    [JsonPropertyName("description")]
    public string Description { get; set; } = "";

    [JsonPropertyName("icon")]
    public string Icon { get; set; } = "";
}

public class WindInfo
{
    [JsonPropertyName("speed")]
    public double Speed { get; set; }
}

لماذا JsonPropertyName؟

لأن أسماء الحقول في JSON تختلف عن أسماء خصائص C# (مثل feels_like مقابل FeelsLike). هذا الوسم يربط بينهما تلقائياً.

استخدم أداة json2csharp.com أو ميزة Paste JSON as Classes في Visual Studio لتوليد الكلاسات تلقائياً من أي JSON.

خدمة الطقس (Service)

خدمة الطقس هي المسؤولة عن الاتصال بالـ API. نحقن HttpClient عبر IHttpClientFactory — أفضل ممارسة في .NET.

Services/WeatherService.cs
using System.Net.Http.Json;
using WeatherApp.Models;

namespace WeatherApp.Services;

public class WeatherService
{
    private readonly HttpClient _http;
    private readonly string _apiKey;

    public WeatherService(HttpClient http, IConfiguration config)
    {
        _http = http;
        _apiKey = config["OpenWeather:ApiKey"]
            ?? throw new InvalidOperationException("API key missing");

        _http.BaseAddress = new Uri("https://api.openweathermap.org/");
        _http.Timeout = TimeSpan.FromSeconds(10);
    }

    public async Task<WeatherResponse> GetWeatherAsync(
        string city,
        CancellationToken ct = default)
    {
        var url = $"data/2.5/weather?q={Uri.EscapeDataString(city)}"
                + $"&appid={_apiKey}&units=metric&lang=ar";

        var response = await _http.GetAsync(url, ct);

        if (!response.IsSuccessStatusCode)
        {
            if (response.StatusCode == HttpStatusCode.NotFound)
                throw new Exception("المدينة غير موجودة");

            throw new HttpRequestException(
                $"فشل الاتصال: {response.StatusCode}");
        }

        var data = await response.Content
            .ReadFromJsonAsync<WeatherResponse>(cancellationToken: ct);

        return data ?? throw new Exception("استجابة فارغة");
    }
}

تسجيل الخدمة في DI

Program.cs
var builder = WebApplication.CreateBuilder(args);

builder.Services.AddHttpClient<WeatherService>();
builder.Services.AddScoped<WeatherService>();

var app = builder.Build();
app.Run();

مزايا IHttpClientFactory

يدير دورة حياة HttpClient تلقائياً، يمنع مشكلة "استنفاد المقابس" (Socket Exhaustion)، ويدعم إعادة المحاولة (Retry) عبر Polly.

مثال استخدام في ViewModel

ViewModels/WeatherViewModel.cs
public class WeatherViewModel : ObservableObject
{
    private readonly WeatherService _service;
    private string _city = "الرياض";
    private WeatherResponse? _weather;
    private bool _isLoading;
    private string? _error;

    public string City
    {
        get => _city;
        set => SetProperty(ref _city, value);
    }

    public WeatherResponse? Weather
    {
        get => _weather;
        set => SetProperty(ref _weather, value);
    }

    public bool IsLoading
    {
        get => _isLoading;
        set => SetProperty(ref _isLoading, value);
    }

    public string? Error
    {
        get => _error;
        set => SetProperty(ref _error, value);
    }

    public async Task SearchAsync()
    {
        IsLoading = true;
        Error = null;

        try
        {
            Weather = await _service.GetWeatherAsync(City);
        }
        catch (Exception ex)
        {
            Error = ex.Message;
            Weather = null;
        }
        finally
        {
            IsLoading = false;
        }
    }
}

معالجة الأخطاء والتحميل

تطبيق احترافي لا يتعطل عند فشل الشبكة. نعالج 3 حالات: التحميل، النجاح، الخطأ.

سير العمل

  1. المستخدم يضغط بحث: نتحقق من أن المدينة غير فارغة.
  2. بدء التحميل: نعرض مؤشر دوّار ونعطّل زر البحث.
  3. الاتصال بالـ API: نستخدم try/catch ونمرر CancellationToken.
  4. الاستجابة: نتحقق من الحالة، نحلل JSON، ونحدّث الواجهة.
  5. الخطأ: نعرض رسالة واضحة بالعربية ونسجل التفاصيل في الـ log.
  6. إنهاء التحميل: نخفي المؤشر ونعيد تفعيل الزر في finally.
معالجة شاملة للأخطاء
public async Task SearchAsync(CancellationToken ct = default)
{
    if (string.IsNullOrWhiteSpace(City))
    {
        Error = "الرجاء إدخال اسم مدينة";
        return;
    }

    IsLoading = true;
    Error = null;

    try
    {
        Weather = await _service.GetWeatherAsync(City, ct);

        // حفظ آخر مدينة
        Preferences.Set("last_city", City);
    }
    catch (OperationCanceledException)
    {
        // تجاهل — المستخدم ألغى الطلب
    }
    catch (HttpRequestException)
    {
        Error = "تعذّر الاتصال بالإنترنت. تحقق من اتصالك.";
    }
    catch (Exception ex)
    {
        Error = ex.Message;
        Debug.WriteLine($"خطأ: {ex}");
    }
    finally
    {
        IsLoading = false;
    }
}

لا تبتلع الاستثناءات

catch (Exception) { } بدون عرض أو تسجيل يجعل تصحيح الأخطاء مستحيلاً. دائماً سجّل التفاصيل.

إعادة المحاولة بـ Polly

Program.cs — Retry Policy
builder.Services
    .AddHttpClient<WeatherService>()
    .AddTransientHttpErrorPolicy(p => p
        .WaitAndRetryAsync(3, retry =>
            TimeSpan.FromSeconds(Math.Pow(2, retry))));

هذه السياسة تعيد المحاولة 3 مرات بفاصل متزايد (2, 4, 8 ثوانٍ) عند فشل الشبكة أو ردّ الخادم بـ 5xx — مما يحسن موثوقية التطبيق.

8

أفضل الممارسات

  • استخدم IHttpClientFactory: لا تنشئ HttpClient يدوياً في كل مرة.
  • مرّر CancellationToken: لدعم إلغاء الطلبات الطويلة.
  • لا تضع مفاتيح API في الكود: استخدم متغيرات البيئة أو User Secrets.
  • عيّن Timeout: لا تنتظر للأبد — 10 ثوانٍ كافية لمعظم الطلبات.
  • خزّن مؤقتاً (Cache): لا تطلب نفس المدينة مرتين خلال دقيقة.
  • تحقق من الاستجابة: استخدم EnsureSuccessStatusCode أو تحقق يدوياً.
  • اعرض حالة التحميل: المستخدم يجب أن يعرف أن التطبيق يعمل.
  • سجّل الأخطاء: استخدم ILogger لتتبع المشاكل في الإنتاج.

مثال: تخزين مؤقت بسيط

MemoryCache
public async Task<WeatherResponse> GetWeatherAsync(string city)
{
    var cacheKey = $"weather_{city.ToLower()}";

    if (_cache.TryGetValue(cacheKey, out WeatherResponse? cached))
        return cached!;

    var fresh = await FetchFromApiAsync(city);

    _cache.Set(cacheKey, fresh, TimeSpan.FromMinutes(10));

    return fresh;
}

قاعدة ذهبية

أي تطبيق يستهلك API خارجي يجب أن يكون مقاوماً للفشل. الشبكة قد تنقطع، الخادم قد يسقط، والمفتاح قد ينتهي — تطبيقك يجب أن يستمر بالعمل.
