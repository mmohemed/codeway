LINQ — الاستعلام الموحّد في C#

Language Integrated Query

1

ما هي LINQ ولماذا نستخدمها؟ WHAT IS LINQ?

LINQ (Language Integrated Query) هي ميزة في C# تسمح لك بكتابة استعلامات على أي مجموعة بيانات — مصفوفة، List<T>، قاعدة بيانات SQL، XML، أو حتى كائنات في الذاكرة — بنفس الصياغة الموحّدة. بدلاً من كتابة حلقات foreach متداخلة ومعقدة، تكتب استعلاماً واضحاً يعبّر عن نيتك مباشرة.

تخيل أن لديك قائمة موظفين وتريد استخراج من هم أكبر من 30 سنة، مرتبين حسب الراتب، وأسماؤهم فقط. بدون LINQ تحتاج حلقة + شرط + قائمة مؤقتة + عملية ترتيب. مع LINQ، سطر واحد يفي بالغرض.

الفرق العملي — قبل وبعد

C# — بدون LINQ (الطريقة التقليدية) 
// بدون LINQ: حلقة يدوية + قائمة مؤقتة
var result = new List<string>();
foreach (var emp in employees)
{
    if (emp.Age > 30)
        result.Add(emp.Name);
}
result.Sort(); // ترتيب يدوي
C# — باستخدام LINQ (طريقة واحدة فقط) 
// مع LINQ: تعبير واحد واضح
var result = employees
    .Where(e => e.Age > 30)
    .OrderBy(e => e.Name)
    .Select(e => e.Name)
    .ToList();

الفكرة الجوهرية: LINQ لا تعطيك قدرات جديدة — كل ما تفعله يمكن فعله بحلقات. لكنها تعطيك وضوحاً (Readability) وأماناً في الأنواع (Type Safety) وتوحيداً عبر مصادر بيانات مختلفة.

مصدر واحد

نفس الصياغة تعمل على Objects و SQL و XML و Entities.

أمان الأنواع

المترجم يكتشف الأخطاء وقت الترجمة، لا وقت التشغيل.

إيجاز

سطر واحد يستبدل 10 أسطر من الحلقات المتداخلة.

تأجيل التنفيذ

الاستعلام لا يُنفّذ إلا عند التكرار عليه فعلياً.

2

صيغتا الكتابة — Query vs Method TWO SYNTAXES

LINQ تدعم صيغتين متكافئتين تماماً: صيغة الاستعلام (Query Syntax) المشابهة لـ SQL، وصيغة الدوال (Method Syntax) التي تعتمد على دوال الامتداد (Extension Methods). كلاهما يُترجم إلى نفس الكود النهائي — اختر ما يقرأه فريقك بوضوح.

المعيار Query Syntax Method Syntax
الشكل from x in src where ... select ... src.Where(...).Select(...)
القراءة أقرب لـ SQL — مألوفة لمن يعرف قواعد البيانات أقرب لبرمجة C# — متسلسلة وسهلة التركيب
المرونة محدودة — لا تدعم كل المؤثرات كاملة — تدعم كل مؤثرات LINQ
الأداء نفس الأداء تماماً نفس الأداء تماماً

نفس الاستعلام — صيغتان

C# — Query Syntax 
var highEarners =
    from e in employees
    where e.Salary > 10000
    orderby e.Salary descending
    select new { e.Name, e.Salary };
C# — Method Syntax (نفس النتيجة بالضبط) 
var highEarners = employees
    .Where(e => e.Salary > 10000)
    .OrderByDescending(e => e.Salary)
    .Select(e => new { e.Name, e.Salary });

توصية عملية: ابدأ بصيغة الدوال (Method Syntax) لأنها الأكثر مرونة والأكثر شيوعاً في المشاريع الحقيقية. استخدم Query Syntax فقط عندما تكون فيه أوضح لفريقك (خاصة مع join).

3

المؤثرات الأساسية في LINQ CORE OPERATORS

مؤثرات LINQ تُصنّف إلى مجموعات حسب الوظيفة. إليك الأكثر استخداماً — أتقنها أولاً فهي تغطي 90% من احتياجك اليومي:

Where

تصفية العناصر حسب شرط

Select

تحويل كل عنصر إلى شكل آخر

OrderBy / ThenBy

ترتيب تصاعدي (أو تنازلي)

First / FirstOrDefault

أول عنصر (أو null إن لم يوجد)

Any / All

هل يوجد عنصر؟ هل كل العناصر؟

Count / Sum / Average

إحصاءات سريعة على المجموعة

GroupBy

تجميع العناصر حسب مفتاح

Distinct

إزالة التكرار

Take / Skip

أخذ أول N أو تجاوزها

Join

ربط مجموعتين بمفتاح مشترك

SelectMany

تسطيح المجموعات المتداخلة

ToList / ToArray

تحويل النتيجة إلى مجموعة فعلية

مثال تطبيقي — Where + Select + OrderBy

C# — نموذج البيانات والاستعلام 
public record Employee(string Name, int Age, decimal Salary, string Dept);

var employees = new List<Employee>
{
    new("أحمد",  28, 8500,  "تطوير"),
    new("سارة",  35, 12000, "تصميم"),
    new("خالد",  42, 15000, "إدارة"),
    new("نورة",  31, 9800,  "تطوير"),
};

// الموظفون فوق 30 سنة، مرتبون حسب الراتب تنازلياً، الاسم والراتب فقط
var seniors = employees
    .Where(e => e.Age > 30)
    .OrderByDescending(e => e.Salary)
    .Select(e => new { e.Name, e.Salary });

foreach (var s in seniors)
    Console.WriteLine($"{s.Name} — {s.Salary:C}");

// الناتج:
// خالد — 15,000
// سارة — 12,000
// نورة — 9,800

مثال — GroupBy (تجميع حسب القسم)

C# — التجميع والإحصاء 
var byDept = employees
    .GroupBy(e => e.Dept)
    .Select(g => new
    {
        Dept      = g.Key,
        Count     = g.Count(),
        AvgSalary = g.Average(e => e.Salary),
        MaxSalary = g.Max(e => e.Salary)
    });

// الناتج:
// تطوير: 2 موظفين، متوسط 9,150، أعلى 9,800
// تصميم: 1، متوسط 12,000، أعلى 12,000
// إدارة:  1، متوسط 15,000، أعلى 15,000

انتبه للفرق بين First وFirstOrDefault: الأول يرمي استثناءً InvalidOperationException إن لم يجد عنصراً، والثاني يُرجع null. في الإنتاج، فضّل FirstOrDefault مع فحص النتيجة.

التأجيل والتنفيذ — Deferred Execution DEFERRED VS EAGER EXECUTION

هذه من أكثر النقاط التي تفاجئ المبتدئين. عندما تكتب استعلام LINQ، فإنه لا يُنفّذ فوراً. الاستعلام يُخزّن فقط "الوصفة" (البيانات + المؤثرات)، ولا يُنفّذ فعلياً إلا عندما تكرّر عليه (foreach) أو تحوّله إلى مجموعة (ToList، ToArray) أو تطلب منه إحصاءً (Count، Sum).

C# — التأجيل في العمل 
var numbers = new List<int> { 1, 2, 3, 4, 5 };

// لم يُنفّذ بعد! مجرد "وصفة"
var query = numbers.Where(n => n > 2);

// نضيف عنصراً جديداً إلى المصدر
numbers.Add(10);

// الآن فقط يُنفّذ — وسيلتقط العنصر الجديد أيضاً!
foreach (var n in query)
    Console.Write(n + " ");
// الناتج: 3 4 5 10

// لو أردنا نتيجة ثابتة، نحول فوراً:
var snapshot = numbers.Where(n => n > 2).ToList();

خطأ شائع: استدعاء استعلام LINQ داخل حلقة (مثلاً في كل طلب HTTP) دون ToList قد يُنفّذ الاستعلام مرات عديدة على قاعدة البيانات. احفظ النتيجة في متغير منفّذ مسبقاً إذا كنت ستستخدمها أكثر من مرة.

المؤثر نوع التنفيذ ملاحظة
Where, Select, OrderBy, GroupBy, Join مؤجّل (Deferred) لا يُنفّذ حتى تكرّر عليه
ToList, ToArray, ToDictionary فوري (Eager) ينفّذ الاستعلام ويحفظ النتيجة
Count, Sum, Any, All, First, Max فوري (Eager) ينفّذ ويُرجع قيمة واحدة

أفضل الممارسات الاحترافية BEST PRACTICES

لكتابة استعلامات LINQ نظيفة وفعّالة، اتبع هذه الإرشادات:

  • فضّل Method Syntax على Query Syntax ما لم تكن Query أوضح لفريقك — خاصة في join.
  • استخدم ToList() أو ToArray() عندما تُريد حفظ النتيجة واستخدامها أكثر من مرة، لتجنّب التنفيذ المتكرر.
  • فضّل Any() على Count() > 0 لفحص وجود عنصر — Any يتوقف عن المراجعة عند أول تطابق، أسرع بكثير.
  • استخدم FirstOrDefault وSingleOrDefault في السياقات التي قد لا يوجد فيها العنصر المطلوب، مع فحص null بعدها.
  • لا تضع استعلام LINQ داخل حلقة دون داعٍ — انقله خارج الحلقة إذا كان على نفس المصدر.
  • عند العمل مع EF Core، تحقق من أن استعلامك قابل للترجمة إلى SQL. بعض الدوال (مثل الدوال المخصصة) قد تُنفّذ في الذاكرة بعد جلب كل البيانات.

الخلاصة والاختبار السريع SUMMARY & QUIZ

ما تعلمته في هذا الدرس

  • ما هي LINQ ولماذا تُوحّد الاستعلامات عبر مصادر البيانات المختلفة.
  • الفرق بين Query Syntax و Method Syntax — ومتى تختار كلاً منهما.
  • المؤثرات الأساسية (Where / Select / OrderBy / GroupBy / Join) وأمثلة عملية.
  • مفهوم التأجيل (Deferred Execution) وأثره على الأداء والسلوك.
  • أفضل الممارسات لتجنّب التنفيذ المتكرر وأخطاء الأداء.
