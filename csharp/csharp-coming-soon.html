Reflection والسمات

Reflection API, Attributes & Metadata Inspection

Reflection هو قدرة البرنامج على فحص نفسه أثناء التشغيل — قراءة الأنواع، الخصائص، الدوال، والسمات (Attributes) التي تحملها. هو المحرك الخفي وراء Entity Framework، Dependency Injection، والمُحوّلات (Serializers).

ما هو Reflection؟ WHAT IS REFLECTION?

Reflection هو فضاء الأسماء System.Reflection الذي يسمح لبرنامجك بفحص نفسه أو أي تجميعة (Assembly) أثناء التشغيل. بمعنى آخر: الكود يستطيع أن "ينظر في المرآة" ليعرف: ما هي الأنواع الموجودة؟ ما خصائصها؟ ما دوالها؟ ما السمات المرفقة بها؟

بدون Reflection، كل شيء يجب أن يُعرف وقت الترجمة. معه، يمكنك بناء أنظمة مرنة تتكيف مع الأنواع التي لم تكن معروفة عند كتابة الكود — وهذا جوهر عمل أطر العمل الحديثة.

Assembly

ملف .dll أو .exe يحتوي على الأنواع. نقطة البداية لفحص أي تجميعة.

Type

يمثّل نوعاً (فئة، واجهة، struct، enum). يحتوي على معلومات كاملة عنه.

PropertyInfo

معلومات عن خاصية: اسمها، نوعها، هل لها getter/setter.

MethodInfo

معلومات عن دالة: معاملاتها، نوع إرجاعها، إمكانية استدعائها.

أين تستخدم Reflection يومياً؟ Entity Framework يحوّل خصائص فئتك إلى أعمدة SQL. System.Text.Json يقرأ خصائصك ليكتب JSON. DI Container يبحث عن الـ Constructors لإنشاء الكائنات. كل هذا Reflection.

أول خطوة: الحصول على Type

C# — Getting a Type 
using System;
using System.Reflection;

// 3 طرق للحصول على Type
Type t1 = typeof(string);           // وقت الترجمة
Type t2 = "hello".GetType();           // من كائن
Type t3 = Type.GetType("System.String"); // من اسم نصي

// معلومات أساسية
Console.WriteLine(t1.Name);         // String
Console.WriteLine(t1.Namespace);    // System
Console.WriteLine(t1.IsClass);      // True
Console.WriteLine(t1.IsAbstract);   // True

فحص الأنواع — Inspection EXPLORING MEMBERS

بعد الحصول على Type، يمكنك استكشاف كل ما يحتويه: الخصائص، الدوال، الحقول، الأحداث، الواجهات، الفئات الأساسية. هذه المعلومات متاحة عبر مجموعات (PropertyInfo[]، MethodInfo[]، إلخ).

الخاصية ماذا تُرجع الاستخدام
GetProperties() PropertyInfo[] قراءة/كتابة الخصائص
GetMethods() MethodInfo[] استدعاء الدوال
GetFields() FieldInfo[] قراءة/كتابة الحقول
GetConstructors() ConstructorInfo[] إنشاء كائنات
GetInterfaces() Type[] فحص الواجهات المنفذة
GetCustomAttributes() Attribute[] قراءة السمات المرفقة
C# — Exploring a Type 
public class User
{
    public int Id { get; set; }
    public string Name { get; set; } = "";
    public void Greet() => Console.WriteLine("Hi");
}

Type t = typeof(User);

// فحص الخصائص
foreach (PropertyInfo p in t.GetProperties())
    Console.WriteLine($"{p.Name} : {p.PropertyType.Name}");
// Id : Int32
// Name : String

// فحص الدوال (Public فقط افتراضياً)
foreach (MethodInfo m in t.GetMethods(BindingFlags.Public | BindingFlags.Instance | BindingFlags.DeclaredOnly))
    Console.WriteLine($"{m.ReturnType.Name} {m.Name}({string.Join(", ", m.GetParameters().Select(p => p.ParameterType.Name))})");

BindingFlags مهمة جداً: بدونها GetMethods تُرجع الدوال العامة (public) فقط. استخدم NonPublic للوصول للخاصة، وDeclaredOnly لتجاهل الموروثة، وStatic لفحص الدوال الثابتة.

فحص التجميعات (Assemblies)

C# — Assembly Inspection 
using System.Reflection;

// التجميعة الحالية
Assembly asm = Assembly.GetExecutingAssembly();
Console.WriteLine(asm.FullName);

// كل الأنواع العامة في التجميعة
foreach (Type t in asm.GetExportedTypes())
    Console.WriteLine(t.FullName);

// البحث عن نوع بالاسم
Type? userType = asm.GetType("MyApp.Models.User");

إنشاء الكائنات واستدعاء الدوال DYNAMIC CREATION & INVOCATION

Reflection لا يقتصر على الفحص — يمكنه الإنشاء والتنفيذ. يمكنك إنشاء كائن من نوع لا تعرفه وقت الترجمة، تعيين خصائصه، واستدعاء دواله. هذا هو أساس أنظمة الـ Plugins والـ DI Containers.

C# — Create & Invoke 
Type t = typeof(User);

// 1. إنشاء كائن — استدعاء constructor بدون معاملات
object? user = Activator.CreateInstance(t);

// 2. تعيين قيمة خاصية
t.GetProperty("Id")?.SetValue(user, 1);
t.GetProperty("Name")?.SetValue(user, "أحمد");

// 3. قراءة قيمة خاصية
object? name = t.GetProperty("Name")?.GetValue(user);
Console.WriteLine(name); // أحمد

// 4. استدعاء دالة
t.GetMethod("Greet")?.Invoke(user, null); // Hi

// 5. استدعاء دالة مع معاملات
MethodInfo? method = t.GetMethod("Add");
object? result = method?.Invoke(user, new object[] { 3, 4 });

أداء Reflection: استدعاء Invoke أبطأ بـ 10-100 مرة من الاستدعاء المباشر. لا تستخدمه في الحلقات الحرجة. بدائل أسرع: Compiled Expressions أو DynamicMethod أو المكتبات المتخصصة مثل FastMember.

مثال واقعي: نظام إضافات (Plugin System)

C# — Plugin Loader 
public interface IPlugin
{
    string Name { get; }
    void Execute();
}

// تحميل مكتبة .dll والبحث عن الأنواع المنفذة للواجهة
Assembly asm = Assembly.LoadFrom("MyPlugin.dll");

foreach (Type t in asm.GetTypes())
{
    if (typeof(IPlugin).IsAssignableFrom(t) && !t.IsAbstract)
    {
        IPlugin plugin = (IPlugin)Activator.CreateInstance(t)!;
        plugin.Execute();
    }
}

السمات — Attributes CUSTOM ATTRIBUTES

السمة (Attribute) هي بيانات وصفية (Metadata) تُرفق بالأنواع، الخصائص، أو الدوال. تخيّل أنها "ملاحظات لاصقة" (Post-it Notes) تُلصق على أجزاء الكود. المترجم لا يستخدمها، لكن Reflection يقرأها لتغيير السلوك.

كثير من ميزات C# مبنية على السمات: [Obsolete]، [Serializable]، [Required]، [Route] في ASP.NET. والأهم: يمكنك إنشاء سماتك الخاصة.

السمة ماذا تفعل المكان الشائع
[Obsolete] تحذير أن الكود قديم (تحذير أو خطأ) دوال، فئات
[Serializable] تمكين التسلسل الثنائي (قديم) فئات
[Required] حقل مطلوب (في DataAnnotations) خصائص
[Range(1, 100)] نطاق قيمة مسموح خصائص
[HttpGet] تحديد نوع HTTP (ASP.NET) دوال

إنشاء سمة مخصصة

C# — Custom Attribute 
using System;

// 1. تعريف سمة (ترث Attribute)
[AttributeUsage(AttributeTargets.Property)]
public class DisplayNameAttribute : Attribute
{
    public string DisplayName { get; }
    public DisplayNameAttribute(string name) => DisplayName = name;
}

// 2. استخدامها
public class User
{
    [DisplayName("الرقم")]
    public int Id { get; set; }

    [DisplayName("الاسم الكامل")]
    public string Name { get; set; } = "";
}

// 3. قراءتها عبر Reflection
foreach (PropertyInfo p in typeof(User).GetProperties())
{
    var attr = p.GetCustomAttribute<DisplayNameAttribute>();
    Console.WriteLine($"{p.Name} → {attr?.DisplayName}");
}
// Id → الرقم
// Name → الاسم الكامل

مثال واقعي: نظام تحقق (Validation)

C# — Attribute-based Validation 
public class RequiredAttribute : Attribute { }

public class User
{
    [Required]
    public string Name { get; set; } = "";

    public string Email { get; set; } = "";
}

// محقق عام يقرأ السمات
public static List<string> Validate(object obj)
{
    var errors = new List<string>();
    Type t = obj.GetType();

    foreach (PropertyInfo p in t.GetProperties())
    {
        bool required = p.GetCustomAttribute<RequiredAttribute>() != null;
        if (required && string.IsNullOrEmpty(p.GetValue(obj) as string))
            errors.Add($"{p.Name} مطلوب");
    }
    return errors;
}

var errors = Validate(new User());
// ["Name مطلوب"]

هذا هو جوهر أطر العمل: ASP.NET Core Validation، Entity Framework Mapping، AutoMapper، إلخ — كلها تقرأ سمات عبر Reflection وتبني عليها سلوكاً. بمجرد فهم هذا النمط، تفهم كيف تعمل معظم المكتبات.

أفضل الممارسات الاحترافية BEST PRACTICES

Reflection قوي لكنه مكلف. استخدمه بذكاء:

  • استخدمه فقط عند الحاجة الفعلية — إذا كان النوع معروفاً وقت الترجمة، لا تستخدم Reflection.
  • خزّن نتائج Reflection في الكاش (Cache) — GetProperties() مكلفة جداً؛ استدعها مرة واحدة وخزّنها في Dictionary<Type, PropertyInfo[]>.
  • استخدم GetCustomAttribute<T>() بدلاً من GetCustomAttributes() — أسرع وأكثر أماناً في الأنواع.
  • لا تستخدم Reflection مع بيانات غير موثوقة — قد يفتح ثغرات (Type Injection). تحقق دائماً من الأسماء المسموح بها.
  • فضّل dynamic أو Generics عندما يكون ذلك ممكناً — كلاهما أسرع من Invoke ويحافظ على الأمان.
  • حدّد BindingFlags بدقة — استدعاء GetMethods() بدون تحديد يجلب دوال الكائن الأساسي (object) كلها.
  • استخدم [AttributeUsage] بشكل صحيح لتحديد أين يمكن استخدام السمة (Property, Class, Method, All).

الخلاصة والاختبار السريع SUMMARY & QUIZ

ما تعلمته في هذا الدرس

  • Reflection يتيح فحص الأنواع أثناء التشغيل — الأساس وراء EF Core، DI، و Serializers.
  • ثلاث طرق للحصول على Type واستخدام GetProperties()، GetMethods()، إلخ للفحص.
  • الإنشاء الديناميكي والاستدعاء عبر Activator.CreateInstance وInvoke — مع تحذير الأداء.
  • السمات (Attributes) كبيانات وصفية تُقرأ عبر Reflection — وكيف تصنع سمة مخصصة.
  • مثال واقعي على نظام تحقق (Validation) مبني بالكامل على السمات + Reflection.
