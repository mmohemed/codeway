نظرة عامة على المشروع PROJECT OVERVIEW

دفتر العناوين هو التطبيق الذي ينتقل بك من مجرد "حاسبة" إلى تطبيق يحفظ بيانات ويستعيدها. ستتعلم خلاله كيف تصنع CRUD كامل (Create, Read, Update, Delete)، كيف تستخدم LINQ للبحث والفرز، وكيف تحفظ البيانات في ملف JSON ليستعيدها في التشغيل التالي.

المشروع مقسّم إلى أربع طبقات — كل طبقة مسؤولة عن شيء واحد فقط:

النموذج (Model)

فئة Contact تحمل بيانات جهة الاتصال: الاسم، الهاتف، البريد، الشركة.

المستودع (Repository)

فئة ContactRepository تُدير قائمة الاتصالات في الذاكرة.

الحفظ (Storage)

حفظ/تحميل القائمة من/إلى ملف JSON باستخدام System.Text.Json.

الواجهة (UI)

Form أو تطبيق ويب يعرض القائمة ويسمح بالإضافة والحذف والبحث.

القيمة التعليمية: هذا المشروع يعلمك نمط Repository Pattern الذي يُستخدم في كل التطبيقات الاحترافية. بدلاً من الوصول للملف مباشرة من الواجهة، تمر عبر طبقة وسيطة — تجعل تغيير مكان التخزين (ملف → قاعدة بيانات) أمراً سهلاً.

2

نموذج البيانات — Contact DATA MODEL

كل شيء يبدأ من النموذج. فئة Contact هي تجسيد لجهة اتصال واحدة. نستخدم record في C# 9+ لأنها توفر خصائص غير قابلة للتغيير وقيمة مساواة تلقائية — مثالية لكيانات البيانات.

C# — Contact.cs 
public record Contact
{
    public Guid   Id        { get; init; } = Guid.NewGuid();
    public string Name      { get; init; } = "";
    public string Phone     { get; init; } = "";
    public string Email     { get; init; } = "";
    public string Company   { get; init; } = "";
}

لماذا Guid للمعرّف؟ لأننا قد نحذف جهة اتصال ثم نضيف أخرى بنفس الاسم. لو استخدمنا int متزايداً، فقد نعيد استخدام رقم محذوف ونسبب التباساً. Guid فريد دائماً.

التحقق من الصحة (Validation)

قبل حفظ أي جهة اتصال، يجب التحقق من بياناتها. نضع التحقق داخل دالة مستقلة تُرجع قائمة أخطاء — بدلاً من رمي استثناء في كل مرة.

C# — Validation 
using System.Net.Mail;

public static List<string> Validate(Contact c)
{
    var errors = new List<string>();

    if (string.IsNullOrWhiteSpace(c.Name))
        errors.Add("الاسم مطلوب");

    if (string.IsNullOrWhiteSpace(c.Phone))
        errors.Add("رقم الهاتف مطلوب");
    else if (!System.Text.RegularExpressions.Regex.IsMatch(c.Phone, @"^\+?[0-9]{7,15}$"))
        errors.Add("رقم الهاتف غير صالح");

    if (!string.IsNullOrWhiteSpace(c.Email))
    {
        try { _ = new MailAddress(c.Email); }
        catch { errors.Add("البريد الإلكتروني غير صالح"); }
    }

    return errors;
}

لا تتحقق داخل الـ Model نفسه: اترك Contact كياناً بسيطاً (POCO). ضع التحقق في طبقة خدمة. هذا يسمح بإعادة استخدام النموذج في سياقات مختلفة (مثلاً استيراد من ملف بدون تحقق صارم).

طبقة الخدمة — ContactRepository SERVICE LAYER

هذه هي الطبقة التي تُنفّذ العمليات على القائمة: إضافة، حذف، تعديل، بحث. الواجهة لا تعرف كيف تعمل هذه العمليات — تستدعي الدوال فقط. هذا يسمح باختبار المنطق بمعزل عن الواجهة.

C# — ContactRepository.cs 
using System.Linq;

public class ContactRepository
{
    private readonly List<Contact> _contacts = new();

    // إنشاء
    public Contact Add(Contact c)
    {
        var errors = Validate(c);
        if (errors.Any())
            throw new ArgumentException(string.Join("; ", errors));

        _contacts.Add(c);
        return c;
    }

    // قراءة (كل الجهات)
    public IReadOnlyList<Contact> GetAll() => _contacts.AsReadOnly();

    // قراءة (واحد بالمعرّف)
    public Contact? GetById(Guid id) =>
        _contacts.FirstOrDefault(c => c.Id == id);

    // تحديث
    public void Update(Contact updated)
    {
        var index = _contacts.FindIndex(c => c.Id == updated.Id);
        if (index == -1)
            throw new KeyNotFoundException("جهة الاتصال غير موجودة");

        _contacts[index] = updated;
    }

    // حذف
    public bool Delete(Guid id) =>
        _contacts.RemoveAll(c => c.Id == id) > 0;

    // بحث
    public IEnumerable<Contact> Search(string term)
    {
        if (string.IsNullOrWhiteSpace(term))
            return _contacts;

        term = term.ToLower();
        return _contacts.Where(c =>
            c.Name.ToLower().Contains(term) ||
            c.Phone.Contains(term) ||
            c.Email.ToLower().Contains(term) ||
            c.Company.ToLower().Contains(term));
    }
}

لاحظ استخدام LINQ: FirstOrDefault، Any، Where — كلها من درس LINQ. المشاريع الحقيقية تجمع بين المفاهيم، وهكذا تفهمها فعلاً. البحث هنا يقارن بأربعة حقول دفعة واحدة بسطر واحد.

الفرز والترتيب

دالة GetSortedBy تعيد القائمة مرتبة حسب الحقل المطلوب:

C# — Sorting 
public IEnumerable<Contact> GetSortedBy(string field, bool ascending = true)
{
    Func<Contact, string> selector = field.ToLower() switch
    {
        "name"    => c => c.Name,
        "company" => c => c.Company,
        "phone"   => c => c.Phone,
        _          => c => c.Name
    };

    return ascending
        ? _contacts.OrderBy(selector)
        : _contacts.OrderByDescending(selector);
}

الحفظ الدائم في JSON JSON PERSISTENCE

التطبيق بدون حفظ هو مجرد لعبة. عندما يغلق المستخدم البرنامج ويفتحه، يجب أن يجد بياناته في مكانها. هذا هو دور طبقة التخزين.

C# — JsonContactStorage.cs 
using System.IO;
using System.Text.Json;
using System.Threading.Tasks;

public class JsonContactStorage
{
    private readonly string _filePath;

    public JsonContactStorage(string filePath = "contacts.json")
    {
        _filePath = filePath;
    }

    private static readonly JsonSerializerOptions _options = new()
    {
        WriteIndented = true,
        PropertyNamingPolicy = JsonNamingPolicy.CamelCase
    };

    // حفظ كامل القائمة
    public async Task SaveAsync(IEnumerable<Contact> contacts)
    {
        string json = JsonSerializer.Serialize(contacts, _options);
        await File.WriteAllTextAsync(_filePath, json);
    }

    // تحميل — يُرجع قائمة فارغة إن لم يوجد الملف
    public async Task<List<Contact>> LoadAsync()
    {
        if (!File.Exists(_filePath))
            return new List<Contact>();

        try
        {
            string json = await File.ReadAllTextAsync(_filePath);
            return JsonSerializer.Deserialize<List<Contact>>(json, _options)
                   ?? new List<Contact>();
        }
        catch (JsonException)
        {
            // ملف تالف — نبدأ بقائمة فارغة بدلاً من الانهيار
            return new List<Contact>();
        }
    }
}

نمط الاستخدام: عند بدء التطبيق: LoadAsync() → تحميل إلى ContactRepository. عند أي تغيير (إضافة/حذف/تعديل): SaveAsync(). هذا النمط يسمى Write-Through Cache.

لا تحفظ بعد كل حرف: لو حفظت بعد كل إدخال حرفي، ستكتب إلى القرص مئات المرات في الثانية. احفظ عند الحاجة فقط (بعد إتمام عملية، أو كل 30 ثانية تلقائياً).

ربط كل شيء في Main

C# — Program.cs 
var storage = new JsonContactStorage("my_contacts.json");
var repo = new ContactRepository();

// تحميل عند البدء
var loaded = await storage.LoadAsync();
foreach (var c in loaded) repo.Add(c);

// العمليات
repo.Add(new Contact { Name = "أحمد", Phone = "+966501234567" });
repo.Add(new Contact { Name = "سارة", Phone = "+966509876543" });

// حفظ بعد أي تغيير
await storage.SaveAsync(repo.GetAll());

البحث والفرز المتقدم SEARCH & SORT

البحث الجيد هو ما يفرّق بين تطبيق "يعمل" وتطبيق "يُستخدم". إليك التحسينات التي تطبقها في المشاريع الحقيقية:

1. البحث الضبابي (Fuzzy Search)

بدلاً من مطابقة دقيقة، اسمح بأخطاء إملائية بسيطة:

C# — Fuzzy Search with Levenshtein 
public static int Levenshtein(string a, string b)
{
    int[,] dp = new int[a.Length + 1, b.Length + 1];
    for (int i = 0; i <= a.Length; i++) dp[i, 0] = i;
    for (int j = 0; j <= b.Length; j++) dp[0, j] = j;

    for (int i = 1; i <= a.Length; i++)
        for (int j = 1; j <= b.Length; j++)
            dp[i, j] = Math.Min(Math.Min(
                dp[i - 1, j] + 1,
                dp[i, j - 1] + 1),
                dp[i - 1, j - 1] + (a[i - 1] == b[j - 1] ? 0 : 1));

    return dp[a.Length, b.Length];
}

// استخدام: البحث عن "احمد" يجد "أحمد" (مسافة تحرير 1)
var matches = _contacts.Where(c => Levenshtein(c.Name, term) <= 2);

2. البحث الفوري أثناء الكتابة (Debouncing)

في تطبيقات الواجهة، كل ضغطة زر تطلق بحثاً. إذا كانت القائمة كبيرة، هذا يبطئ الواجهة. الحل: انتظر 300 مللي ثانية بعد آخر ضغطة:

C# — Debounce Search 
private System.Timers.Timer? _debounceTimer;

private void txtSearch_TextChanged(object sender, EventArgs e)
{
    _debounceTimer?.Stop();
    _debounceTimer = new System.Timers.Timer(300) { AutoReset = false };
    _debounceTimer.Elapsed += (s, ev) =>
    {
        Invoke(new Action(() => PerformSearch(txtSearch.Text)));
    };
    _debounceTimer.Start();
}

3. الفرز المتعدد

في المشاريع الحقيقية تريد أحياناً فرزاً متعدد المستويات: بالشركة أولاً، ثم بالاسم داخل كل شركة:

C# — Multi-Level Sort 
var sorted = _contacts
    .OrderBy(c => c.Company)
    .ThenBy(c => c.Name)
    .ToList();

لا تفرز القائمة الأصلية: _contacts.Sort() تعدّل القائمة الحقيقية. استخدم OrderBy وOrderByDescending التي تُرجع IEnumerable جديداً — الأصل يبقى سليماً.

الخلاصة والاختبار السريع SUMMARY & QUIZ

ما أنجزته في هذا المشروع

  • بنيت CRUD كامل (إضافة/قراءة/تعديل/حذف) على فئة ContactRepository.
  • استخدمت LINQ في البحث (Where، Contains) والفرز (OrderBy، ThenBy).
  • فصلت طبقة التخزين (JsonContactStorage) — تحفظ/تحمل بـ System.Text.Json.
  • أضفت تحققاً (Validation) من البيانات قبل الحفظ — لا استثناءات غير متوقعة.
  • تعرفت على تقنيات تحسين: البحث الضبابي، Debouncing، والفرز المتعدد.
