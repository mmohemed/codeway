1

ما هو EF Core؟

Entity Framework Core (EF Core) هو إطار ORM (Object-Relational Mapper) من مايكروسوفت. وظيفته: تحويل كائنات C# إلى صفوف في قاعدة بيانات، والعكس — دون كتابة SQL يدوياً في معظم الحالات.

لماذا EF Core؟

إنتاجية عالية

لا تكتب CRUD يدوياً — EF يفعله عنك.

أمان أكبر

يحميك من SQL Injection تلقائياً عبر Parameterized Queries.

دعم LINQ

استعلامات مكتوبة بـ C# تُترجم إلى SQL.

تتبع التغييرات

يكتشف ما تغيّر تلقائياً ويولّد UPDATE ذكياً.

مزودون مدعومون

قاعدة البيانات الحزمة الترخيص
SQL Server Microsoft.EntityFrameworkCore.SqlServer مجاني
PostgreSQL Npgsql.EntityFrameworkCore.PostgreSQL مجاني
MySQL / MariaDB Pomelo.EntityFrameworkCore.MySql مجاني
SQLite Microsoft.EntityFrameworkCore.Sqlite مجاني
Cosmos DB Microsoft.EntityFrameworkCore.Cosmos مدفوع

EF Core ليس بديلاً عن SQL

معرفة SQL أساسية حتى مع EF. ستحتاجها لتشخيص الأداء، تحليل الاستعلامات، وتحسين الاستعلامات البطيئة.

2

Entity & DbContext

أي تطبيق EF Core يقوم على عنصرين أساسيين: Entity (كلاس C# يمثّل جدولاً) وDbContext (الجسر بين الكود وقاعدة البيانات).

1) Entity — الكيان

Models/User.cs
public class User
{
    public int Id { get; set; }             // PK
    public string Name { get; set; } = "";
    public string Email { get; set; } = "";
    public DateTime CreatedAt { get; set; } = DateTime.UtcNow;
    public bool IsActive { get; set; } = true;

    // Navigation — العلاقة مع Orders
    public List<Order> Orders { get; set; } = new();
}

2) DbContext — السياق

Data/AppDbContext.cs
using Microsoft.EntityFrameworkCore;

public class AppDbContext : DbContext
{
    public DbSet<User> Users { get; set; }
    public DbSet<Order> Orders { get; set; }
    public DbSet<Product> Products { get; set; }

    public AppDbContext(DbContextOptions<AppDbContext> options)
        : base(options) { }

    protected override void OnModelCreating(ModelBuilder mb)
    {
        // تخصيص الجداول
        mb.Entity<User>(b =>
        {
            b.ToTable("Users");
            b.HasKey(u => u.Id);
            b.HasIndex(u => u.Email).IsUnique();
            b.Property(u => u.Email)
                .IsRequired()
                .HasMaxLength(200);
            b.Property(u => u.Name)
                .IsRequired()
                .HasMaxLength(100);
        });
    }
}

تسجيل DbContext في DI

Program.cs
// SQL Server
builder.Services.AddDbContext<AppDbContext>(opts =>
    opts.UseSqlServer(
        builder.Configuration.GetConnectionString("Default")));

// أو SQLite للتطوير
builder.Services.AddDbContext<AppDbContext>(opts =>
    opts.UseSqlite("Data Source=app.db"));

// في appsettings.json
// "ConnectionStrings": {
//   "Default": "Server=localhost;Database=AppDB;Trusted_Connection=True;"
// }

DbContext دورة حياته Scoped

AddDbContext يسجّل السياق كـ Scoped تلقائياً — نسخة واحدة لكل طلب HTTP. لا تحاول تسجيله Singleton.

3

العلاقات (Relationships)

EF Core يدعم 3 أنواع من العلاقات. فهمها ضروري لتصميم قاعدة بيانات سليمة.

مخطط الكيانات
User
Id int (PK) Name string Email string (unique) CreatedAt DateTime
Order
Id int (PK) UserId int (FK) Total decimal Status string CreatedAt DateTime
OrderItem
Id int (PK) OrderId int (FK) ProductId int (FK) Quantity int Price decimal
Product
Id int (PK) Name string Price decimal Stock int

1) One-to-Many (واحد لمتعدد)

مستخدم واحد له عدة طلبات، لكن كل طلب يخص مستخدماً واحداً.

One-to-Many
public class User
{
    public int Id { get; set; }
    public string Name { get; set; } = "";

    // علاقة "واحد لمتعدد" — مستخدم له طلبات كثيرة
    public List<Order> Orders { get; set; } = new();
}

public class Order
{
    public int Id { get; set; }

    // Foreign Key
    public int UserId { get; set; }

    // Navigation — الطلب يخص مستخدماً واحداً
    public User? User { get; set; }

    public decimal Total { get; set; }
}

2) One-to-One (واحد لواحد)

مستخدم واحد له ملف شخصي واحد فقط. مثال: User ↔ Profile.

One-to-One
public class User
{
    public int Id { get; set; }
    public UserProfile? Profile { get; set; }
}

public class UserProfile
{
    public int Id { get; set; }
    public int UserId { get; set; }
    public User User { get; set; } = null!;
    public string? Bio { get; set; }
    public string? AvatarUrl { get; set; }
}

// في OnModelCreating
mb.Entity<User>()
  .HasOne(u => u.Profile)
  .WithOne(p => p.User)
  .HasForeignKey<UserProfile>(p => p.UserId);

3) Many-to-Many (متعدد لمتعدد)

طلب له منتجات كثيرة، والمنتج قد يظهر في طلبات كثيرة. مثال: Order ↔ Product.

Many-to-Many
public class Order
{
    public int Id { get; set; }
    public List<OrderItem> Items { get; set; } = new();
}

public class Product
{
    public int Id { get; set; }
    public string Name { get; set; } = "";
    public List<OrderItem> Orders { get; set; } = new();
}

// جدول وسيط يحمل بيانات إضافية
public class OrderItem
{
    public int Id { get; set; }
    public int OrderId { get; set; }
    public Order Order { get; set; } = null!;

    public int ProductId { get; set; }
    public Product Product { get; set; } = null!;

    public int Quantity { get; set; }
    public decimal Price { get; set; }
}

Lazy Loading محظور افتراضياً

EF Core لا يدعم Lazy Loading افتراضياً (بعكس EF6). يجب إما: استخدام Include() (Eager)، أو تفعيل Lazy Proxies من الحزم الإضافية.

4

Migrations — إدارة تغييرات المخطط

Migrations هي الطريقة الآمنة لتحديث قاعدة البيانات بعد تعديل الـ Models. بدلاً من تنفيذ SQL يدوياً، EF يولد migration تلقائياً.

دورة العمل

  1. عدّل الـ Model: أضف خاصية أو كلاساً جديداً.
  2. أنشئ Migration: dotnet ef migrations add Name.
  3. راجع الملف: افتح Migration وتأكد من التغييرات.
  4. طبّق: dotnet ef database update.
  5. كرر: لكل تغيير مستقبلي.

أوامر أساسية

Terminal
# تثبيت أدوات EF (مرة واحدة)
dotnet tool install --global dotnet-ef

# إنشاء أول migration
dotnet ef migrations add InitialCreate

# تطبيق على قاعدة البيانات
dotnet ef database update

# عرض قائمة Migrations
dotnet ef migrations list

# التراجع عن آخر migration (لم تُطبّق)
dotnet ef migrations remove

# التراجع إلى migration سابقة (مُطبّقة)
dotnet ef database update PreviousMigrationName

# إنشاء سكريبت SQL يدوي (للإنتاج)
dotnet ef migrations script -o migrate.sql

شكل ملف Migration

Migrations/20261103_InitialCreate.cs
public partial class InitialCreate : Migration
{
    protected override void Up(MigrationBuilder mb)
    {
        mb.CreateTable(
            name: "Users",
            columns: table => new
            {
                Id = table.Column<int>()
                    .Annotation("SqlServer:Identity", "1, 1")
                    .NotNull(),
                Name = table.Column<string>(100).NotNull(),
                Email = table.Column<string>(200).NotNull(),
                CreatedAt = table.Column<DateTime>().NotNull(),
                Constraints = table.PrimaryKey(
                    name: "PK_Users",
                    column: x => x.Id)
            });

        mb.CreateIndex(
            name: "IX_Users_Email",
            table: "Users",
            column: "Email",
            unique: true);
    }

    protected override void Down(MigrationBuilder mb)
    {
        mb.DropTable(name: "Users");
    }
}

في الإنتاج

لا تنفّذ database update مباشرة على الإنتاج. استخدم migrations script لتوليد SQL، وراجعه مع فريق DBA قبل التطبيق.

5

LINQ إلى SQL

EF Core يترجم استعلامات LINQ إلى SQL. هذا يعني أنك تكتب C#، لكن قاعدة البيانات تنفذ SQL محسّناً.

SQL مباشر
SELECT u.Id, u.Name, u.Email FROM Users u WHERE u.IsActive = 1 AND u.CreatedAt > '2026-01-01' ORDER BY u.CreatedAt DESC;
LINQ (C#)
var users = await _db.Users .Where(u => u.IsActive) .Where(u => u.CreatedAt > cutoff) .OrderByDescending(u => u.CreatedAt) .ToListAsync();

عمليات شائعة

LINQ Operations
// 1) تصفية + ترتيب
var activeUsers = await _db.Users
    .Where(u => u.IsActive)
    .OrderBy(u => u.Name)
    .ToListAsync();

// 2) بحث
var search = await _db.Users
    .Where(u => u.Name.Contains("Ahmed"))
    .ToListAsync();

// 3) Pagination
var page = await _db.Users
    .OrderBy(u => u.Id)
    .Skip((pageNum - 1) * pageSize)
    .Take(pageSize)
    .ToListAsync();

// 4) Join
var userOrders = await _db.Orders
    .Include(o => o.User)
    .Where(o => o.Total > 100)
    .Select(o => new
    {
        OrderId = o.Id,
        UserName = o.User!.Name,
        o.Total
    })
    .ToListAsync();

// 5) تجميع
var stats = await _db.Orders
    .GroupBy(o => o.UserId)
    .Select(g => new
    {
        UserId = g.Key,
        Count = g.Count(),
        Total = g.Sum(o => o.Total)
    })
    .ToListAsync();

// 6) تحديث جماعي
await _db.Users
    .Where(u => !u.IsActive)
    .ExecuteUpdateAsync(s => s
        .SetProperty(u => u.IsActive, true));

// 7) حذف جماعي
await _db.Users
    .Where(u => u.CreatedAt < cutoff)
    .ExecuteDeleteAsync();

ExecuteUpdate / ExecuteDelete

في EF Core 7+، يمكنك تنفيذ تحديث/حذف جماعي دون تحميل الكيانات إلى الذاكرة. أسرع بكثير لعشرات الآلاف من السجلات.

6

الأداء و N+1

EF Core سهل، لكنه قد يخفي مشاكل أداء خطيرة. أخطرها: N+1 Problem.

مشكلة N+1

عندما تحمّل 100 مستخدم، ثم تحمّل طلبات كل مستخدم في حلقة — EF ينفذ استعلاماً لكل مستخدم (101 استعلام). هذا يبطئ التطبيق بشكل كبير.

❌ N+1
// سيّئ: 1 + N استعلام
var users = await _db.Users.ToListAsync();

foreach (var user in users)
{
    // استعلام جديد لكل مستخدم!
    var orders = await _db.Orders
        .Where(o => o.UserId == user.Id)
        .ToListAsync();
}
✅ Include
// جيد: استعلام واحد مع JOIN
var users = await _db.Users
    .Include(u => u.Orders)
    .ToListAsync();

foreach (var user in users)
{
    // Orders محمّلة مسبقاً — لا استعلام إضافي
    var orders = user.Orders;
}

تقنيات تحسين الأداء

التقنية الفائدة الاستخدام
AsNoTracking إلغاء تتبع التغييرات .AsNoTracking() للقراءة فقط
Select جلب أعمدة محددة فقط .Select(x => new { x.Id })
AsSplitQuery تجنب Cartesian Explosion .AsSplitQuery()
Pagination جلب جزء من البيانات .Skip(n).Take(m)
Compiled Queries تحسين الاستعلامات المتكررة EF.CompileQuery()
Indexes تسريع البحث .HasIndex(...)

AsNoTracking للقراءة فقط

في الاستعلامات التي لا تحتاج تحديثاً، استخدم AsNoTracking() — يوفر 30-50% من الذاكرة والوقت لأنه يلغي تتبع التغييرات.

7

Repository Pattern

بدلاً من استخدام DbContext مباشرة في الـ Controllers، غلّفه في Repository. هذا يفصل منطق الأعمال عن الوصول للبيانات.

الواجهة

Repositories/IUserRepository.cs
public interface IUserRepository
{
    Task<User?> GetByIdAsync(int id);
    Task<List<User>> GetAllAsync();
    Task<List<User>> SearchAsync(string term);
    Task<User> AddAsync(User user);
    Task UpdateAsync(User user);
    Task DeleteAsync(int id);
    Task<bool> ExistsAsync(int id);
}

التنفيذ

Repositories/UserRepository.cs
public class UserRepository : IUserRepository
{
    private readonly AppDbContext _db;

    public UserRepository(AppDbContext db) => _db = db;

    public async Task<User?> GetByIdAsync(int id) =>
        await _db.Users.FindAsync(id);

    public async Task<List<User>> GetAllAsync() =>
        await _db.Users
            .AsNoTracking()
            .ToListAsync();

    public async Task<List<User>> SearchAsync(string term) =>
        await _db.Users
            .AsNoTracking()
            .Where(u => u.Name.Contains(term) ||
                        u.Email.Contains(term))
            .ToListAsync();

    public async Task<User> AddAsync(User user)
    {
        _db.Users.Add(user);
        await _db.SaveChangesAsync();
        return user;
    }

    public async Task UpdateAsync(User user)
    {
        _db.Users.Update(user);
        await _db.SaveChangesAsync();
    }

    public async Task DeleteAsync(int id)
    {
        var user = await _db.Users.FindAsync(id);
        if (user is not null)
        {
            _db.Users.Remove(user);
            await _db.SaveChangesAsync();
        }
    }

    public async Task<bool> ExistsAsync(int id) =>
        await _db.Users.AnyAsync(u => u.Id == id);
}

تسجيله في DI

Program.cs
builder.Services.AddDbContext<AppDbContext>(...);

builder.Services.AddScoped<IUserRepository, UserRepository>();
builder.Services.AddScoped<IOrderRepository, OrderRepository>();
builder.Services.AddScoped<IUserService, UserService>();

فوائد Repository

قابلية الاختبار (Mock)، مركزية الاستعلامات، وإمكانية تبديل مصدر البيانات. لكن لا تُفرط — بعض الفرق تفضّل استخدام DbContext مباشرة في الخدمات.

محاكي SQL تفاعلي

اكتب استعلام LINQ وشاهد كيف يترجمه EF Core إلى SQL. اختر من أمثلة جاهزة أو اكتب استعلامك.

LINQ → SQL Translator
EF Core 8
LINQ 
await _db.Users.ToListAsync();
EF Core يترجم تلقائياً
SQL الناتج 
SELECT [u].[Id], [u].[Name], [u].[Email], [u].[CreatedAt], [u].[IsActive]
FROM [Users] AS [u]
استعلام بسيط — يجلب كل الأعمدة. للقراءة فقط استخدم AsNoTracking().
9

أفضل الممارسات

  • Async دائماً: استخدم ToListAsync, SaveChangesAsync.
  • AsNoTracking للقراءة: يوفر 30-50% من الأداء في عمليات القراءة.
  • تجنب N+1: استخدم Include أو Select لجلب علاقات.
  • Projection: استخدم Select لجلب الأعمدة التي تحتاجها فقط.
  • Pagination دائماً: لا تجلب جدولاً كاملاً أبداً — استخدم Skip/Take.
  • Add Indexes: أضف Indexes للأعمدة التي تُستخدم في WHERE/JOIN.
  • DbContext Scoped: لا تشاركه بين الطلبات — Scoped هي القاعدة.
  • لا تحمّل أكثر من الحاجة: استعلامات دقيقة أفضل من تحميل ثم تصفية.
  • ExecuteUpdate/Delete: للعمليات الجماعية — أسرع بكثير من تحميل الكيانات.
  • راجع SQL المولّد: استخدم .ToQueryString() في التطوير.
  • Migrations في Git: احفظ كل Migration في المستودع.
  • راجع Migrations قبل التطبيق: خاصة في الإنتاج — استخدم script.

قاعدة ذهبية

EF Core أداة قوية — لكنها ليست سحراً. فهم ما يفعله تحت الغطاء، ومراجعة SQL المولّد، وتحسين الأداء، أمور ضرورية لأي تطبيق احترافي.
