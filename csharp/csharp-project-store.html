نماذج البيانات والعلاقات DATA MODELS & RELATIONSHIPS

النظام الحقيقي له علاقات بين الكيانات. سطر بيع يحتوي على عدة منتجات، كل منتج ينتمي لسطر بيع واحد. هذه العلاقة One-to-Many تُنمذج بوضوح في EF Core.

الكيان الوصف العلاقات
Product منتج في المتجر: اسم، سعر، مخزون، تصنيف له عدة SaleItem
Sale عملية بيع واحدة: تاريخ، إجمالي، ربح تحتوي على عدة SaleItem
SaleItem سطر بيع: منتج، كمية، سعر وقت البيع مرتبط بـ Sale وProduct

Product — المنتج

C# — Product.cs 
public class Product
{
    public int Id { get; set; }
    public string Name { get; set; } = "";
    public string Category { get; set; } = "";
    public decimal Price { get; set; }
    public int Stock { get; set; }

    // علاقة: منتج واحد ← عدة أسطر بيع
    public ICollection<SaleItem> SaleItems { get; set; } = new List<SaleItem>();
}

Sale و SaleItem

C# — Sale.cs + SaleItem.cs 
public class Sale
{
    public int Id { get; set; }
    public DateTime Date { get; set; } = DateTime.UtcNow;
    public decimal Total { get; set; }

    public ICollection<SaleItem> Items { get; set; } = new List<SaleItem>();
}

public class SaleItem
{
    public int Id { get; set; }
    public int SaleId { get; set; }
    public Sale? Sale { get; set; }

    public int ProductId { get; set; }
    public Product? Product { get; set; }

    public int Quantity { get; set; }
    public decimal UnitPrice { get; set; } // السعر وقت البيع
}

لماذا UnitPrice في SaleItem؟ لأن سعر المنتج قد يتغيّر لاحقاً. الفاتورة يجب أن تحتفظ بالسعر الأصلي وقت البيع. لو استخدمت Product.Price مباشرة، ستتغير كل الفواتير القديمة عند تحديث سعر المنتج — كارثة محاسبية!

EF Core + SQLite DATABASE CONTEXT

فئة DbContext هي جسر بين كودك وقاعدة البيانات. تعرّف فيها الجداول والعلاقات وإعداداتها. EF Core يترجم عمليات LINQ إلى SQL تلقائياً.

C# — StoreContext.cs 
using Microsoft.EntityFrameworkCore;

public class StoreContext : DbContext
{
    public DbSet<Product> Products { get; set; } = null!;
    public DbSet<Sale>    Sales    { get; set; } = null!;
    public DbSet<SaleItem> SaleItems { get; set; } = null!;

    protected override void OnConfiguring(DbContextOptionsBuilder options)
    {
        options.UseSqlite("Data Source=store.db");
    }

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        // فهرسة الاسم للبحث السريع
        modelBuilder.Entity<Product>()
            .HasIndex(p => p.Name);

        // علاقة Sale → Items (حذف متتالي)
        modelBuilder.Entity<Sale>()
            .HasMany(s => s.Items)
            .WithOne(i => i.Sale)
            .HasForeignKey(i => i.SaleId)
            .OnDelete(DeleteBehavior.Cascade);

        // الدقة العشرية للسعر
        modelBuilder.Entity<Product>()
            .Property(p => p.Price).HasPrecision(18, 2);

        // بذور بيانات أولية
        modelBuilder.Entity<Product>().HasData(
            new Product { Id = 1, Name = "لابتوب", Category = "إلكترونيات", Price = 3500m, Stock = 15 },
            new Product { Id = 2, Name = "ماوس", Category = "إلكترونيات", Price = 75m, Stock = 80 },
            new Product { Id = 3, Name = "كرة قدم", Category = "رياضة", Price = 120m, Stock = 5 }
        );
    }
}

الترحيلات (Migrations): في المشروع الحقيقي، تستخدم dotnet ef migrations add InitialCreate ثم dotnet ef database update. هذا ينشئ ملف SQLite ويطبّق المخطط تلقائياً. للتبسيط في مشروعنا، نستخدم db.Database.EnsureCreated() في البداية.

لماذا LINQ إلى SQL أفضل من SQL اليدوي؟

C# — LINQ vs Raw SQL 
// ❌ SQL خام — عرضة للأخطاء والحقن
string sql = $"SELECT * FROM Products WHERE Price > {minPrice}";
var products = db.Products.FromSqlRaw(sql).ToList();

// ✅ LINQ — آمن، مكتوب بأنواع، ويُترجم إلى SQL
var products = await db.Products
    .Where(p => p.Price > minPrice)
    .OrderBy(p => p.Name)
    .ToListAsync();

خدمة المبيعات — SaleService SALES SERVICE

هذه هي قلب النظام. دالة Checkout() يجب أن تكون ذرية (Atomic): إما أن تنجح بالكامل (بيع + خصم مخزون) أو تفشل بالكامل. لو انخفض المخزون ثم فشل حفظ البيع، تصبح البيانات غير متسقة.

C# — SaleService.cs 
public class SaleService
{
    private readonly StoreContext _db;

    public SaleService(StoreContext db) => _db = db;

    public async Task<Sale> CheckoutAsync(Dictionary<int, int> cart)
    {
        // 1. تحقق من توفر المخزون أولاً
        var productIds = cart.Keys.ToList();
        var products = await _db.Products
            .Where(p => productIds.Contains(p.Id))
            .ToListAsync();

        foreach (var (productId, qty) in cart)
        {
            var product = products.First(p => p.Id == productId);
            if (product.Stock < qty)
                throw new InvalidOperationException(
                    $"مخزون '{product.Name}' غير كافٍ (متوفر: {product.Stock})");
        }

        // 2. إنشاء البيع مع عناصره
        var sale = new Sale { Date = DateTime.UtcNow };

        foreach (var (productId, qty) in cart)
        {
            var product = products.First(p => p.Id == productId);

            sale.Items.Add(new SaleItem
            {
                ProductId = productId,
                Quantity  = qty,
                UnitPrice = product.Price
            });

            // خصم المخزون
            product.Stock -= qty;
        }

        sale.Total = sale.Items.Sum(i => i.Quantity * i.UnitPrice);

        // 3. حفظ البيع والمخزون في transaction واحدة
        _db.Sales.Add(sale);
        await _db.SaveChangesAsync();

        return sale;
    }
}

لماذا نتحقق قبل الحفظ؟ لو خصمنا المخزون ثم اكتشفنا نقصه، ستصبح البيانات غير متسقة. الحل: تحقق أولاً، ثم عُدّل، ثم احفظ كل شيء مرة واحدة (EF Core يغلّف SaveChanges في transaction تلقائياً).

حماية من التزامن (Concurrency)

ماذا لو حاول مستخدمان شراء آخر قطعة في نفس اللحظة؟ بدون حماية، الاثنان سينجحان — والمخزون يصبح سالباً. الحل: قفل متفائل عبر RowVersion:

C# — Optimistic Concurrency 
// أضف إلى Product
[Timestamp]
public byte[] RowVersion { get; set; } = null!;

// عند الحفظ، EF Core يتحقق أن RowVersion لم يتغيّر
try
{
    await _db.SaveChangesAsync();
}
catch (DbUpdateConcurrencyException)
{
    // مستخدم آخر عدّل نفس السطر — أبلغ المستخدم وأعد المحاولة
}

التقارير — LINQ GroupBy REPORTS & ANALYTICS

التقارير هي ما يجعل النظام التجاري قيّماً. كل تقرير هنا هو استعلام LINQ واحد — يُترجم إلى SQL ويُنفّذ على قاعدة البيانات بكفاءة.

C# — Report Queries 
// 1. الأكثر مبيعاً (Top 5)
var topSelling = await _db.SaleItems
    .GroupBy(i => i.Product!.Name)
    .Select(g => new
    {
        Product = g.Key,
        Quantity = g.Sum(i => i.Quantity),
        Revenue = g.Sum(i => i.Quantity * i.UnitPrice)
    })
    .OrderByDescending(x => x.Quantity)
    .Take(5)
    .ToListAsync();

// 2. الإيرادات حسب التصنيف
var revenueByCategory = await _db.SaleItems
    .GroupBy(i => i.Product!.Category)
    .Select(g => new
    {
        Category = g.Key,
        Revenue = g.Sum(i => i.Quantity * i.UnitPrice)
    })
    .ToListAsync();

// 3. تنبيه المخزون المنخفض (أقل من 10)
var lowStock = await _db.Products
    .Where(p => p.Stock < 10)
    .OrderBy(p => p.Stock)
    .ToListAsync();

// 4. مبيعات اليوم
var today = DateTime.UtcNow.Date;
var todayRevenue = await _db.Sales
    .Where(s => s.Date >= today)
    .SumAsync(s => s.Total);

تحقق من SQL المولّد: استخدم db.Database.Log = Console.Write; أو ToQueryString() لترى SQL النهائي. بعض استعلامات LINQ قد تُترجم بشكل غير فعّال — المراقبة ضرورية في الإنتاج.

تصدير التقارير

C# — Export to CSV 
public async Task ExportSalesCsvAsync(string path)
{
    var sales = await _db.Sales
        .Include(s => s.Items)
        .OrderByDescending(s => s.Date)
        .ToListAsync();

    var lines = new List<string> { "Id,Date,Total,Items" };

    foreach (var s in sales)
    {
        lines.Add($"{s.Id},{s.Date:yyyy-MM-dd HH:mm},{s.Total},{s.Items.Count}");
    }

    await File.WriteAllLinesAsync(path, lines);
}
