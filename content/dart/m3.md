=== lesson
## كل شيء كائن

في Dart **كل قيمة كائن**، حتى الأرقام والنصوص والدوال. وفي Flutter **كل شيء Widget**، وكل Widget صنف. لذلك البرمجة الكائنية أساس لا غنى عنه.

## تعريف صنف

```dart
class Product {
  String name;
  double price;
  int stock;

  Product(this.name, this.price, this.stock);

  bool get isAvailable => stock > 0;

  void sell(int qty) {
    if (qty > stock) {
      print('الكمية غير متوفرة من $name');
      return;
    }
    stock -= qty;
    print('بيع $qty من $name، المتبقي $stock');
  }
}

void main() {
  var phone = Product('هاتف', 2200, 3);
  phone.sell(2);
  phone.sell(5);
  print(phone.isAvailable);
}
```

```output
بيع 2 من هاتف، المتبقي 1
الكمية غير متوفرة من هاتف
true
```

- **الخصائص (Fields):** `name` و `price` و `stock`.
- **المُنشئ (Constructor):** `Product(this.name, this.price, this.stock);` صيغة مختصرة رائعة في Dart تعني "خذ الوسائط وضعها مباشرة في الخصائص".
- **getter:** `isAvailable` تُقرأ كخاصية دون أقواس، لكنها تُحسب في كل مرة.
- **الطرق (Methods):** دوال تعمل على بيانات الكائن.
- لا نحتاج كلمة `new` لإنشاء كائن.

## المُنشئ بمعاملات مسماة

الأسلوب الأكثر شيوعاً في Flutter:

```dart
class User {
  final String name;
  final String email;
  final bool isAdmin;

  const User({required this.name, required this.email, this.isAdmin = false});

  @override
  String toString() => 'User($name, $email, admin: $isAdmin)';
}

void main() {
  const u = User(name: 'نوف', email: 'nouf@mail.com');
  print(u);
  print(u.isAdmin);
}
```

```output
User(نوف, nouf@mail.com, admin: false)
false
```

- خصائص `final` تجعل الكائن **غير قابل للتعديل (Immutable)**، وهذا أسلوب مفضل في Flutter.
- `const` قبل المُنشئ يسمح بإنشاء كائنات ثابتة عند الترجمة، فيوفر الذاكرة.
- `@override toString()` يحدد كيف يُطبع الكائن.

## المُنشئات المسماة

يمكن أن يكون للصنف أكثر من طريقة إنشاء:

```dart
class Temperature {
  final double celsius;

  Temperature(this.celsius);
  Temperature.fromFahrenheit(double f) : celsius = (f - 32) * 5 / 9;
  Temperature.freezing() : celsius = 0;

  String describe() => '${celsius.toStringAsFixed(1)}°C';
}

void main() {
  print(Temperature(25).describe());
  print(Temperature.fromFahrenheit(212).describe());
  print(Temperature.freezing().describe());
}
```

```output
25.0°C
100.0°C
0.0°C
```

`Temperature.fromFahrenheit` مُنشئ مسمى، و `: celsius = ...` تسمى **قائمة التهيئة (Initializer List)**. ستقابل في Flutter مُنشئات مسماة كثيرة مثل `ListView.builder` و `Image.network`.

## الخصوصية بـ _

لا توجد كلمة `private` في Dart. أي اسم يبدأ بشرطة سفلية `_` يكون **خاصاً بالملف**:

```dart
class Wallet {
  double _balance = 0;

  double get balance => _balance;

  void deposit(double amount) {
    if (amount <= 0) return;
    _balance += amount;
  }
}

void main() {
  var w = Wallet();
  w.deposit(150);
  w.deposit(-20);
  print(w.balance);
}
```

```output
150
```

## ملخص الدرس

- الصنف قالب: خصائص + مُنشئ + طرق.
- `ClassName(this.a, this.b)` مُنشئ مختصر، و `{required this.a}` بمعاملات مسماة.
- `get` لخاصية محسوبة، و `final` للخصائص الثابتة، و `const` للمُنشئ الثابت.
- المُنشئات المسماة `ClassName.named()`، و `_` للخصوصية.

## البناء على صنف موجود

**الوراثة** تتيح لصنف أن يأخذ كل ما في صنف آخر ويضيف عليه أو يعدّل:

```dart
class Animal {
  final String name;
  Animal(this.name);

  String speak() => '$name يصدر صوتاً';
  String describe() => 'أنا $name';
}

class Cat extends Animal {
  final bool indoor;
  Cat(super.name, {this.indoor = true});

  @override
  String speak() => '$name يقول مياو';
}

void main() {
  final cat = Cat('مشمش');
  print(cat.speak());
  print(cat.describe());
  print(cat.indoor);
  print(cat is Animal);
}
```

```output
مشمش يقول مياو
أنا مشمش
true
true
```

- `extends Animal` يرث كل الخصائص والطرق.
- `super.name` يمرر المعامل مباشرة لمُنشئ الأب (صيغة Dart 3 المختصرة).
- `@override` يعيد تعريف طريقة الأب، وكتابته توضح النية ويحميك من الأخطاء الإملائية.
- `is` للتحقق من النوع.

## استدعاء نسخة الأب بـ super

```dart

class Manager extends Employee {

```

## تعدد الأشكال (Polymorphism)

قائمة من النوع الأب يمكن أن تحتوي كائنات من الأبناء، وكل منها يتصرف بطريقته:

```dart
class Shape {
  double area() => 0;
}

class Square extends Shape {
  final double side;
  Square(this.side);
  @override
  double area() => side * side;
}

class Circle extends Shape {
  final double r;
  Circle(this.r);
  @override
  double area() => 3 * r * r;
}

void main() {
  final List<Shape> shapes = [Square(4), Circle(2), Square(1.5)];
  for (final s in shapes) {
    print('${s.runtimeType}: ${s.area()}');
  }
}
```

```output
Square: 16
Circle: 12
Square: 2.25
```

حلقة واحدة تتعامل مع كل الأشكال دون أن تعرف نوع كل منها. و `runtimeType` يعطيك النوع الفعلي للكائن.

## مشاركة السلوك دون وراثة

Dart تسمح بالوراثة من **صنف واحد فقط**. فماذا لو أردت أن يمتلك `Duck` قدرة السباحة **و** الطيران، وأن يمتلك `Fish` السباحة فقط؟ الحل: **Mixins**، وهي حزم من السلوك "تخلطها" في أي صنف.

## تعريف واستخدام Mixin

```dart
mixin Swimmer {
  String swim() => 'يسبح في الماء';
}

mixin Flyer {
  String fly() => 'يطير في السماء';
}

class Animal {
  final String name;
  Animal(this.name);
}

class Duck extends Animal with Swimmer, Flyer {
  Duck(super.name);
}

class Fish extends Animal with Swimmer {
  Fish(super.name);
}

void main() {
  final duck = Duck('بطة');
  final fish = Fish('سمكة');
  print('${duck.name}: ${duck.swim()} و ${duck.fly()}');
  print('${fish.name}: ${fish.swim()}');
  print(duck is Flyer);
  print(fish is Flyer);
}
```

```output
بطة: يسبح في الماء و يطير في السماء
سمكة: يسبح في الماء
true
false
```

- `mixin` يعرّف حزمة سلوك.
- `with A, B` تضيف المزيج إلى الصنف.
- الصنف يستطيع أن يرث من صنف واحد ويضيف عدة mixins.

## Mixins مع حالة

يمكن للمزيج أن يحتوي متغيرات أيضاً:

```dart
mixin Logger {
  final List<String> _logs = [];

  void log(String msg) => _logs.add(msg);
  List<String> get history => List.unmodifiable(_logs);
}

class Cart with Logger {
  int items = 0;

  void add() {
    items++;
    log('أضيف منتج، المجموع $items');
  }
}

void main() {
  final cart = Cart();
  cart.add();
  cart.add();
  for (final line in cart.history) {
    print(line);
  }
}
```

```output
أضيف منتج، المجموع 1
أضيف منتج، المجموع 2
```

## تقييد المزيج بـ on

أحياناً يحتاج المزيج أن يعمل فقط مع أصناف معينة:

```dart
class Account {
  double balance = 0;
}

mixin Interest on Account {
  void addInterest(double rate) => balance += balance * rate / 100;
}

class SavingsAccount extends Account with Interest {}

void main() {
  final s = SavingsAccount();
  s.balance = 1000;
  s.addInterest(5);
  print(s.balance);
}
```

```output
1050
```

`on Account` تعني أن `Interest` لا يُستخدم إلا مع أصناف ترث من `Account`، فيستطيع استخدام `balance` بأمان.

## ملخص الدرس

- Dart تسمح بوراثة صنف واحد، و Mixins تضيف سلوكاً من مصادر متعددة.
- `mixin Name { ... }` للتعريف، و `class C with A, B` للاستخدام.
- المزيج يمكن أن يحتوي طرقاً ومتغيرات.
- `mixin M on BaseClass` لتقييد استخدامه.

mixin Rateable {
  final List<int> _ratings = [];

  void rate(int stars) => _ratings.add(stars);

  double get average {
    if (_ratings.isEmpty) return 0;
    return _ratings.reduce((a, b) => a + b) / _ratings.length;
  }
}

class Restaurant with Rateable {

  Restaurant(this.name);
}

  r.rate(5);
  r.rate(4);
  r.rate(3);

## عقود بلا تفاصيل

أحياناً نريد تحديد **ماذا** يجب أن يفعل الصنف، دون **كيف**. مثلاً: كل وسيلة دفع يجب أن تمتلك `pay()`، لكن الدفع ببطاقة يختلف عن المحفظة الرقمية.

## الأصناف المجردة (abstract)

```dart
abstract class PaymentMethod {
  String get name;
  bool pay(double amount);

  void checkout(double amount) {
    final ok = pay(amount);
    print(ok ? 'تم الدفع بـ $name' : 'فشل الدفع بـ $name');
  }
}

class CreditCard extends PaymentMethod {
  @override
  String get name => 'البطاقة';

  @override
  bool pay(double amount) => amount <= 5000;
}

class Wallet extends PaymentMethod {
  double balance;
  Wallet(this.balance);

  @override
  String get name => 'المحفظة';

  @override
  bool pay(double amount) {
    if (amount > balance) return false;
    balance -= amount;
    return true;
  }
}

void main() {
  final methods = <PaymentMethod>[CreditCard(), Wallet(100)];
  for (final m in methods) {
    m.checkout(250);
  }
}
```

```output
تم الدفع بـ البطاقة
فشل الدفع بـ المحفظة
```

- `abstract class` لا يمكن إنشاء كائن منه مباشرة: `PaymentMethod()` خطأ.
- الطرق بلا جسم (`bool pay(double amount);`) **يجب** على كل ابن تعريفها، وإلا يرفض المترجم.
- الصنف المجرد يمكن أن يحتوي طرقاً كاملة أيضاً مثل `checkout`.

## الواجهات: implements

في Dart **كل صنف هو واجهة ضمنياً**. بـ `implements` تتعهد بتنفيذ **كل** ما في الصنف، دون أن ترث أي كود:

```dart
abstract class Printable {
  String printOut();
}

abstract class Exportable {
  String export();
}

class Invoice implements Printable, Exportable {
  final int number;
  Invoice(this.number);

  @override
  String printOut() => 'فاتورة رقم $number';

  @override
  String export() => '{"invoice": $number}';
}

void main() {
  final inv = Invoice(77);
  print(inv.printOut());
  print(inv.export());
  print(inv is Printable && inv is Exportable);
}
```

```output
فاتورة رقم 77
{"invoice": 77}
true
```

## الفرق بين extends و implements و with

| الكلمة | ماذا تأخذ | العدد |
|---|---|---|
| `extends` | الكود والواجهة، ويمكن إعادة تعريف بعضها | صنف واحد |
| `implements` | الواجهة فقط، ويجب تنفيذ كل شيء | عدة أصناف |
| `with` | كود جاهز من mixins | عدة mixins |

## الأصناف المختومة (sealed): أقوى مع switch

منذ Dart 3، `sealed class` تحدد مجموعة **مغلقة** من الأبناء، فيعرف المترجم كل الاحتمالات ويتأكد أن `switch` تغطيها جميعاً:

```dart
sealed class Result {}

class Success extends Result {
  final String data;
  Success(this.data);
}

class Failure extends Result {
  final String error;
  Failure(this.error);
}

class Loading extends Result {}

String render(Result r) => switch (r) {
  Success(data: final d) => 'البيانات: $d',
  Failure(error: final e) => 'خطأ: $e',
  Loading() => 'جاري التحميل...',
};

void main() {
  print(render(Loading()));
  print(render(Success('3 منتجات')));
  print(render(Failure('لا يوجد اتصال')));
}
```

```output
جاري التحميل...
البيانات: 3 منتجات
خطأ: لا يوجد اتصال
```

لو أضفت حالة رابعة ونسيت معالجتها في `switch`، **يرفض المترجم** البرنامج. هذا النمط شائع جداً في Flutter لإدارة حالات الشاشة: تحميل ونجاح وخطأ.

## ملخص الدرس

- `abstract class` تحدد ما يجب تنفيذه، ولا يُنشأ منها كائن مباشرة.
- `implements` لتنفيذ واجهة أو أكثر دون وراثة الكود.
- `extends` لصنف واحد مع الكود، و `implements` لعدة واجهات، و `with` للـ mixins.
- `sealed class` مع `switch` تضمن معالجة كل الحالات.

--- exercise
1. أنشئ صنفاً مجرداً `Notifier` فيه طريقة مجردة `String send(String message)`.
2. أنشئ `EmailNotifier` و `SmsNotifier` يرثان منه:
   - البريد يُرجع `📧 بريد: X`
   - الرسائل القصيرة تُرجع `📱 SMS: X` لكن تقطع الرسالة لأول **10 أحرف** فقط إذا كانت أطول (استخدم `substring(0, 10)`).

الكود في `main` جاهز.

~~~starter
// اكتب الأصناف هنا

void main() {
  final List<Notifier> channels = [EmailNotifier(), SmsNotifier()];
  for (final c in channels) {
    print(c.send('تم شحن طلبك بنجاح'));
  }
}
~~~
~~~expected
📧 بريد: تم شحن طلبك بنجاح
📱 SMS: تم شحن طلب
~~~
~~~solution
abstract class Notifier {
  String send(String message);
}

class EmailNotifier extends Notifier {
  @override
  String send(String message) => '📧 بريد: $message';
}

class SmsNotifier extends Notifier {
  @override
  String send(String message) {
    final text = message.length > 10 ? message.substring(0, 10) : message;
    return '📱 SMS: $text';
  }
}

void main() {
  final List<Notifier> channels = [EmailNotifier(), SmsNotifier()];
  for (final c in channels) {
    print(c.send('تم شحن طلبك بنجاح'));
  }
}
~~~
