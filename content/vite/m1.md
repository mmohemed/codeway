=== lesson
## ما هو npm؟

كل مشروع JavaScript حديث يعتمد على كود كتبه آخرون: مكتبات للتواريخ، وأطر عمل مثل React، وأدوات بناء مثل Vite. **npm (Node Package Manager)** هو مدير الحزم الذي:

- يحمّل هذه الحزم من **سجل npm** (أكثر من مليوني حزمة).
- يسجّل ما يحتاجه مشروعك في ملف واحد: `package.json`.
- يشغّل أوامر المشروع مثل التشغيل والبناء والاختبار.

npm يأتي مع **Node.js**، بيئة تشغيل JavaScript خارج المتصفح. تأكد من تثبيتهما:

```terminal-new
$ node -v
v22.12.0
$ npm -v
10.9.0
```

> 💡 ثبّت Node.js من nodejs.org واختر نسخة **LTS** (الدعم الطويل)، فهي الأكثر استقراراً.

## إنشاء package.json

`package.json` هو «بطاقة هوية» المشروع. أنشئه بـ `npm init`، والخيار `-y` يقبل القيم الافتراضية دون أسئلة:

```terminal
$ npm init -y
Wrote to /project/package.json:

{
  "name": "project",
  "version": "1.0.0",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "keywords": [],
  "author": "",
  "license": "ISC",
  "description": ""
}

```

## حقول package.json

| الحقل | المعنى |
|---|---|
| `name` | اسم المشروع (أحرف صغيرة بلا مسافات) |
| `version` | رقم الإصدار بصيغة SemVer |
| `main` | الملف الرئيسي عند استخدام المشروع كمكتبة |
| `scripts` | أوامر مختصرة تشغّلها بـ `npm run` |
| `type` | `"module"` لاستخدام `import` و `export` |
| `dependencies` | الحزم التي يحتاجها التطبيق ليعمل |
| `devDependencies` | حزم التطوير فقط: أدوات البناء والفحص والاختبار |

## تعديل package.json من الطرفية

يمكنك تعديل الملف في محررك مباشرة، أو بالأمر `npm pkg` الذي يضمن صيغة JSON صحيحة دائماً:

```terminal
$ npm pkg set description="متجر لبيع الكتب" version=0.1.0 type=module
$ npm pkg get name version
{
  "name": "project",
  "version": "0.1.0"
}
$ npm pkg get type
"module"
```

## أول برنامج Node.js

```terminal
$ cat > index.js <<EOF
> const name = "CodeWay";
> console.log(`مرحباً من ${name}`);
> console.log({ lessons: 8, tools: ["npm", "Vite"] });
> EOF
$ node index.js
مرحباً من CodeWay
{ lessons: 8, tools: [ 'npm', 'Vite' ] }
```

لاحظ أن Node يطبع الكائنات بصيغته الخاصة: النصوص بين علامتي تنصيص مفردة، ومسافات داخل الأقواس.

## CommonJS أم ES Modules؟

Node يدعم نظامين للوحدات:

| | CommonJS | ES Modules |
|---|---|---|
| الاستيراد | `require("x")` | `import x from "x"` |
| التصدير | `module.exports = ...` | `export default ...` |
| التفعيل | الافتراضي | `"type": "module"` أو امتداد `.mjs` |

بعد أن ضبطنا `type` على `module`، نستخدم `import`:

```terminal
$ cat > math.js <<EOF
> export const add = (a, b) => a + b;
> EOF
$ cat > app.js <<EOF
> import { add } from "./math.js";
> console.log(add(2, 3));
> EOF
$ node app.js
5
```

> ⚠️ في ES Modules يجب كتابة امتداد الملف في المسار: `"./math.js"` وليس `"./math"`.

## ملخص الدرس

- npm مدير حزم JavaScript ويأتي مع Node.js.
- `npm init -y` ينشئ `package.json`، و `npm pkg set/get` يعدّله ويقرؤه.
- `dependencies` لما يحتاجه التطبيق، و `devDependencies` لأدوات التطوير.
- `"type": "module"` يفعّل `import` و `export` في Node.

## تثبيت حزمة

لنبدأ مشروعاً ونثبّت مكتبة `dayjs` للتعامل مع التواريخ:

```terminal-new
$ npm init -y
Wrote to /project/package.json:

{
  "name": "project",
  "version": "1.0.0",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "keywords": [],
  "author": "",
  "license": "ISC",
  "description": ""
}

$ npm install dayjs

added 1 package, and audited 2 packages in 1s

found 0 vulnerabilities
$ npm pkg get dependencies
{
  "dayjs": "^1.11.13"
}
$ ls
node_modules  package-lock.json  package.json
```

ثلاثة أشياء حدثت:

1. نُزّلت الحزمة إلى مجلد **`node_modules`**.
2. أُضيفت إلى `dependencies` في `package.json` برقم إصدارها.
3. أُنشئ **`package-lock.json`** الذي يسجّل الإصدار الدقيق لكل حزمة.

استخدامها:

```terminal
$ cat > index.js <<EOF
> const dayjs = require("dayjs");
> const start = dayjs("2025-03-01");
> console.log(start.add(30, "day").format("DD/MM/YYYY"));
> EOF
$ node index.js
31/03/2025
```

## حزم التطوير

أدوات مثل Prettier و Vite تحتاجها أثناء التطوير فقط. ثبّتها بـ `-D` (اختصار `--save-dev`):

```terminal
$ npm install -D prettier

added 1 package, and audited 3 packages in 1s

found 0 vulnerabilities
$ npm ls
project@1.0.0 /project
├── dayjs@1.11.13
└── prettier@3.9.10
```

## اعتماديات الاعتماديات

بعض الحزم تحتاج حزماً أخرى. لاحظ كم حزمة تُضاف مع `axios`:

```terminal
$ npm install axios

added 9 packages, and audited 12 packages in 1s

found 0 vulnerabilities
$ ls node_modules
asynckit  axios  combined-stream  dayjs  delayed-stream  follow-redirects  form-data  mime-db  mime-types  prettier  proxy-from-env
```

حزمة واحدة طلبتها، لكن ثُبّتت معها 8 حزم تعتمد عليها. لذلك يكبر `node_modules` بسرعة، ولذلك **لا يُرفع إلى Git أبداً**.

## الإصدارات: ^ و ~

npm يحفظ الإصدار مع رمز يحدد التحديثات المقبولة، حسب نظام SemVer (`MAJOR.MINOR.PATCH`):

| الكتابة | تقبل | مثال لـ 4.17.20 |
|---|---|---|
| `^4.17.20` | أي MINOR و PATCH أحدث (الافتراضي) | حتى ما قبل 5.0.0 |
| `~4.17.20` | PATCH أحدث فقط | حتى ما قبل 4.18.0 |
| `4.17.20` | هذا الإصدار بالضبط | 4.17.20 فقط |

لتثبيت إصدار معيّن اكتبه بعد `@`، ثم اكتشف التحديثات بـ `npm outdated`:

```terminal
$ npm install lodash@4.17.19

added 1 package, and audited 13 packages in 1s

found 0 vulnerabilities
$ npm outdated
Package  Current  Wanted   Latest   Location             Depended by
lodash   4.17.19  4.17.21  4.17.21  node_modules/lodash  project
$ npm update

changed 1 package, and audited 13 packages in 1s

found 0 vulnerabilities
$ npm ls
project@1.0.0 /project
├── axios@1.7.9
├── dayjs@1.11.13
├── lodash@4.17.21
└── prettier@3.9.10
```

- **Current** المثبت الآن، و **Wanted** أحدث ما يسمح به النطاق، و **Latest** أحدث إصدار منشور.
- `npm update` يحدّث إلى Wanted ولا يتجاوز النطاق، فلا يكسر مشروعك بإصدار MAJOR جديد.

## إزالة حزمة

```terminal
$ npm uninstall axios

removed 9 packages, and audited 4 packages in 1s

found 0 vulnerabilities
$ npm ls
project@1.0.0 /project
├── dayjs@1.11.13
├── lodash@4.17.21
└── prettier@3.9.10
```

## package-lock.json و npm ci

`package.json` يقول «أريد lodash من 4.17 فما فوق»، و `package-lock.json` يقول «ثبّتنا 4.17.21 بالضبط». لذلك:

- **احفظ الملفين في Git**، وتجاهل `node_modules`.
- زميلك بعد `git clone` ينفّذ `npm install` فيحصل على نفس الإصدارات بالضبط.
- في خوادم CI استخدم `npm ci`: أسرع وأدق، يثبّت من القفل حرفياً.

## ملخص الدرس

- `npm install pkg` يثبّت حزمة ويضيفها لـ `dependencies`، و `-D` لـ `devDependencies`.
- `node_modules` يحتوي الحزم واعتمادياتها، ولا يُرفع إلى Git.
- `^` يقبل تحديثات MINOR و PATCH، و `~` يقبل PATCH فقط.
- `npm outdated` يكشف التحديثات، و `npm update` يطبقها ضمن النطاق.
- `package-lock.json` يثبّت الإصدارات الدقيقة، ويُحفظ في Git.

## سكربتات npm

بدل أن يحفظ كل عضو في الفريق أوامر طويلة، نكتبها مرة واحدة في `scripts` داخل `package.json`، ويشغّلها الجميع بنفس الاسم:

```json
{
  "scripts": {
    "start": "node server.js",
    "dev": "vite",
    "build": "vite build",
    "lint": "eslint .",
    "test": "vitest"
  }
}
```

هذا عقد موحّد: في أي مشروع تقريباً، `npm run dev` يشغّل بيئة التطوير، و `npm run build` يبني للإنتاج.

## إضافة سكربت وتشغيله

```terminal-new
$ npm init -y
Wrote to /project/package.json:

{
  "name": "project",
  "version": "1.0.0",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "keywords": [],
  "author": "",
  "license": "ISC",
  "description": ""
}

$ echo "console.log('الخادم يعمل على المنفذ 3000')" > server.js
$ npm pkg set scripts.start="node server.js"
$ npm run start

> project@1.0.0 start
> node server.js

الخادم يعمل على المنفذ 3000
```

npm يطبع اسم السكربت والأمر الذي سينفّذه، ثم مخرجاته.

## اختصارات: start و test

بعض الأسماء خاصة ولا تحتاج `run`: `npm start` و `npm test`:

```terminal
$ npm start

> project@1.0.0 start
> node server.js

الخادم يعمل على المنفذ 3000
$ npm test

> project@1.0.0 test
> echo "Error: no test specified" && exit 1

Error: no test specified
```

`npm test` نفّذ السكربت الافتراضي الذي وضعه `npm init`، وهو يطبع رسالة ويخرج بخطأ عمداً حتى تضع اختباراتك الحقيقية.

## عرض كل السكربتات

```terminal
$ npm pkg set scripts.hello="node hello.js"
$ npm run
Lifecycle scripts included in project@1.0.0:
  test
    echo "Error: no test specified" && exit 1
  start
    node server.js

available via `npm run-script`:
  hello
    node hello.js
```

## تمرير معاملات للسكربت

كل ما بعد `--` يُمرَّر للأمر داخل السكربت:

```terminal
$ cat > hello.js <<EOF
> const name = process.argv[2] || "صديقي";
> console.log(`أهلاً يا ${name}`);
> EOF
$ npm run hello

> project@1.0.0 hello
> node hello.js

أهلاً يا صديقي
$ npm run hello -- سارة

> project@1.0.0 hello
> node hello.js سارة

أهلاً يا سارة
```

`process.argv` مصفوفة معاملات سطر الأوامر: الأول مسار node، والثاني مسار الملف، ثم معاملاتك.

## السكربتات pre و post

إذا وُجد سكربت اسمه `prebuild` يعمل تلقائياً **قبل** `build`، و `postbuild` **بعده**:

```terminal
$ echo "console.log('تنظيف المجلد القديم...')" > clean.js
$ echo "console.log('بناء المشروع...')" > build.js
$ npm pkg set scripts.prebuild="node clean.js" scripts.build="node build.js"
$ npm run build

> project@1.0.0 prebuild
> node clean.js

تنظيف المجلد القديم...

> project@1.0.0 build
> node build.js

بناء المشروع...
```

## ربط أوامر متتالية

`&&` تشغّل الأمر التالي فقط إذا نجح السابق:

```terminal
$ echo "console.log('فحص الكود...')" > check.js
$ npm pkg set scripts.ci="node check.js && npm run build"
$ npm run ci

> project@1.0.0 ci
> node check.js && npm run build

فحص الكود...

> project@1.0.0 prebuild
> node clean.js

تنظيف المجلد القديم...

> project@1.0.0 build
> node build.js

بناء المشروع...
```

## السكربتات تجد أدوات المشروع

داخل السكربت، npm يبحث عن الأوامر في `node_modules` أولاً. لذلك `"dev": "vite"` يعمل دون تثبيت Vite على جهازك عالمياً، بشرط أن يكون مثبتاً في المشروع:

```terminal
$ npm pkg set scripts.dev="vite"
$ npm run dev

> project@1.0.0 dev
> vite

ERR: sh: 1: vite: not found
$ npm install -D vite

added 8 packages, and audited 9 packages in 1s

found 0 vulnerabilities
$ npm run dev

> project@1.0.0 dev
> vite



  VITE v6.0.7  ready in 120 ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: use --host to expose
  ➜  press h + enter to show help
```

> 💡 لتشغيل أداة مثبتة في المشروع خارج السكربتات استخدم `npx`، مثل `npx vite` أو `npx eslint .`.

## ملخص الدرس

- `scripts` في `package.json` أوامر موحّدة للفريق، تُشغَّل بـ `npm run name`.
- `npm start` و `npm test` لا يحتاجان `run`، و `npm run` وحده يعرض السكربتات.
- `npm run x -- args` يمرّر معاملات، ويقرؤها الكود من `process.argv`.
- `preX` و `postX` يعملان تلقائياً قبل X وبعده، و `&&` يربط أوامر متتالية.
- السكربتات تجد الأدوات المثبتة في `node_modules`، و `npx` يشغّلها من الطرفية.
