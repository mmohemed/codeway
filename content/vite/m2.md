=== lesson
## لماذا نحتاج أداة بناء؟

المتصفح يفهم HTML و CSS و JavaScript، لكن المشاريع الحديثة تكتب:

- كوداً مقسماً على عشرات الملفات بـ `import`.
- مكتبات من npm مثل React، والمتصفح لا يعرف أين `node_modules`.
- JSX و TypeScript، وهي لغات لا يفهمها المتصفح مباشرة.

**أداة البناء** تحل هذا: أثناء التطوير تخدم الملفات بسرعة وتحدّث الصفحة لحظياً، وعند النشر تجمع كل شيء في ملفات قليلة صغيرة محسّنة.

## لماذا Vite؟

**Vite** (تُنطق «فيت» وتعني «سريع» بالفرنسية) أصبح الخيار الأول لمشاريع الواجهات:

| | الأدوات القديمة (Webpack) | Vite |
|---|---|---|
| تشغيل خادم التطوير | يجمع المشروع كله أولاً، قد يستغرق دقيقة | فوري تقريباً، يخدم الملفات عند طلبها |
| تحديث الصفحة بعد التعديل | يعيد بناء أجزاء كبيرة | يحدّث الوحدة المعدّلة فقط (HMR) |
| الإعدادات | ملف إعدادات طويل | يعمل دون إعدادات تقريباً |

Vite يستخدمه React و Vue و Svelte و SolidJS، وحتى Laravel يعتمد عليه.

## إنشاء مشروع

```terminal-new
$ npm create vite@latest my-shop -- --template vanilla

> npx
> create-vite my-shop --template vanilla


Scaffolding project in /project/my-shop...

Done. Now run:

  cd my-shop
  npm install
  npm run dev
```

- `npm create vite@latest` يشغّل أداة إنشاء المشاريع الرسمية بأحدث إصدار.
- `my-shop` اسم المجلد، و `--template` القالب: `vanilla` (JavaScript فقط)، `react`، `vue`، `svelte`، ولكل منها نسخة TypeScript مثل `react-ts`.
- `--` ضروري ليمرر npm الخيارات للأداة.

> 💡 إذا كتبت `npm create vite@latest` وحده، ستسألك الأداة عن الاسم والقالب بقوائم تفاعلية.

| الملف | الدور |
|---|---|
| `index.html` | **نقطة الدخول**، في جذر المشروع وليس في public |
| `src/` | كودك: JavaScript و CSS والصور التي تستوردها |
| `public/` | ملفات تُنسخ كما هي، تصل لها بمسار مطلق مثل `/vite.svg` |
| `package.json` | السكربتات الثلاثة: `dev` و `build` و `preview` |
| `.gitignore` | جاهز ويتجاهل `node_modules` و `dist` |

لاحظ في `index.html` السطر الذي يربط كل شيء:

```terminal
$ grep script index.html

```

`type="module"` يعني أن المتصفح يحمّل الملف كوحدة ES، ومنه تبدأ سلسلة الاستيرادات.

## خادم التطوير

`npm run dev` يشغّل خادم Vite. على جهازك الحقيقي يبقى يعمل في الطرفية حتى توقفه بـ `Ctrl+C`، وأثناء ذلك:

- **HMR (Hot Module Replacement)**: عند حفظ ملف، يُستبدل الجزء المعدّل فقط في الصفحة المفتوحة، دون إعادة تحميلها ودون أن تفقد حالتها.
- أخطاء الكود تظهر في الطرفية وفوق الصفحة مباشرة.
- لا يجمع Vite المشروع: المتصفح يطلب كل ملف عند الحاجة، لذلك البدء فوري مهما كبر المشروع.

## ملف الإعدادات vite.config.js

بدل كتابة الخيارات في كل مرة، ضعها في `vite.config.js` في جذر المشروع:

```terminal
$ cat > vite.config.js <<EOF
> import { defineConfig } from "vite";
> 
> export default defineConfig({
>   server: {
>     port: 3000,
>     open: true,
>   },
> });
> EOF
$ npm run dev

> store@0.0.0 dev
> vite


  VITE v6.0.7  ready in 171 ms

  ➜  Local:   http://localhost:3000/
  ➜  Network: use --host to expose
  ➜  press h + enter to show help
```

`defineConfig` لا يغيّر شيئاً في الإعدادات، لكنه يجعل محررك يقترح الخيارات المتاحة ويشرحها.

| الخيار | المعنى |
|---|---|
| `server.port` | المنفذ |
| `server.open` | فتح المتصفح تلقائياً |
| `server.host` | الإتاحة على الشبكة |
| `server.proxy` | تحويل طلبات `/api` إلى خادم الواجهة الخلفية |
| `resolve.alias` | اختصارات للمسارات مثل `@` لمجلد `src` |
| `plugins` | الإضافات مثل React و Vue |

## متغيرات البيئة

الإعدادات التي تختلف بين بيئة التطوير والإنتاج، مثل رابط الـ API، توضع في ملفات `.env`:

```terminal
$ cat > .env <<EOF
> VITE_API_URL=http://localhost:8000
> VITE_APP_NAME=متجري
> DB_PASSWORD=secret123
> EOF
```

وتُقرأ في الكود من `import.meta.env`:

```js
const res = await fetch(`${import.meta.env.VITE_API_URL}/products`);
document.title = import.meta.env.VITE_APP_NAME;
```

> ⚠️ Vite يكشف للكود فقط المتغيرات التي تبدأ بـ `VITE_`. هذه حماية: كل ما يصل للكود سيكون مرئياً لأي زائر في المتصفح. لذلك `DB_PASSWORD` لن يصل أبداً، ولا يجوز وضع أسرار في متغيرات `VITE_`.

## ملفات حسب البيئة

| الملف | متى يُحمَّل |
|---|---|
| `.env` | دائماً |
| `.env.local` | دائماً، ويتجاهله Git (لإعداداتك الشخصية) |
| `.env.development` | مع `npm run dev` |
| `.env.production` | مع `npm run build` |

القيم في الملف الأكثر تحديداً تتغلب. ومتغيرات مدمجة متاحة دائماً: `import.meta.env.MODE` و `DEV` و `PROD`.

## ملخص الدرس

- خادم التطوير فوري ويحدّث الوحدات المعدّلة فقط بـ HMR.
- `vite.config.js` بـ `defineConfig` لضبط المنفذ والاختصارات والإضافات.
- متغيرات البيئة في `.env`، وتُقرأ من `import.meta.env`.
- فقط المتغيرات التي تبدأ بـ `VITE_` تصل للكود، فلا تضع فيها أسراراً.

ماذا فعل Vite؟

1. تتبّع الاستيرادات بدءاً من `index.html`.

4. أضاف **بصمة (hash)** لأسماء الملفات.
5. كتب النتيجة في مجلد `dist`.

## لماذا البصمة في الاسم؟

`index-BCclrd_w.js` بدل `index.js`. المتصفحات تحفظ الملفات (Cache) لتسريع الزيارات. لو بقي الاسم ثابتاً، قد يرى المستخدم النسخة القديمة بعد نشرك تحديثاً. البصمة تُحسب من المحتوى: **يتغير المحتوى فيتغير الاسم**، فيحمّل المتصفح الجديد تلقائياً، ويمكن حفظ الملفات في الكاش لمدة طويلة بأمان.

## أين أنشر dist؟

مجلد `dist` ملفات ثابتة فقط، يمكن رفعها لأي استضافة: **Netlify** و **Vercel** و **GitHub Pages** و **Cloudflare Pages**. معظمها يتصل بمستودعك على GitHub وينفّذ `npm run build` تلقائياً مع كل push.

> ⚠️ لا ترفع `dist` إلى Git، فهو يُولَّد من الكود. قالب Vite يضيفه إلى `.gitignore` مسبقاً.

## ملخص الدرس

- `npm run build` يجمع ويضغط ويكتب النتيجة في `dist`.
- البصمة في أسماء الملفات تضمن وصول التحديثات رغم الكاش.
- متغيرات `VITE_` تُستبدل بقيمها في الكود المبني.
- `npm run preview` لمعاينة البناء، و `base` للنشر في مسار فرعي.
