## ما هو ESLint؟

**ESLint** أداة **فحص ثابت (Linter)**: تقرأ كودك دون تشغيله، وتكتشف الأخطاء والممارسات الخطرة قبل أن تصل للمستخدمين:

- متغيرات معرّفة ولا تُستخدم (غالباً علامة على خطأ).
- استخدام متغير غير معرّف بسبب خطأ إملائي.
- مقارنة `==` التي تحوّل الأنواع بشكل مفاجئ.
- كود لا يمكن الوصول إليه بعد `return`.

ESLint هو المعيار في عالم JavaScript، ومعظم المشاريع المحترفة تمنع دمج أي كود لا يجتاز فحصه.

## التثبيت

```terminal-new
$ npm init -y
Wrote to /project/package.json:

{
  "name": "project",
  "version": "1.0.0",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "keywords": [],
  "author": "",
  "license": "ISC",
  "description": ""
}

$ npm pkg set type=module
$ npm install -D eslint @eslint/js globals

added 10 packages, and audited 11 packages in 1s

found 0 vulnerabilities
```

- `eslint` الأداة نفسها.
- `@eslint/js` مجموعة القواعد الموصى بها رسمياً.
- `globals` قوائم المتغيرات العامة لكل بيئة (مثل `window` و `document` في المتصفح، و `process` في Node).

## ملف الإعدادات eslint.config.js

منذ ESLint 9 أصبحت الإعدادات مصفوفة كائنات في `eslint.config.js` (تسمى Flat Config):

```terminal
$ cat > eslint.config.js <<EOF
> import js from "@eslint/js";
> import globals from "globals";
> 
> export default [
>   js.configs.recommended,
>   {
>     languageOptions: {
>       globals: globals.browser,
>     },
>   },
> ];
> EOF
```

- `js.configs.recommended` تفعّل القواعد الأساسية الموصى بها.
- `globals.browser` تخبر ESLint أن `document` و `window` موجودة، فلا يعتبرها أخطاء.

## أول فحص

```terminal
$ cat > cart.js <<EOF
> const items = [];
> let discount = 0.1;
> 
> function total(cart) {
>   let sum = 0;
>   for (const item of cart) sum += item.price;
>   return sum;
>   console.log("done");
> }
> 
> document.title = totl(items);
> EOF
$ npx eslint .

/project/cart.js
  2:5    error  'discount' is assigned a value but never used.  no-unused-vars
  4:10   error  'total' is defined but never used.              no-unused-vars
  8:3    error  Unreachable code.                               no-unreachable
  11:18  error  'totl' is not defined.                          no-undef

✖ 4 problems (4 errors, 0 warnings)

```

اقرأ كل سطر: **الموقع** `سطر:عمود`، ثم **الخطورة**، ثم **الرسالة**، ثم **اسم القاعدة**. اكتشف ESLint خطأ إملائياً (`totl`) كان سيظهر فقط عند تشغيل الصفحة، وكوداً بعد `return` لن يعمل أبداً.

## تخصيص القواعد

كل قاعدة لها ثلاث درجات: `"off"` و `"warn"` و `"error"`. الأخطاء تفشل الفحص، والتحذيرات تنبّه فقط:

```terminal
$ cat > eslint.config.js <<EOF
> import js from "@eslint/js";
> import globals from "globals";
> 
> export default [
>   { ignores: ["dist/"] },
>   js.configs.recommended,
>   {
>     languageOptions: {
>       globals: globals.browser,
>     },
>     rules: {
>       eqeqeq: "error",
>       "prefer-const": "error",
>       "no-console": "warn",
>       "no-unused-vars": "warn",
>     },
>   },
> ];
> EOF
$ npx eslint .

/project/cart.js
  2:5    warning  'discount' is assigned a value but never used.        no-unused-vars
  2:5    error    'discount' is never reassigned. Use 'const' instead.  prefer-const
  4:10   warning  'total' is defined but never used.                    no-unused-vars
  8:3    error    Unreachable code.                                     no-unreachable
  8:3    warning  Unexpected console statement.                         no-console
  11:18  error    'totl' is not defined.                                no-undef

✖ 6 problems (3 errors, 3 warnings)
  1 error and 0 warnings potentially fixable with the `--fix` option.

```

| القاعدة | تمنع |
|---|---|
| `eqeqeq` | `==` و `!=`، وتفرض `===` و `!==` |
| `prefer-const` | `let` لمتغير لا يُعاد تعيينه |
| `no-console` | ترك `console.log` في الكود |
| `no-unused-vars` | متغيرات لا تُستخدم |

و `{ ignores: ["dist/"] }` وحده في كائن يجعل ESLint يتجاهل المجلد كاملاً. `node_modules` مُتجاهَل دائماً.

## الإصلاح التلقائي

بعض القواعد تعرف كيف تصلح نفسها، مثل `prefer-const`. الخيار `--fix` يطبّق هذه الإصلاحات:

```terminal
$ npx eslint . --fix

/project/cart.js
  2:7    warning  'discount' is assigned a value but never used.  no-unused-vars
  4:10   warning  'total' is defined but never used.              no-unused-vars
  8:3    error    Unreachable code.                               no-unreachable
  8:3    warning  Unexpected console statement.                   no-console
  11:18  error    'totl' is not defined.                          no-undef

✖ 5 problems (2 errors, 3 warnings)

$ head -n 2 cart.js
const items = [];

```

الباقي يحتاج قرارك أنت: هل `discount` متغير زائد يجب حذفه، أم نسيت استخدامه؟

## ملخص الدرس

- ESLint يحلل الكود دون تشغيله ويكتشف الأخطاء والممارسات الخطرة.
- الإعدادات في `eslint.config.js`: مصفوفة تبدأ عادة بـ `js.configs.recommended`.
- `languageOptions.globals` يعرّف بيئة التشغيل، و `rules` يخصص القواعد بـ off و warn و error.
- `npx eslint . --fix` يصلح ما يمكن إصلاحه تلقائياً.

## ما هو Prettier؟

**Prettier** منسّق كود: يعيد كتابة الشكل (المسافات، والأقواس، وعلامات التنصيص، وطول الأسطر) بأسلوب موحّد، دون أن يغيّر السلوك.

لماذا هو مهم في الفرق؟

- **ينهي النقاشات**: لا جدال بعد اليوم حول المسافات أو الفواصل المنقوطة.
- **مراجعة أنظف**: الفرق في Pull Request يُظهر التغييرات الحقيقية فقط، لا تغييرات التنسيق.
- **سرعة**: تكتب كيفما شئت، ويرتّبه Prettier عند الحفظ.

> 💡 الفرق مع ESLint: ESLint يبحث عن **أخطاء ومشاكل جودة**، و Prettier يهتم **بالشكل** فقط. تستخدمهما معاً.

## التثبيت والتجربة

الوثائق الرسمية توصي بتثبيته بإصدار دقيق `-E`، لأن أي تغيير في أسلوبه بين الإصدارات يعيد تنسيق المشروع كله:

```terminal-new
$ npm init -y
Wrote to /project/package.json:

{
  "name": "project",
  "version": "1.0.0",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "keywords": [],
  "author": "",
  "license": "ISC",
  "description": ""
}

$ npm install -D -E prettier

added 1 package, and audited 2 packages in 1s

found 0 vulnerabilities
$ cat > app.js <<EOF
> const user={name:'Sara',
>     age:25,skills:["js","css"]}
> function greet(u){return "مرحباً "+u.name}
> EOF
$ npx prettier app.js
const user = { name: "Sara", age: 25, skills: ["js", "css"] };
function greet(u) {
  return "مرحباً " + u.name;
}
```

بدون خيارات، يطبع Prettier النسخة المنسقة دون أن يعدّل الملف.

## check و write

```terminal
$ npx prettier --check .
Checking formatting...
[warn] app.js
[warn] Code style issues found in the above file. Run Prettier with --write to fix.
$ npx prettier --write .
app.js 2ms
package.json 6ms (unchanged)
$ npx prettier --check .
Checking formatting...
All matched files use Prettier code style!
$ cat app.js
const user = { name: "Sara", age: 25, skills: ["js", "css"] };
function greet(u) {
  return "مرحباً " + u.name;
}
```

- `--check` يفحص فقط ويفشل إذا وُجدت ملفات غير منسقة. مناسب لـ CI.
- `--write` يعيد كتابة الملفات منسقة. `(unchanged)` تعني أن الملف كان منسقاً أصلاً.

## الإعدادات: .prettierrc

Prettier يعمل بإعدادات افتراضية جيدة، ويقبل خيارات قليلة عمداً:

```terminal
$ cat > .prettierrc <<EOF
> {
>   "semi": false,
>   "singleQuote": true,
>   "printWidth": 100
> }
> EOF
$ npx prettier --write app.js
app.js 3ms
$ cat app.js
const user = { name: 'Sara', age: 25, skills: ['js', 'css'] }
function greet(u) {
  return 'مرحباً ' + u.name
}
```

| الخيار | الافتراضي | المعنى |
|---|---|---|
| `semi` | `true` | فاصلة منقوطة في نهاية الجمل |
| `singleQuote` | `false` | علامة تنصيص مفردة للنصوص |
| `printWidth` | `80` | أقصى طول للسطر قبل الكسر |
| `tabWidth` | `2` | عدد مسافات المسافة البادئة |
| `trailingComma` | `"all"` | فاصلة بعد آخر عنصر في القوائم المكسورة |

## تجاهل ملفات: .prettierignore

Prettier يتجاهل `node_modules` وما في `.gitignore` تلقائياً. لاستثناء ملفات أخرى:

```terminal
$ echo "const   legacy    =   1" > legacy.js
$ echo "legacy.js" > .prettierignore
$ npx prettier --check .
Checking formatting...
All matched files use Prettier code style!
```

## سكربتات التنسيق

```terminal
$ npm pkg set scripts.format="prettier --write ." scripts.format:check="prettier --check ."
$ npm run format:check

> project@1.0.0 format:check
> prettier --check .

Checking formatting...
All matched files use Prettier code style!
```

## Prettier مع ESLint

بعض قواعد ESLint القديمة تهتم بالتنسيق (مثل `semi` و `quotes`) وقد تتعارض مع Prettier. الحل: الحزمة `eslint-config-prettier` تطفئ كل قواعد التنسيق في ESLint، ويُوضع في **آخر** المصفوفة:

```js
import js from "@eslint/js";
import prettier from "eslint-config-prettier";

export default [
  js.configs.recommended,
  prettier, // آخر عنصر: يطفئ قواعد التنسيق
];
```

> 💡 فعّل في VS Code خيار **Format On Save** مع إضافة Prettier، فيُنسَّق كل ملف تلقائياً عند الحفظ.

## ملخص الدرس

- Prettier ينسق الشكل فقط، و ESLint يبحث عن المشاكل، ويعملان معاً.
- ثبّته بـ `npm install -D -E prettier`.
- `--check` للفحص في CI، و `--write` للتنسيق.
- الإعدادات في `.prettierrc`، والاستثناءات في `.prettierignore`.
- `eslint-config-prettier` يمنع التعارض مع ESLint.
