=== lesson
## البرنامج لا ينتظر

بعض العمليات تأخذ وقتاً: جلب بيانات من خادم، قراءة ملف، أو انتظار مؤقت. لو انتظرت JavaScript انتهاء كل عملية قبل الانتقال للتالية، **لتجمدت الصفحة** كلها ولم يستطع المستخدم الضغط على أي شيء.

لذلك تعمل JavaScript بأسلوب **غير متزامن (Asynchronous)**: تبدأ العملية الطويلة، وتكمل باقي الكود، ثم تعود لنتيجة العملية عندما تجهز.

## setTimeout: أول تجربة

`setTimeout` تنفّذ دالة بعد مدة محددة بالملي ثانية (1000 = ثانية واحدة):

```js
console.log("1. طلبت قهوة");

setTimeout(() => {
  console.log("3. القهوة جاهزة ☕");
}, 1000);

console.log("2. أتصفح هاتفي أثناء الانتظار");
```

```output
1. طلبت قهوة
2. أتصفح هاتفي أثناء الانتظار
3. القهوة جاهزة ☕
```

لاحظ الترتيب! السطر الثالث في الكود طُبع **قبل** الثاني، لأن JavaScript لم تنتظر انتهاء المؤقت. حتى `setTimeout(fn, 0)` تُنفَّذ بعد انتهاء الكود الحالي كله.

## Callbacks: "اتصل بي عندما تنتهي"

الطريقة التقليدية للتعامل مع العمليات غير المتزامنة هي تمرير **دالة callback** تُستدعى عند انتهاء العملية:

```js
function downloadFile(name, callback) {
  console.log(`بدأ تحميل ${name}...`);
  setTimeout(() => {
    callback(`محتوى ${name}`);
  }, 500);
}

downloadFile("report.pdf", content => {
  console.log(`انتهى التحميل: ${content}`);
});
console.log("يمكنك متابعة العمل");
```

```output
بدأ تحميل report.pdf...
يمكنك متابعة العمل
انتهى التحميل: محتوى report.pdf
```

## التعامل مع الأخطاء في Callbacks

العرف المتبع (خاصة في Node.js) أن يكون أول معامل للـ callback هو الخطأ:

```js
function getUser(id, callback) {
  setTimeout(() => {
    if (id <= 0) {
      callback("معرّف غير صالح", null);
    } else {
      callback(null, { id, name: "مستخدم " + id });
    }
  }, 300);
}

getUser(5, (error, user) => {
  if (error) return console.log(`خطأ: ${error}`);
  console.log(user.name);
});
getUser(-1, (error, user) => {
  if (error) return console.log(`خطأ: ${error}`);
  console.log(user.name);
});
```

```output
مستخدم 5
خطأ: معرّف غير صالح
```

## جحيم الـ Callbacks

المشكلة تظهر عندما تعتمد العمليات على بعضها: اجلب المستخدم، ثم طلباته، ثم تفاصيل أول طلب...

```js-error
getUser(1, (err, user) => {
  getOrders(user.id, (err, orders) => {
    getOrderDetails(orders[0], (err, details) => {
      getShipping(details.id, (err, shipping) => {
        // ... وهكذا إلى ما لا نهاية
      });
    });
  });
});
```

هذا الشكل الهرمي يسمى **Callback Hell** أو "هرم الهلاك". صعب القراءة، وصعب التعامل مع أخطائه. ولحله جاءت **Promises** التي سنتعلمها في الدرس القادم.

## ملخص الدرس

- العمليات الطويلة في JavaScript غير متزامنة حتى لا تتجمد الصفحة.
- `setTimeout(fn, ms)` تنفّذ الدالة بعد مدة، والكود الذي بعدها لا ينتظر.
- الـ callback دالة نمررها لتُستدعى عند انتهاء العملية.
- تداخل الـ callbacks يصنع "Callback Hell"، والحل هو Promises.

استخدمها لتحضير الطبقين في الكود. لاحظ أن ترتيب الجاهزية يعتمد على المدة وليس على ترتيب البدء.

~~~starter
cook("سلطة", 2, message => console.log(message));
console.log("المطبخ يعمل...");
~~~

## وعد بنتيجة مستقبلية

**الوعد (Promise)** كائن يمثل نتيجة ستأتي في المستقبل. تخيّل أنك طلبت وجبة فأعطوك **إيصالاً**: الإيصال ليس الوجبة، لكنه وعد بأنك ستحصل عليها، أو ستُخبر بأنها نفدت.

للوعد ثلاث حالات:

| الحالة | المعنى |
|---|---|
| `pending` (معلّق) | العملية ما زالت تعمل |
| `fulfilled` (تحقق) | انتهت بنجاح ومعها النتيجة |
| `rejected` (رُفض) | فشلت ومعها سبب الخطأ |

## استخدام وعد: then و catch

معظم الوقت ستستخدم وعوداً جاهزة (مثل `fetch`). نتعامل معها بـ `then` للنجاح و `catch` للفشل:

```js
function getPrice(product) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (product === "ذهب") resolve(250);
      else reject("المنتج غير موجود");
    }, 300);
  });
}

getPrice("ذهب")
  .then(price => console.log(`السعر: ${price}`))
  .catch(error => console.log(`خطأ: ${error}`));

getPrice("فضة")
  .then(price => console.log(`السعر: ${price}`))
  .catch(error => console.log(`خطأ: ${error}`));
```

```output
السعر: 250
خطأ: المنتج غير موجود
```

## إنشاء وعد

داخل `new Promise` نكتب دالة تستقبل دالتين:

- `resolve(value)`: نستدعيها عند النجاح ونمرر النتيجة.
- `reject(error)`: نستدعيها عند الفشل ونمرر السبب.

```js
const wait = ms => new Promise(resolve => setTimeout(resolve, ms));

wait(500).then(() => console.log("مرت نصف ثانية"));
```

```output
مرت نصف ثانية
```

دالة `wait` هذه مفيدة جداً، وسنستخدمها كثيراً.

## السلسلة: نهاية هرم الهلاك

قيمة `then` الكبرى أنها تُرجع **وعداً جديداً**، فنستطيع ربط العمليات بشكل مسطح بدلاً من التداخل:

```js
const wait = (ms, value) => new Promise(resolve => setTimeout(() => resolve(value), ms));

wait(100, 5)
  .then(n => {
    console.log(`البداية: ${n}`);
    return n * 2;
  })
  .then(n => {
    console.log(`بعد المضاعفة: ${n}`);
    return wait(100, n + 1);
  })
  .then(n => console.log(`النتيجة النهائية: ${n}`))
  .catch(err => console.log(err))
  .finally(() => console.log("انتهت العملية"));
```

```output
البداية: 5
بعد المضاعفة: 10
النتيجة النهائية: 11
انتهت العملية
```

- ما تُرجعه `then` يصل للـ `then` التالية.
- إذا أرجعت وعداً، تنتظره السلسلة قبل المتابعة.
- `catch` واحدة في النهاية تلتقط خطأ **أي** خطوة.
- `finally` تُنفَّذ دائماً، نجاحاً أو فشلاً، وهي مناسبة لإخفاء مؤشر التحميل مثلاً.

## تشغيل عدة وعود معاً

```js
const task = (name, ms) => new Promise(r => setTimeout(() => r(name), ms));

Promise.all([task("المستخدم", 300), task("الطلبات", 100), task("الإشعارات", 200)])
  .then(results => console.log(results));

Promise.race([task("خادم 1", 250), task("خادم 2", 150)])
  .then(winner => console.log(`الأسرع: ${winner}`));
```

```output
الأسرع: خادم 2
["المستخدم","الطلبات","الإشعارات"]
```

| الدالة | تتحقق عندما |
|---|---|
| `Promise.all` | **تنجح كل** الوعود، وتُرجع النتائج بنفس الترتيب. تفشل إذا فشل أي وعد |
| `Promise.allSettled` | تنتهي كل الوعود، نجاحاً أو فشلاً، وتعطيك حالة كل واحد |
| `Promise.race` | ينتهي **أول** وعد |
| `Promise.any` | ينجح أول وعد |

> 💡 `Promise.all` أسرع بكثير من تنفيذ العمليات واحدة بعد الأخرى، لأنها تعمل بالتوازي. في المثال انتهت الثلاثة خلال 300 ملي ثانية بدلاً من 600.

## ملخص الدرس

- الوعد يمثل نتيجة مستقبلية بحالة pending أو fulfilled أو rejected.
- `then` للنتيجة، و `catch` للخطأ، و `finally` تُنفَّذ دائماً.
- السلسلة تجعل العمليات المتتابعة مسطحة وواضحة.
- `Promise.all` لتشغيل عدة عمليات بالتوازي.

--- exercise
اكتب دالة `checkStock(item)` تُرجع **وعداً** يتحقق بعد 200 ملي ثانية:

- إذا كان `item` موجوداً في الكائن `stock` وكميته أكبر من 0، يتحقق بالنص `X متوفر (الكمية: N)`.

~~~starter
  .then(msg => console.log(msg))
  .then(() => checkStock("دفتر"))
  .then(msg => console.log(msg))

  .finally(() => console.log("انتهى الفحص"));
~~~

~~~solution
        resolve(`${item} متوفر (الكمية: ${stock[item]})`);

        reject(`${item} غير متوفر`);

checkStock("قلم")
  .then(msg => console.log(msg))
  .then(() => checkStock("دفتر"))
  .then(msg => console.log(msg))
  .catch(err => console.log(err))
  .finally(() => console.log("انتهى الفحص"));
~~~

## كتابة الكود غير المتزامن كأنه متزامن

`async` و `await` صيغة أحدث مبنية على الوعود، تجعل الكود غير المتزامن **يُقرأ من الأعلى للأسفل** كالكود العادي تماماً. وهي الطريقة الأكثر استخداماً اليوم.

## المقارنة

نفس العملية بالطريقتين:

```js
const wait = (ms, v) => new Promise(r => setTimeout(() => r(v), ms));

// باستخدام then
function withThen() {
  return wait(100, "علي").then(name => {
    return wait(100, `${name} - 3 طلبات`);
  });
}

// باستخدام async/await
async function withAwait() {
  const name = await wait(100, "علي");
  const summary = await wait(100, `${name} - 3 طلبات`);
  return summary;
}

withThen().then(r => console.log(r));
withAwait().then(r => console.log(r));
```

```output
علي - 3 طلبات
علي - 3 طلبات
```

النسخة الثانية أوضح بكثير، خاصة عندما تكثر الخطوات.

## القواعد

1. `async` قبل الدالة تجعلها **تُرجع وعداً دائماً**.
2. `await` توقف تنفيذ **هذه الدالة فقط** حتى يتحقق الوعد، ثم تعطيك قيمته مباشرة.
3. `await` لا تُستخدم إلا داخل دالة `async`.

```js
async function getNumber() {
  return 42;
}

const result = getNumber();
console.log(result instanceof Promise);
result.then(n => console.log(n));
```

```output
true
42
```

حتى لو أرجعت رقماً عادياً، الدالة `async` تغلّفه في وعد.

## await لا تجمّد البرنامج

`await` توقف الدالة الحالية فقط، أما باقي البرنامج فيستمر:

```js
const wait = ms => new Promise(r => setTimeout(r, ms));

async function task() {
  console.log("بدأت المهمة");
  await wait(200);
  console.log("انتهت المهمة");
}

task();
console.log("البرنامج مستمر");
```

```output
بدأت المهمة
البرنامج مستمر
انتهت المهمة
```

## الأخطاء مع try...catch

بدلاً من `.catch()`، نستخدم `try...catch` المألوفة:

```js
function login(password) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      password === "1234" ? resolve("تم الدخول") : reject(new Error("كلمة المرور خاطئة"));
    }, 100);
  });
}

async function attempt(pass) {
  try {
    const msg = await login(pass);
    console.log(msg);
  } catch (error) {
    console.log(`فشل: ${error.message}`);
  } finally {
    console.log("--");
  }
}

attempt("0000").then(() => attempt("1234"));
```

```output
فشل: كلمة المرور خاطئة
--
تم الدخول
--
```

## خطأ شائع: الانتظار المتتابع دون داعٍ

```js
const wait = (ms, v) => new Promise(r => setTimeout(() => r(v), ms));

async function slow() {
  const a = await wait(300, "أ");
  const b = await wait(300, "ب");
  return a + b;
}

async function fast() {
  const [a, b] = await Promise.all([wait(300, "أ"), wait(300, "ب")]);
  return a + b;
}

const t = Date.now();
fast().then(r => console.log(r, Date.now() - t < 450 ? "سريع" : "بطيء"));
```

```output
أب سريع
```

إذا كانت العمليتان **مستقلتين** عن بعضهما، لا تنتظر الأولى قبل بدء الثانية. `slow` تأخذ 600 ملي ثانية، و `fast` تأخذ 300 فقط.

> 💡 القاعدة: `await` متتابعة عندما تحتاج نتيجة الخطوة السابقة، و `Promise.all` عندما تكون العمليات مستقلة.

## ملخص الدرس

- `async` تجعل الدالة تُرجع وعداً، و `await` تنتظر الوعد وتعطيك قيمته.
- `await` توقف الدالة الحالية فقط وليس البرنامج كله.
- استخدم `try...catch` لالتقاط الأخطاء.
- استخدم `Promise.all` مع `await` للعمليات المستقلة.

## التحدث مع الخوادم

معظم التطبيقات الحديثة تجلب بياناتها من **خادم** عبر الإنترنت: المنتجات، والأخبار، والطقس، والتعليقات. الواجهة البرمجية التي يوفرها الخادم تسمى **API**، والدالة المدمجة في المتصفح للتواصل معها هي `fetch`.

## طلب GET: جلب البيانات

```js-error
async function loadUsers() {
  const response = await fetch("https://jsonplaceholder.typicode.com/users");
```

1. `fetch(url)` ترسل الطلب وتُرجع وعداً بكائن **Response** (الاستجابة).
2. `response.json()` تقرأ جسم الاستجابة وتحوّله من JSON إلى كائن، وهي أيضاً غير متزامنة.

> 💡 `jsonplaceholder.typicode.com` خادم تجريبي مجاني ممتاز للتدرب. جرّب المثال في وحدة التحكم في متصفحك (F12). أما تمارين هذا الدرس فتستخدم **خادماً محاكياً** حتى تعمل دون إنترنت.

## كائن Response

| الخاصية | معناها |
|---|---|
| `response.ok` | `true` إذا كان رمز الحالة بين 200 و 299 |
| `response.status` | رمز الحالة: 200 نجاح، 404 غير موجود، 500 خطأ في الخادم |
| `response.json()` | قراءة الجسم كـ JSON |
| `response.text()` | قراءة الجسم كنص |

## طلب POST: إرسال البيانات

لإنشاء شيء جديد على الخادم (تسجيل مستخدم، إضافة تعليق)، نمرر خيارات إضافية:

```js-error
async function createPost() {
  const response = await fetch("https://jsonplaceholder.typicode.com/posts", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ title: "أول منشور", body: "مرحباً", userId: 1 })
  });
  const created = await response.json();
  console.log(created.id);
}
createPost();
```

```output
101
```

- `method`: نوع الطلب.
- `headers`: معلومات إضافية، وهنا نخبر الخادم أن الجسم بصيغة JSON.
- `body`: البيانات المرسلة، ويجب تحويلها لنص بـ `JSON.stringify`.

## أنواع الطلبات (HTTP Methods)

| النوع | الاستخدام | مثال |
|---|---|---|
| `GET` | قراءة بيانات | عرض المنتجات |
| `POST` | إنشاء جديد | تسجيل حساب |
| `PUT` و `PATCH` | تعديل موجود | تعديل الملف الشخصي |
| `DELETE` | حذف | حذف تعليق |

## عرض البيانات في الصفحة

هكذا يبدو النمط الكامل في مشروع حقيقي: نجلب البيانات، ثم نبني عناصر DOM منها:

```js-error
async function showProducts() {
```

## ملخص الدرس

- `fetch(url)` ترسل طلباً وتُرجع وعداً بالاستجابة.
- `await response.json()` لتحويل الجسم إلى كائن.
- `response.ok` و `response.status` لمعرفة نجاح الطلب.
- لطلب POST نمرر `method` و `headers` و `body` بصيغة JSON.

=== lesson
## الشبكة لا تُعتمد عليها دائماً

الإنترنت ينقطع، والخوادم تتعطل، والروابط تتغير. التطبيق الاحترافي **يتوقع الفشل** ويتعامل معه بلطف، بدلاً من أن يتجمد أو يعرض شاشة فارغة.

## نوعان من الفشل

هذه نقطة يخطئ فيها كثير من المطورين:

| الحالة | ماذا تفعل `fetch` |
|---|---|
| انقطاع الإنترنت أو الخادم لا يرد | **ترفض** الوعد، فينتقل التنفيذ إلى `catch` |
| الخادم رد بخطأ (404 أو 500) | **لا ترفض!** يتحقق الوعد عادياً لكن `response.ok` تكون `false` |

> ⚠️ `fetch` لا تعتبر رمز 404 أو 500 خطأ، لأن الخادم ردّ فعلاً. يجب أن تفحص `response.ok` بنفسك.

## النمط الصحيح

```js
// خادم محاكي للتجربة
const fetch = url => new Promise((resolve, reject) => setTimeout(() => {
  if (url === "/offline") reject(new TypeError("Failed to fetch"));
  else if (url === "/missing") resolve({ ok: false, status: 404 });
  else resolve({ ok: true, status: 200, json: async () => ({ name: "بيانات" }) });
}, 50));

async function getData(url) {
  try {
    const response = await fetch(url);
    if (!response.ok) {
      throw new Error(`خطأ من الخادم: ${response.status}`);
    }
    const data = await response.json();
    console.log(`نجاح: ${data.name}`);
  } catch (error) {
    console.log(`تعذر التحميل (${error.message})`);
  }
}

getData("/ok")
  .then(() => getData("/missing"))
  .then(() => getData("/offline"));
```

```output
نجاح: بيانات
تعذر التحميل (خطأ من الخادم: 404)
تعذر التحميل (Failed to fetch)
```

نرمي خطأ بأنفسنا بـ `throw` عندما يكون `response.ok` خاطئاً، فيصل إلى نفس `catch` التي تعالج انقطاع الشبكة. هكذا نتعامل مع كل أنواع الفشل في مكان واحد.

## إعادة المحاولة

بعض الأخطاء مؤقتة. يمكننا إعادة المحاولة عدة مرات قبل الاستسلام:

```js
let calls = 0;
const unstableServer = () => new Promise((resolve, reject) => {
  calls++;
  setTimeout(() => (calls < 3 ? reject(new Error("timeout")) : resolve("البيانات")), 50);
});

async function withRetry(fn, attempts = 3) {
  for (let i = 1; i <= attempts; i++) {
    try {
      return await fn();
    } catch (error) {
      console.log(`المحاولة ${i} فشلت`);
      if (i === attempts) throw error;
    }
  }
}

withRetry(unstableServer).then(data => console.log(`نجحت: ${data}`));
```

```output
المحاولة 1 فشلت
المحاولة 2 فشلت
نجحت: البيانات
```

## تجربة المستخدم أثناء التحميل والخطأ

التعامل مع الأخطاء ليس تقنياً فقط، بل هو تجربة مستخدم:

- **أثناء التحميل:** اعرض مؤشراً مثل "جاري التحميل..." وعطّل زر الإرسال حتى لا يُضغط مرتين.
- **عند الخطأ:** رسالة واضحة بلغة المستخدم، وليس `TypeError: Failed to fetch`، مع زر "إعادة المحاولة".
- **عند النجاح بلا بيانات:** رسالة مثل "لا توجد منتجات بعد" بدلاً من صفحة فارغة.

```js-error
async function loadComments() {
  const status = document.querySelector("#status");
  const button = document.querySelector("#reload");
  status.textContent = "جاري التحميل...";
  button.disabled = true;
  try {
    const response = await fetch("/api/comments");
    if (!response.ok) throw new Error(response.status);
    const comments = await response.json();
    status.textContent = comments.length ? "" : "لا توجد تعليقات بعد";
    // ... عرض التعليقات
  } catch {
    status.textContent = "تعذر تحميل التعليقات. تحقق من اتصالك وحاول مجدداً.";
  } finally {
    button.disabled = false;
  }
}
```

## إلغاء الطلبات البطيئة

بـ `AbortController` يمكنك إلغاء طلب أخذ وقتاً أطول من اللازم:

```js-error
const controller = new AbortController();
setTimeout(() => controller.abort(), 5000);
const response = await fetch(url, { signal: controller.signal });
```

## ملخص الدرس

- `fetch` ترفض عند فشل الشبكة فقط، أما 404 و 500 فيجب فحصها بـ `response.ok`.
- ارمِ خطأ بـ `throw` عند `!response.ok` لتعالج كل الأخطاء في `catch` واحدة.
- أعد المحاولة للأخطاء المؤقتة.
- اهتم بتجربة المستخدم: مؤشر تحميل، ورسائل واضحة، و `finally` لإعادة الواجهة لحالتها.
