=== lesson
## من يستدعيني؟

الكلمة `this` من أكثر ما يربك مبرمجي JavaScript، لأن قيمتها **لا تُحدد عند كتابة الدالة، بل عند استدعائها**. القاعدة الذهبية: انظر إلى ما **قبل النقطة** لحظة الاستدعاء.

## this داخل طرق الكائن

```js
const user = {
  name: "عبير",
  greet() {
    return `مرحباً، أنا ${this.name}`;
  }
};

console.log(user.greet());
```

```output
مرحباً، أنا عبير
```

استدعينا `user.greet()`، وما قبل النقطة هو `user`، إذن `this` هي `user`.

## نفس الدالة، this مختلفة

```js
function introduce() {
  return `أنا ${this.name}`;
}

const a = { name: "أحمد", introduce };
const b = { name: "بشرى", introduce };

console.log(a.introduce());
console.log(b.introduce());
```

```output
أنا أحمد
أنا بشرى
```

دالة واحدة، لكن `this` تتغير حسب الكائن الذي استُدعيت منه.

## المشكلة: فقدان this

عندما تأخذ الطريقة **بعيداً** عن كائنها، تفقد `this`:

```js-error
const timer = {
  seconds: 10,
  show() {
    console.log(this.seconds);
  }
};

timer.show();            // 10
const detached = timer.show;
detached();              // undefined، لا يوجد شيء قبل النقطة!
```

هذا يحدث كثيراً عند تمرير الطريقة كـ callback، مثلاً `setTimeout(timer.show, 1000)` أو `button.addEventListener("click", obj.handle)`.

## الحل 1: bind

`bind` تنشئ نسخة من الدالة مربوطة بـ `this` محددة **للأبد**:

```js
const timer = {
  seconds: 10,
  show() {
    return this.seconds;
  }
};

const bound = timer.show.bind(timer);
console.log(bound());
```

```output
10
```

## الحل 2: الدوال السهمية

الدوال السهمية **ليس لها `this` خاص بها**، بل تأخذه من المكان الذي كُتبت فيه. وهذا يجعلها مثالية داخل الطرق:

```js
const team = {
  name: "الصقور",
  members: ["علي", "سعد"],
  list() {
    return this.members.map(m => `${m} من فريق ${this.name}`);
  }
};

console.log(team.list());
```

```output
["علي من فريق الصقور","سعد من فريق الصقور"]
```

الدالة السهمية داخل `map` أخذت `this` من `list`، أي `team`.

> ⚠️ لهذا السبب **لا تستخدم دالة سهمية كطريقة في كائن**: `{ greet: () => this.name }` لن تعمل، لأن السهمية ستأخذ `this` من خارج الكائن.

## call و apply: تحديد this لاستدعاء واحد

```js
function describe(city, country) {
  return `${this.name} من ${city}، ${country}`;
}

const person = { name: "هالة" };
console.log(describe.call(person, "أبها", "السعودية"));
console.log(describe.apply(person, ["الدوحة", "قطر"]));
```

```output
هالة من أبها، السعودية
هالة من الدوحة، قطر
```

الفرق الوحيد: `call` تأخذ الوسائط منفصلة، و `apply` تأخذها في مصفوفة.

## ملخص قواعد this

| طريقة الاستدعاء | قيمة this |
|---|---|
| `obj.method()` | `obj` |
| `new Class()` | الكائن الجديد |
| `fn.call(x)` أو `fn.bind(x)()` | `x` |
| دالة سهمية | `this` من المكان المحيط بها |
| `fn()` منفردة | `undefined` في الوضع الصارم |
| معالج حدث بدالة عادية | العنصر الذي وقع عليه الحدث |

## ملخص الدرس

- `this` تُحدد لحظة الاستدعاء: انظر لما قبل النقطة.
- فصل الطريقة عن كائنها يُفقدها `this`.
- `bind` تربط `this` بشكل دائم، و `call` و `apply` لاستدعاء واحد.
- الدوال السهمية ترث `this` من محيطها، فهي ممتازة داخل الطرق وسيئة كطرق.

## من أين جاءت هذه الدوال؟

أنشأت مصفوفة فارغة `[]`، ومع ذلك تستطيع استدعاء `push` و `map` و `filter` عليها. أين عُرّفت هذه الدوال؟ الإجابة: في **النموذج الأولي (Prototype)**.

## سلسلة النماذج الأولية

كل كائن في JavaScript له رابط خفي إلى كائن آخر اسمه **prototype**. عندما تطلب خاصية غير موجودة في الكائن، تبحث JavaScript في الـ prototype، ثم في prototype الـ prototype، وهكذا. هذا يسمى **سلسلة النماذج (Prototype Chain)**:

```js
const arr = [1, 2, 3];

console.log(Object.getPrototypeOf(arr) === Array.prototype);
console.log(arr.hasOwnProperty("map"));
console.log("map" in arr);
console.log(Object.getPrototypeOf(Array.prototype) === Object.prototype);
```

```output
true
false
true
true
```

السلسلة هنا: `arr` ← `Array.prototype` (فيه map و push) ← `Object.prototype` (فيه hasOwnProperty) ← `null`.

## إنشاء كائن يرث من آخر

```js
const animal = {
  eat() {
    return `${this.name} يأكل`;
  }
};

const dog = Object.create(animal);
dog.name = "ريكس";
dog.bark = function () {
  return "هاو!";
};

console.log(dog.bark());
console.log(dog.eat());
console.log(Object.keys(dog));
```

```output
هاو!
ريكس يأكل
["name","bark"]
```

`dog` لا يملك `eat`، لكنه وجدها في نموذجه الأولي `animal`. و `Object.keys` تعرض فقط الخصائص **الخاصة** بالكائن.

## الأصناف مبنية على النماذج الأولية

الأصناف التي تعلمناها في الوحدة السابقة هي **صيغة أجمل** فوق نفس النظام:

```js
class User {
  constructor(name) {
    this.name = name;
  }
  hello() {
    return `أهلاً ${this.name}`;
  }
}

const u1 = new User("وعد");
const u2 = new User("جاسم");

console.log(typeof User);
console.log(u1.hello === u2.hello);
console.log(Object.getPrototypeOf(u1) === User.prototype);
```

```output
function
true
true
```

الصنف في الحقيقة دالة، والطريقة `hello` محفوظة **مرة واحدة** في `User.prototype` وتتشاركها كل النسخ، بدلاً من نسخة لكل كائن. وهذا يوفر الذاكرة.

## الطريقة القديمة: دوال البناء

قبل الأصناف (2015) كان يُكتب الكود هكذا، وستراه في المشاريع القديمة:

```js
function Car(brand) {
  this.brand = brand;
}
Car.prototype.drive = function () {
  return `${this.brand} تسير`;
};

const car = new Car("نيسان");
console.log(car.drive());
```

```output
نيسان تسير
```

## تظليل خصائص النموذج

إذا أضفت خاصية للكائن بنفس اسم خاصية في نموذجه، فالكائن يفوز:

```js
const base = { greet() { return "مرحباً من النموذج"; } };
const obj = Object.create(base);
obj.greet = () => "مرحباً من الكائن نفسه";
console.log(obj.greet());
console.log(base.greet());
```

```output
مرحباً من الكائن نفسه
مرحباً من النموذج
```

> ⚠️ لا تعدّل أبداً النماذج المدمجة مثل `Array.prototype.myFunc = ...` في مشاريعك، لأن ذلك قد يتعارض مع مكتبات أخرى أو إصدارات مستقبلية من اللغة.

## ملخص الدرس

- كل كائن مرتبط بنموذج أولي، والبحث عن الخصائص يمر عبر السلسلة.
- `Object.create(proto)` تنشئ كائناً يرث من proto.
- الأصناف صيغة فوق النماذج الأولية، والطرق تُخزن مرة واحدة في `Class.prototype`.
- `hasOwnProperty` و `Object.keys` تعرضان الخصائص الخاصة فقط.

## خيط واحد، مهام كثيرة

JavaScript تعمل على **خيط واحد (Single Thread)**: تنفّذ شيئاً واحداً فقط في كل لحظة. فكيف تتعامل مع المؤقتات والطلبات والضغطات في نفس الوقت؟ الإجابة هي **حلقة الأحداث (Event Loop)**، وهي من أشهر أسئلة المقابلات المتقدمة.

## المكونات الأربعة

1. **مكدس الاستدعاءات (Call Stack):** الكود الذي يُنفَّذ الآن. الدالة تدخل المكدس عند استدعائها، وتخرج عند انتهائها.
2. **واجهات المتصفح (Web APIs):** المؤقتات و fetch والأحداث تعمل هنا **خارج** JavaScript، في المتصفح نفسه.
3. **طابور المهام (Task Queue):** عندما ينتهي مؤقت أو يقع حدث، توضع دالته هنا تنتظر دورها.
4. **طابور المهام الدقيقة (Microtask Queue):** خاص بالوعود (`then` و `await`)، وله **أولوية أعلى**.

**حلقة الأحداث** وظيفتها بسيطة: عندما يفرغ المكدس، تنفّذ **كل** المهام الدقيقة أولاً، ثم تأخذ مهمة **واحدة** من طابور المهام، وتكرر.

## اختبر نفسك: ما الترتيب؟

```js
console.log("1");

setTimeout(() => console.log("2"), 0);

Promise.resolve().then(() => console.log("3"));

console.log("4");
```

```output
1
4
3
2
```

لماذا؟

1. `1` و `4` كود متزامن يُنفَّذ فوراً في المكدس.
2. `setTimeout` وضعت دالتها في **طابور المهام**.
3. `then` وضعت دالتها في **طابور المهام الدقيقة**.
4. فرغ المكدس، فنُفّذت المهام الدقيقة أولاً: `3`.
5. ثم مهمة من طابور المهام: `2`.

> 💡 حتى `setTimeout(fn, 0)` لا تُنفَّذ فوراً. الصفر يعني "في أقرب فرصة بعد انتهاء كل شيء آخر"، والوعود تسبقها دائماً.

## مثال أعمق

```js
console.log("بداية");

setTimeout(() => console.log("مؤقت 1"), 0);

Promise.resolve()
  .then(() => console.log("وعد 1"))
  .then(() => console.log("وعد 2"));

queueMicrotask(() => console.log("مهمة دقيقة"));

setTimeout(() => console.log("مؤقت 2"), 0);

console.log("نهاية");
```

```output
بداية
نهاية
وعد 1
مهمة دقيقة
وعد 2
مؤقت 1
مؤقت 2
```

`وعد 2` لم تُضف إلى الطابور إلا بعد انتهاء `وعد 1`، فجاءت بعد `مهمة دقيقة`. لكنها ما زالت قبل كل المؤقتات، لأن حلقة الأحداث تفرغ طابور المهام الدقيقة **بالكامل** قبل أي مؤقت.

## async و await في حلقة الأحداث

ما بعد `await` يُعامل كمهمة دقيقة:

```js
async function run() {
  console.log("أ");
  await null;
  console.log("ج");
}

run();
console.log("ب");
```

```output
أ
ب
ج
```

## لماذا يهمك هذا عملياً؟

**لا تحجب المكدس:** أي كود متزامن طويل (حلقة على مليون عنصر مثلاً) يجمّد الصفحة كاملة، فلا ضغطات ولا رسوم ولا مؤقتات، لأن حلقة الأحداث لا تستطيع العمل حتى يفرغ المكدس.

```js-error
button.addEventListener("click", () => {
  // ❌ يجمّد الصفحة عدة ثوانٍ
  for (let i = 0; i < 5_000_000_000; i++) {}
});
```

الحلول: تقسيم العمل إلى أجزاء صغيرة بـ `setTimeout`، أو نقله إلى **Web Worker** يعمل في خيط منفصل. (محرر CodeWay نفسه يشغّل كودك في Web Worker حتى لا تتجمد الصفحة!)

## ملخص الدرس

- JavaScript تنفّذ شيئاً واحداً في كل لحظة على مكدس الاستدعاءات.
- المؤقتات والأحداث تذهب لطابور المهام، والوعود لطابور المهام الدقيقة.
- الترتيب: الكود المتزامن ← كل المهام الدقيقة (الوعود) ← مهمة واحدة (مؤقت) ← وتكرار.
- الكود المتزامن الطويل يجمّد الصفحة.

## الأخطاء جزء من البرمجة

لا يوجد برنامج بلا أخطاء. المهم ألا **ينهار** البرنامج كله بسبب خطأ واحد، وأن يُعرض للمستخدم ما يفهمه. لهذا نستخدم `try...catch`.

## بدون معالجة: البرنامج يتوقف

```js-error
console.log("قبل");
const data = JSON.parse("{خطأ}"); // SyntaxError يوقف كل شيء
console.log("بعد");               // لن يُطبع أبداً
```

## مع try...catch

```js
console.log("قبل");
try {
  const data = JSON.parse("{خطأ}");
  console.log("لن يُنفّذ هذا السطر");
} catch (error) {
  console.log(`حدث خطأ: ${error.name}`);
}
console.log("بعد، والبرنامج مستمر");
```

```output
قبل
حدث خطأ: SyntaxError
بعد، والبرنامج مستمر
```

- `try`: الكود الذي قد يفشل. عند أول خطأ يتوقف ويقفز إلى `catch`.
- `catch (error)`: يُنفَّذ فقط عند حدوث خطأ، ويستقبل كائن الخطأ.
- `finally` (اختياري): يُنفَّذ دائماً في الحالتين.

## كائن الخطأ

```js
try {
  const user = null;
  user.name;
} catch (error) {
  console.log(error.name);
  console.log(error.message);
  console.log(error instanceof TypeError);
}
```

```output
TypeError
Cannot read properties of null (reading 'name')
true
```

أشهر أنواع الأخطاء:

| النوع | السبب الشائع |
|---|---|
| `ReferenceError` | استخدام متغير غير معرّف |
| `TypeError` | استخدام قيمة بطريقة خاطئة، مثل استدعاء خاصية على `null` |
| `SyntaxError` | كود أو JSON مكتوب بشكل خاطئ |
| `RangeError` | قيمة خارج النطاق المسموح |

## رمي الأخطاء بنفسك: throw

عندما تكتشف دالتك وضعاً غير صالح، ترمي خطأ بنفسها:

```js
function withdraw(balance, amount) {
  if (typeof amount !== "number" || amount <= 0) {
    throw new Error("المبلغ يجب أن يكون رقماً موجباً");
  }
  if (amount > balance) {
    throw new RangeError(`الرصيد غير كافٍ (المتاح ${balance})`);
  }
  return balance - amount;
}

for (const amount of [50, -5, 900]) {
  try {
    console.log(`الرصيد الجديد: ${withdraw(200, amount)}`);
  } catch (error) {
    console.log(`${error.name}: ${error.message}`);
  }
}
```

```output
الرصيد الجديد: 150
Error: المبلغ يجب أن يكون رقماً موجباً
RangeError: الرصيد غير كافٍ (المتاح 200)
```

## أخطاء مخصصة

بالوراثة من `Error` يمكنك إنشاء أنواع أخطاء خاصة بتطبيقك، وتمييزها بـ `instanceof`:

```js
class ValidationError extends Error {
  constructor(field, message) {
    super(message);
    this.name = "ValidationError";
    this.field = field;
  }
}

function register(email) {
  if (!email.includes("@")) {
    throw new ValidationError("email", "البريد الإلكتروني غير صالح");
  }
  return "تم التسجيل";
}

try {
  register("ali.mail.com");
} catch (error) {
  if (error instanceof ValidationError) {
    console.log(`خطأ في الحقل ${error.field}: ${error.message}`);
  } else {
    throw error;
  }
}
```

```output
خطأ في الحقل email: البريد الإلكتروني غير صالح
```

لاحظ `else { throw error; }`: نعالج الأخطاء التي **نتوقعها** فقط، ونعيد رمي غيرها، حتى لا نخفي أخطاء برمجية حقيقية.

## نصائح احترافية

- لا تكتب `catch` فارغة تبتلع الخطأ بصمت. على الأقل سجّله بـ `console.error`.
- لا تغلّف كل الكود بـ `try`. استخدمها حول العمليات التي **قد تفشل فعلاً**: تحليل JSON، والطلبات، ومدخلات المستخدم.
- رسالة الخطأ للمطور يجب أن تكون دقيقة، ورسالة المستخدم يجب أن تكون بسيطة ومفيدة.

## ملخص الدرس

- `try...catch` يمنع انهيار البرنامج ويعالج الخطأ.
- كائن الخطأ فيه `name` و `message`.
- `throw new Error("...")` لرمي خطأ عند وضع غير صالح.
- الأخطاء المخصصة بـ `extends Error` و `instanceof` لتمييزها.

## النمط الآمن للقراءة

قد تكون القيمة غير موجودة، أو تالفة، أو قد يكون التخزين معطلاً في التصفح الخاص. لذلك نكتب دالة قراءة آمنة:

```js
function load(key, fallback) {
  try {
    const raw = localStorage.getItem(key);
    return raw === null ? fallback : JSON.parse(raw);
  } catch {
    return fallback;
  }
}

function save(key, value) {
  try {
    localStorage.setItem(key, JSON.stringify(value));
  } catch {
    // التخزين ممتلئ أو معطّل، نتجاهل بهدوء
  }
}

localStorage.setItem("broken", "{not json");
console.log(load("settings", { theme: "light" }).theme);
console.log(load("broken", "قيمة احتياطية"));
save("score", 42);
console.log(load("score", 0) + 8);
```

## sessionStorage

نفس الدوال تماماً، لكن البيانات تُحذف عند **إغلاق التبويب**. مناسبة لبيانات مؤقتة مثل خطوات نموذج طويل.

## ما لا يجب تخزينه

| مناسب | غير مناسب |
|---|---|
| تفضيلات الواجهة (الوضع، اللغة) | كلمات المرور |
| مسودة نص لم يُرسل | بيانات بطاقات الدفع |
| سلة مشتريات زائر | رموز الدخول الحساسة إن أمكن تجنبها |
| تقدّم في درس | البيانات التي يجب أن تُشارك بين الأجهزة |

> ⚠️ أي كود JavaScript في الصفحة يستطيع قراءة localStorage، والمساحة محدودة بحوالي 5 ميجابايت، والبيانات موجودة على جهاز واحد فقط. البيانات المهمة مكانها الخادم.

## ملخص الدرس

- `localStorage` تخزين دائم في المتصفح، و `sessionStorage` حتى إغلاق التبويب.
- يخزّن نصوصاً فقط، فاستخدم `JSON.stringify` و `JSON.parse` للكائنات.
- احمِ القراءة بـ `try...catch` وقيمة احتياطية.
- لا تخزّن بيانات حساسة.
