=== lesson
## المشكلة التي يحلها Git

تخيّل أنك تعمل على مشروع، وتحفظ نسخاً هكذا:

```text
project-final.zip
project-final-2.zip
project-final-REALLY-final.zip
project-final-fixed-ahmed.zip
```

بعد أسبوع لا تعرف أي نسخة هي الأحدث، ولا ما الذي تغيّر بين نسختين، ولا كيف تدمج تعديلاتك مع تعديلات زميلك. هذه بالضبط المشكلة التي يحلها **نظام التحكم بالإصدارات (Version Control System)**.

## ما هو Git؟

**Git** نظام تحكم بالإصدارات يحفظ تاريخ مشروعك كاملاً على شكل **لقطات (commits)**. كل لقطة تسجّل:

- حالة كل الملفات في تلك اللحظة.
- من قام بالتغيير ومتى.
- رسالة تشرح **لماذا** حدث التغيير.

بهذا تستطيع الرجوع لأي نسخة سابقة، ومعرفة من غيّر أي سطر، والعمل مع فريق كامل على نفس الملفات دون أن يمسح أحد عمل الآخر.

| بدون Git | مع Git |
|---|---|
| نسخ يدوية بأسماء عشوائية | تاريخ مرتب بلقطات ورسائل واضحة |
| لا تعرف ماذا تغيّر | `git diff` يُظهر كل سطر تغيّر |
| الخطأ قد يضيّع العمل | ترجع لأي لقطة سابقة بأمر واحد |
| العمل الجماعي فوضى | فروع ودمج ومراجعة منظمة |

## Git ليس GitHub

خلط شائع عند المبتدئين:

- **Git** برنامج يعمل على جهازك ويدير التاريخ محلياً، ويعمل حتى بدون إنترنت.
- **GitHub** موقع يستضيف مستودعات Git على الإنترنت، ويضيف أدوات للتعاون: Pull Requests ومراجعة الكود و Issues. توجد بدائل مثل GitLab و Bitbucket.

## المفاهيم الثلاثة الأساسية

Git يتعامل مع ملفاتك في ثلاث مناطق:

1. **مجلد العمل (Working Directory)**: الملفات كما تراها وتعدّلها الآن.
2. **منطقة التجهيز (Staging Area)**: التغييرات التي اخترت أن تدخل في اللقطة القادمة.
3. **المستودع (Repository)**: التاريخ المحفوظ من اللقطات، داخل مجلد مخفي اسمه `.git`.

> 💡 فكّر في منطقة التجهيز كصندوق تضع فيه ما تريد إرساله، ثم تغلق الصندوق وتختمه بـ commit.

## أول أوامر Git

قبل أي شيء، عرّف Git باسمك وبريدك. هذه المعلومات تُكتب على كل commit تصنعه:

```terminal
$ git --version
git version 2.47.0
$ git config --global user.name "Sara Ahmed"
$ git config --global user.email "sara@example.com"
$ git config user.name
Sara Ahmed
```

> ⚠️ على جهازك الحقيقي تكفي هذه الإعدادات مرة واحدة فقط بفضل `--global`. في تمارين المنصة تبدأ كل مرة بطرفية جديدة.

## الطرفية في هذه الدورة

كل تمارين الدورة تعمل في **طرفية محاكاة** داخل المتصفح: تكتب الأوامر كما تكتبها على جهازك، فتظهر مخرجات مطابقة لمخرجات Git الحقيقي. يمكنك أيضاً إنشاء ملفات بأوامر بسيطة:

```terminal
$ echo "مرحباً" > hello.txt
$ cat hello.txt
مرحباً
$ ls
hello.txt
```

- `echo "نص" > ملف` تكتب النص في ملف (وتستبدل محتواه).
- `echo "نص" >> ملف` تضيف النص في نهاية الملف.
- `cat ملف` تعرض محتوى الملف، و `ls` تعرض ملفات المجلد.

## ملخص الدرس

- نظام التحكم بالإصدارات يحفظ تاريخ المشروع كلقطات قابلة للرجوع إليها.
- Git يعمل محلياً، و GitHub منصة استضافة وتعاون فوقه.
- المناطق الثلاث: مجلد العمل، منطقة التجهيز، المستودع.
- `git config` يحدد اسمك وبريدك الظاهرين على كل commit.

## إنشاء مستودع: git init

لتبدأ تتبع مشروع بـ Git، ادخل مجلده ونفّذ `git init` مرة واحدة:

```terminal-new
$ git init
Initialized empty Git repository in /project/.git/
$ git status
On branch main

No commits yet

nothing to commit (create/copy files and use "git add" to track)
```

`git init` أنشأ مجلد `.git` المخفي، وأصبح المجلد مستودعاً. `git status` هو أهم أمر ستستخدمه: يخبرك بحالة كل شيء.

## الدورة الكاملة: تعديل ثم add ثم commit

أنشئ ملفاً، ثم اسأل Git عن الحالة:

```terminal
$ echo "# متجر الكتب" > README.md
$ git status
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
	README.md

nothing added to commit but untracked files present (use "git add" to track)
```

الملف **غير متتبَّع (untracked)**: Git يراه لكنه لا يحفظ تاريخه. لنضعه في منطقة التجهيز بـ `git add`:

```terminal
$ git add README.md
$ git status
On branch main

No commits yet

Changes to be committed:
  (use "git restore --staged <file>..." to unstage)
	new file:   README.md
```

الآن هو في قسم «Changes to be committed». لنحفظ اللقطة بـ `git commit` مع رسالة `-m`:

```terminal
$ git commit -m "إضافة ملف README"
[main (root-commit) 14df902] إضافة ملف README
 1 file changed, 1 insertion(+)
 create mode 100644 README.md
$ git status
On branch main

nothing to commit, working tree clean
```

السطر `[main (root-commit) ...]` يعني: أول commit على الفرع `main`، والرمز بعده هو **المعرّف المختصر** للـ commit. ثم `1 file changed, 1 insertion(+)` ملخص التغيير.

## تعديل ملف متتبَّع

عندما تعدّل ملفاً سبق حفظه، يصبح «modified»:

```terminal
$ echo "متجر لبيع الكتب العربية" >> README.md
$ echo "console.log('hi')" > app.js
$ git status
On branch main

Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   README.md

Untracked files:
  (use "git add <file>..." to include in what will be committed)
	app.js

no changes added to commit (use "git add" and/or "git commit -a")
```

لاحظ القسمين: `README.md` **معدّل لكن غير مجهّز**، و `app.js` **غير متتبَّع**. لنجهّز كل شيء دفعة واحدة بـ `git add .` (النقطة تعني: كل الملفات في المجلد):

```terminal
$ git add .
$ git status --short
M  README.md
A  app.js
$ git commit -m "إضافة وصف المتجر وملف التطبيق"
[main 45036a3] إضافة وصف المتجر وملف التطبيق
 2 files changed, 2 insertions(+)
 create mode 100644 app.js
```

`git status --short` نسخة مختصرة: `M` معدّل، و `A` جديد مجهّز، و `??` غير متتبَّع.

## اختصار: commit -a

الخيار `-a` يجهّز تلقائياً كل **الملفات المتتبَّعة** المعدّلة قبل الحفظ، فيمكن دمجه مع `-m` هكذا `-am`:

```terminal
$ echo "// v2" >> app.js
$ git commit -am "تحديث التطبيق"
[main 9fadf76] تحديث التطبيق
 1 file changed, 1 insertion(+)
```

> ⚠️ `-a` لا يضيف الملفات الجديدة غير المتتبَّعة، لها لا بد من `git add` أولاً.

## التراجع عن التجهيز

أضفت ملفاً بالخطأ؟ أخرجه من منطقة التجهيز دون أن تخسر محتواه:

```terminal
$ echo "password=123" > secret.txt
$ git add secret.txt
$ git restore --staged secret.txt
$ git status --short
?? secret.txt
```

## ملخص الدرس

- `git init` ينشئ مستودعاً جديداً مرة واحدة لكل مشروع.
- الدورة الأساسية: عدّل ← `git add` ← `git commit -m "رسالة"`.
- `git status` يخبرك دائماً بما يحدث، و `--short` نسخة مختصرة.
- `git add .` يجهّز الكل، و `commit -am` يجهّز المتتبَّع ويحفظ.
- `git restore --staged ملف` يلغي التجهيز.

## سجل التغييرات: git log

كل commit يُحفظ في التاريخ. لنصنع مشروعاً صغيراً ثم نستعرض تاريخه:

```terminal-new
$ git init
Initialized empty Git repository in /project/.git/
$ echo "قائمة المهام" > todo.txt
$ git add todo.txt
$ git commit -m "بداية قائمة المهام"
[main (root-commit) dbf6193] بداية قائمة المهام
 1 file changed, 1 insertion(+)
 create mode 100644 todo.txt
$ echo "- شراء الحليب" >> todo.txt
$ git commit -am "إضافة مهمة الحليب"
[main 4338670] إضافة مهمة الحليب
 1 file changed, 1 insertion(+)
$ echo "- مراجعة الدرس" >> todo.txt
$ git commit -am "إضافة مهمة المراجعة"
[main f123059] إضافة مهمة المراجعة
 1 file changed, 1 insertion(+)
$ git log
commit f123059567c264ba5694773583b2ab0c71298017 (HEAD -> main)
Author: CodeWay Student <student@codeway.dev>
Date:   Mon Jan 6 10:03:00 2025 +0300

    إضافة مهمة المراجعة

commit 4338670eaf441aa55cb338aeb28d2453fea65494
Author: CodeWay Student <student@codeway.dev>
Date:   Mon Jan 6 10:02:00 2025 +0300

    إضافة مهمة الحليب

commit dbf6193d33016b627412635d324920408087bb93
Author: CodeWay Student <student@codeway.dev>
Date:   Mon Jan 6 10:01:00 2025 +0300

    بداية قائمة المهام
```

كل commit يعرض:

- **المعرّف الكامل** (40 حرفاً): بصمة فريدة لهذه اللقطة.
- `(HEAD -> main)`: أنت الآن هنا، على الفرع `main`.
- الكاتب والتاريخ والرسالة.

## سجل مختصر

`git log` الكامل طويل، والصيغة المختصرة أكثر استخداماً يومياً:

```terminal
$ git log --oneline
f123059 (HEAD -> main) إضافة مهمة المراجعة
4338670 إضافة مهمة الحليب
dbf6193 بداية قائمة المهام
$ git log --oneline -2
f123059 (HEAD -> main) إضافة مهمة المراجعة
4338670 إضافة مهمة الحليب
```

`-2` تعني آخر لقطتين فقط. ويمكنك اختيار ما يُعرض بـ `--format`:

```terminal
$ git log --format="%h | %an | %s"
f123059 | CodeWay Student | إضافة مهمة المراجعة
4338670 | CodeWay Student | إضافة مهمة الحليب
dbf6193 | CodeWay Student | بداية قائمة المهام
```

| الرمز | المعنى |
|---|---|
| `%h` | المعرّف المختصر |
| `%H` | المعرّف الكامل |
| `%an` | اسم الكاتب |
| `%s` | رسالة الـ commit |

## ماذا تغيّر؟ git diff

`git diff` يعرض الفرق بين مجلد العمل وآخر نسخة مجهّزة، أي التعديلات التي لم تُجهَّز بعد:

```terminal
$ echo "- كتابة التقرير" >> todo.txt
$ git diff
diff --git a/todo.txt b/todo.txt
--- a/todo.txt
+++ b/todo.txt
@@ -1,3 +1,4 @@
 قائمة المهام
 - شراء الحليب
 - مراجعة الدرس
+- كتابة التقرير
```

اقرأ المخرجات هكذا:

- `--- a/todo.txt` النسخة القديمة و `+++ b/todo.txt` النسخة الجديدة.
- الأسطر التي تبدأ بـ `+` أُضيفت، والتي تبدأ بـ `-` حُذفت، والتي تبدأ بمسافة لم تتغير.

## diff بعد التجهيز

بعد `git add` يصبح `git diff` فارغاً، لأن التغيير انتقل لمنطقة التجهيز. لرؤيته استخدم `--staged`:

```terminal
$ git add todo.txt
$ git diff
$ git diff --staged
diff --git a/todo.txt b/todo.txt
--- a/todo.txt
+++ b/todo.txt
@@ -1,3 +1,4 @@
 قائمة المهام
 - شراء الحليب
 - مراجعة الدرس
+- كتابة التقرير
$ git commit -m "إضافة مهمة التقرير"
[main 5c90e98] إضافة مهمة التقرير
 1 file changed, 1 insertion(+)
```

> 💡 عادة احترافية: راجع `git diff --staged` قبل كل commit لتتأكد أنك تحفظ ما تقصده فقط.

## عرض commit واحد: git show

```terminal
$ git show HEAD~1
commit f123059567c264ba5694773583b2ab0c71298017
Author: CodeWay Student <student@codeway.dev>
Date:   Mon Jan 6 10:03:00 2025 +0300

    إضافة مهمة المراجعة

diff --git a/todo.txt b/todo.txt
--- a/todo.txt
+++ b/todo.txt
@@ -1,2 +1,3 @@
 قائمة المهام
 - شراء الحليب
+- مراجعة الدرس
```

`HEAD` آخر commit، و `HEAD~1` الذي قبله، و `HEAD~2` الذي قبلهما وهكذا. `git show` يعرض معلومات الـ commit والتغييرات التي أحدثها.

## ملخص الدرس

- `git log` يعرض التاريخ، و `--oneline` يختصره، و `-n` يحدد العدد.
- `--format` يخصص ما يُعرض، مثل `%h` و `%s`.
- `git diff` يُظهر التعديلات غير المجهّزة، و `git diff --staged` المجهّزة.
- `HEAD` يشير لآخر commit، و `HEAD~1` لما قبله، و `git show` يعرض تفاصيل أي commit.
