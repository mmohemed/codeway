=== lesson
## المستودع البعيد (Remote)

حتى الآن كل شيء على جهازك فقط. **المستودع البعيد** نسخة من مستودعك على خادم مثل GitHub، تفيدك في:

- **النسخ الاحتياطي**: لو تعطل جهازك، مشروعك محفوظ.
- **العمل الجماعي**: كل عضو في الفريق يرفع عمله ويسحب عمل الآخرين.
- **النشر والعرض**: ملفك في GitHub هو سيرتك الذاتية كمطوّر.

## إنشاء مستودع على GitHub

يمكنك إنشاء المستودع من موقع GitHub بزر **New repository**، أو من الطرفية بأداة GitHub الرسمية `gh`:

```terminal-new
$ git init
Initialized empty Git repository in /project/.git/
$ echo "# متجر الكتب" > README.md
$ git add .
$ git commit -m "البداية"
[main (root-commit) 2248e7e] البداية
 1 file changed, 1 insertion(+)
 create mode 100644 README.md
$ gh repo create bookstore --public --source=.
✓ Created repository student/bookstore on GitHub
  https://github.com/student/bookstore
✓ Added remote https://github.com/student/bookstore.git
$ git remote -v
origin	https://github.com/student/bookstore.git (fetch)
origin	https://github.com/student/bookstore.git (push)
```

الخيار `--source=.` ربط المجلد الحالي بالمستودع الجديد باسم **origin**، وهو الاسم المتعارف عليه للمستودع البعيد الرئيسي.

> 💡 إذا أنشأت المستودع من الموقع، تربطه يدوياً: `git remote add origin https://github.com/user/bookstore.git`.

## الرفع: git push

```terminal
$ git push -u origin main
To https://github.com/student/bookstore.git
 * [new branch]      main -> main
branch 'main' set up to track 'origin/main'.
$ git status
On branch main
Your branch is up to date with 'origin/main'.

nothing to commit, working tree clean
```

- `origin` المستودع البعيد، و `main` الفرع الذي نرفعه.
- `-u` تربط فرعك المحلي بالفرع البعيد (**upstream**)، فتكفي بعدها `git push` و `git pull` وحدهما.
- `Your branch is up to date with 'origin/main'` تعني أن المحلي والبعيد متطابقان.

بعد commit جديد، يخبرك `git status` أنك متقدم على البعيد:

```terminal
$ echo "متجر لبيع الكتب العربية" >> README.md
$ git commit -am "وصف المتجر"
[main 23d5866] وصف المتجر
 1 file changed, 1 insertion(+)
$ git status
On branch main
Your branch is ahead of 'origin/main' by 1 commit.
  (use "git push" to publish your local commits)

nothing to commit, working tree clean
$ git push
To https://github.com/student/bookstore.git
   2248e7e..23d5866  main -> main
```

> ⚠️ على جهازك الحقيقي ستظهر أسطر إضافية مثل `Enumerating objects` و `Writing objects`، وهي مؤشرات تقدّم فقط. الأسطر المهمة هي التي تراها هنا.

## الاستنساخ: git clone

زميلتك هدى تريد العمل على المشروع. تنسخه كاملاً بتاريخه إلى جهازها:

```terminal
$ git clone https://github.com/student/bookstore.git huda-laptop
Cloning into 'huda-laptop'...
$ cd huda-laptop
$ git log --oneline
23d5866 (HEAD -> main, origin/main) وصف المتجر
2248e7e البداية
```

`clone` ينزّل كل شيء ويضبط `origin` تلقائياً. سنستخدم المجلد `huda-laptop` لنمثّل جهاز هدى:

```terminal
$ echo "قسم الروايات" > novels.txt
$ git add .
$ git commit -m "إضافة قسم الروايات"
[main 1ab7ac9] إضافة قسم الروايات
 1 file changed, 1 insertion(+)
 create mode 100644 novels.txt
$ git push
To https://github.com/student/bookstore.git
   23d5866..1ab7ac9  main -> main
$ cd ..
```

## السحب: git pull

الآن على جهازك، المستودع البعيد فيه عمل جديد من هدى. اسحبه:

```terminal
$ git pull
From https://github.com/student/bookstore.git
   23d5866..1ab7ac9  main       -> origin/main
Updating 23d5866..1ab7ac9
Fast-forward
 novels.txt | 1 +
 1 file changed, 1 insertion(+)
 create mode 100644 novels.txt
$ ls
README.md  huda-laptop  novels.txt
$ git log --oneline
1ab7ac9 (HEAD -> main, origin/main) إضافة قسم الروايات
23d5866 وصف المتجر
2248e7e البداية
```

`git pull` يجلب التغييرات من البعيد (`fetch`) ثم يدمجها في فرعك (`merge`).

> 💡 عادة يومية: ابدأ يومك بـ `git pull` لتعمل على آخر نسخة، وارفع عملك بـ `git push` في نهاية كل مهمة.

## ملخص الدرس

- المستودع البعيد اسمه المعتاد `origin`، و `git remote -v` يعرضه.
- `git push -u origin main` أول رفع، وبعدها `git push` يكفي.
- `git clone URL` ينسخ المستودع كاملاً، و `git pull` يجلب ويدمج الجديد.
- إذا رُفض الرفع: اسحب أولاً (`git pull --rebase` مثلاً) ثم ارفع.

## ما هو Pull Request؟

في الفرق المحترفة لا أحد يرفع مباشرة إلى `main`. بدلاً من ذلك:

1. تنشئ فرعاً لمهمتك وتعمل عليه.
2. ترفع الفرع إلى GitHub.
3. تفتح **Pull Request** (طلب دمج): «هذه تغييراتي، أرجو مراجعتها ودمجها في main».
4. يراجع الفريق الكود ويناقشه، وتعمل الاختبارات الآلية.
5. بعد الموافقة يُدمج الطلب.

> 💡 في GitLab يسمّى Merge Request، والفكرة نفسها.


## الخطوة 5: الدمج

GitHub يوفر ثلاث طرق للدمج:

| الطريقة | الخيار | النتيجة |
|---|---|---|
| Merge commit | `--merge` | كل commits الفرع + commit دمج |
| Squash and merge | `--squash` | commit واحد يجمع كل تغييرات الطلب |
| Rebase and merge | `--rebase` | commits الفرع فوق main بلا commit دمج |

`--squash` شائع جداً لأنه يجعل تاريخ `main` نظيفاً: commit واحد لكل ميزة. و `--delete-branch` يحذف الفرع بعد الدمج وينقلك إلى `main` محدّثاً:

```terminal
$ gh pr merge 1 --squash --delete-branch
✓ Merged pull request student/shop#1 (إضافة خانة البحث)
Switched to branch 'main'
From https://github.com/student/shop.git
   f1b54e3..ec983ac  main       -> origin/main
Updating f1b54e3..ec983ac
Fast-forward
 search.html | 1 +
 1 file changed, 1 insertion(+)
 create mode 100644 search.html
✓ Deleted local branch feature/search
✓ Deleted remote branch feature/search
$ git branch
* main
$ git log --oneline
ec983ac (HEAD -> main, origin/main) إضافة خانة البحث (#1)
f1b54e3 الصفحة الرئيسية
```

## ملخص الدرس

- Pull Request طلب لدمج فرع في `main` بعد المراجعة.
- الخطوات: فرع ← commits ← `git push -u` ← `gh pr create` ← مراجعة ← دمج.
- الوصف الجيد يشرح ماذا ولماذا وكيف تختبر.
- طرق الدمج: merge و squash و rebase، و `--delete-branch` ينظّف الفرع بعدها.

## لماذا مراجعة الكود؟

**مراجعة الكود (Code Review)** أن يقرأ زميل تغييراتك قبل دمجها. فوائدها:

- اكتشاف الأخطاء مبكراً، قبل أن تصل للمستخدمين.
- نشر المعرفة: أكثر من شخص يفهم كل جزء من المشروع.
- توحيد الأسلوب والجودة في الفريق.
- تعلّم مستمر: المراجِع والمراجَع يتعلمان معاً.

## قراءة الطلب

أول خطوة للمراجِع: افهم **ماذا** و**لماذا** من الوصف، ثم اقرأ الفرق:

```terminal
$ gh pr list

Showing 1 of 1 open pull request in student/shop
#1  خصم 10% على السلة  feature/discount
$ gh pr diff 1
diff --git a/cart.js b/cart.js
--- a/cart.js
+++ b/cart.js
@@ -1,1 +1,2 @@
 const total = price;
+const discount = price * 1.0;
```

لاحظت المشكلة؟ الوصف يقول خصم 10%، لكن الكود يضرب في `1.0`، أي خصم 100%!

## تجربة الطلب محلياً

أحياناً تحتاج تشغيل الكود بنفسك. `gh pr checkout` ينقلك إلى فرع الطلب:

```terminal
$ gh pr checkout 1
Switched to branch 'feature/discount'
$ cat cart.js
const total = price;
const discount = price * 1.0;
$ git switch main
Switched to branch 'main'
```

## كتابة المراجعة

ثلاثة أنواع للمراجعة:

| النوع | الخيار | المعنى |
|---|---|---|
| موافقة | `--approve` | الكود جاهز للدمج |
| طلب تعديلات | `--request-changes` | يجب إصلاح شيء قبل الدمج |
| تعليق | `--comment` | ملاحظات أو أسئلة بلا قرار |

```terminal
$ gh pr review 1 --request-changes --body "نسبة الخصم 100% بدل 10%، المفروض price * 0.1"
+ Requested changes to pull request student/shop#1
$ gh pr view 1
خصم 10% على السلة student/shop#1
Open • huda wants to merge 1 commit into main from feature/discount
Reviewers: student (Changes requested)

  يطبّق خصم 10% على إجمالي السلة

student requested changes • نسبة الخصم 100% بدل 10%، المفروض price * 0.1

View this pull request on GitHub: https://github.com/student/shop/pull/1
```


لاحظ أن GitHub منع هدى من الموافقة على طلبها: **المراجعة يجب أن تكون من شخص آخر**.

## آداب المراجعة

- **انتقد الكود لا الشخص**: «هذه الدالة يمكن تبسيطها» وليس «كتبت كوداً سيئاً».
- **اسأل بدل أن تأمر**: «ما رأيك لو استخدمنا map هنا؟».
- **وضّح السبب**: لا تكتب «خطأ» فقط، اشرح لماذا واقترح البديل.
- **امدح الجيد**: كلمة «فكرة ذكية» تبني فريقاً أفضل.
- **فرّق بين الإلزامي والاختياري**: ابدأ الملاحظة الاختيارية بـ `nit:`.

## ملخص الدرس

- المراجعة تكتشف الأخطاء وتنشر المعرفة وتوحد الجودة.
- `gh pr diff` لقراءة التغييرات، و `gh pr checkout` لتجربتها محلياً.
- `gh pr review` بثلاثة خيارات: approve و request-changes و comment.
- لا يمكن الموافقة على طلبك بنفسك، ولطف الأسلوب جزء من الاحتراف.

## Issues: قائمة مهام المشروع

**Issue** (مشكلة أو تذكرة) سجل لأي عمل يخص المشروع: خطأ اكتُشف، ميزة مطلوبة، سؤال، أو تحسين. كل مشروع جاد على GitHub يدير عمله عبرها، والمشاريع مفتوحة المصدر تستقبل بها بلاغات المستخدمين.

## ملخص الدرس

- Issue سجل لخطأ أو ميزة أو سؤال، وهي قائمة مهام المشروع.
- البلاغ الجيد فيه خطوات إعادة المشكلة والمتوقع والفعلي والبيئة.
- التصنيفات والإسناد ينظمان العمل.
- `Closes #N` في وصف الطلب يغلق المشكلة تلقائياً عند الدمج.
