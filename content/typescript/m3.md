## وصف شكل الكائن

الكائنات في كل مكان في JavaScript. الـ **interface** تعطي اسماً لشكل كائن: ما خصائصه وما نوع كل منها.

```ts
interface User {
  id: number;
  name: string;
  email: string;
}

const user: User = {
  id: 1,
  name: "هيفاء",
  email: "haifa@mail.com"
};

function welcome(u: User): string {
  return `مرحباً ${u.name} (${u.email})`;
}

console.log(welcome(user));
```

```output
مرحباً هيفاء (haifa@mail.com)
```

## TypeScript تفحص الشكل بدقة

```ts
interface User {
  id: number;
  name: string;
  email: string;
}

const broken: User = {
  id: 2,
  name: "طلال"
};
```

```output
ERR: line 7: Property 'email' is missing in type '{ id: number; name: string; }' but required in type 'User'.
```

خاصية ناقصة؟ خطأ. وخاصية زائدة غير معرّفة؟ أيضاً خطأ:

```ts
interface Point { x: number; y: number }
const p: Point = { x: 1, y: 2, z: 3 };
```

```output
ERR: line 2: Object literal may only specify known properties, and 'z' does not exist in type 'Point'.
```

## الكتابة الهيكلية (Structural Typing)

مبدأ مهم: TypeScript تهتم **بالشكل** وليس بالاسم. أي كائن له الخصائص المطلوبة يُقبل:

```ts
interface Named {
  name: string;
}

function hello(x: Named) {
  return `أهلاً ${x.name}`;
}

const product = { name: "ساعة", price: 300 };
console.log(hello(product));
```

```output
أهلاً ساعة
```

`product` لم يُعرّف كـ `Named`، لكنه يملك `name: string`، فقُبل. (الخصائص الزائدة ممنوعة فقط عند كتابة الكائن مباشرة في نفس المكان.)

## ملخص الدرس

- `interface` تصف شكل كائن: خصائصه وأنواعها وطرقه.
- TypeScript ترفض الخصائص الناقصة، والزائدة عند الكتابة المباشرة.
- `extends` لتوسيع واجهة من أخرى.
- الكتابة هيكلية: الشكل هو المهم وليس الاسم.

3. اكتب دالة `describe(book: Book): string` تُرجع `X - Y (N صفحة)`.

الكود في الأسفل جاهز.

~~~starter

const digital: EBook = { title: "مدن الملح", author: "عبدالرحمن منيف", pages: 600, sizeMB: 4 };

  title: string;
  author: string;
  pages: number;

}

const paper: Book = { title: "الأيام", author: "طه حسين", pages: 180 };
const digital: EBook = { title: "مدن الملح", author: "عبدالرحمن منيف", pages: 600, sizeMB: 4 };

console.log(describe(paper));
console.log(describe(digital));
console.log(`${digital.sizeMB} MB`);
~~~

## اسم لأي نوع

`type` تعطي اسماً لأي نوع، وليس الكائنات فقط:

```ts
type ID = number;
type Name = string;
type Coordinates = [number, number];
type Product = {
  id: ID;
  name: Name;
  location: Coordinates;
};

const p: Product = { id: 7, name: "مكتب", location: [21.4, 39.8] };
console.log(p.name, p.location[0]);
```

```output
مكتب 21.4
```

## أنواع الاتحاد: أكثر من احتمال

القوة الحقيقية لـ `type` تظهر مع **الاتحاد (Union)** بالعلامة `|`:

```ts
type Status = "loading" | "success" | "error";
type IdValue = number | string;

let state: Status = "loading";
state = "success";

function show(id: IdValue) {
  console.log(`المعرّف: ${id}`);
}
show(42);
show("A-17");

state = "done";
```

```output
ERR: line 13: Type '"done"' is not assignable to type 'Status'.
```

`Status` لا يقبل إلا ثلاث قيم محددة. أي قيمة أخرى، حتى لو كانت نصاً، تُرفض. (الوحدة الرابعة كلها عن الأنواع المركبة.)

## أنواع الدوال

```ts
type Formatter = (value: number) => string;
type Callback = () => void;

const toSAR: Formatter = v => `${v} ر.س`;
const toPercent: Formatter = v => `${(v * 100).toFixed(0)}%`;

function apply(values: number[], fmt: Formatter): string[] {
  return values.map(fmt);
}

console.log(apply([10, 25], toSAR));
console.log(apply([0.15, 0.5], toPercent));
```

```output
["10 ر.س","25 ر.س"]
["15%","50%"]
```

## دمج الأنواع: &

```ts
type HasId = { id: number };
type Timestamps = { createdAt: string; updatedAt: string };
type Post = HasId & Timestamps & { title: string };

const post: Post = {
  id: 1,
  title: "مقال جديد",
  createdAt: "2025-01-01",
  updatedAt: "2025-01-05"
};
console.log(post.title, post.updatedAt);
```

```output
مقال جديد 2025-01-05
```

`&` تجمع الأنواع: `Post` يجب أن يحتوي **كل** خصائص الثلاثة. وهذا يسمى **التقاطع (Intersection)**.

## ملخص الدرس

- `type Name = ...` اسم لأي نوع: بدائي، أو Tuple، أو كائن، أو دالة.
- `A | B` اتحاد: القيمة من أحد الأنواع.
- `A & B` تقاطع: القيمة تحتوي خصائص النوعين معاً.
- `type Fn = (x: number) => string` لأنواع الدوال.

--- exercise
1. عرّف `type Currency` يقبل فقط `"SAR"` أو `"USD"` أو `"EUR"`.
2. عرّف `type Money` ككائن فيه `amount` رقم و `currency` من نوع `Currency`.
3. عرّف `type Converter` كنوع دالة تستقبل `Money` وتُرجع `Money`.
4. اكتب `toUSD: Converter` تحوّل الريال إلى دولار بقسمته على `3.75`، وتُرجع الدولار كما هو، وأي عملة أخرى ترجعها كما هي.

~~~starter
// الأنواع والدالة هنا

const prices: Money[] = [
  { amount: 375, currency: "SAR" },
  { amount: 20, currency: "USD" }
];

for (const p of prices) {
  const r = toUSD(p);
  console.log(`${r.amount} ${r.currency}`);
}
~~~
~~~expected
100 USD

~~~
~~~solution
type Currency = "SAR" | "USD" | "EUR";

  amount: number;
  currency: Currency;
};

const toUSD: Converter = m =>
  m.currency === "SAR" ? { amount: m.amount / 3.75, currency: "USD" } : m;

const prices: Money[] = [
  { amount: 375, currency: "SAR" },
  { amount: 20, currency: "USD" }
];

for (const p of prices) {
  const r = toUSD(p);
  console.log(`${r.amount} ${r.currency}`);
}
~~~

## خصائص ليست دائماً موجودة

بعض الخصائص اختيارية بطبيعتها: رقم الهاتف، والصورة الشخصية، والملاحظات. نضيف `?` بعد اسم الخاصية:

```ts
interface Profile {
  name: string;
  bio?: string;
  website?: string;
}

const a: Profile = { name: "حمد" };
const b: Profile = { name: "شوق", bio: "مطورة واجهات" };

function card(p: Profile): string {
  return `${p.name} - ${p.bio ?? "بدون نبذة"}`;
}

console.log(card(a));
console.log(card(b));
```

```output
حمد - بدون نبذة
شوق - مطورة واجهات
```

الخاصية الاختيارية نوعها الفعلي `string | undefined`، لذلك يجب التعامل مع احتمال غيابها:

```ts
interface Profile {
  name: string;
  website?: string;
}

function domain(p: Profile): string {
  return p.website.replace("https://", "");
}
```

```output
ERR: line 7: 'p.website' is possibly 'undefined'.
```

## أدوات التعامل مع الاختياري

```ts
interface Settings {
  theme?: { color?: string };
}

const s1: Settings = {};
const s2: Settings = { theme: { color: "أزرق" } };

console.log(s1.theme?.color ?? "افتراضي");
console.log(s2.theme?.color ?? "افتراضي");
```

```output
افتراضي
أزرق
```

- `?.` (Optional Chaining): إذا كان ما قبلها `undefined` تتوقف وتُرجع `undefined` بدل الانهيار.
- `??` (Nullish Coalescing): قيمة بديلة إذا كان الطرف الأيسر `null` أو `undefined`.

## الخصائص للقراءة فقط: readonly

```ts
interface Order {
  readonly id: number;
  status: string;
}

const order: Order = { id: 501, status: "جديد" };
order.status = "مشحون";
console.log(order.status);
order.id = 999;
```

```output
ERR: line 9: Cannot assign to 'id' because it is a read-only property.
```

`readonly` تمنع تعديل الخاصية بعد إنشاء الكائن. مناسبة للمعرّفات والقيم التي يجب ألا تتغير.

> 💡 `readonly` فحص وقت الترجمة فقط، ولا يمنع التعديل وقت التشغيل. للمنع الكامل استخدم `Object.freeze()`.

## as const: كل شيء ثابت

```ts
const config = {
  apiUrl: "https://api.example.com",
  retries: 3
} as const;

config.retries = 5;
```

```output
ERR: line 6: Cannot assign to 'retries' because it is a read-only property.
```

`as const` تجعل كل الخصائص `readonly`، وتجعل كل قيمة نوعاً حرفياً.

## ملخص الدرس

- `prop?: type` خاصية اختيارية، ونوعها يشمل `undefined`.
- `?.` للوصول الآمن، و `??` للقيمة البديلة.
- `readonly prop` تمنع التعديل بعد الإنشاء.
- `as const` تجعل الكائن كله ثابتاً.

2. اكتب دالة `finalPrice(p: Product): number` تُرجع السعر بعد الخصم، وإذا لم يوجد خصم تعتبره `0` (استخدم `??`).

=== lesson
## سؤال يتكرر كثيراً

`interface` و `type` يستطيعان وصف شكل كائن. فأيهما تستخدم؟ الجواب المختصر: **كلاهما جيد للكائنات، والفروق قليلة**. لكن لنعرف الفروق بدقة.

## ما يستطيعه type فقط

```ts
type Id = number | string;
type Pair = [string, number];
type Handler = (e: string) => void;
type Status = "on" | "off";

const id: Id = "u-1";
const pair: Pair = ["عمر", 30];
const s: Status = "on";
console.log(id, pair, s);
```

```output
u-1 ["عمر",30] on
```

الاتحادات، والأنواع البدائية، والـ Tuples، والأنواع الحرفية: كلها لـ `type` فقط. `interface` تصف كائنات فقط.

## ما تستطيعه interface فقط: الدمج

إذا عرّفت `interface` بنفس الاسم مرتين، **تندمج** تلقائياً:

```ts
interface Window2 {
  title: string;
}
interface Window2 {
  width: number;
}

const w: Window2 = { title: "الرئيسية", width: 800 };
console.log(w.title, w.width);
```

```output
الرئيسية 800
```

هذا مفيد لتوسيع أنواع مكتبات خارجية (مثل إضافة خاصية لكائن `Window` في المتصفح). أما `type` فلا تسمح بالتكرار:

```ts
type Car = { brand: string };
type Car = { year: number };
```

```output
ERR: line 1: Duplicate identifier 'Car'. | line 2: Duplicate identifier 'Car'.
```

## التوسيع: extends مقابل &

النتيجة متشابهة جداً:

```ts
interface A1 { x: number }
interface B1 extends A1 { y: number }

type A2 = { x: number };
type B2 = A2 & { y: number };

const one: B1 = { x: 1, y: 2 };
const two: B2 = { x: 3, y: 4 };
console.log(one.x + one.y, two.x + two.y);
```

```output
3 7
```

الفرق الدقيق: `extends` تكشف التعارض فوراً برسالة خطأ واضحة، أما `&` فقد تنتج نوعاً مستحيلاً (`never`) بصمت عند التعارض.

## الملخص بالجدول

| | `interface` | `type` |
|---|---|---|
| وصف الكائنات | ✅ | ✅ |
| اتحادات وأنواع بدائية و Tuples | ❌ | ✅ |
| الدمج بتكرار الاسم | ✅ | ❌ |
| التوسيع | `extends` | `&` |
| رسائل الخطأ | أوضح غالباً | قد تكون أطول |

## القاعدة العملية

> 💡 اختر أسلوباً واحداً والتزم به في المشروع. شائع جداً: **`interface` لأشكال الكائنات** (المستخدم، والمنتج، وخصائص المكونات)، و **`type` لكل ما عداها** (الاتحادات، وأنواع الدوال، والأنواع المركبة). ووثائق TypeScript الرسمية تميل إلى `interface` للكائنات.

## ملخص الدرس

- كلاهما يصف الكائنات، والفرق في الحالات الخاصة.
- `type` وحده للاتحادات والبدائيات والـ Tuples.
- `interface` وحدها تندمج عند تكرار الاسم.
- المهم الاتساق داخل المشروع.

--- exercise
حوّل التعريفات بحيث يستخدم كل منها الأداة المناسبة:

1. `Role` اتحاد من `"admin"` و `"editor"` و `"viewer"`، لذلك يجب أن يكون `type`.
2. `Member` شكل كائن فيه `name` نص و `role` من نوع `Role`، اجعله `interface`.
3. `Admin` توسّع `Member` بخاصية `permissions` (مصفوفة نصوص)، استخدم `interface ... extends`.

حالياً الكود معطوب لأن `Role` معرّف كـ `interface`.

~~~starter
interface Role = "admin" | "editor" | "viewer";

type Member = {
  name: string;
  role: Role;
};

const admin: Admin = { name: "لانا", role: "admin", permissions: ["حذف", "نشر"] };
const editor: Member = { name: "سيف", role: "editor" };
console.log(`${admin.name}: ${admin.permissions.join("، ")}`);
console.log(`${editor.name}: ${editor.role}`);
~~~
~~~expected
لانا: حذف، نشر
سيف: editor
~~~
~~~solution
type Role = "admin" | "editor" | "viewer";

interface Member {
  name: string;
  role: Role;
}

interface Admin extends Member {
  permissions: string[];
}

const admin: Admin = { name: "لانا", role: "admin", permissions: ["حذف", "نشر"] };
const editor: Member = { name: "سيف", role: "editor" };
console.log(`${admin.name}: ${admin.permissions.join("، ")}`);
console.log(`${editor.name}: ${editor.role}`);
~~~
