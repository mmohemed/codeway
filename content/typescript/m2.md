## الأنواع البدائية

هي نفس أنواع JavaScript، لكن الآن نكتبها صراحة:

```ts
let title: string = "دورة TypeScript";
let lessons: number = 28;
let price: number = 49.99;
let published: boolean = true;
let nothing: null = null;
let notSet: undefined = undefined;
let big: bigint = 9007199254740993n;

console.log(title, lessons, price, published, nothing, notSet);
console.log(typeof big);
```

```output
دورة TypeScript 28 49.99 true null undefined
bigint
```

| النوع | يشمل |
|---|---|
| `string` | كل النصوص |
| `number` | كل الأرقام: صحيحة وعشرية وسالبة |
| `boolean` | `true` و `false` |
| `null` و `undefined` | غياب القيمة |
| `bigint` | أرقام صحيحة ضخمة، تنتهي بـ `n` |
| `symbol` | معرّفات فريدة |

> ⚠️ اكتب الأنواع بأحرف صغيرة: `string` وليس `String`. الكبيرة تشير لكائنات تغليف نادراً ما تحتاجها.

## الأنواع تمنع الخلط

```ts
let score: number = 90;
score = "مئة";
```

```output
ERR: سطر 2: Type 'string' is not assignable to type 'number'.
```

بعد تحديد النوع، لا يمكن وضع قيمة من نوع آخر في المتغير.

## أنواع الدوال

نحدد نوع كل معامل ونوع الإرجاع. والدالة التي لا تُرجع شيئاً نوعها `void`:

```ts
function formatPrice(amount: number, currency: string = "ريال"): string {
  return `${amount.toFixed(2)} ${currency}`;
}

function logMessage(msg: string): void {
  console.log(`[سجل] ${msg}`);
}

console.log(formatPrice(15));
console.log(formatPrice(9.5, "دولار"));
logMessage("تم الحفظ");
```

```output
15.00 ريال
9.50 دولار
[سجل] تم الحفظ
```

## المعاملات الاختيارية

العلامة `?` تجعل المعامل اختيارياً، فيكون نوعه داخل الدالة `string | undefined`:

```ts
function fullName(first: string, last?: string): string {
  return last ? `${first} ${last}` : first;
}

console.log(fullName("ماجد"));
console.log(fullName("ماجد", "السالم"));
```

```output
ماجد
ماجد السالم
```

## ملخص الدرس

- الأنواع البدائية: `string` و `number` و `boolean` و `null` و `undefined` و `bigint`.
- بعد تحديد النوع لا يمكن تغييره.
- `void` للدوال التي لا تُرجع شيئاً.
- `param?: type` لمعامل اختياري، و `param = value` لقيمة افتراضية.

## المصفوفات

نوع المصفوفة يُكتب بطريقتين متكافئتين:

```ts
const scores: number[] = [90, 85, 77];
const names: Array<string> = ["هدى", "سعد"];

scores.push(100);
console.log(scores, names);
```

```output
[90,85,77,100] ["هدى","سعد"]
```

والمصفوفة محددة النوع لا تقبل عناصر من نوع آخر:

```ts
const prices: number[] = [10, 20];
prices.push("ثلاثون");
```

```output
ERR: سطر 2: Argument of type 'string' is not assignable to parameter of type 'number'.
```

## مصفوفة من الكائنات

الشكل الأكثر شيوعاً في التطبيقات:

```ts
const products: { name: string; price: number }[] = [
  { name: "ساعة", price: 450 },
  { name: "حقيبة", price: 200 }
];

const cheap = products.filter(p => p.price < 300).map(p => p.name);
console.log(cheap);
```

```output
["حقيبة"]
```

لاحظ أننا لم نكتب نوع `p` في `filter` و `map`: عرفته TypeScript تلقائياً من نوع المصفوفة.

## الصفوف (Tuples): مصفوفة بطول وأنواع ثابتة

عندما يكون لكل موقع معنى ونوع محدد:

```ts
const point: [number, number] = [24.7, 46.7];
const entry: [string, number] = ["أحمد", 92];

const [studentName, grade] = entry;
console.log(`${studentName}: ${grade}`);
console.log(point[0] + point[1]);
```

```output
أحمد: 92
71.4
```

الـ Tuple مفيد لإرجاع عدة قيم من دالة. React Hook المشهور `useState` يُرجع Tuple: `[value, setValue]`.

```ts
function minMax(nums: number[]): [number, number] {
  return [Math.min(...nums), Math.max(...nums)];
}

const [low, high] = minMax([7, 2, 9, 4]);
console.log(low, high);
```

```output
2 9
```

## مصفوفات للقراءة فقط

```ts
const days: readonly string[] = ["السبت", "الأحد"];
days.push("الاثنين");
```

```output
ERR: سطر 2: Property 'push' does not exist on type 'readonly string[]'.
```

`readonly` يمنع أي تعديل على المصفوفة، وهو مفيد للبيانات الثابتة.

## ملخص الدرس

- `type[]` أو `Array<type>` لنوع المصفوفة.
- مصفوفة الكائنات: `{ name: string }[]`.
- الـ Tuple `[string, number]` طول ثابت ونوع لكل موقع.
- `readonly type[]` يمنع تعديل المصفوفة.

## عندما لا نعرف النوع

أحياناً لا نعرف نوع القيمة مسبقاً: بيانات من الخادم، أو مدخلات من المستخدم. لـ TypeScript ثلاثة أنواع خاصة لهذه الحالات، ولكل منها معنى مختلف تماماً.

## any: أطفئ الفحص

`any` تعني "لا تفحص هذه القيمة أبداً". يمكنك فعل أي شيء بها:

```ts
let data: any = "نص";
data = 42;
data.foo.bar();
```

```output
ERR: TypeError: Cannot read properties of undefined (reading 'bar')
```

مرّت كل الأسطر من المترجم، ثم انهار البرنامج عند التشغيل! `any` تُعيدك إلى JavaScript بلا حماية.

> ⚠️ تجنّب `any`. كل `any` في كودك ثغرة في حزام الأمان. استخدمها فقط مؤقتاً عند تحويل مشروع قديم.

## unknown: النسخة الآمنة من any

`unknown` تقبل أي قيمة أيضاً، لكنها **لا تسمح باستخدامها** حتى تتحقق من نوعها:

```ts
let input: unknown = "مرحباً";
console.log(input.toUpperCase());
```

```output
ERR: سطر 2: 'input' is of type 'unknown'.
```

يجب التحقق أولاً:

```ts
function describe(value: unknown): string {
  if (typeof value === "string") {
    return `نص طوله ${value.length}`;
  }
  if (typeof value === "number") {
    return `رقم، ضعفه ${value * 2}`;
  }
  if (Array.isArray(value)) {
    return `مصفوفة فيها ${value.length} عناصر`;
  }
  return "نوع آخر";
}

console.log(describe("مرحبا"));
console.log(describe(21));
console.log(describe([1, 2, 3]));
console.log(describe(true));
```

```output
نص طوله 5
رقم، ضعفه 42
مصفوفة فيها 3 عناصر
نوع آخر
```

بعد `typeof value === "string"` تعرف TypeScript أن `value` نص داخل الـ if، فتسمح بـ `.length`. هذا يسمى **التضييق (Narrowing)**، وسنتعمق فيه في الوحدة الرابعة.

> 💡 القاعدة: إذا لم تعرف النوع استخدم `unknown` وليس `any`. هكذا تُجبر نفسك على التحقق قبل الاستخدام.

## never: ما لا يحدث أبداً

`never` نوع لا توجد له أي قيمة. يظهر في حالتين:

**1. دالة لا تنتهي بشكل طبيعي** (ترمي خطأ دائماً):

```ts
function fail(message: string): never {
  throw new Error(message);
}

try {
  fail("حدث خطأ متوقع");
} catch (e) {
  console.log((e as Error).message);
}
```

```output
حدث خطأ متوقع
```

**2. التحقق من تغطية كل الحالات:**

```ts
type Status = "new" | "paid" | "shipped";

function label(s: Status): string {
  switch (s) {
    case "new": return "جديد";
    case "paid": return "مدفوع";
    case "shipped": return "تم الشحن";
    default:
      const check: never = s;
      return check;
  }
}

console.log(label("paid"));
```

```output
مدفوع
```

إذا أضاف أحدهم حالة جديدة `"cancelled"` للنوع ونسي معالجتها، يصل `s` إلى `default` بنوع `"cancelled"` الذي لا يمكن وضعه في `never`، فيظهر **خطأ ترجمة** يذكّره بالمعالجة.

## مقارنة سريعة

| النوع | يقبل أي قيمة؟ | يمكن استخدامه مباشرة؟ |
|---|---|---|
| `any` | نعم | نعم، دون أي فحص (خطير) |
| `unknown` | نعم | لا، بعد التحقق من النوع فقط |
| `never` | لا شيء | يمثل المستحيل |

## ملخص الدرس

- `any` يلغي الفحص فتجنّبه.
- `unknown` آمن: يقبل أي شيء لكن يتطلب التحقق قبل الاستخدام.
- `never` لدوال لا تنتهي، وللتأكد من تغطية كل الحالات.

function safeParse(value: unknown): number {

  if (typeof value === "string") {

    return Number.isNaN(n) ? 0 : n;
  }
  return 0;
}

console.log(safeParse(15));
console.log(safeParse("42"));
console.log(safeParse("abc"));
console.log(safeParse(null));
~~~

## TypeScript ذكية

لا تحتاج كتابة النوع في كل مكان. في أغلب الحالات **تستنتج** TypeScript النوع من القيمة:

```ts
let city = "جدة";
let count = 10;
let active = true;
let tags = ["ts", "js"];

city = 5;
```

```output
ERR: سطر 6: Type 'number' is not assignable to type 'string'.
```

لم نكتب أي نوع، ومع ذلك عرفت TypeScript أن `city` نص، فرفضت وضع رقم فيه. مرّر الفأرة فوق أي متغير في VS Code وسترى نوعه المستنتج.

## استنتاج نوع الإرجاع

```ts
function add(a: number, b: number) {
  return a + b;
}

function greet(name: string) {
  return `أهلاً ${name}`;
}

const sum = add(2, 3);
const message = greet("رنا");
console.log(sum.toFixed(1), message.toUpperCase());
```

```output
5.0 أهلاً رنا
```

TypeScript عرفت أن `add` تُرجع `number` و `greet` تُرجع `string`، فسمحت بـ `toFixed` و `toUpperCase`.

## const مقابل let

```ts
let a = "مرحبا";
const b = "مرحبا";

let direction: "يمين" | "يسار" = "يمين";
const fixed = "يسار";
direction = fixed;
console.log(direction);
```

```output
يسار
```

- `let a = "مرحبا"` نوعه `string`، لأن قيمته قد تتغير لأي نص.
- `const b = "مرحبا"` نوعه الحرفي `"مرحبا"` بالضبط، لأنه لن يتغير أبداً.

لهذا قُبل إسناد `fixed` إلى `direction`: نوعه الحرفي `"يسار"` من القيم المسموحة. (سنتعلم الأنواع الحرفية في الوحدة الرابعة.)

## الاستنتاج من السياق

```ts
const prices = [100, 250, 80];

prices.forEach(p => {
  console.log(p.toFixed(2));
});
```

```output
100.00
250.00
80.00
```

لم نكتب نوع `p`، لكن TypeScript تعرف أنه `number` لأنه عنصر من `number[]`.

## متى تكتب النوع بنفسك؟

| اكتب النوع | دع TypeScript تستنتج |
|---|---|
| معاملات الدوال (إلزامي في strict) | المتغيرات المهيأة بقيمة واضحة |
| نوع إرجاع الدوال العامة والمهمة | المتغيرات المحلية الصغيرة |
| المتغيرات التي تبدأ فارغة: `let users: User[] = []` | معاملات الـ callbacks مثل `map(x => ...)` |
| عندما يكون الاستنتاج أوسع مما تريد | |

> 💡 لا تكتب أنواعاً واضحة بلا داعٍ مثل `const count: number = 5`. الكود الأنظف يترك الاستنتاج يعمل حيث يكفي.

## المصفوفة الفارغة: الخطأ يظهر بعيداً عن سببه

المصفوفة الفارغة لا تكشف نوعها. في الوضع الصارم تراقب TypeScript ما تضيفه إليها وتبني نوعها تدريجياً:

```ts
const items = [];
items.push("قلم");
items.push(5);
const first: string = items[0];
console.log(first);
```

```output
ERR: سطر 4: Type 'string | number' is not assignable to type 'string'.   Type 'number' is not assignable to type 'string'.
```

السبب الحقيقي هو `push(5)` في السطر الثالث، لكن الخطأ ظهر في السطر الرابع، لأن TypeScript استنتجت أن المصفوفة "نصوص وأرقام" وقبلت الإضافة. مع مصفوفة تُملأ في أماكن كثيرة، قد يظهر الخطأ في ملف آخر تماماً! الحل أن تعلن نيتك من البداية:

```ts
const items: string[] = [];
items.push("قلم");
items.push(5);
```

```output
ERR: سطر 3: Argument of type 'number' is not assignable to parameter of type 'string'.
```

الآن يظهر الخطأ في مكان سببه بالضبط.

## ملخص الدرس

- TypeScript تستنتج الأنواع من القيم ومن السياق.
- `let` تستنتج نوعاً عاماً، و `const` تستنتج النوع الحرفي.
- اكتب أنواع معاملات الدوال، وحدد نوع المصفوفات التي تبدأ فارغة حتى يظهر الخطأ في مكان سببه، ودع الباقي للاستنتاج.
