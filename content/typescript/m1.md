## JavaScript مع حزام أمان

**TypeScript** هي JavaScript مضافاً إليها **نظام أنواع**. كل كود JavaScript صحيح هو كود TypeScript صحيح، لكن TypeScript تسمح لك بأن تصف **نوع** كل قيمة: هل هي رقم؟ نص؟ كائن بخصائص معينة؟ ثم تفحص كودك **قبل التشغيل** وتنبهك للأخطاء.

طورتها Microsoft عام 2012، واليوم تُستخدم في معظم المشاريع الاحترافية: VS Code نفسه، و Slack، و Airbnb، وأغلب مشاريع React و Angular و Node.js الحديثة.

## المشكلة التي تحلها

في JavaScript هذا الكود يعمل، لكنه يعطي نتيجة خاطئة بصمت:

```js-error
function total(price, qty) {
  return price * qty;
}
total("100", 2);      // 200 بالصدفة
total({ price: 100 }, 2); // NaN، ولن تعرف إلا عندما يشتكي المستخدم
```

في TypeScript نصف الأنواع، فيُكتشف الخطأ فوراً:

```ts
function total(price: number, qty: number): number {
  return price * qty;
}

console.log(total(100, 2));
console.log(total("100", 2));
```

```output
ERR: سطر 6: Argument of type 'string' is not assignable to parameter of type 'number'.
```

لاحظ أن الكود **لم يُشغَّل أصلاً**: TypeScript رفضته وأخبرتك بالسطر والسبب. في المحرر الحقيقي يظهر هذا الخطأ كخط أحمر **أثناء الكتابة**.

## ماذا تكسب؟

| الميزة | الشرح |
|---|---|
| **اكتشاف الأخطاء مبكراً** | أخطاء كثيرة تظهر في المحرر بدل ظهورها للمستخدم |
| **إكمال تلقائي ذكي** | المحرر يعرف خصائص كل كائن فيقترحها عليك |
| **توثيق حي** | الأنواع تشرح ما تتوقعه الدالة وما تُرجعه |
| **إعادة هيكلة آمنة** | غيّر اسم خاصية فيدلك المحرر على كل مكان يجب تعديله |
| **عمل الفريق** | الكود الكبير يصبح مفهوماً لمن لم يكتبه |

## كيف تعمل؟

المتصفحات و Node.js لا تفهم TypeScript مباشرة. لذلك هناك خطوة **ترجمة (Compile)**:

1. تكتب ملف `app.ts`.
2. مترجم TypeScript (`tsc`) **يفحص الأنواع**.
3. ثم **يحذف الأنواع** وينتج ملف `app.js` عادياً يعمل في أي مكان.

الأنواع موجودة وقت الكتابة فقط، ولا أثر لها عند التشغيل.

> 💡 محرر CodeWay يحتوي مترجم TypeScript الرسمي نفسه: يفحص كودك بوضع `strict` (الأكثر صرامة)، ثم يشغّل الناتج. وهو يعمل دون إنترنت.

## ملخص الدرس

- TypeScript هي JavaScript + أنواع.
- الأخطاء تُكتشف قبل التشغيل، مع إكمال تلقائي وتوثيق أفضل.
- الكود يُترجم إلى JavaScript عادي، والأنواع تختفي عند التشغيل.

## إعداد مشروع TypeScript

في هذه الدورة لا تحتاج أي تثبيت. لكن في مشروعك الحقيقي على جهازك تحتاج **Node.js** أولاً، ثم:

```text
npm install --save-dev typescript
npx tsc --init
```

- الأمر الأول يثبت TypeScript في المشروع.
- الثاني ينشئ ملف الإعدادات `tsconfig.json`.

## ملف tsconfig.json

هو قلب أي مشروع TypeScript، ويحدد كيف يعمل المترجم:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "strict": true,
    "outDir": "dist",
    "rootDir": "src",
    "noUncheckedIndexedAccess": true
  },
  "include": ["src"]
}
```

| الخيار | وظيفته |
|---|---|
| `target` | إصدار JavaScript الناتج |
| `module` | نظام الوحدات (import و export) |
| `strict` | **أهم خيار**: يفعّل كل الفحوص الصارمة |
| `outDir` و `rootDir` | أين الملفات المصدرية وأين يوضع الناتج |
| `include` | الملفات التي يترجمها |

## الوضع الصارم strict

`strict: true` يفعّل مجموعة فحوص، أهمها:

- **`noImplicitAny`**: كل معامل يجب أن يكون له نوع معروف.
- **`strictNullChecks`**: لا يمكن استخدام قيمة قد تكون `null` أو `undefined` دون فحص.

```ts
function double(n) {
  return n * 2;
}
console.log(double(4));
```

```output
ERR: سطر 1: Parameter 'n' implicitly has an 'any' type.
```

بدون نوع للمعامل `n`، لا تعرف TypeScript ما هو، فتعتبره ضمنياً `any` (أي شيء)، والوضع الصارم يرفض ذلك. الحل كتابة النوع:

```ts
function double(n: number) {
  return n * 2;
}
console.log(double(4));
```

```output
8
```

> 💡 ابدأ كل مشروع جديد بـ `strict: true`. تحويله لاحقاً في مشروع كبير مؤلم جداً.

## من الكتابة إلى التشغيل

لنفهم ماذا يحدث بالضبط عندما يترجم المترجم ملفك. هذا كود TypeScript:

```ts
type Product = {
  name: string;
  price: number;
};

const items: Product[] = [
  { name: "قلم", price: 5 },
  { name: "دفتر", price: 12 }
];

const total: number = items.reduce((sum, item) => sum + item.price, 0);
console.log(`الإجمالي: ${total}`);
```

```output
الإجمالي: 17
```

وهذا ما ينتجه المترجم (JavaScript):

```js
const items = [
  { name: "قلم", price: 5 },
  { name: "دفتر", price: 12 }
];

const total = items.reduce((sum, item) => sum + item.price, 0);
console.log(`الإجمالي: ${total}`);
```

```output
الإجمالي: 17
```

النوع `Product` اختفى تماماً، وكذلك `: number` و `: Product[]`. الكود الناتج هو JavaScript الذي تعرفه.

## تعليقات الأنواع (Type Annotations)

الصيغة دائماً: **اسم ثم نقطتان ثم النوع**:

```ts
let city: string = "الرياض";
let population: number = 7_000_000;
let isCapital: boolean = true;

function area(width: number, height: number): number {
  return width * height;
}

console.log(city, population, isCapital, area(4, 5));
```

```output
الرياض 7000000 true 20
```

- `let city: string` نوع المتغير.
- `(width: number, ...)` نوع كل معامل.
- `): number` بعد الأقواس: نوع ما تُرجعه الدالة.
- `7_000_000` الشرطة السفلية فاصل للقراءة فقط، والرقم هو 7000000.

## أخطاء شائعة يكتشفها المترجم

```ts
const user = { name: "فارس", email: "faris@mail.com" };
console.log(user.emial);
```

```output
ERR: سطر 2: Property 'emial' does not exist on type '{ name: string; email: string; }'. Did you mean 'email'?
```

خطأ إملائي في اسم الخاصية. JavaScript تُرجع `undefined` بصمت، أما TypeScript فتكتشفه وتقترح الاسم الصحيح.

```ts
function getLength(text: string) {
  return text.length;
}
console.log(getLength(null));
```

```output
ERR: سطر 4: Argument of type 'null' is not assignable to parameter of type 'string'.
```

تمرير `null` لدالة تتوقع نصاً. هذا الخطأ من أشهر أسباب انهيار التطبيقات، والوضع الصارم يمنعه.

## ملخص الدرس

- المترجم يفحص الأنواع ثم يحذفها، فينتج JavaScript عادياً.
- الصيغة: `name: type` للمتغيرات والمعاملات، و `): type` لنوع الإرجاع.
- TypeScript تكتشف الأخطاء الإملائية في الخصائص وتمرير `null` حيث لا يجوز.
