## استعلام داخل استعلام

**الاستعلام الفرعي (Subquery)** استعلام كامل نضعه داخل استعلام آخر بين قوسين. نستخدمه عندما نحتاج نتيجة استعلام لنبني عليها استعلاماً آخر.

سؤال: "ما المنتجات التي سعرها أعلى من متوسط الأسعار؟" نحتاج أولاً معرفة المتوسط، ثم المقارنة به:

```sql
SELECT name, price
FROM products
WHERE price > (SELECT AVG(price) FROM products)
ORDER BY price DESC;
```

```output
name | price
لابتوب | 3500
ساعة ذكية | 900
```

يُنفَّذ الاستعلام الداخلي أولاً فيُرجع `579.5`، ثم يكمل الخارجي كأننا كتبنا `WHERE price > 579.5`. الميزة أن الاستعلام يبقى صحيحاً حتى لو تغيّرت الأسعار.

## استعلام فرعي يُرجع قائمة: IN

```sql
SELECT name, city
FROM customers
WHERE id IN (
  SELECT customer_id FROM orders WHERE status = 'قيد التنفيذ'
);
```

```output
name | city
سارة | جدة
عمر | الرياض
```

الاستعلام الداخلي أرجع قائمة أرقام العملاء، والخارجي اختار من هم ضمنها. و `NOT IN` تعطي العكس.

> ⚠️ احذر `NOT IN` إذا كانت القائمة قد تحتوي `NULL`: النتيجة تصبح فارغة دائماً! في هذه الحالة استخدم `NOT EXISTS`.

## EXISTS: هل يوجد صف واحد على الأقل؟

```sql
SELECT p.name
FROM products p
WHERE NOT EXISTS (
  SELECT 1 FROM order_items oi WHERE oi.product_id = p.id
);
```

```output
name
حقيبة
```

هذا **استعلام فرعي مترابط (Correlated)**: يستخدم `p.id` من الاستعلام الخارجي، فيُنفَّذ ذهنياً لكل منتج على حدة. `EXISTS` تتوقف عند أول صف تجده، فهي سريعة.

## استعلام فرعي في SELECT

يمكن وضع استعلام يُرجع قيمة واحدة كعمود:

```sql
SELECT c.name,
       (SELECT COUNT(*) FROM orders o WHERE o.customer_id = c.id) AS orders
FROM customers c
ORDER BY orders DESC, c.id
LIMIT 4;
```

```output
name | orders
أحمد | 3
سارة | 2
نورة | 2
خالد | 1
```

## استعلام فرعي في FROM

نتيجة أي استعلام هي جدول، فيمكن الاستعلام منها:

```sql
SELECT AVG(order_total) AS avg_order
FROM (
  SELECT order_id, SUM(quantity * unit_price) AS order_total
  FROM order_items
  GROUP BY order_id
) AS totals;
```

```output
avg_order
1171.5
```

حسبنا إجمالي كل طلب في الداخل، ثم متوسط الإجماليات في الخارج. هذا مستحيل باستعلام واحد بسيط لأنه "تجميع فوق تجميع".

## ملخص الدرس

- الاستعلام الفرعي استعلام بين قوسين داخل آخر.
- يُرجع قيمة واحدة للمقارنة، أو قائمة مع `IN`، أو جدولاً في `FROM`.
- `EXISTS` و `NOT EXISTS` لفحص وجود صفوف مرتبطة.
- احذر `NOT IN` مع القوائم التي قد تحتوي NULL.

## الاستعلامات الفرعية تصبح معقدة

عندما تتداخل الاستعلامات الفرعية، يصعب قراءة الاستعلام من الداخل للخارج. **تعبير الجدول المشترك (CTE)** يحل هذا: تعطي الاستعلام الفرعي **اسماً** في البداية، ثم تستخدمه كجدول عادي.

## صيغة WITH

```sql
WITH order_totals AS (
  SELECT order_id, SUM(quantity * unit_price) AS total
  FROM order_items
  GROUP BY order_id
)
SELECT order_id, total
FROM order_totals
WHERE total > 1000
ORDER BY total DESC;
```

```output
order_id | total
101 | 4000
107 | 3500
110 | 1060
```

يُقرأ من الأعلى للأسفل كقصة: "أولاً احسب إجماليات الطلبات، ثم اختر الكبيرة منها".

## عدة CTEs متتالية

نفصل بينها بفاصلة، وكل واحد يستطيع استخدام ما قبله:

```sql
WITH order_totals AS (
  SELECT o.customer_id, SUM(oi.quantity * oi.unit_price) AS total
  FROM orders o
  JOIN order_items oi ON oi.order_id = o.id
  WHERE o.status = 'مكتمل'
  GROUP BY o.id
),
customer_spending AS (
  SELECT customer_id,
         COUNT(*) AS orders,
         SUM(total) AS spent
  FROM order_totals
  GROUP BY customer_id
)
SELECT c.name, cs.orders, cs.spent
FROM customer_spending cs
JOIN customers c ON c.id = cs.customer_id
ORDER BY cs.spent DESC;
```

```output
name | orders | spent
أحمد | 3 | 5080
ليلى | 1 | 3500
نورة | 2 | 1245
سارة | 1 | 450
```

ثلاث خطوات واضحة، كل منها باسم يشرح نفسه. هذا أسلوب محللي البيانات المحترفين: تقسيم المشكلة الكبيرة إلى خطوات صغيرة مسماة.

## CTE أم استعلام فرعي؟

| CTE | استعلام فرعي |
|---|---|
| يُقرأ من الأعلى للأسفل | يُقرأ من الداخل للخارج |
| يمكن استخدامه أكثر من مرة في نفس الاستعلام | يجب تكراره |
| اسم يوثّق الهدف | بلا اسم |
| أفضل للاستعلامات الطويلة | مناسب للحالات القصيرة |

## CTE العودي (Recursive)

ميزة متقدمة وقوية: CTE يستدعي نفسه. مثالي للبيانات الهرمية مثل شجرة الموظفين:

```sql
WITH RECURSIVE chain AS (
  SELECT id, name, manager_id, 0 AS level
  FROM employees
  WHERE manager_id IS NULL

  UNION ALL

  SELECT e.id, e.name, e.manager_id, chain.level + 1
  FROM employees e
  JOIN chain ON e.manager_id = chain.id
)
SELECT level, name
FROM chain
ORDER BY level, id;
```

```output
level | name
0 | منصور
1 | ريم
1 | سلطان
1 | جود
2 | ياسر
2 | دانة
2 | لمى
2 | بدر
```

1. **الجزء الأساسي:** المدير الأعلى (مستوى 0).
2. **الجزء العودي:** من مديرهم في النتيجة السابقة، فيصبحون المستوى التالي.
3. يتكرر حتى لا يوجد صفوف جديدة.

ويُستخدم أيضاً لتوليد سلاسل أرقام وتواريخ:

```sql
WITH RECURSIVE nums(n) AS (
  SELECT 1
  UNION ALL
  SELECT n + 1 FROM nums WHERE n < 5
)
SELECT n, n * n AS square FROM nums;
```

```output
n | square
1 | 1
2 | 4
3 | 9
4 | 16
5 | 25
```

## ملخص الدرس

- `WITH اسم AS (استعلام)` يعطي استعلاماً فرعياً اسماً نستخدمه كجدول.
- يمكن تعريف عدة CTEs مفصولة بفواصل، وكل واحد يستخدم ما قبله.
- `WITH RECURSIVE` للبيانات الهرمية وتوليد السلاسل.

## الشروط داخل الاستعلام

`CASE` هي "if/else" في SQL: تُرجع قيمة حسب شروط، وتُستخدم داخل `SELECT` أو `ORDER BY` أو حتى داخل دوال التجميع.

## الصيغة

```sql
SELECT name, price,
       CASE
         WHEN price >= 1000 THEN 'فاخر'
         WHEN price >= 200 THEN 'متوسط'
         ELSE 'اقتصادي'
       END AS segment
FROM products
ORDER BY price DESC;
```

```output
name | price | segment
لابتوب | 3500 | فاخر
ساعة ذكية | 900 | متوسط
نظارة | 350 | متوسط
حذاء رياضي | 300 | متوسط
سماعة | 250 | متوسط
حقيبة | 180 | اقتصادي
قميص | 120 | اقتصادي
شاحن | 80 | اقتصادي
كتاب طبخ | 70 | اقتصادي
رواية | 45 | اقتصادي
```

- تُفحص الشروط **بالترتيب**، وأول شرط صحيح يُستخدم.
- `ELSE` للحالة الافتراضية. بدونها تكون النتيجة `NULL` إذا لم يتحقق أي شرط.
- `END` تغلق التعبير، ثم نعطيه اسماً بـ `AS`.

## الصيغة المختصرة

عند مقارنة عمود واحد بقيم محددة:

```sql
SELECT id,
       CASE status
         WHEN 'مكتمل' THEN '✅'
         WHEN 'ملغي' THEN '❌'
         ELSE '⏳'
       END AS icon
FROM orders
WHERE id <= 106;
```

```output
id | icon
101 | ✅
102 | ✅
103 | ✅
104 | ❌
105 | ✅
106 | ⏳
```

## CASE مع التجميع: الجداول المحورية

من أقوى الاستخدامات: عدّ أو جمع حسب فئات في صف واحد:

```sql
SELECT
  COUNT(*) AS total,
  SUM(CASE WHEN status = 'مكتمل' THEN 1 ELSE 0 END) AS completed,
  SUM(CASE WHEN status = 'ملغي' THEN 1 ELSE 0 END) AS cancelled,
  SUM(CASE WHEN status = 'قيد التنفيذ' THEN 1 ELSE 0 END) AS pending
FROM orders;
```

```output
total | completed | cancelled | pending
10 | 7 | 1 | 2
```

ومع GROUP BY نحصل على جدول محوري كامل:

```sql
SELECT department,
       SUM(CASE WHEN salary >= 12000 THEN 1 ELSE 0 END) AS senior,
       SUM(CASE WHEN salary < 12000 THEN 1 ELSE 0 END) AS junior
FROM employees
GROUP BY department
ORDER BY department;
```

```output
department | senior | junior
الإدارة | 1 | 0
التقنية | 3 | 0
الدعم | 0 | 1
المبيعات | 1 | 2
```

## CASE في الترتيب المخصص

ترتيب الحالات حسب أهميتها وليس أبجدياً:

```sql
SELECT id, status
FROM orders
ORDER BY CASE status
           WHEN 'قيد التنفيذ' THEN 1
           WHEN 'مكتمل' THEN 2
           ELSE 3
         END, id
LIMIT 4;
```

```output
id | status
106 | قيد التنفيذ
108 | قيد التنفيذ
101 | مكتمل
102 | مكتمل
```

## دوال مختصرة مرتبطة

| الدالة | تعادل |
|---|---|
| `COALESCE(a, b)` | أول قيمة ليست NULL |
| `NULLIF(a, b)` | NULL إذا تساوتا، وإلا a |
| `IIF(cond, a, b)` في SQLite و SQL Server | CASE بشرط واحد |

```sql
SELECT name, COALESCE(city, 'غير محدد') AS city
FROM customers
WHERE id >= 7;
```

```output
name | city
عمر | الرياض
هند | غير محدد
```

## ملخص الدرس

- `CASE WHEN شرط THEN قيمة ... ELSE قيمة END` تُرجع قيمة حسب الشروط بالترتيب.
- `SUM(CASE WHEN ... THEN 1 ELSE 0 END)` لعدّ الفئات في أعمدة (جدول محوري).
- يمكن استخدام CASE في ORDER BY لترتيب مخصص.
- `COALESCE` لاستبدال NULL بقيمة افتراضية.

(التواريخ نصوص بصيغة YYYY-MM-DD، فالمقارنة `hire_date < '2021-01-01'` تعمل بشكل صحيح.)
