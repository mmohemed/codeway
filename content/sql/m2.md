## SELECT: اختر ما تريد رؤيته

`SELECT` هي أهم عبارة في SQL، وأكثرها استخداماً. صيغتها الأساسية:

```sql-error
SELECT الأعمدة
FROM الجدول;
```

## كل الأعمدة بـ *

```sql
SELECT * FROM customers;
```

```output
id | name | city | email | joined
1 | أحمد | الرياض | ahmed@mail.com | 2024-01-15
2 | سارة | جدة | sara@mail.com | 2024-02-20
3 | خالد | الرياض | khaled@mail.com | 2024-03-05
4 | نورة | الدمام | noura@mail.com | 2024-03-18
5 | فهد | جدة | NULL | 2024-05-01
6 | ليلى | مكة | layla@mail.com | 2024-06-12
7 | عمر | الرياض | omar@mail.com | 2024-07-30
8 | هند | NULL | hind@mail.com | 2024-09-09
```

النجمة `*` تعني "كل الأعمدة". مفيدة للاستكشاف السريع، لكن في الكود الحقيقي **حدد الأعمدة التي تحتاجها فقط**، فهذا أسرع وأوضح.

## أعمدة محددة

```sql
SELECT name, city FROM customers;
```

```output
name | city
أحمد | الرياض
سارة | جدة
خالد | الرياض
نورة | الدمام
فهد | جدة
ليلى | مكة
عمر | الرياض
هند | NULL
```

ترتيب الأعمدة في النتيجة هو ترتيبك في الاستعلام، وليس ترتيبها في الجدول.

## تسمية الأعمدة بـ AS

`AS` تعطي العمود اسماً مستعاراً (Alias) في النتيجة:

```sql
SELECT name AS product, price AS price_sar
FROM products
LIMIT 3;
```

```output
product | price_sar
لابتوب | 3500
سماعة | 250
شاحن | 80
```

## الحسابات داخل SELECT

يمكنك إجراء عمليات حسابية على الأعمدة، وإنشاء أعمدة جديدة في النتيجة دون تغيير الجدول:

```sql
SELECT name,
       price,
       ROUND(price * 1.15, 2) AS price_with_tax,
       stock * price AS stock_value
FROM products
LIMIT 3;
```

```output
name | price | price_with_tax | stock_value
لابتوب | 3500 | 4025 | 42000
سماعة | 250 | 287.5 | 10000
شاحن | 80 | 92 | 0
```

العمليات المتاحة: `+` و `-` و `*` و `/` و `%`.

## دمج النصوص

في SQLite و PostgreSQL ندمج النصوص بـ `||`:

```sql
SELECT name || ' من ' || city AS info
FROM customers
LIMIT 3;
```

```output
info
أحمد من الرياض
سارة من جدة
خالد من الرياض
```

> 💡 في MySQL تستخدم الدالة `CONCAT(name, ' من ', city)` بدلاً من `||`. هذا من الفروق القليلة بين الأنظمة.

## دوال مفيدة

```sql
SELECT UPPER('sql') AS upper_text,
       LENGTH('مرحبا') AS len,
       ROUND(19.567, 1) AS rounded,
       ABS(-7) AS absolute;
```

```output
upper_text | len | rounded | absolute
SQL | 5 | 19.6 | 7
```

لاحظ أن `SELECT` يمكن استخدامها دون جدول أصلاً، كآلة حاسبة.

## ملخص الدرس

- `SELECT أعمدة FROM جدول` الصيغة الأساسية.
- `*` لكل الأعمدة، والأفضل تحديد الأعمدة المطلوبة.
- `AS` لتسمية الأعمدة في النتيجة.
- يمكن الحساب والدمج `||` واستخدام الدوال داخل SELECT.

## تصفية الصفوف

`SELECT` تحدد **الأعمدة**، و `WHERE` تحدد **الصفوف**: تعرض فقط الصفوف التي تحقق شرطاً.

```sql
SELECT name, price
FROM products
WHERE category = 'كتب';
```

```output
name | price
رواية | 45
كتاب طبخ | 70
```

## عوامل المقارنة

| العامل | المعنى |
|---|---|
| `=` | يساوي (علامة واحدة، وليس `==`) |
| `<>` أو `!=` | لا يساوي |
| `>` و `<` و `>=` و `<=` | أكبر وأصغر |

```sql
SELECT name, stock
FROM products
WHERE stock = 0;
```

```output
name | stock
شاحن | 0
حقيبة | 0
```

## دمج الشروط: AND و OR و NOT

```sql
SELECT name, category, price
FROM products
WHERE category = 'إلكترونيات' AND price < 1000;
```

```output
name | category | price
سماعة | إلكترونيات | 250
شاحن | إلكترونيات | 80
ساعة ذكية | إلكترونيات | 900
```

```sql
SELECT name, city
FROM customers
WHERE city = 'جدة' OR city = 'الدمام';
```

```output
name | city
سارة | جدة
نورة | الدمام
فهد | جدة
```

> ⚠️ `AND` تُنفَّذ قبل `OR`. عند الدمج بينهما استخدم الأقواس دائماً: `WHERE (a OR b) AND c`.

## BETWEEN: نطاق من القيم

```sql
SELECT name, price
FROM products
WHERE price BETWEEN 100 AND 300;
```

```output
name | price
سماعة | 250
قميص | 120
حذاء رياضي | 300
حقيبة | 180
```

`BETWEEN` تشمل الحدين، فهي تعادل `price >= 100 AND price <= 300`.

## IN: قائمة من القيم

```sql
SELECT id, status
FROM orders
WHERE id IN (101, 104, 108);
```

```output
id | status
101 | مكتمل
104 | ملغي
108 | قيد التنفيذ
```

أوضح بكثير من كتابة `id = 101 OR id = 104 OR id = 108`. ونقيضها `NOT IN`.

## LIKE: البحث بنمط

للبحث في النصوص بنمط جزئي:

- `%` تعني "أي عدد من الأحرف" (حتى صفر).
- `_` تعني "حرفاً واحداً بالضبط".

```sql
SELECT name, email
FROM customers
WHERE email LIKE 's%';
```

```output
name | email
سارة | sara@mail.com
```

```sql
SELECT name FROM products WHERE name LIKE '%ة%';
```

```output
name
سماعة
رواية
ساعة ذكية
حقيبة
نظارة
```

## التعامل مع NULL

لا يمكن مقارنة NULL بـ `=`، لأن NULL "غير معروف"، وأي مقارنة معه نتيجتها غير معروفة أيضاً. نستخدم `IS NULL` و `IS NOT NULL`:

```sql
SELECT name FROM customers WHERE email IS NULL;
SELECT name FROM customers WHERE email = NULL;
```

```output
name
فهد

name
```

الاستعلام الثاني لم يُرجع أي صف، رغم وجود عميل بلا بريد! هذا خطأ شائع جداً.

## ملخص الدرس

- `WHERE` تصفّي الصفوف حسب شرط.
- `=` للمساواة، و `<>` لعدم المساواة.
- `AND` و `OR` و `NOT` لدمج الشروط، والأقواس لتوضيح الأولوية.
- `BETWEEN` للنطاقات، و `IN` للقوائم، و `LIKE` مع `%` و `_` للأنماط.
- `IS NULL` وليس `= NULL`.

## ترتيب النتائج

بدون ترتيب صريح، **لا تضمن** قاعدة البيانات أي ترتيب للصفوف. إذا كان الترتيب مهماً، استخدم `ORDER BY`:

```sql
SELECT name, price
FROM products
ORDER BY price;
```

```output
name | price
رواية | 45
كتاب طبخ | 70
شاحن | 80
قميص | 120
حقيبة | 180
سماعة | 250
حذاء رياضي | 300
نظارة | 350
ساعة ذكية | 900
لابتوب | 3500
```

## تصاعدي وتنازلي

- `ASC` تصاعدي (الافتراضي): من الأصغر للأكبر، ومن أ إلى ي.
- `DESC` تنازلي: من الأكبر للأصغر.

```sql
SELECT name, salary
FROM employees
ORDER BY salary DESC;
```

```output
name | salary
منصور | 25000
ريم | 18000
دانة | 15500
ياسر | 14000
سلطان | 12000
لمى | 9500
بدر | 9500
جود | 8000
```

## الترتيب بأكثر من عمود

عندما تتساوى القيم في العمود الأول، يُستخدم الثاني للحسم:

```sql
SELECT name, category, price
FROM products
ORDER BY category, price DESC;
```

```output
name | category | price
نظارة | إكسسوارات | 350
حقيبة | إكسسوارات | 180
لابتوب | إلكترونيات | 3500
ساعة ذكية | إلكترونيات | 900
سماعة | إلكترونيات | 250
شاحن | إلكترونيات | 80
كتاب طبخ | كتب | 70
رواية | كتب | 45
حذاء رياضي | ملابس | 300
قميص | ملابس | 120
```

رُتبت التصنيفات أبجدياً، وداخل كل تصنيف رُتبت الأسعار تنازلياً.

## الترتيب بعمود محسوب

يمكن الترتيب بالاسم المستعار أو بأي تعبير:

```sql
SELECT name, price * stock AS stock_value
FROM products
ORDER BY stock_value DESC;
```

```output
name | stock_value
لابتوب | 42000
سماعة | 10000
ساعة ذكية | 4500
نظارة | 3500
قميص | 3000
رواية | 2700
حذاء رياضي | 2400
كتاب طبخ | 1050
شاحن | 0
حقيبة | 0
```

## LIMIT: عدد محدود من الصفوف

```sql
SELECT name, price
FROM products
ORDER BY price DESC
LIMIT 3;
```

```output
name | price
لابتوب | 3500
ساعة ذكية | 900
نظارة | 350
```

`ORDER BY` مع `LIMIT` هما معاً طريقة الإجابة عن أسئلة مثل "أغلى 3 منتجات" أو "أحدث 10 طلبات".

## OFFSET: تخطي صفوف (الصفحات)

```sql
SELECT id, order_date
FROM orders
ORDER BY order_date
LIMIT 3 OFFSET 3;
```

```output
id | order_date
104 | 2025-02-20
105 | 2025-03-02
106 | 2025-03-15
```

تخطينا أول 3 طلبات وأخذنا الثلاثة التالية. هكذا تُبنى **الصفحات (Pagination)** في المواقع: الصفحة رقم n تعني `LIMIT size OFFSET (n - 1) * size`.

> 💡 في SQL Server تُكتب `SELECT TOP 3 ...` بدلاً من `LIMIT`، وفي المعيار الحديث `FETCH FIRST 3 ROWS ONLY`. لكن `LIMIT` تعمل في PostgreSQL و MySQL و SQLite.

## ترتيب تنفيذ الاستعلام

نكتب الاستعلام بترتيب، لكن قاعدة البيانات تنفّذه بترتيب آخر:

1. `FROM` اختيار الجدول
2. `WHERE` تصفية الصفوف
3. `SELECT` اختيار الأعمدة وحسابها
4. `ORDER BY` الترتيب
5. `LIMIT` القص

لهذا يمكن استخدام الاسم المستعار في `ORDER BY`، لكن ليس في `WHERE` (في معظم الأنظمة)، لأن `WHERE` تُنفَّذ قبل أن يُنشأ الاسم.

## ملخص الدرس

- `ORDER BY عمود` للترتيب، و `DESC` للتنازلي.
- يمكن الترتيب بعدة أعمدة وبأعمدة محسوبة.
- `LIMIT n` لعدد محدود، و `OFFSET` للتخطي وبناء الصفحات.
- بدون ORDER BY لا يوجد ترتيب مضمون.

## إزالة التكرار

أحياناً تريد معرفة **القيم المختلفة** في عمود، وليس كل الصفوف. مثلاً: من أي مدن عملاؤنا؟

```sql
SELECT city FROM customers;
```

```output
city
الرياض
جدة
الرياض
الدمام
جدة
مكة
الرياض
NULL
```

المدن مكررة. `DISTINCT` تعرض كل قيمة **مرة واحدة**:

```sql
SELECT DISTINCT city FROM customers;
```

```output
city
الرياض
جدة
الدمام
مكة
NULL
```

لاحظ أن `NULL` ظهرت كقيمة مستقلة، فـ DISTINCT تعاملها كقيمة واحدة.

## DISTINCT مع عدة أعمدة

عندها تكون **التركيبة** هي الفريدة، وليس كل عمود وحده:

```sql
SELECT DISTINCT category, stock > 0 AS in_stock
FROM products
ORDER BY category;
```

```output
category | in_stock
إكسسوارات | 0
إكسسوارات | 1
إلكترونيات | 1
إلكترونيات | 0
كتب | 1
ملابس | 1
```

تظهر "إلكترونيات" مرتين لأن فيها منتجات متوفرة (1) وأخرى نفدت (0)، فهما تركيبتان مختلفتان. وفي SQLite نتيجة المقارنة رقم: `1` للصحيح و `0` للخطأ.

## عدّ القيم الفريدة

```sql
SELECT COUNT(DISTINCT city) AS cities,
       COUNT(DISTINCT category) AS categories
FROM customers, products;
```

```output
cities | categories
4 | 4
```

`COUNT(DISTINCT عمود)` تعدّ القيم المختلفة، وتتجاهل `NULL`. (استخدمنا جدولين في `FROM` هنا فقط لإظهار النتيجتين معاً، وسنتعلم الطريقة الصحيحة لدمج الجداول في وحدة الربط.)

## أمثلة على أسئلة عمل

```sql
SELECT DISTINCT status FROM orders;
SELECT DISTINCT department FROM employees ORDER BY department;
```

```output
status
مكتمل
ملغي
قيد التنفيذ

department
الإدارة
التقنية
الدعم
المبيعات
```

"ما حالات الطلبات الممكنة في نظامنا؟" و"ما الأقسام الموجودة؟" أسئلة تجيب عنها DISTINCT مباشرة.

> 💡 DISTINCT تحتاج من قاعدة البيانات مقارنة كل الصفوف، فهي مكلفة مع الجداول الضخمة. لا تضفها "احتياطاً"، بل عندما تحتاجها فعلاً.

## ملخص الدرس

- `SELECT DISTINCT عمود` تعرض كل قيمة مرة واحدة.
- مع عدة أعمدة تكون التركيبة هي الفريدة.
- `COUNT(DISTINCT عمود)` تعدّ القيم المختلفة وتتجاهل NULL.
