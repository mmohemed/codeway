## إضافة بيانات جديدة

حتى الآن كنا نقرأ البيانات فقط. الآن نتعلم تعديلها، بدءاً بإضافة صفوف جديدة بـ `INSERT`.

> 💡 تذكير: قاعدة بيانات التمرين تبدأ من جديد في كل تشغيل، فجرّب بحرية.

## إدخال صف واحد

```sql
INSERT INTO products (name, category, price, stock)
VALUES ('ماوس', 'إلكترونيات', 95, 30);

SELECT id, name, price, stock FROM products WHERE name = 'ماوس';
```

```output
id | name | price | stock
11 | ماوس | 95 | 30
```

- `INSERT INTO الجدول (الأعمدة)` تحدد أين نُدخل.
- `VALUES (...)` القيم بنفس ترتيب الأعمدة.
- لم نحدد `id`، فأعطته قاعدة البيانات تلقائياً الرقم التالي `11` لأنه مفتاح أساسي رقمي.

## دائماً حدد الأعمدة

يمكن حذف قائمة الأعمدة وإعطاء قيم لكل الأعمدة بالترتيب:

```sql-error
INSERT INTO customers VALUES (9, 'رياض', 'تبوك', 'riyad@mail.com', '2025-01-01');
```

لكن هذا هش: إذا أُضيف عمود جديد للجدول يوماً ما، سيفشل الاستعلام. **حدد الأعمدة دائماً**.

## الأعمدة غير المذكورة

تأخذ قيمتها **الافتراضية** (`DEFAULT`) إن وُجدت، وإلا `NULL`:

```sql
INSERT INTO products (name, price) VALUES ('ملصقات', 10);

SELECT name, category, price, stock FROM products WHERE id = 11;
```

```output
name | category | price | stock
ملصقات | NULL | 10 | 0
```

`category` أصبحت NULL، و `stock` أخذت الافتراضي `0` المعرّف في تصميم الجدول.

## إدخال عدة صفوف

```sql
INSERT INTO customers (name, city, email, joined) VALUES
  ('رياض', 'تبوك', 'riyad@mail.com', '2025-07-01'),
  ('شهد', 'أبها', 'shahd@mail.com', '2025-07-02');

SELECT id, name, city FROM customers WHERE id > 7;
```

```output
id | name | city
8 | هند | NULL
9 | رياض | تبوك
10 | شهد | أبها
```

إدخال عدة صفوف في عبارة واحدة أسرع بكثير من عبارات منفصلة.

## القيود تحمي البيانات

```sql
INSERT INTO customers (name, email) VALUES ('مكرر', 'sara@mail.com');
```

```output

ERR: UNIQUE constraint failed: customers.email
```

العمود `email` معرّف بـ `UNIQUE`، فرفضت قاعدة البيانات البريد المكرر. وكذلك `NOT NULL` يمنع إدخال صف بلا اسم. هذه **القيود** خط الدفاع الأول ضد البيانات الخاطئة، وسنتعلم تعريفها في الوحدة 7.

## الإدخال من استعلام

يمكن إدخال نتيجة SELECT مباشرة:

```sql
CREATE TABLE vip_customers (customer_id INTEGER, name TEXT);

INSERT INTO vip_customers (customer_id, name)
SELECT c.id, c.name
FROM customers c
WHERE (SELECT COUNT(*) FROM orders o WHERE o.customer_id = c.id) >= 2;

SELECT * FROM vip_customers;
```

```output
customer_id | name
1 | أحمد
2 | سارة
4 | نورة
```

## ملخص الدرس

- `INSERT INTO جدول (أعمدة) VALUES (قيم)` لإضافة صف.
- حدد الأعمدة دائماً، والأعمدة المحذوفة تأخذ DEFAULT أو NULL.
- يمكن إدخال عدة صفوف في عبارة واحدة، أو إدخال نتيجة SELECT.
- القيود مثل UNIQUE و NOT NULL ترفض البيانات المخالفة.

## تعديل البيانات الموجودة

`UPDATE` تغيّر قيم أعمدة في صفوف موجودة:

```sql
UPDATE products
SET price = 270
WHERE id = 2;

SELECT name, price FROM products WHERE id = 2;
```

```output
name | price
سماعة | 270
```

- `UPDATE الجدول` أي جدول نعدّل.
- `SET عمود = قيمة` ماذا نغيّر.
- `WHERE` **أي الصفوف** نعدّل.

## أخطر خطأ في SQL

> ⚠️ **`UPDATE` بدون `WHERE` يعدّل كل صفوف الجدول!** كتابة `UPDATE products SET price = 0;` تجعل كل المنتجات مجانية في لحظة. قبل تشغيل أي UPDATE على بيانات حقيقية، شغّل `SELECT` بنفس الـ WHERE أولاً لترى أي صفوف ستتأثر.

```sql
SELECT COUNT(*) AS will_change FROM products WHERE category = 'كتب';
```

```output
will_change
2
```

## تعديل عدة أعمدة وبقيم محسوبة

```sql
UPDATE products
SET price = price * 0.8,
    stock = stock + 10
WHERE category = 'كتب';

SELECT name, price, stock FROM products WHERE category = 'كتب';
```

```output
name | price | stock
رواية | 36 | 70
كتاب طبخ | 56 | 25
```

القيمة الجديدة يمكن أن تعتمد على القديمة: خصم 20% وزيادة المخزون 10 قطع.

## التعديل بشروط مركبة

```sql
UPDATE orders
SET status = 'متأخر'
WHERE status = 'قيد التنفيذ'
  AND order_date < '2025-04-01';

SELECT id, order_date, status FROM orders WHERE status IN ('متأخر', 'قيد التنفيذ');
```

```output
id | order_date | status
106 | 2025-03-15 | متأخر
108 | 2025-04-11 | قيد التنفيذ
```

## التعديل باستعلام فرعي

```sql
UPDATE products
SET stock = stock - (
  SELECT quantity FROM order_items oi
  WHERE oi.product_id = products.id AND oi.order_id = 108
)
WHERE id IN (SELECT product_id FROM order_items WHERE order_id = 108);

SELECT id, name, stock FROM products WHERE id IN (4, 5);
```

```output
id | name | stock
4 | قميص | 23
5 | حذاء رياضي | 7
```

خصمنا من مخزون كل منتج في الطلب 108 الكمية المطلوبة منه في هذا الطلب: القميص كان 25 والحذاء 8.

## ملخص الدرس

- `UPDATE جدول SET عمود = قيمة WHERE شرط` لتعديل صفوف موجودة.
- بدون WHERE يتعدّل كل الجدول، فاختبر الشرط بـ SELECT أولاً.
- يمكن تعديل عدة أعمدة، وبقيم محسوبة من القيم الحالية أو من استعلام فرعي.

## حذف الصفوف

`DELETE` تحذف صفوفاً من الجدول:

```sql
DELETE FROM order_items
WHERE order_id = 104;

SELECT COUNT(*) AS items_left FROM order_items;
```

```output
items_left
15
```

كان هناك 16 سطراً، وحذفنا سطر الطلب الملغي.

> ⚠️ مثل UPDATE تماماً: **`DELETE FROM جدول;` بدون WHERE يحذف كل الصفوف!** والحذف في قواعد البيانات الحقيقية غالباً لا يمكن التراجع عنه إلا من نسخة احتياطية.

## الحذف بشروط واستعلامات فرعية

حذف كل الطلبات الملغاة مع أسطرها:

```sql
DELETE FROM order_items
WHERE order_id IN (SELECT id FROM orders WHERE status = 'ملغي');

DELETE FROM orders
WHERE status = 'ملغي';

SELECT status, COUNT(*) AS orders FROM orders GROUP BY status ORDER BY orders DESC;
```

```output
status | orders
مكتمل | 7
قيد التنفيذ | 2
```

لاحظ الترتيب: حذفنا **الأسطر أولاً** ثم **الطلبات**. لو حذفنا الطلب أولاً لبقيت أسطره "يتيمة" تشير لطلب غير موجود. وسنرى في الوحدة القادمة كيف تمنع **المفاتيح الأجنبية** هذا تلقائياً.

## DELETE مقابل TRUNCATE مقابل DROP

| الأمر | ماذا يحذف | ملاحظة |
|---|---|---|
| `DELETE FROM t WHERE ...` | صفوفاً محددة | يمكن التحكم بالشرط |
| `DELETE FROM t` | كل الصفوف، والجدول يبقى | بطيء مع الجداول الضخمة |
| `TRUNCATE TABLE t` | كل الصفوف بسرعة | غير موجود في SQLite |
| `DROP TABLE t` | الجدول كاملاً مع بنيته | لا يبقى شيء |

```sql
CREATE TABLE logs (msg TEXT);
INSERT INTO logs VALUES ('a'), ('b');
DELETE FROM logs;
SELECT COUNT(*) AS rows_after_delete FROM logs;
DROP TABLE logs;
SELECT COUNT(*) AS tables_named_logs FROM sqlite_master WHERE name = 'logs';
```

```output
rows_after_delete
0

tables_named_logs
0
```

## الحذف الناعم (Soft Delete)

في التطبيقات الحقيقية كثيراً ما **لا نحذف** البيانات فعلياً، بل نضع علامة:

```sql
ALTER TABLE customers ADD COLUMN deleted_at TEXT;

UPDATE customers SET deleted_at = '2025-07-15' WHERE id = 8;

SELECT COUNT(*) AS active_customers FROM customers WHERE deleted_at IS NULL;
```

```output
active_customers
7
```

المزايا: يمكن استعادة البيانات، وتبقى السجلات القديمة (مثل الفواتير) سليمة، ونحتفظ بتاريخ الحذف. والثمن: تذكّر إضافة `WHERE deleted_at IS NULL` في الاستعلامات.

## ملخص الدرس

- `DELETE FROM جدول WHERE شرط` لحذف صفوف محددة.
- بدون WHERE يُحذف كل شيء، فاختبر بـ SELECT أولاً.
- احذف الصفوف التابعة قبل الأساسية.
- `DROP TABLE` يحذف الجدول نفسه، والحذف الناعم بديل آمن في التطبيقات.
