## المشكلة: العمليات الطويلة

التطبيقات تجلب البيانات من الإنترنت وتقرأ قواعد البيانات. في Android، إذا نفّذت عملية طويلة على **الخيط الرئيسي (Main Thread)** تتجمد الواجهة، وبعد 5 ثوانٍ يعرض النظام رسالة "التطبيق لا يستجيب".

الحل التقليدي كان **الخيوط (Threads)** والـ callbacks، وهي ثقيلة ومعقدة. Kotlin تقدم حلاً أنيقاً: **Coroutines**، وهي "مهام خفيفة" يمكن إيقافها مؤقتاً واستئنافها دون حجز خيط.

## أول coroutine

```kotlin
import kotlinx.coroutines.*

fun main() = runBlocking {
    launch {
        delay(300)
        println("3. انتهت المهمة الطويلة")
    }
    println("1. بدأت المهمة")
    println("2. البرنامج لا ينتظر")
}
```

```output
1. بدأت المهمة
2. البرنامج لا ينتظر
3. انتهت المهمة الطويلة
```

- `runBlocking { }` تشغّل coroutines في `main` وتنتظر انتهاءها (للأمثلة والاختبارات فقط، لا تستخدمها في التطبيقات).
- `launch { }` تبدأ coroutine جديدة تعمل بالتوازي.
- `delay(300)` توقف **هذه الـ coroutine فقط** 300 ملي ثانية، دون حجز الخيط.

## coroutines خفيفة جداً

```kotlin
import kotlinx.coroutines.*

fun main() = runBlocking {
    val jobs = List(10_000) {
        launch {
            delay(100)
        }
    }
    jobs.forEach { it.join() }
    println("انتهت ${jobs.size} مهمة")
}
```

```output
انتهت 10000 مهمة
```

عشرة آلاف coroutine تعمل في جزء من الثانية. لو أنشأت 10,000 خيط حقيقي لنفدت ذاكرة الجهاز.

## انتظار النتيجة: async و await

`launch` لا تُرجع نتيجة. عندما تحتاج نتيجة، استخدم `async`:

```kotlin
import kotlinx.coroutines.*

fun main() = runBlocking {
    val start = System.currentTimeMillis()

    val user = async { delay(300); "لينا" }
    val orders = async { delay(300); 4 }

    println("${user.await()} لديها ${orders.await()} طلبات")
    val elapsed = System.currentTimeMillis() - start
    println(if (elapsed < 500) "بالتوازي" else "بالتتابع")
}
```

```output
لينا لديها 4 طلبات
بالتوازي
```

العمليتان عملتا **بالتوازي**، فاستغرقتا 300 ملي ثانية تقريباً بدلاً من 600.

| الأداة | تُرجع | الاستخدام |
|---|---|---|
| `launch` | `Job` بلا نتيجة | "افعل هذا" |
| `async` | `Deferred<T>` مع `await()` | "احسب هذا وأعطني النتيجة" |

## Coroutines في Android

```kotlin-error
class ProductsViewModel : ViewModel() {
    fun load() {
        viewModelScope.launch {
            val products = repository.fetchProducts() // لا تجمّد الواجهة
            _state.value = UiState.Success(products)

```

`viewModelScope` نطاق يُلغي كل الـ coroutines تلقائياً عند إغلاق الشاشة، فلا تتسرب الذاكرة.

## ملخص الدرس

- Coroutines مهام خفيفة غير متزامنة لا تجمّد الواجهة.
- `launch` تبدأ مهمة بلا نتيجة، و `async` و `await` لمهمة بنتيجة.
- `delay` توقف الـ coroutine مؤقتاً دون حجز الخيط.
- `runBlocking` للأمثلة فقط، وفي Android يُستخدم `viewModelScope`.

## دوال قابلة للإيقاف

`suspend` كلمة تجعل الدالة **قابلة للإيقاف**: يمكنها استدعاء `delay` ودوال suspend أخرى، وتنتظر النتائج دون أن تحجز الخيط:

```kotlin
import kotlinx.coroutines.*

suspend fun fetchUser(id: Int): String {
    delay(200)
    return "مستخدم $id"
}

suspend fun fetchOrders(user: String): List<String> {
    delay(200)
    return listOf("طلب 1", "طلب 2")
}

fun main() = runBlocking {
    val user = fetchUser(7)
    val orders = fetchOrders(user)
    println("$user: ${orders.size} طلبات")
}
```

```output
مستخدم 7: 2 طلبات
```

لاحظ أن الكود **يُقرأ كأنه متزامن** من الأعلى للأسفل، بلا callbacks ولا تداخل. هذه أكبر ميزة للـ coroutines.

## القواعد

1. دالة `suspend` لا تُستدعى إلا من coroutine أو من دالة `suspend` أخرى.
2. الاستدعاء يبدو عادياً تماماً، دون `await`.

```kotlin
import kotlinx.coroutines.*

suspend fun load(): String {
    delay(100)
    return "بيانات"
}

fun main() {
    println(load())
}
```

```output
ERR: line 9: suspend function 'suspend fun load(): String' can only be called from a coroutine or another suspend function.
```

## معالجة الأخطاء

`try` و `catch` العادية تعمل بشكل طبيعي:

```kotlin
import kotlinx.coroutines.*

suspend fun login(password: String): String {
    delay(100)
    if (password != "1234") throw IllegalStateException("كلمة المرور خاطئة")
    return "مرحباً بك"
}

fun main() = runBlocking {
    for (p in listOf("0000", "1234")) {
        try {
            println(login(p))
        } catch (e: IllegalStateException) {
            println("فشل: ${e.message}")
        }
    }
}
```

```output
فشل: كلمة المرور خاطئة
مرحباً بك
```

## تبديل الخيط: withContext

```kotlin
import kotlinx.coroutines.*

suspend fun heavyCalculation(): Long = withContext(Dispatchers.Default) {
    (1..1_000_000L).sum()
}

fun main() = runBlocking {
    println("المجموع: ${heavyCalculation()}")
}
```

```output
المجموع: 500000500000
```

| Dispatcher | الاستخدام |
|---|---|
| `Dispatchers.Main` | تحديث الواجهة في Android |
| `Dispatchers.IO` | الشبكة وقواعد البيانات والملفات |
| `Dispatchers.Default` | الحسابات الثقيلة على المعالج |

النمط في Android: الـ ViewModel يعمل على Main، و Repository يستخدم `withContext(Dispatchers.IO)` للشبكة، فلا تتجمد الواجهة أبداً.

## المهلة الزمنية

```kotlin
import kotlinx.coroutines.*

suspend fun slowServer(): String {
    delay(2000)
    return "رد"
}

fun main() = runBlocking {
    val result = withTimeoutOrNull(500) { slowServer() }
    println(result ?: "انتهت المهلة، حاول لاحقاً")
}
```

```output
انتهت المهلة، حاول لاحقاً
```

## ملخص الدرس

- `suspend fun` دالة قابلة للإيقاف، تُستدعى من coroutine أو دالة suspend.
- الكود غير المتزامن يُقرأ كالمتزامن، دون callbacks.
- `try` و `catch` لمعالجة الأخطاء.
- `withContext(Dispatchers.IO)` لتبديل الخيط، و `withTimeoutOrNull` للمهلة.

suspend fun getPrice(productId: Int): Int {
    delay(100)
    if (productId != 1) throw IllegalArgumentException("منتج غير موجود")
    return 350
}

suspend fun createOrder(price: Int): Int {
    delay(100)
    return 9001
}

suspend fun placeOrder(productId: Int) {
    try {
        val price = getPrice(productId)
        println("السعر: $price")
        println("رقم الطلب: ${createOrder(price)}")
    } catch (e: IllegalArgumentException) {
        println("تعذر الطلب: ${e.message}")
    }
}

fun main() = runBlocking {
    placeOrder(1)
    placeOrder(7)
}
~~~

## تدفق من القيم

`suspend fun` تُرجع **قيمة واحدة**. لكن ماذا عن بيانات تصل **باستمرار**: رسائل الدردشة، وموقع GPS، وتحديثات قاعدة البيانات؟ هنا نستخدم **Flow**: تدفق غير متزامن من القيم.

## إنشاء Flow والاستماع له

```kotlin
import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*

fun countdown(from: Int): Flow<Int> = flow {
    for (i in from downTo 1) {
        delay(100)
        emit(i)
    }
}

fun main() = runBlocking {
    countdown(3).collect { println("$it...") }
    println("انطلق! 🚀")
}
```

```output
3...
2...
1...
انطلق! 🚀
```

- `flow { }` يبني التدفق، و `emit(value)` ترسل قيمة.
- `collect { }` تستمع وتستقبل كل قيمة عند وصولها.
- التدفق **بارد (Cold)**: لا يبدأ إلا عند `collect`.

## تحويل التدفقات

نفس دوال المجموعات تقريباً:

```kotlin
import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*

fun main() = runBlocking {
    (1..6).asFlow()
        .filter { it % 2 == 0 }
        .map { it * 10 }
        .collect { println(it) }

    val total = (1..6).asFlow().reduce { a, b -> a + b }
    println("المجموع: $total")

    val first = flowOf("أ", "ب", "ج").take(2).toList()
    println(first)
}
```

```output
20
40
60
المجموع: 21
[أ, ب]
```

## مثال واقعي: البحث أثناء الكتابة

```kotlin
import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*

fun main() = runBlocking {
    val typed = flowOf("ك", "كو", "كوت", "كوتل", "كوتلن")
    typed
        .filter { it.length >= 3 }
        .map { query -> "نتائج البحث عن «$query»" }
        .collect { println(it) }
}
```

```output
نتائج البحث عن «كوت»
نتائج البحث عن «كوتل»
نتائج البحث عن «كوتلن»
```

في التطبيقات الحقيقية يُضاف `debounce(300)` لانتظار توقف المستخدم عن الكتابة قبل إرسال الطلب.

## StateFlow: الحالة المشتركة

في تطبيقات Android الحديثة، الـ ViewModel يحمل حالة الشاشة في `StateFlow`، والواجهة تستمع لها وتعيد الرسم مع كل تغيير:

```kotlin
import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*

class CounterViewModel {
    private val _count = MutableStateFlow(0)
    val count: StateFlow<Int> = _count

    fun increment() {
        _count.value++
    }
}

fun main() = runBlocking {
    val vm = CounterViewModel()
    vm.increment()
    vm.increment()
    println("القيمة الحالية: ${vm.count.value}")
}
```

```output
القيمة الحالية: 2
```

- `MutableStateFlow` قابلة للتعديل داخل الـ ViewModel، و `StateFlow` للقراءة فقط من الخارج.
- في Compose تستمع الواجهة بـ `val count by vm.count.collectAsState()`.
