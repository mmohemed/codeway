## أصناف مختصرة جداً

في Kotlin يمكن تعريف صنف بخصائصه في سطر واحد:

```kotlin
class Product(val name: String, var price: Double, var stock: Int) {
    val isAvailable: Boolean
        get() = stock > 0

    fun sell(qty: Int) {
        if (qty > stock) {
            println("الكمية غير متوفرة من $name")
            return
        }
        stock -= qty
        println("بيع $qty من $name، المتبقي $stock")
    }
}

fun main() {
    val phone = Product("هاتف", 2200.0, 3)
    phone.sell(2)
    phone.sell(5)
    println(phone.isAvailable)
    phone.price = 1999.0
    println(phone.price)
}
```

```output
بيع 2 من هاتف، المتبقي 1
الكمية غير متوفرة من هاتف
true
1999.0
```

- `class Product(val name: String, ...)` المُنشئ الأساسي يعرّف الخصائص مباشرة.
- `val` خاصية للقراءة فقط، و `var` قابلة للتعديل.
- `get() = ...` خاصية محسوبة.
- لا نحتاج `new` لإنشاء كائن.

## كتلة init والتحقق

```kotlin
class Account(val owner: String, initialBalance: Double) {
    var balance = initialBalance
        private set

    init {
        require(initialBalance >= 0) { "الرصيد لا يمكن أن يكون سالباً" }
    }

    fun deposit(amount: Double) {
        if (amount > 0) balance += amount
    }
}

fun main() {
    val acc = Account("سعود", 100.0)
    acc.deposit(50.0)
    println("${acc.owner}: ${acc.balance}")
    try {
        Account("خطأ", -10.0)
    } catch (e: IllegalArgumentException) {
        println(e.message)
    }
}
```

```output
سعود: 150.0
الرصيد لا يمكن أن يكون سالباً
```

- `init { }` تُنفَّذ عند إنشاء الكائن، ومناسبة للتحقق.
- `require(condition) { message }` ترمي خطأ إذا لم يتحقق الشرط.
- `private set` تجعل القراءة متاحة للجميع والتعديل من داخل الصنف فقط.

## الوراثة: open

الأصناف في Kotlin **مغلقة افتراضياً**، فلا يمكن الوراثة منها إلا إذا أضفت `open`:

```kotlin
open class Animal(val name: String) {
    open fun speak() = "$name يصدر صوتاً"
}

class Cat(name: String) : Animal(name) {
    override fun speak() = "$name يقول مياو"
}

fun main() {
    val animals = listOf(Animal("حيوان"), Cat("مشمش"))
    animals.forEach { println(it.speak()) }
}
```

```output
حيوان يصدر صوتاً
مشمش يقول مياو
```

- `open class` تسمح بالوراثة، و `open fun` تسمح بإعادة التعريف.
- `: Animal(name)` الوراثة مع تمرير المعامل لمُنشئ الأب.
- `override` إلزامية عند إعادة التعريف.

## الواجهات

```kotlin
interface Payable {
    fun pay(amount: Double): Boolean
    fun receipt(amount: Double) = "تم دفع $amount"
}

class Card(private val limit: Double) : Payable {
    override fun pay(amount: Double) = amount <= limit
}

fun main() {
    val card = Card(500.0)
    if (card.pay(200.0)) println(card.receipt(200.0))
    println(card.pay(900.0))
}
```

```output
تم دفع 200.0
false
```

الواجهة في Kotlin يمكن أن تحتوي تنفيذاً افتراضياً لبعض الطرق، مثل `receipt`.

## ملخص الدرس

- `class Name(val a: Type, var b: Type)` يعرّف الصنف وخصائصه معاً.
- `init` للتحقق عند الإنشاء، و `private set` لحماية التعديل.
- الأصناف مغلقة افتراضياً، و `open` للسماح بالوراثة، و `override` لإعادة التعريف.
- الواجهات `interface` يمكن أن تحتوي تنفيذاً افتراضياً.

## أصناف للبيانات

كثير من الأصناف وظيفتها **حمل بيانات** فقط: مستخدم، ومنتج، ورد من خادم. Kotlin توفر لها **data class** التي تولّد تلقائياً كل ما تحتاجه:

```kotlin
data class User(val name: String, val age: Int, val city: String = "الرياض")

fun main() {
    val u1 = User("نوف", 28)
    val u2 = User("نوف", 28)
    println(u1)
    println(u1 == u2)
}
```

```output
User(name=نوف, age=28, city=الرياض)
true
```

بكلمة واحدة `data` حصلنا على:

- **`toString()`** مقروء: `User(name=نوف, age=28, city=الرياض)`.
- **`equals()`** يقارن المحتوى: `u1 == u2` صحيحة لأن البيانات متطابقة.
- **`hashCode()`** متوافق، فيعمل الكائن في `Set` و `Map` بشكل صحيح.
- **`copy()`** و **التفكيك**.

## مقارنة بالصنف العادي

```kotlin
class PlainUser(val name: String)
data class DataUser(val name: String)

fun main() {
    println(PlainUser("علي") == PlainUser("علي"))
    println(DataUser("علي") == DataUser("علي"))
    println(DataUser("علي"))
}
```

```output
false
true
DataUser(name=علي)
```

الصنف العادي يقارن **الهوية** (هل هما نفس الكائن في الذاكرة؟)، و data class تقارن **المحتوى**.

## copy: نسخة مع تعديل

```kotlin
data class Order(val id: Int, val status: String, val total: Double)

fun main() {
    val order = Order(101, "جديد", 250.0)
    val shipped = order.copy(status = "مشحون")
    println(order)
    println(shipped)
}
```

```output
Order(id=101, status=جديد, total=250.0)
Order(id=101, status=مشحون, total=250.0)
```

لم نعدّل الكائن الأصلي، بل أنشأنا نسخة جديدة. هذا أسلوب **البيانات غير القابلة للتعديل (Immutable)**، وهو أساس إدارة الحالة في Jetpack Compose: `state = state.copy(isLoading = false)`.

## التفكيك (Destructuring)

```kotlin
data class Point(val x: Int, val y: Int)

fun main() {
    val (x, y) = Point(3, 7)
    println("x = $x، y = $y")

    val points = listOf(Point(1, 2), Point(5, 6))
    for ((a, b) in points) println(a + b)
}
```

```output
x = 3، y = 7
3
11
```

## ملخص الدرس

- `data class` لأصناف البيانات، وتولّد `toString` و `equals` و `hashCode` و `copy` تلقائياً.
- `==` تقارن المحتوى في data class.
- `copy(prop = value)` تنشئ نسخة معدّلة دون تغيير الأصل.
- `val (a, b) = obj` لتفكيك الكائن.

## مجموعة مغلقة من الأنواع

**sealed class** (أو `sealed interface`) تحدد مجموعة **محدودة ومعروفة** من الأنواع الفرعية. المترجم يعرف كل الاحتمالات، فيتأكد أن `when` تعالجها جميعاً.

النمط الأشهر في تطبيقات Android: حالات الشاشة.

```kotlin
sealed class UiState {
    object Loading : UiState()
    data class Success(val items: List<String>) : UiState()
    data class Error(val message: String) : UiState()
}

fun render(state: UiState): String = when (state) {
    is UiState.Loading -> "⏳ جاري التحميل..."
    is UiState.Success -> "✅ ${state.items.size} عناصر: ${state.items.joinToString("، ")}"
    is UiState.Error -> "❌ ${state.message}"
}

fun main() {
    println(render(UiState.Loading))
    println(render(UiState.Success(listOf("أ", "ب"))))
    println(render(UiState.Error("لا يوجد اتصال")))
}
```

```output
⏳ جاري التحميل...
✅ 2 عناصر: أ، ب
❌ لا يوجد اتصال
```

- لا حاجة لفرع `else` في `when`، لأن المترجم يعرف أن هذه كل الحالات.
- داخل `is UiState.Success ->` يتحول النوع تلقائياً، فنصل إلى `state.items`.
- `object Loading` حالة بلا بيانات، فنكتفي بنسخة واحدة منها.

## إذا نسيت حالة

```kotlin
sealed interface Payment
data class Card(val last4: String) : Payment
object Cash : Payment
data class Wallet(val app: String) : Payment

fun describe(p: Payment): String = when (p) {
    is Card -> "بطاقة ${p.last4}"
    Cash -> "نقداً"
}

fun main() {
    println(describe(Cash))
}
```

```output
ERR: line 6: 'when' expression must be exhaustive. Add the 'is Wallet' branch or an 'else' branch.
```

نسيت `Wallet`؟ **المترجم يرفض الكود**. وعند إضافة طريقة دفع جديدة لاحقاً، يدلك المترجم على كل `when` تحتاج تحديثاً.

## sealed مقابل enum

```kotlin
enum class Level { LOW, MEDIUM, HIGH }

fun main() {
    val level = Level.MEDIUM
    println(level)
    println(level.ordinal)
    println(Level.values().joinToString())
}
```

```output
MEDIUM
1
LOW, MEDIUM, HIGH
```

| `enum class` | `sealed class` |
|---|---|
| قيم ثابتة بلا بيانات مختلفة | كل نوع يحمل بيانات مختلفة |
| `Level.LOW` نسخة واحدة | `Error("رسالة")` نسخ كثيرة ببيانات مختلفة |
| مناسب للأولويات والاتجاهات | مناسب للحالات والنتائج والأحداث |

## ملخص الدرس

- `sealed class` أو `sealed interface` تحدد مجموعة مغلقة من الأنواع الفرعية.
- `when` عليها لا تحتاج `else`، والمترجم يضمن تغطية كل الحالات.
- نمط حالات الشاشة: Loading و Success و Error.
- `enum` للقيم الثابتة البسيطة، و `sealed` عندما تحمل الحالات بيانات مختلفة.

--- exercise
عرّف `sealed interface Result` فيها ثلاث حالات:

- `data class Ok(val value: Int)`
- `data class Fail(val reason: String)`
- `object Empty`

ثم اكتب دالة `parse(input: String): Result`:

- نص فارغ (`isBlank()`) يُرجع `Empty`.
- نص يتحول لرقم (`toIntOrNull()`) يُرجع `Ok`.
- غير ذلك يُرجع `Fail("ليس رقماً: X")`.

ودالة `show(r: Result): String` بـ `when` دون `else`.

~~~starter
// الأنواع والدالتان هنا

fun main() {
    for (input in listOf("42", "", "abc")) {
        println(show(parse(input)))
    }
}
~~~
~~~expected
رقم: 42
فارغ
خطأ: ليس رقماً: abc
~~~
~~~solution
sealed interface Result
data class Ok(val value: Int) : Result
data class Fail(val reason: String) : Result
object Empty : Result

fun parse(input: String): Result {
    if (input.isBlank()) return Empty
    val n = input.toIntOrNull() ?: return Fail("ليس رقماً: $input")
    return Ok(n)
}

fun show(r: Result): String = when (r) {
    is Ok -> "رقم: ${r.value}"
    is Fail -> "خطأ: ${r.reason}"
    Empty -> "فارغ"
}

fun main() {
    for (input in listOf("42", "", "abc")) {
        println(show(parse(input)))
    }
}
~~~

- تجعل when أسرع
- تمنع الوراثة كلياً
> نسيان حالة يصبح خطأ ترجمة.

? متى تختار sealed class بدل enum؟
+ عندما تحمل كل حالة بيانات مختلفة، مثل Error فيها رسالة
- دائماً
- للقيم الثابتة البسيطة
> enum للقيم البسيطة، و sealed للحالات الغنية.

? لماذا تُعرَّف حالة Loading كـ object؟
+ لأنها لا تحمل بيانات، فتكفي نسخة واحدة منها
- لأن object أسرع
- لأن data class لا تعمل مع sealed
> لا داعي لإنشاء نسخ متعددة متطابقة.

## كائن واحد فقط

أحياناً تحتاج **نسخة واحدة فقط** من شيء في كل التطبيق: إعدادات التطبيق، أو مدير قاعدة البيانات، أو سجل الأحداث. في Kotlin تكتب `object` بدل `class`:

```kotlin
object AppConfig {
    const val VERSION = "2.1.0"
    var darkMode = false
    private val visits = mutableListOf<String>()

    fun log(page: String) {
        visits.add(page)
    }

    fun summary() = "زيارات: ${visits.size}، الوضع الليلي: $darkMode"
}

fun main() {
    AppConfig.log("الرئيسية")
    AppConfig.log("المنتجات")
    AppConfig.darkMode = true
    println(AppConfig.VERSION)
    println(AppConfig.summary())
}
```

```output
2.1.0
زيارات: 2، الوضع الليلي: true
```

- `object` ينشئ الصنف **ونسخته الوحيدة** معاً، وهو نمط التصميم المسمى **Singleton**.
- نصل إليه باسمه مباشرة: `AppConfig.log(...)`.
- `const val` ثابت يُعرف وقت الترجمة.

## companion object: أعضاء الصنف نفسه

ما يقابل `static` في Java. أعضاء تنتمي للصنف وليس لكل نسخة:

```kotlin
class User private constructor(val name: String, val role: String) {
    companion object {
        private var created = 0

        fun admin(name: String): User {
            created++
            return User(name, "مدير")
        }

        fun guest(): User {
            created++
            return User("زائر", "ضيف")
        }

        fun count() = created
    }

    override fun toString() = "$name ($role)"
}

fun main() {
    val a = User.admin("هند")
    val g = User.guest()
    println(a)
    println(g)
    println("أُنشئ ${User.count()} مستخدمين")
}
```

```output
هند (مدير)
زائر (ضيف)
أُنشئ 2 مستخدمين
```

`private constructor` يمنع إنشاء المستخدم مباشرة، فالطريقة الوحيدة هي **الدوال المصنعية (Factory Functions)** في الـ companion. هذا النمط شائع جداً: `newInstance()` في Fragments بـ Android.

## ملخص الدرس

- `object` ينشئ صنفاً ونسخته الوحيدة (Singleton).
- `companion object` لأعضاء الصنف نفسه، مثل الدوال المصنعية والعدّادات.
- `const val` للثوابت المعروفة وقت الترجمة.
- `object : Interface { }` لكائن مجهول ينفّذ واجهة.

object Cart {
    private val items: MutableList<Pair<String, Double>> = mutableListOf()

    fun add(name: String, price: Double) {
        items.add(name to price)

    fun total(): Double = items.sumOf { it.second }

}

    companion object {
        fun of(code: String): Coupon? = if (code == "SAVE10") Coupon(code, 10) else null
    }
}

fun main() {
