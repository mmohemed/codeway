=== lesson
## اختبار المكونات

اختبارات الوحدات تختبر الدوال. لكن الواجهة مكونات: زر، ونموذج، وقائمة تتغير. كيف نختبر أن المكون **يعرض** الشيء الصحيح؟

**Testing Library** أشهر مكتبة لذلك، وفلسفتها جملة واحدة:

> 💡 «كلما شابهت اختباراتك طريقة استخدام البرنامج الحقيقية، زادت الثقة التي تمنحك إياها».

لذلك لا تبحث عن العناصر بأصناف CSS أو بنية HTML الداخلية، بل كما يبحث المستخدم: بالنص الظاهر، وبدور العنصر (زر، رابط، عنوان)، وبعنوان الحقل.

> 💡 المكتبة لها نسخ لكل إطار: `@testing-library/react` و `@testing-library/vue` وغيرها، والفرق الوحيد دالة `render`. سنستخدم النسخة الأساسية `@testing-library/dom` مع مكونات JavaScript عادية، وكل ما تتعلمه ينطبق كما هو على React.

## أول اختبار مكون

## أنواع الاستعلامات

| البادئة | إذا لم يوجد العنصر | الاستخدام |
|---|---|---|
| `getBy...` | يرمي خطأ | العنصر يجب أن يكون موجوداً |
| `queryBy...` | يُرجع `null` | للتأكد أن عنصراً **غير** موجود |
| `findBy...` | ينتظر حتى يظهر (وعد) | العناصر التي تظهر لاحقاً بعد طلب شبكة |
| `getAllBy...` | مصفوفة | عدة عناصر |

## بماذا نبحث؟ بترتيب الأولوية

1. **`getByRole`**: الأفضل. يبحث بالدور الذي تعلنه عناصر HTML لقارئات الشاشة: `button` و `link` و `heading` و `textbox` و `checkbox` و `listitem`، مع `{ name }` للنص.
2. **`getByLabelText`**: لحقول النماذج، بنص `<label>` المرتبط بها.
3. **`getByPlaceholderText`** و **`getByText`**: للنصوص الظاهرة.
4. **`getByTestId`**: الملاذ الأخير، بالخاصية `data-testid`.

ميزة خفية: إذا لم تجد `getByRole` زرك، فقارئ الشاشة لن يجده أيضاً. اختباراتك تكشف مشاكل **إمكانية الوصول** تلقائياً!

## مطابقات jest-dom

`@testing-library/jest-dom` يضيف مطابقات خاصة بالواجهة:

| المطابقة | تتحقق من |
|---|---|
| `toBeInTheDocument()` | العنصر موجود في الصفحة |
| `toHaveTextContent("...")` | النص داخل العنصر |
| `toBeVisible()` | ظاهر للمستخدم |
| `toBeDisabled()` و `toBeEnabled()` | حالة التعطيل |
| `toHaveValue("...")` | قيمة الحقل |
| `toBeChecked()` | مربع الاختيار محدد |
| `toHaveClass("...")` و `toHaveAttribute(...)` | الأصناف والخصائص |

## ملخص الدرس

- Testing Library تختبر المكونات كما يراها المستخدم، لا كما كُتب HTML.
- `getBy` للعنصر الموجود، و `queryBy` لغير الموجود، و `findBy` لما يظهر لاحقاً.
- الأولوية: `getByRole` ثم `getByLabelText` ثم النص، و `getByTestId` أخيراً.
- الاستعلام بالدور يكشف مشاكل إمكانية الوصول.

## اختبار التفاعل

المكونات تتغير عندما يتفاعل المستخدم: ينقر، ويكتب، ويختار. **user-event** يحاكي هذه التفاعلات كما يفعلها الإنسان: النقر يطلق كل أحداث الفأرة بالترتيب، والكتابة تُدخل حرفاً حرفاً مع أحداث لوحة المفاتيح.

```testfiles
// file: Counter.js
export function Counter({ max = 3 } = {}) {
  const box = document.createElement("div");
  box.innerHTML = `<p>العدد: <output>0</output></p><button>زيادة</button><button>تصفير</button>`;
  const [inc, reset] = box.querySelectorAll("button");
  const out = box.querySelector("output");
  let n = 0;
  const update = () => { out.textContent = n; inc.disabled = n >= max; };
  inc.addEventListener("click", () => { n++; update(); });
  reset.addEventListener("click", () => { n = 0; update(); });
  return box;
}
// file: Counter.test.js
import { it, expect } from "vitest";
import { screen } from "@testing-library/dom";
import userEvent from "@testing-library/user-event";
import { Counter } from "./Counter.js";

it("يزيد ويتوقف عند الحد الأقصى", async () => {
  const user = userEvent.setup();
  document.body.append(Counter({ max: 2 }));
  const inc = screen.getByRole("button", { name: "زيادة" });

  await user.click(inc);
  await user.click(inc);

  expect(screen.getByText("العدد: 2")).toBeInTheDocument();
  expect(inc).toBeDisabled();
});

it("التصفير يعيد العدد ويفعّل الزر", async () => {
  const user = userEvent.setup();
  document.body.append(Counter({ max: 1 }));
  await user.click(screen.getByRole("button", { name: "زيادة" }));
  await user.click(screen.getByRole("button", { name: "تصفير" }));

  expect(screen.getByText("العدد: 0")).toBeInTheDocument();
  expect(screen.getByRole("button", { name: "زيادة" })).toBeEnabled();
});
```

## الكتابة في الحقول والنماذج

```testfiles
// file: Subscribe.js
export function Subscribe(onSubscribe) {
  const form = document.createElement("form");
  form.noValidate = true; // نتحقق بأنفسنا بدل رسائل المتصفح
  form.innerHTML = `
    <label for="mail">بريدك</label>
    <input id="mail" type="email" />
    <button type="submit">اشترك</button>
    <p role="alert"></p>
  `;
  form.addEventListener("submit", (e) => {
    e.preventDefault();
    const email = form.querySelector("input").value.trim();
    const alert = form.querySelector("[role=alert]");
    if (!email.includes("@")) { alert.textContent = "البريد غير صحيح"; return; }
    onSubscribe(email);
    alert.textContent = "شكراً لاشتراكك!";
  });
  return form;
}
// file: Subscribe.test.js
import { describe, it, expect, vi } from "vitest";
import { screen } from "@testing-library/dom";
import userEvent from "@testing-library/user-event";
import { Subscribe } from "./Subscribe.js";

describe("Subscribe", () => {
  it("يرسل البريد الصحيح", async () => {
    const user = userEvent.setup();
    const onSubscribe = vi.fn();
    document.body.append(Subscribe(onSubscribe));

    await user.type(screen.getByLabelText("بريدك"), "sara@mail.com");
    await user.click(screen.getByRole("button", { name: "اشترك" }));

    expect(onSubscribe).toHaveBeenCalledWith("sara@mail.com");
    expect(screen.getByRole("alert")).toHaveTextContent("شكراً لاشتراكك!");
  });

  it("يرفض البريد غير الصحيح", async () => {
    const user = userEvent.setup();
    const onSubscribe = vi.fn();
    document.body.append(Subscribe(onSubscribe));

    await user.type(screen.getByLabelText("بريدك"), "sara{enter}");

    expect(onSubscribe).not.toHaveBeenCalled();
    expect(screen.getByRole("alert")).toHaveTextContent("البريد غير صحيح");
  });
});
```

## اختبر السلوك، لا التفاصيل

> ⚠️ لا تختبر المتغيرات الداخلية أو أسماء الدوال الخاصة. اختبر ما يراه المستخدم ويفعله: «نقرت زيادة فظهر 2». هكذا تستطيع إعادة كتابة المكون بالكامل، وتبقى الاختبارات صحيحة طالما السلوك صحيح.

## ملخص الدرس

- `userEvent.setup()` ثم `await user.click()` و `await user.type()` لمحاكاة المستخدم.
- `{enter}` داخل النص يضغط Enter، فيُرسل النموذج.
- الدوال الوهمية تتحقق مما يبلغه المكون للخارج.
- `findBy` للمحتوى الذي يظهر بعد عملية غير متزامنة.
- اختبر السلوك الظاهر لا التفاصيل الداخلية.

اكتب `TodoApp.test.js` باستخدام `userEvent` يتحقق من:

1. إضافة مهمتين تظهران في القائمة، ويصبح النص `المتبقي: 2`، ويُفرَّغ الحقل بعد الإضافة.
2. تحديد مهمة كمنجزة يجعل `المتبقي: 1`.

~~~setup
// file: TodoApp.js
export function TodoApp() {
  const app = document.createElement("div");
  app.innerHTML = `
    <label for="t">مهمة جديدة</label>
    <input id="t" />
    <button>أضف</button>
    <ul></ul>
    <p>المتبقي: 0</p>
  `;
  const input = app.querySelector("input"), list = app.querySelector("ul"), left = app.querySelector("p");
  const refresh = () => { left.textContent = `المتبقي: ${list.querySelectorAll("input:not(:checked)").length}`; };
  app.querySelector("button").addEventListener("click", () => {
    const title = input.value.trim();
    if (!title) return;
    const li = document.createElement("li");
    li.innerHTML = `<label><input type="checkbox" /> ${title}</label>`;
    li.querySelector("input").addEventListener("change", refresh);
    list.append(li);
    input.value = "";
    refresh();
  });
  return app;
}
~~~

--- quiz
? لماذا نكتب `await` قبل `user.click(...)`؟
+ لأن تفاعلات user-event غير متزامنة وتُرجع وعداً
- لأن click بطيئة جداً
- ليست ضرورية أبداً
> الانتظار يضمن اكتمال كل الأحداث قبل التحقق.

? كيف تكتب نصاً ثم تضغط Enter بـ user-event؟
+ `await user.type(input, "نص{enter}")`
- `await user.type(input, "نص\n")`
- `await user.enter(input)`
> الأقواس المعقوفة للمفاتيح الخاصة.

? ماذا يعني «اختبر السلوك، لا التفاصيل»؟
+ تحقق مما يراه المستخدم ويفعله، لا من المتغيرات والدوال الداخلية
- لا تكتب اختبارات للتفاصيل الصغيرة
- اختبر CSS فقط
> فتبقى الاختبارات صحيحة عند إعادة كتابة المكون.
