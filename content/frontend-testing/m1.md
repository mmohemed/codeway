=== lesson
## لماذا نكتب اختبارات؟

تخيّل متجراً إلكترونياً فيه دالة تحسب الخصم. عدّلها زميلك لإضافة ميزة جديدة، فتعطلت حالة لم ينتبه لها، وصار العملاء يدفعون أكثر من المطلوب لثلاثة أيام قبل أن يلاحظ أحد.

**الاختبار الآلي** كود يتحقق من أن كودك يعمل كما تتوقع. تكتبه مرة، ويعمل آلاف المرات: بعد كل تعديل، وقبل كل دمج، وقبل كل نشر. فوائده:

- **ثقة عند التعديل**: تعيد هيكلة الكود وأنت مطمئن، فأي كسر سيظهر فوراً.
- **اكتشاف الأخطاء مبكراً**: إصلاح الخطأ أثناء التطوير أرخص بكثير من إصلاحه بعد وصوله للمستخدمين.
- **توثيق حي**: الاختبارات تشرح كيف يُفترض أن يعمل الكود، بأمثلة تعمل فعلاً.

## هرم الاختبارات

| النوع | يختبر | السرعة | العدد المعتاد |
|---|---|---|---|
| **الوحدات (Unit)** | دالة أو وحدة صغيرة منفردة | أجزاء من الثانية | كثير جداً |
| **التكامل والمكونات (Integration)** | عدة أجزاء معاً، مثل مكون واجهة | سريع | متوسط |
| **الشامل (End-to-End)** | التطبيق كاملاً في متصفح حقيقي كما يستخدمه الإنسان | بطيء | قليل للمسارات المهمة |

القاعدة: كثير من اختبارات الوحدات السريعة في القاعدة، وقليل من الاختبارات الشاملة البطيئة في القمة. هذه الدورة تغطي المستويات الثلاثة: **Vitest** للوحدات، و **Testing Library** للمكونات، و **Playwright** للاختبار الشامل.

## تشريح الاختبار

كل اختبار يتبع نمط **AAA**: التجهيز (Arrange)، ثم التنفيذ (Act)، ثم التحقق (Assert):

```testfiles
// file: price.js
export function finalPrice(price, discountPercent) {
  return price - (price * discountPercent) / 100;
}
// file: price.test.js
import { describe, it, expect } from "vitest";
import { finalPrice } from "./price.js";

describe("finalPrice", () => {
  it("يطبق خصم 20% على 100", () => {
    // Arrange: البيانات
    const price = 100;
    // Act: نستدعي الكود
    const result = finalPrice(price, 20);
    // Assert: نتحقق من النتيجة
    expect(result).toBe(80);
  });

  it("لا يغير السعر عند خصم 0%", () => {
    expect(finalPrice(250, 0)).toBe(250);
  });
});
```

```output
 RUN  v3.2.4 /project

 ✓ price.test.js > finalPrice > يطبق خصم 20% على 100
 ✓ price.test.js > finalPrice > لا يغير السعر عند خصم 0%

 Test Files  1 passed (1)
      Tests  2 passed (2)
```

- `describe` يجمع الاختبارات المتعلقة بنفس الدالة في مجموعة.
- `it` (أو `test`) اختبار واحد، وعنوانه جملة تصف السلوك المتوقع.
- `expect(قيمة).toBe(متوقع)` هو التحقق: إذا لم تتطابق القيمتان يفشل الاختبار.

> 💡 في هذه الدورة تكتب ملفات الكود والاختبارات في محرر واحد، كل ملف يبدأ بسطر `// file: الاسم`. ملفات `*.test.js` تُشغَّل كاختبارات بمشغّل متوافق مع Vitest، وتظهر النتيجة بنفس صيغة Vitest.

## عندما يفشل اختبار

لنفترض أن أحدهم أخطأ في الدالة:

## ماذا نختبر؟

- **الحالة العادية**: الاستخدام المعتاد.
- **الحالات الحدية**: صفر، قائمة فارغة، أكبر قيمة مسموحة، نص فارغ.
- **الأخطاء**: مدخلات غير صالحة يجب أن ترمي خطأ أو تُرفض.

## ملخص الدرس

- الاختبار الآلي كود يتحقق من سلوك كودك، ويعطيك ثقة عند كل تعديل.
- الهرم: اختبارات وحدات كثيرة، وتكامل أقل، وشاملة قليلة للمسارات المهمة.
- نمط AAA: تجهيز ثم تنفيذ ثم تحقق.
- اختبر الحالة العادية والحدية والأخطاء، فاختبار واحد قد ينجح بالصدفة.

لديك الدالة `isValidPassword(password)` في `password.js`: كلمة المرور صالحة إذا كان طولها 8 أحرف على الأقل **وتحتوي رقماً واحداً على الأقل**.

## Vitest و Jest

**Jest** كان لسنوات أشهر مشغّل اختبارات في JavaScript. **Vitest** جاء أحدث، مبنياً على Vite، فهو:

- **أسرع بكثير**، ويعيد تشغيل الاختبارات المتأثرة فقط عند الحفظ.
- يدعم ES Modules و TypeScript دون إعدادات.
- **متوافق مع واجهة Jest** تقريباً بالكامل: `describe` و `it` و `expect` بنفس الأسماء.

| | Jest | Vitest |
|---|---|---|
| دالة وهمية | `jest.fn()` | `vi.fn()` |
| محاكاة وحدة | `jest.mock()` | `vi.mock()` |
| المؤقتات | `jest.useFakeTimers()` | `vi.useFakeTimers()` |
| الإعداد | `jest.config.js` و Babel غالباً | `vite.config.js` نفسه |

ما تتعلمه هنا ينطبق على الاثنين. المشاريع الجديدة (خصوصاً مع Vite) تختار Vitest، وستجد Jest في مشاريع كثيرة قائمة.

## التثبيت والتشغيل

```bash
npm install -D vitest
```

```json
{
  "scripts": {
    "test": "vitest"
  }
}
```

`npm test` يشغّل Vitest في وضع المراقبة: يعيد التشغيل عند كل حفظ. و `npx vitest run` يشغّل مرة واحدة (مناسب لـ CI). وكل ملف ينتهي بـ `.test.js` أو `.spec.js` يُعتبر ملف اختبار.

## المطابقات (Matchers)

```testfiles
// file: matchers.test.js
import { describe, it, expect } from "vitest";

describe("المطابقات الأساسية", () => {
  it("toBe للقيم البسيطة", () => {
    expect(2 + 2).toBe(4);
    expect("Code" + "Way").toBe("CodeWay");
  });

  it("toEqual للكائنات والمصفوفات", () => {
    const user = { name: "ليان", roles: ["admin"] };
    expect(user).toEqual({ name: "ليان", roles: ["admin"] });
    // toBe هنا سيفشل: كائنان مختلفان في الذاكرة
    expect(user).not.toBe({ name: "ليان", roles: ["admin"] });
  });

  it("الأعداد", () => {
    expect(0.1 + 0.2).toBeCloseTo(0.3);
    expect(10).toBeGreaterThan(5);
  });

  it("النصوص والمصفوفات", () => {
    expect("مرحباً بالعالم").toContain("بالعالم");
    expect(["أ", "ب", "ج"]).toHaveLength(3);
    expect("user@mail.com").toMatch(/@/);
  });

  it("الصحة والقيم الخاصة", () => {
    expect(null).toBeNull();
    expect(undefined).toBeUndefined();
    expect("نص").toBeTruthy();
    expect(0).toBeFalsy();
  });
});
```

| المطابقة | للتحقق من |
|---|---|
| `toBe` | التطابق التام (للأرقام والنصوص) |
| `toEqual` | تساوي المحتوى (للكائنات والمصفوفات) |
| `toBeCloseTo` | الأعداد العشرية (0.1 + 0.2 ليست 0.3 بالضبط!) |
| `toContain` و `toHaveLength` و `toMatch` | المحتوى والطول والنمط |
| `toThrow` | أن الدالة ترمي خطأ |
| `.not` | عكس أي مطابقة |

```testfiles
export function withdraw(balance, amount) {
  if (amount <= 0) throw new Error("المبلغ يجب أن يكون موجباً");

});
```

## التجهيز المشترك: beforeEach

إذا احتاجت كل الاختبارات نفس البداية، ضعها في `beforeEach` فتعمل قبل كل اختبار، فيبدأ كل اختبار من حالة نظيفة مستقلة:

```testfiles
// file: cart.js
export function createCart() {
  const items = [];
  return {
    add: (name, price) => items.push({ name, price }),
    total: () => items.reduce((s, i) => s + i.price, 0),
    count: () => items.length,
  };
}
// file: cart.test.js
import { describe, it, expect, beforeEach } from "vitest";
import { createCart } from "./cart.js";

describe("السلة", () => {
  let cart;
  beforeEach(() => {
    cart = createCart();
    cart.add("كتاب", 50);
  });

  it("تحسب الإجمالي", () => {
    cart.add("قلم", 5);
    expect(cart.total()).toBe(55);
  });

  it("تبدأ كل اختبار بعنصر واحد", () => {
    expect(cart.count()).toBe(1);
  });
});
```

## ملخص الدرس

- Vitest سريع ومتوافق مع Jest: `vi` بدل `jest` في المحاكاة.
- `toBe` للقيم البسيطة، و `toEqual` للكائنات، و `toBeCloseTo` للكسور.
- `expect(() => fn()).toThrow("رسالة")` لاختبار الأخطاء.
- `beforeEach` يجهز حالة نظيفة قبل كل اختبار، و `it.each` لعدة حالات.

اكتب اختبارات لدالة `shippingCost(total)` في `shipping.js`:

- الطلب الذي إجماليه 200 ر.س **فأكثر**: الشحن مجاني (0).
- أقل من 200: الشحن 25.

~~~starter
// file: shipping.test.js
import { describe, it, expect } from "vitest";
import { shippingCost } from "./shipping.js";

});
~~~

~~~solution
// file: shipping.test.js
import { describe, it, expect } from "vitest";
import { shippingCost } from "./shipping.js";

describe("shippingCost", () => {

    [350, 0],
~~~

+ `toEqual`

## لماذا المحاكاة؟

الكود الحقيقي يعتمد على أشياء خارجية: واجهة برمجية عبر الشبكة، والوقت الحالي، وخدمة إرسال بريد، وقاعدة بيانات. اختبارها مباشرة يجعل الاختبار:

- **بطيئاً**: ينتظر الشبكة.
- **متقلباً**: ينجح اليوم ويفشل غداً لأن الخادم توقف.
- **خطيراً**: يرسل بريداً حقيقياً لعميل!

**المحاكاة (Mocking)** تستبدل هذه الأشياء ببدائل وهمية نتحكم فيها تماماً.

## الدالة الوهمية: vi.fn

`vi.fn()` دالة تسجّل كل استدعاء لها: كم مرة، وبأي معاملات. ونحدد ما تُرجعه:

```testfiles
// file: notify.js
export function notifyAll(users, sendEmail) {
  users.filter((u) => u.subscribed).forEach((u) => sendEmail(u.email, "عرض جديد!"));
}
// file: notify.test.js
import { it, expect, vi } from "vitest";
import { notifyAll } from "./notify.js";

it("يرسل للمشتركين فقط", () => {
  const sendEmail = vi.fn();
  const users = [
    { email: "a@x.com", subscribed: true },
    { email: "b@x.com", subscribed: false },
    { email: "c@x.com", subscribed: true },
  ];

  notifyAll(users, sendEmail);

  expect(sendEmail).toHaveBeenCalledTimes(2);
  expect(sendEmail).toHaveBeenCalledWith("a@x.com", "عرض جديد!");
  expect(sendEmail).not.toHaveBeenCalledWith("b@x.com", "عرض جديد!");
});
```

## التحكم في القيمة المُرجعة

```testfiles
// file: weather.js
export async function weatherMessage(api, city) {
  try {
    const t = await api.getTemperature(city);
    return t >= 35 ? `الجو حار في ${city}: ${t}°` : `الجو معتدل في ${city}: ${t}°`;
  } catch {
    return "تعذّر جلب حالة الطقس";
  }
}
// file: weather.test.js
import { describe, it, expect, vi } from "vitest";
import { weatherMessage } from "./weather.js";

describe("weatherMessage", () => {
  it("حار", async () => {
    const api = { getTemperature: vi.fn().mockResolvedValue(42) };
    expect(await weatherMessage(api, "الرياض")).toBe("الجو حار في الرياض: 42°");
  });

  it("معتدل", async () => {
    const api = { getTemperature: vi.fn().mockResolvedValue(24) };
    await expect(weatherMessage(api, "أبها")).resolves.toBe("الجو معتدل في أبها: 24°");
  });

  it("فشل الشبكة", async () => {
    const api = { getTemperature: vi.fn().mockRejectedValue(new Error("timeout")) };
    expect(await weatherMessage(api, "جدة")).toBe("تعذّر جلب حالة الطقس");
  });
});
```

```output

 ✓ weather.test.js > weatherMessage > حار
 ✓ weather.test.js > weatherMessage > معتدل
 ✓ weather.test.js > weatherMessage > فشل الشبكة

 Test Files  1 passed (1)
      Tests  3 passed (3)
```

| الدالة | تجعل الدالة الوهمية |
|---|---|
| `mockReturnValue(v)` | تُرجع v |
| `mockResolvedValue(v)` | تُرجع وعداً ينجح بـ v |
| `mockRejectedValue(e)` | تُرجع وعداً يفشل بـ e |
| `mockImplementation(fn)` | تنفذ fn |

لاحظ كيف اختبرنا حالة **فشل الشبكة** بسهولة، وهي حالة يصعب جداً إحداثها مع خادم حقيقي.

## محاكاة وحدة كاملة: vi.mock

إذا كان الكود يستورد الوحدة بنفسه (لا يستلمها كمعامل)، استبدلها كلها بـ `vi.mock`:

```testfiles
// file: api.js
export async function fetchProducts() {
  const res = await fetch("https://api.shop.com/products");
  return res.json();
}
// file: store.js
import { fetchProducts } from "./api.js";
export async function cheapestProduct() {
  const products = await fetchProducts();
  return products.reduce((a, b) => (b.price < a.price ? b : a)).name;
}
// file: store.test.js
import { it, expect, vi } from "vitest";
import { cheapestProduct } from "./store.js";

vi.mock("./api.js", () => ({
  fetchProducts: vi.fn().mockResolvedValue([
    { name: "شاشة", price: 900 },
    { name: "فأرة", price: 60 },
    { name: "لوحة", price: 150 },
  ]),
}));

it("يجد أرخص منتج", async () => {
  expect(await cheapestProduct()).toBe("فأرة");
});
```

## المؤقتات الوهمية

كود فيه `setTimeout` لمدة دقيقة؟ لن ننتظر دقيقة في الاختبار. `vi.useFakeTimers()` يجعلنا نتحكم في الوقت:

```testfiles
// file: session.js
export function startSession(onExpire) {
  setTimeout(onExpire, 15 * 60 * 1000); // 15 دقيقة
}
// file: session.test.js
import { it, expect, vi } from "vitest";
import { startSession } from "./session.js";

it("تنتهي الجلسة بعد 15 دقيقة بالضبط", () => {
  vi.useFakeTimers();
  const onExpire = vi.fn();
  startSession(onExpire);

  vi.advanceTimersByTime(14 * 60 * 1000);
  expect(onExpire).not.toHaveBeenCalled();

  vi.advanceTimersByTime(60 * 1000);
  expect(onExpire).toHaveBeenCalledTimes(1);
  vi.useRealTimers();
});
```

```output

 Test Files  1 passed (1)
      Tests  1 passed (1)
```

> ⚠️ لا تحاكِ كل شيء: كلما زادت المحاكاة، قلّ ما يختبره الاختبار فعلاً. حاكِ الحدود الخارجية (الشبكة والوقت والبريد)، واترك منطقك الحقيقي يعمل.

## ملخص الدرس

- المحاكاة تستبدل الاعتماديات الخارجية لاختبارات سريعة وثابتة وآمنة.
- `vi.fn()` تسجل الاستدعاءات، و `toHaveBeenCalledWith` و `toHaveBeenCalledTimes` تتحقق منها.
- `mockResolvedValue` و `mockRejectedValue` لمحاكاة النجاح والفشل.
- `vi.mock(path, factory)` يستبدل وحدة كاملة، و `vi.useFakeTimers()` يتحكم في الوقت.

--- exercise
الدالة `placeOrder(cart, payment, mailer)` في `order.js`:

- إذا كانت السلة فارغة: ترمي خطأ `السلة فارغة` **دون** أي دفع.
- وإلا تستدعي `payment.charge(total)` بمجموع الأسعار، ثم `mailer.send("تم تأكيد طلبك")`، وتُرجع `"confirmed"`.
- إذا فشل الدفع (رفض الوعد): تُرجع `"payment_failed"` **دون** إرسال بريد.

اكتب `order.test.js` يغطي الحالات الثلاث باستخدام `vi.fn()`.

~~~setup
// file: order.js
export async function placeOrder(cart, payment, mailer) {
  if (cart.length === 0) throw new Error("السلة فارغة");
  const total = cart.reduce((s, i) => s + i.price, 0);
  try {
    await payment.charge(total);
  } catch {
    return "payment_failed";
  }
  mailer.send("تم تأكيد طلبك");
  return "confirmed";
}
~~~
~~~starter
// file: order.test.js
import { describe, it, expect, vi } from "vitest";
import { placeOrder } from "./order.js";

describe("placeOrder", () => {
  it("يؤكد الطلب", async () => {
    const payment = { charge: vi.fn() };
    const mailer = { send: vi.fn() };
  });
});
~~~
~~~solution
// file: order.test.js
import { describe, it, expect, vi } from "vitest";
import { placeOrder } from "./order.js";

describe("placeOrder", () => {
  it("يؤكد الطلب ويدفع المجموع ويرسل بريداً", async () => {
    const payment = { charge: vi.fn().mockResolvedValue("ok") };
    const mailer = { send: vi.fn() };
    const result = await placeOrder([{ price: 30 }, { price: 70 }], payment, mailer);
    expect(result).toBe("confirmed");
    expect(payment.charge).toHaveBeenCalledWith(100);
    expect(mailer.send).toHaveBeenCalledWith("تم تأكيد طلبك");
  });

  it("يرفض السلة الفارغة دون دفع", async () => {
    const payment = { charge: vi.fn() };
    const mailer = { send: vi.fn() };
    await expect(placeOrder([], payment, mailer)).rejects.toThrow("السلة فارغة");
    expect(payment.charge).not.toHaveBeenCalled();
  });

  it("لا يرسل بريداً إذا فشل الدفع", async () => {
    const payment = { charge: vi.fn().mockRejectedValue(new Error("declined")) };
    const mailer = { send: vi.fn() };
    expect(await placeOrder([{ price: 10 }], payment, mailer)).toBe("payment_failed");
    expect(mailer.send).not.toHaveBeenCalled();
  });
});
~~~
