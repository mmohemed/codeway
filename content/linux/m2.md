## المستخدمون: من يملك ماذا

Linux نظام متعدد المستخدمين: لكل مستخدم رقم **UID**، ومجموعة رئيسية **GID**، ومجلد رئيسي، وطرفية. و **root** (UID 0) هو المدير الذي يستطيع كل شيء.

```terminal
$ id
uid=1000(sara) gid=1000(sara) groups=1000(sara),4(adm),27(sudo)
$ grep sara /etc/passwd
sara:x:1000:1000:Sara:/home/sara:/bin/bash
$ tail -n 4 /etc/passwd
nobody:x:65534:65534:nobody:/nonexistent:/usr/sbin/nologin
syslog:x:102:102::/nonexistent:/usr/sbin/nologin
sshd:x:105:65534::/run/sshd:/usr/sbin/nologin
sara:x:1000:1000:Sara:/home/sara:/bin/bash
```

سطر `/etc/passwd`: `الاسم:x:UID:GID:الوصف:المجلد:الطرفية`.

- `x` يعني أن بصمة كلمة المرور في `/etc/shadow` المحمي، لا هنا.
- **حسابات الخدمات** مثل `www-data` طرفيتها `/usr/sbin/nologin`: لا يمكن الدخول بها، فلو اختُرق خادم الويب لا يحصل المهاجم على طرفية بسهولة.

## sudo: صلاحيات المدير عند الحاجة فقط

لا تعمل كـ root دائماً. أعضاء مجموعة `sudo` ينفذون أمراً واحداً بصلاحيات المدير بكتابة `sudo` قبله، وكل استخدام يُسجَّل:

```terminal
$ cat /etc/shadow
ERR: cat: /etc/shadow: Permission denied
$ sudo head -n 2 /etc/shadow
root:*:20400:0:99999:7:::
daemon:*:20400:0:99999:7:::
$ sudo -l
Matching Defaults entries for sara on ubuntu:
    env_reset, mail_badpass, secure_path=/usr/local/sbin\:/usr/local/bin\:/usr/sbin\:/usr/bin\:/sbin\:/bin\:/snap/bin, use_pty

User sara may run the following commands on ubuntu:
    (ALL : ALL) ALL
$ grep "COMMAND" /var/log/auth.log | tail -n 1
2026-11-08T10:00:05.000123+00:00 ubuntu sudo[2600]:     sara : TTY=pts/0 ; PWD=/home/sara ; USER=root ; COMMAND=/usr/bin/head -n 2 /etc/shadow
```

في الطرفية الحقيقية يطلب `sudo` كلمة مرورك أول مرة. و `*` في `/etc/shadow` يعني حساباً بلا كلمة مرور صالحة للدخول.

## إنشاء المستخدمين وإدارتهم

```terminal
$ sudo useradd -m -s /bin/bash -c "Ali Hassan" ali
$ id ali
uid=1001(ali) gid=1001(ali) groups=1001(ali)
$ sudo ls -la /home/ali
total 20
drwxr-x--- 2 ali  ali  4096 Nov  8 09:00 .
drwxr-xr-x 4 root root 4096 Nov  8 09:00 ..
-rw-r--r-- 1 ali  ali    17 Nov  8 09:00 .bash_logout
-rw-r--r-- 1 ali  ali    31 Nov  8 09:00 .bashrc
-rw-r--r-- 1 ali  ali    13 Nov  8 09:00 .profile
$ sudo groupadd developers
$ sudo usermod -aG developers ali
$ groups ali
ali : ali developers
$ sudo passwd -S ali
ali L 2025-11-08 0 99999 7 -1
$ sudo passwd ali
New password: 
Retype new password: 
passwd: password updated successfully
```

| الأمر | الوظيفة |
|---|---|
| `useradd -m -s /bin/bash اسم` | مستخدم جديد بمجلد (`-m`) وطرفية (`-s`) |
| `usermod -aG مجموعة اسم` | **إضافة** لمجموعة (بدون `-a` تُستبدل كل مجموعاته!) |
| `passwd اسم` | تعيين كلمة المرور |
| `passwd -l اسم` أو `usermod -L` | **قفل** الحساب (لموظف غادر) |
| `userdel -r اسم` | حذف المستخدم ومجلده |
| `groupadd` و `gpasswd -d` | إنشاء مجموعة، وإزالة عضو منها |

`L` في `passwd -S` يعني أن الحساب مقفل (لا كلمة مرور بعد)، وبعد تعيينها تصبح `P`.

## مبدأ الصلاحيات الدنيا

القاعدة الذهبية في الأمن: **كل مستخدم وكل خدمة تحصل على أقل صلاحيات تكفي عملها فقط** (Least Privilege). المطور لا يحتاج sudo على خادم الإنتاج، وخادم الويب لا يحتاج الكتابة على ملفات الإعدادات.

```terminal
$ sudo useradd -m -s /bin/bash guest
$ sudo -u guest cat /etc/shadow
ERR: cat: /etc/shadow: Permission denied
$ sudo -u guest sudo ls /root
ERR: guest is not in the sudoers file.
```

ومحاولة الحساب `guest` استخدام sudo فشلت **وسُجّلت** في `/var/log/auth.log`: إشارة يراقبها الفريق الأمني.

## قراءة الصلاحيات

كل ملف له ثلاث فئات: **المالك (u)** و **المجموعة (g)** و **الآخرون (o)**، ولكل فئة ثلاث صلاحيات:

| | على الملف | على المجلد |
|---|---|---|
| `r` (4) | قراءة المحتوى | عرض الأسماء بـ `ls` |
| `w` (2) | تعديل المحتوى | إنشاء الملفات وحذفها فيه |
| `x` (1) | تنفيذه كبرنامج | الدخول إليه بـ `cd` والوصول لما فيه |

`-rwxr-x---` تُقرأ: ملف، المالك `rwx`، والمجموعة `r-x`، والآخرون لا شيء. وبالأرقام: نجمع القيم لكل فئة: `rwx = 7` و `r-x = 5` و `--- = 0`، أي **750**.

| الرقم | الصلاحيات | الاستخدام الشائع |
|---|---|---|
| `644` | `rw-r--r--` | ملف عادي يقرؤه الجميع |
| `600` | `rw-------` | ملف سري (مفتاح SSH خاص، ملف `.env`) |
| `755` | `rwxr-xr-x` | سكربت أو مجلد عام |
| `700` | `rwx------` | مجلد خاص (`~/.ssh`) |
| `777` | `rwxrwxrwx` | ⚠️ الجميع يكتب: خطر أمني، تجنبه |

## chmod و chown

```terminal
$ echo "DB_PASSWORD=s3cret" > app.env
$ ls -l app.env
-rw-rw-r-- 1 sara sara 19 Nov  8 10:00 app.env
$ chmod 600 app.env
$ ls -l app.env
-rw------- 1 sara sara 19 Nov  8 10:00 app.env
$ cat > deploy.sh <<EOF
> echo "deploying as $USER"
> EOF
$ ./deploy.sh
ERR: bash: ./deploy.sh: Permission denied
$ chmod u+x deploy.sh
$ ./deploy.sh
deploying as sara
$ chmod go-r deploy.sh
$ stat -c "%a %A %U:%G %n" app.env deploy.sh
600 -rw------- sara:sara app.env
720 -rwx-w---- sara:sara deploy.sh
$ chown root app.env
ERR: chown: changing ownership of 'app.env': Operation not permitted
$ sudo chown root:root app.env
$ cat app.env
ERR: cat: app.env: Permission denied
```

- الصيغة الرمزية: `u+x` أضف التنفيذ للمالك، و `go-r` أزل القراءة من المجموعة والآخرين، و `a=r` للجميع قراءة فقط.
- `chown مالك:مجموعة ملف` يغيّر الملكية ويحتاج root.
- الملفات الجديدة تأخذ `664` والمجلدات `775` بسبب **umask** (`0002`) الذي يحذف صلاحية الكتابة من الآخرين.

## الصلاحيات الخاصة: SUID

إذا كان على البرنامج بت **SUID** (يظهر `s` مكان `x`) فإنه يعمل بصلاحيات **مالكه** لا من شغّله. `passwd` مثلاً يحتاجه ليكتب في `/etc/shadow`:

```terminal
$ ls -l /usr/bin/passwd
-rwsr-xr-x 1 root root 4 Nov  8 09:00 /usr/bin/passwd
$ find /usr/bin -perm -4000 -type f
/usr/bin/chfn
/usr/bin/chsh
/usr/bin/gpasswd
/usr/bin/mount
/usr/bin/newgrp
/usr/bin/passwd
/usr/bin/su
/usr/bin/sudo
/usr/bin/umount
```

برنامج SUID مملوك لـ root فيه ثغرة يعني صلاحيات root للمهاجم، لذلك يراجع المدافعون قائمة ملفات SUID دورياً ويحققون في أي ملف غير متوقع فيها. وكذلك الملفات التي يكتب فيها الجميع:

```terminal
$ ls -ld /tmp
drwxrwxrwt 2 root root 4096 Nov  8 09:00 /tmp
```

`t` في نهاية `/tmp` هو **Sticky Bit**: الجميع يكتب فيه، لكن لا يحذف أحد ملفات غيره.

? ما الفرق بين apt update و apt upgrade؟

- لا خطورة
- يبطئ الإنترنت
> اقرأ السكربت أولاً أو ثبّت من المستودع الرسمي.

? لماذا تزيل البرامج التي لا تحتاجها من الخادم؟
+ لأن كل برنامج إضافي قد تكون فيه ثغرة، فتقل مساحة الهجوم
- لتوفير الكهرباء
- لا داعي لذلك
> تقليل مساحة الهجوم (Attack Surface) مبدأ أساسي.
