## لماذا SEO؟

**تحسين محركات البحث (SEO)** يجعل صفحاتك تظهر في نتائج Google وتبدو جذابة عند مشاركتها في وسائل التواصل. العرض على الخادم يمنحك أهم شيء: محتوى حقيقي في HTML. والباقي بيانات وصفية (Metadata) تخبر المحركات والمنصات عن كل صفحة.

## metadata ثابتة

صدّر الكائن `metadata` من أي `layout.tsx` أو `page.tsx`:

```next
// file: app/layout.tsx
import type { Metadata } from "next";

export const metadata: Metadata = {
  title: {
    default: "CodeWay",
    template: "%s | CodeWay",
  },
  description: "منصة عربية لتعلّم البرمجة",
};

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return <html lang="ar" dir="rtl"><body>{children}</body></html>;
}
// file: app/page.tsx
export default function Home() {
  return <h1>الرئيسية</h1>;
}
// file: app/courses/page.tsx
export const metadata = {
  title: "الدورات",
  description: "كل دورات البرمجة في مكان واحد",
};
export default function Courses() {
  return <h1>الدورات</h1>;
}
// test
for (const url of ["/", "/courses"]) {
  const r = await visit(url);
  print(url, "→", r.title, "|", r.meta("description"));
}
```

```output
/ → CodeWay | منصة عربية لتعلّم البرمجة
/courses → الدورات | CodeWay | كل دورات البرمجة في مكان واحد
```

- `template` في التخطيط يضيف اسم الموقع تلقائياً لعنوان كل صفحة: `%s` يُستبدل بعنوان الصفحة.
- `default` للصفحات التي لا تحدد عنواناً.
- الصفحة ترث ما لم تحدده من التخطيطات فوقها.

## metadata ديناميكية: generateMetadata

لصفحة مقال، العنوان يأتي من البيانات. صدّر الدالة `generateMetadata` بدل الكائن:

```next
// file: app/layout.tsx
export const metadata = { title: { default: "مدونة CodeWay", template: "%s | مدونة CodeWay" } };
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return <html lang="ar" dir="rtl"><body>{children}</body></html>;
}
// file: app/blog/[slug]/page.tsx
type Props = { params: Promise<{ slug: string }> };
type Post = { title: string; body: string };

async function getPost(slug: string): Promise<Post> {
  const res = await fetch(`https://api.codeway.dev/posts/${slug}`, { cache: "force-cache" });
  return res.json();
}

export async function generateMetadata({ params }: Props) {
  const { slug } = await params;
  const post = await getPost(slug);
  return {
    title: post.title,
    description: post.body,
    openGraph: { title: post.title, images: [`/og/${slug}.png`] },
  };
}

export default async function PostPage({ params }: Props) {
  const { slug } = await params;
  const post = await getPost(slug);
  return <h1>{post.title}</h1>;
}
// test
const r = await visit("/blog/server-components");
print("title:", r.title);
print("description:", r.meta("description"));
print("og:image:", r.meta("og:image"));
print("طلبات الواجهة:", api.calls);
```

```output
title: مكونات الخادم | مدونة CodeWay
description: تعمل على الخادم فقط وتقلل JavaScript في المتصفح.
og:image: /og/server-components.png
طلبات الواجهة: 1
```

لاحظ أن `getPost` استُدعيت مرتين (للبيانات الوصفية وللصفحة)، لكن الواجهة طُلبت **مرة واحدة** بفضل التخزين.

## Open Graph: شكل الرابط عند المشاركة

`openGraph` يحدد العنوان والوصف والصورة التي تظهر عند مشاركة الرابط في واتساب و X و LinkedIn. صورة بمقاس 1200×630 تجعل الرابط أكثر جذباً للنقر.

## الصور: next/image

الصور غالباً أثقل ما في الصفحة. مكون `Image` من `next/image` يحسّنها تلقائياً:

- يقدّم الصورة **بالمقاس المناسب** لشاشة كل جهاز، وبصيغ حديثة مثل WebP.
- **تحميل كسول (Lazy Loading)**: الصور خارج الشاشة لا تُحمَّل حتى يقترب المستخدم منها.
- يحجز مساحة الصورة مسبقاً بـ `width` و `height`، فلا «تقفز» الصفحة عند تحميلها (CLS).

```next
// file: app/layout.tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return <html lang="ar" dir="rtl"><body>{children}</body></html>;
}
// file: app/page.tsx
import Image from "next/image";

export default function Page() {
  return <Image src="/team.jpg" alt="فريق CodeWay في المكتب" width={400} height={300} />;
}
// test
print((await visit("/")).body.replace(/ (?=[\w-]+=)/g, "\n  "));
```

```output
<img
  alt="فريق CodeWay في المكتب"
  loading="lazy"
  width="400"
  height="300"
  decoding="async"
  data-nimg="1"
  style="color:transparent"
  srcset="/_next/image?url=%2Fteam.jpg&amp;w=640&amp;q=75 1x, /_next/image?url=%2Fteam.jpg&amp;w=828&amp;q=75 2x"
  src="/_next/image?url=%2Fteam.jpg&amp;w=828&amp;q=75">
```

اقرأ ما ولّده المكون: `loading="lazy"` للتحميل الكسول، و `srcset` يعطي المتصفح نسختين (عادية `1x` ومضاعفة `2x` للشاشات عالية الدقة)، وكلها تمر عبر `/_next/image` الذي يغيّر المقاس والصيغة.

## قواعد إلزامية

- `alt` **إلزامي**: وصف للصورة لقارئات الشاشة ومحركات البحث، أو `alt=""` للصور الزخرفية.
- `width` و `height` إلزاميان للصور المحلية والبعيدة، إلا مع `fill`.

```next
// file: app/layout.tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return <html lang="ar" dir="rtl"><body>{children}</body></html>;
}
// file: app/page.tsx
import Image from "next/image";
export default function Page() {
  return <Image src="/logo.png" width={120} height={40} />;
}
// test
print((await visit("/")).error);
```

```output
Image is missing required "alt" property. Please add Alternative Text to describe the image for screen readers and search engines.
```

## صور الواجهة الأولى: preload

الصورة الكبيرة في أعلى الصفحة (Hero) يراها المستخدم أولاً، فلا تجعلها كسولة. أضف `preload` (كان اسمه `priority` قبل Next.js 16):

```tsx
<Image src="/hero.jpg" alt="..." width={1200} height={600} preload />
```

## صورة تملأ حاويتها: fill

عندما لا تعرف المقاس مسبقاً، استخدم `fill` داخل عنصر له `position: relative`، و `sizes` لتخبر المتصفح بعرضها التقريبي:

```tsx
<div style={{ position: "relative", height: 300 }}>
  <Image src="/cover.jpg" alt="غلاف" fill sizes="(max-width: 768px) 100vw, 50vw" style={{ objectFit: "cover" }} />
</div>
```

## الخطوط: next/font

الخطوط من Google Fonts تُطلب عادة من خوادم Google، فتتأخر وتسبب وميضاً في النص. `next/font` **ينزّل الخط وقت البناء ويخدمه من موقعك**، مع خط بديل بنفس المقاسات فلا تقفز الصفحة:

```next
// file: app/layout.tsx
import { Cairo } from "next/font/google";

const cairo = Cairo({
  subsets: ["arabic", "latin"],
  weight: ["400", "700"],
  display: "swap",
});

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="ar" dir="rtl" className={cairo.className}>
      <body>{children}</body>
    </html>
  );
}
// file: app/page.tsx
export default function Page() {
  return <h1>خط القاهرة</h1>;
}
// test
const r = await visit("/");
print("صنف الخط على html:", r.find("html").attr("class").startsWith("__className_"));
```

```output
صنف الخط على html: true
```

- اسم الخط هو الدالة: `Cairo` و `Tajawal` و `Noto_Sans_Arabic` (المسافات تصبح `_`).
- `subsets` إلزامي: يحدد الحروف المطلوبة فقط فيصغر الملف.
- `className` يطبّق الخط، أو `variable` ليصبح متغير CSS تستخدمه مع Tailwind.

## ملخص الدرس

- `Image` يحسّن المقاس والصيغة، ويحمّل كسولاً، ويمنع قفز الصفحة.
- `alt` إلزامي، و `width` و `height` إلزاميان إلا مع `fill`.
- `preload` لصورة الواجهة الأولى، والنطاقات الخارجية تُسمح في `images.remotePatterns`.
- `next/font/google` يستضيف الخط محلياً، و `subsets` إلزامي، و `className` يطبّقه.

## متغيرات البيئة

الأسرار مثل رابط قاعدة البيانات لا تُكتب في الكود ولا تُرفع إلى Git، بل توضع في `.env.local` محلياً، وفي إعدادات الاستضافة عند النشر:

```text
DATABASE_URL="postgresql://..."
STRIPE_SECRET_KEY="sk_live_..."
NEXT_PUBLIC_SITE_NAME="CodeWay"
```

القاعدة الذهبية:

- المتغيرات العادية **للخادم فقط**: تُقرأ بـ `process.env.X` في مكونات الخادم و Server Actions.
- المتغيرات التي تبدأ بـ `NEXT_PUBLIC_` **تُضمَّن في كود المتصفح**، فلا تضع فيها أسراراً أبداً.

```next
// file: .env.local

NEXT_PUBLIC_SITE_NAME=CodeWay
// file: app/layout.tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return <html lang="ar" dir="rtl"><body>{children}</body></html>;
}
// file: app/ClientInfo.tsx
```

## النشر على Vercel

**Vercel** الشركة المطورة لـ Next.js، ومنصتها أسهل طريقة لنشره:

1. ارفع مشروعك إلى GitHub (راجع دورة Git و GitHub).
2. ادخل vercel.com وسجّل بحساب GitHub، ثم **Add New → Project** واختر المستودع.
3. أضف متغيرات البيئة في **Environment Variables**.
4. اضغط **Deploy**. خلال دقيقة يصبح موقعك على رابط مثل `my-blog.vercel.app`.

بعدها يعمل كل شيء تلقائياً:

| الحدث | ما يفعله Vercel |
|---|---|
| push إلى `main` | نشر جديد للإنتاج |
| فتح Pull Request | **نشر معاينة** برابط خاص لمراجعة التغييرات قبل الدمج |
| خطأ في البناء | يبقى الموقع الحالي يعمل ولا يُنشر المعطوب |

ويمكنك ربط نطاقك الخاص (مثل `codeway.dev`) من **Settings → Domains**، مع شهادة HTTPS مجانية تلقائياً.

> 💡 Next.js ليس محصوراً في Vercel: يعمل على أي خادم Node.js بـ `npm start`، وفي Docker، ومنصات مثل Netlify و Cloudflare و AWS Amplify. واختر `output: "export"` في الإعدادات لموقع ثابت بالكامل بلا خادم.

## قائمة ما قبل الإطلاق

- `npm run build` ينجح دون أخطاء أو تحذيرات أنواع.
- كل الأسرار في متغيرات البيئة، ولا شيء منها في `NEXT_PUBLIC_`.
- `metadata` لكل صفحة مهمة، و `sitemap.ts` و `robots.ts` موجودان.
- الصور عبر `next/image` والخطوط عبر `next/font`.
- صفحات `not-found.tsx` و `error.tsx` مصممة.

## ملخص الدرس

- `npm run build` ثم `npm start` لتجربة الإنتاج محلياً، وجدول البناء يوضح نوع كل صفحة.
- الأسرار في `.env.local` وإعدادات الاستضافة، و `NEXT_PUBLIC_` فقط لما يجوز كشفه.
- Vercel: ربط المستودع، ونشر تلقائي مع كل push، ونشر معاينة لكل Pull Request.
