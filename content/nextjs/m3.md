=== lesson
## جلب البيانات في مكون الخادم

رأينا أن مكون الخادم يجلب البيانات بـ `await fetch(...)` مباشرة. لنتعلم كيف نفعل ذلك باحتراف: التعامل مع الأخطاء، والجلب المتوازي، وصفحات التفاصيل.

## التحقق من الاستجابة

`fetch` لا يرمي خطأ عند 404 أو 500، بل يُرجع استجابة `ok` فيها `false`. افحصها دائماً:

```next
// file: app/layout.tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return <html lang="ar" dir="rtl"><body>{children}</body></html>;
}
// file: app/posts/[slug]/page.tsx
import { notFound } from "next/navigation";

type Post = { slug: string; title: string; body: string; author: string };

async function getPost(slug: string): Promise<Post | null> {
  const res = await fetch(`https://api.codeway.dev/posts/${slug}`);
  if (res.status === 404) return null;
  if (!res.ok) throw new Error(`فشل جلب المقال: ${res.status}`);
  return res.json();
}

export default async function PostPage({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params;
  const post = await getPost(slug);
  if (!post) notFound();
  return (
    <article>
      <h1>{post.title}</h1>
      <p>{post.body}</p>
      <small>بقلم {post.author}</small>
    </article>
  );
}
// test
let res = await visit("/posts/caching");
print(res.status, res.text.replace(/\n/g, " | "));
res = await visit("/posts/not-here");
print(res.status, res.text.replace(/\n/g, " | "));
```

```output
200 التخزين المؤقت | إعادة استخدام النتائج تسرّع الموقع. | بقلم سارة
404 404 | This page could not be found.
```

- دالة مستقلة مثل `getPost` تجعل الكود أوضح، ويمكن إعادة استخدامها.
- `notFound()` يوقف العرض ويعرض صفحة 404 بالحالة الصحيحة، وهذا مهم لمحركات البحث.

## الجلب المتتالي: فخ شائع

```next

  return <html lang="ar" dir="rtl"><body>{children}</body></html>;
}
// file: app/page.tsx
const API = "https://api.codeway.dev";
const getJson = (path: string) => fetch(API + path).then((r) => r.json());

export default async function Home() {
  // الطلبان يبدآن في نفس اللحظة
  const [products, posts] = await Promise.all([getJson("/products"), getJson("/posts")]);
  return (
    <main>
      <p>المنتجات: {products.length}</p>
      <p>المقالات: {posts.length}</p>
    </main>
  );
}
// test

print("الطلبات:", api.log.join(" و "));
```

## صفحات ثابتة مسبقاً: generateStaticParams

لصفحات ديناميكية معروفة مسبقاً (مثل كل المقالات)، أخبر Next.js بها، فيبنيها HTML ثابتاً أثناء البناء، وتُخدم فوراً من CDN:

```next
// file: app/layout.tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return <html lang="ar" dir="rtl"><body>{children}</body></html>;
}
// file: app/posts/[slug]/page.tsx
export async function generateStaticParams() {
  const posts: { slug: string }[] = await fetch("https://api.codeway.dev/posts").then((r) => r.json());
  return posts.map((p) => ({ slug: p.slug }));
}

export default async function Post({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params;
  return <h1>{slug}</h1>;
}
// test
await build();
```

## ملخص الدرس

- افحص `res.ok` و `res.status` بعد كل `fetch`، واستخدم `notFound()` للمحتوى غير الموجود.
- اجمع منطق الجلب في دوال مثل `getPost` لإعادة الاستخدام.
- الطلبات المستقلة تُجلب معاً بـ `Promise.all` بدل انتظار كل منها.
- `generateStaticParams` يبني الصفحات الديناميكية مسبقاً أثناء البناء.

=== lesson
## لماذا التخزين المؤقت؟

لو كانت صفحة المنتجات تطلب الواجهة الخارجية مع كل زائر، فعشرة آلاف زائر يعني عشرة آلاف طلب، رغم أن المنتجات لا تتغير كل ثانية. **التخزين المؤقت (Caching)** يحفظ نتيجة الطلب ويعيد استخدامها: صفحات أسرع، وتكلفة أقل، وضغط أقل على الخوادم.

## السلوك الافتراضي: بلا تخزين

منذ Next.js 15، `fetch` **لا يُخزَّن** افتراضياً: كل زيارة تطلب البيانات من جديد:

```next
// file: app/layout.tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return <html lang="ar" dir="rtl"><body>{children}</body></html>;
}
// file: app/page.tsx
export default async function Page() {
  const res = await fetch("https://api.codeway.dev/products");
  const products: unknown[] = await res.json();
  return <p>{products.length} منتجات</p>;
}
// test
await visit("/"); await visit("/"); await visit("/");
print("3 زيارات =", api.calls, "طلبات");
```

```output
3 زيارات = 3 طلبات
```

## التخزين لمدة محددة: revalidate

`next: { revalidate: ثواني }` يحفظ النتيجة لمدة، ثم يجددها. هذا يسمى **ISR (Incremental Static Regeneration)**:

```next
// file: app/layout.tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return <html lang="ar" dir="rtl"><body>{children}</body></html>;
}
// file: app/page.tsx
export default async function Page() {
  const res = await fetch("https://api.codeway.dev/products/1", { next: { revalidate: 60 } });
  const p: { name: string; price: number } = await res.json();
  return <p>{p.name}: {p.price} ر.س</p>;
}
// test
print("1:", (await visit("/")).text, "| طلبات:", api.calls);
api.update("products", 1, { price: 199 });   // تغيّر السعر في المصدر
print("2:", (await visit("/")).text, "| طلبات:", api.calls);
advance(61);                                  // مرت 61 ثانية
print("3:", (await visit("/")).text, "| طلبات:", api.calls);
print("4:", (await visit("/")).text, "| طلبات:", api.calls);
```

```output
1: لوحة مفاتيح ميكانيكية: 250 ر.س | طلبات: 1
2: لوحة مفاتيح ميكانيكية: 250 ر.س | طلبات: 1
3: لوحة مفاتيح ميكانيكية: 250 ر.س | طلبات: 2
4: لوحة مفاتيح ميكانيكية: 199 ر.س | طلبات: 2
```

اقرأ النتيجة بتمعن:

1. أول زيارة: طلب حقيقي، والنتيجة حُفظت.
2. تغيّر السعر في المصدر، لكن النسخة المحفوظة ما زالت صالحة، فبقي السعر القديم دون أي طلب.
3. بعد انتهاء المدة: الزائر يرى النسخة القديمة **فوراً**، وفي الخلفية يجلب Next.js النسخة الجديدة (**stale-while-revalidate**).
4. الزيارة التالية ترى السعر الجديد.

## خيارات fetch

| الخيار | السلوك |
|---|---|
| (افتراضي) أو `cache: "no-store"` | بلا تخزين، جلب في كل طلب |
| `cache: "force-cache"` | تخزين دائم حتى تُبطله يدوياً |
| `next: { revalidate: 3600 }` | تخزين لمدة ساعة ثم تجديد |
| `next: { tags: ["products"] }` | وسم للإبطال اليدوي لاحقاً |

ولتطبيق مدة على كل طلبات الصفحة: `export const revalidate = 3600;` في ملف الصفحة.

## الإبطال عند الطلب

أحياناً لا تريد الانتظار: أضاف المسؤول منتجاً، فيجب أن يظهر الآن. أبطل النسخة المحفوظة من Server Action أو Route Handler:

```ts
import { revalidatePath, revalidateTag } from "next/cache";

revalidatePath("/products");           // كل بيانات صفحة /products
revalidateTag("products", "max");      // كل طلب عليه الوسم products
```

سنستخدم `revalidatePath` عملياً في درس Server Actions.

## ثابت أم ديناميكي؟

أثناء `next build` يقرر Next.js لكل صفحة: هل يبنيها مسبقاً (○ ثابتة) أم يعرضها عند كل طلب (ƒ ديناميكية)؟ تصبح ديناميكية إذا استخدمت ما يختلف من طلب لآخر: `cookies()` أو `headers()` أو `searchParams` أو `cache: "no-store"`:

```next
// file: app/layout.tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return <html lang="ar" dir="rtl"><body>{children}</body></html>;
}
// file: app/page.tsx
export default function Home() {
  return <h1>الرئيسية</h1>;
}
// file: app/products/page.tsx
export const revalidate = 3600;
export default async function Products() {
  const list: unknown[] = await fetch("https://api.codeway.dev/products").then((r) => r.json());
  return <p>{list.length}</p>;
}
// file: app/live/page.tsx
export default async function Live() {
  const t = await fetch("https://api.codeway.dev/time", { cache: "no-store" }).then((r) => r.json());
  return <p>{t.now}</p>;
}
// test
await build();
```

## ملخص الدرس

- `fetch` لا يُخزَّن افتراضياً منذ Next.js 15.
- `next: { revalidate: N }` يخزن N ثانية ثم يجدد في الخلفية (stale-while-revalidate).
- `cache: "force-cache"` تخزين دائم، و `next: { tags }` للإبطال بالوسم.
- `revalidatePath` و `revalidateTag` يبطلان التخزين فوراً عند تغير البيانات.
- `next build` يحدد كل صفحة: ○ ثابتة أو ƒ ديناميكية.

=== lesson
## ما هي Server Actions؟

**Server Actions** دوال تعمل على الخادم، وتستدعيها مباشرة من النماذج والأزرار، دون أن تكتب واجهة برمجية API بنفسك. هي الطريقة الحديثة في Next.js لإضافة البيانات وتعديلها وحذفها.

تُعرّف بالتوجيه `"use server"`، إما في أول ملف مستقل (كل دواله إجراءات)، أو في أول جسم الدالة.

## نموذج يضيف مهمة

```next
// file: app/layout.tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return <html lang="ar" dir="rtl"><body>{children}</body></html>;
}
// file: lib/prisma.ts
import { PrismaClient } from "@prisma/client";
export const prisma = new PrismaClient();
// file: app/actions.ts
"use server";
import { revalidatePath } from "next/cache";
import { prisma } from "@/lib/prisma";

export async function addTodo(formData: FormData) {
  const title = String(formData.get("title") ?? "").trim();
  if (!title) return;
  await prisma.todo.create({ data: { title, done: false } });
  revalidatePath("/");
}
// file: app/page.tsx
import { prisma } from "@/lib/prisma";
import { addTodo } from "./actions";

export default async function TodosPage() {
  const todos = await prisma.todo.findMany();
  return (
    <main>
      <h1>مهامي ({todos.length})</h1>
      <ul>{todos.map((t) => <li key={t.id}>{t.title}</li>)}</ul>
      <form action={addTodo}>
        <input name="title" placeholder="مهمة جديدة" />
        <button type="submit">أضف</button>
      </form>
    </main>
  );
}
// test
const page = await mount("/");
print(page.text.split("\n").slice(0, 2).join(" | "));
await page.fill("input[name=title]", "قراءة توثيق Next.js");
await page.click("button");
print(page.text.split("\n").slice(0, 3).join(" | "));
```

```output
مهامي (1) | تعلّم Server Actions
مهامي (2) | تعلّم Server Actions | قراءة توثيق Next.js
```

ما حدث:

1. `<form action={addTodo}>`: عند الإرسال يستدعي Next.js الدالة **على الخادم** ويمرر لها `FormData`.
2. `formData.get("title")` يقرأ الحقل الذي اسمه `title`.
3. الإجراء يحفظ في قاعدة البيانات (درس قاعدة البيانات يشرح `prisma` بالتفصيل).
4. `revalidatePath("/")` يجعل الصفحة تُعرض من جديد بالبيانات الجديدة.

> 💡 النموذج يعمل **حتى قبل تحميل JavaScript** في المتصفح، لأنه نموذج HTML حقيقي يُرسل للخادم. هذا يسمى Progressive Enhancement.

## التحويل بعد الحفظ: redirect

بعد إنشاء عنصر، غالباً تنقل المستخدم لصفحته:

```ts
"use server";
import { redirect } from "next/navigation";

export async function createPost(formData: FormData) {
  const post = await prisma.post.create({ data: { title: String(formData.get("title")) } });
  redirect(`/posts/${post.id}`);
}
```

## التحقق من المدخلات والأخطاء: useActionState

**لا تثق أبداً بمدخلات المستخدم**: أي شخص يستطيع إرسال أي بيانات لإجراءاتك. تحقق منها على الخادم دائماً. و `useActionState` في مكون عميل يعرض نتيجة الإجراء (مثل رسالة خطأ):

```next

// file: app/actions.ts
"use server";
import { z } from "zod";

const schema = z.object({
  email: z.string().email("البريد الإلكتروني غير صحيح"),
});

export async function subscribe(prevState: { message: string }, formData: FormData) {
  const result = schema.safeParse({ email: formData.get("email") });
  if (!result.success) return { message: result.error.issues[0].message };
  return { message: `تم اشتراك ${result.data.email} ✓` };
}
// file: app/Subscribe.tsx
"use client";
import { useActionState } from "react";
import { subscribe } from "./actions";

export default function Subscribe() {
  const [state, formAction, pending] = useActionState(subscribe, { message: "" });
  return (
    <form action={formAction}>
      <input name="email" />
      <button disabled={pending}>اشترك</button>
      <p>{state.message}</p>
    </form>
  );
}
```

- مكتبة **Zod** الأشهر للتحقق: تصف شكل البيانات، و `safeParse` يُرجع النجاح أو الأخطاء.
- `useActionState(action, initialState)` يعطيك: الحالة الحالية، ودالة تضعها في `action` النموذج، وهل الإجراء جارٍ (`pending`) لتعطيل الزر.

> ⚠️ Server Action مثل أي واجهة برمجية عامة: تحقق من المدخلات، وتحقق من صلاحية المستخدم داخلها قبل أي تعديل.

## ملخص الدرس

- Server Actions دوال `"use server"` تعمل على الخادم وتُستدعى من النماذج مباشرة.
- `<form action={fn}>` يمرر `FormData`، و `formData.get("name")` يقرأ الحقول.
- `revalidatePath` يحدّث الصفحة بعد التعديل، و `redirect` ينقل المستخدم.
- تحقق من المدخلات على الخادم دائماً (Zod)، واعرض النتيجة بـ `useActionState`.

~~~solution
// file: app/actions.ts
"use server";
import { revalidatePath } from "next/cache";
import { prisma } from "@/lib/prisma";

export async function addComment(formData: FormData) {
  const text = String(formData.get("text") ?? "").trim();
  if (!text) return;
  await prisma.todo.create({ data: { title: text, done: false } });
  revalidatePath("/");
}
// file: app/page.tsx
import { prisma } from "@/lib/prisma";
import { addComment } from "./actions";

export default async function Page() {
  const items = await prisma.todo.findMany();
  return (
    <main>
      <h1>التعليقات: {items.length}</h1>
      <ul>{items.map((t) => <li key={t.id}>{t.title}</li>)}</ul>
      <form action={addComment}>
        <input name="text" />
        <button type="submit">أرسل</button>
      </form>
    </main>
  );
}
~~~

--- quiz
? ما الذي يجعل الدالة Server Action؟
+ التوجيه `"use server"` في أول ملفها أو في أول جسمها
- أن تكون async فقط
- أن يكون اسمها يبدأ بـ action
> فتعمل على الخادم وتُستدعى من النماذج.

? كيف يقرأ الإجراء قيمة الحقل `<input name="email">`؟
+ `formData.get("email")`
- `document.querySelector("email")`
- `request.email`
> FormData يحمل كل حقول النموذج بأسمائها.

? لماذا يجب التحقق من المدخلات داخل Server Action حتى لو تحققت منها في المتصفح؟
+ لأن أي شخص يستطيع استدعاء الإجراء مباشرة بأي بيانات، فهو واجهة عامة
- لأن المتصفح لا يدعم التحقق
- ليس ضرورياً
> التحقق في المتصفح لتجربة المستخدم، وعلى الخادم للأمان.
